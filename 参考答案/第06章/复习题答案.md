# 第 6 章 · 课程参考答案

> 对应[本课程练习](../../练习/第06章-练习.md)，题号与原书 6.10 不同。先完成再核对；这里是课程独立编写的答案。

## 怎么用这份答案

先找自己预计走哪条分支，再核对实际走哪条。输出不同时，追踪条件的真假，比照抄输出语句更有用。完整程序在后面的代码链接中，以下解析解释输入、检查和处理的顺序。

## 任务 1：核对实验

1. 范围外拒绝；0–59 未通过，60–79 C，80–89 B，90–100 A。先检查 >=60 会让 95 落入 C。
2. `false && ...` 与 `true || ...` 不执行右侧，另两种会执行。示例输出 calls 依次为 0、1、1、2；除数为 0 时判断直接为假，没有除法。
3. `A b1!\n`：字母 2、数字 1、空白 2、其他 1；若不输入换行则空白 1。分类前转 unsigned char。
4. 三次 larger 为 8、8、4；相等时选择冒号右边，但值仍为 4。
5. x 提示未知，c/C 继续，p/P 输出提示，q/Q 让 running 为 false；break 只退出 switch。
6. 负数走 continue，0 走 break；总和 12，后面的 100 不处理。
7. abc 造成提取失败，先 clear 恢复状态，再 ignore 丢弃到行尾。负数和 101 是读取成功但范围无效，不必清除失败状态。EOF 退出，不再反复询问。
8. count=3、total=27.5、average 约 9.16667；空文件 count=0；`10 bad 20` 报告 Non-numeric data；`10 20 30` 无末尾换行仍数到 3，合计 60。

### 热身A：三个边界要同时认清

| 输入 | 在0–100内 | 输出等级 |
|---|---|---|
| 59 | 是 | 未通过 |
| 60、61 | 是 | C |
| 89 | 是 | B |
| 90、91、100 | 是 | A |
| 101 | 否 | 拒绝，不进入等级判断 |

95若先匹配 `score>=60`，就会进入C分支；同一else if链命中一项后跳过其余项。所以等级下界应从高到低检查，不能随意调换。

### 热身B：独立问题与一次选择

三个独立if输出 `pass good excellent`，因为95满足三项。改成同样顺序的else if链只输出pass。若只想输出最高等级，要先检查>=90，再>=80，最后>=60。

这里不是if或else if谁“更高级”，而是题目是否允许多个动作同时发生。例如“优秀且获奖”可能是两个独立判断；一个等级只能选一档，则用互斥链。

### 热身C：短路表

| 写法 | 是否执行右侧 | 原因 |
|---|---|---|
| false && 右侧 | 否 | 已不可能同时成立 |
| true && 右侧 | 是 | 还要看右侧 |
| false || 右侧 | 是 | 还没找到成立的一项 |
| true || 右侧 | 否 | 已有一项成立 |

因此检查 `d!=0` 放在 `&&` 左边，d=0时右侧除法才不会被执行。交换顺序之后已经做了危险动作，后面的检查没有保护作用。

### 热身D：沿着嵌套层数看退出位置

普通case的break退出switch，下一次while仍会等命令。q/Q先把running改为false，再break离开switch；下一次检查while条件为假，整个菜单结束。

若删除c/C动作后的break，匹配c后会继续执行p/P动作，显示学习提示和进度提示。这叫贯穿；它不是重新检测command是否等于p。

### 热身E：读取成功不代表值合要求

| 输入 | 成功提取整数 | 范围有效 | 要clear吗 |
|---|---|---|---|
| abc | 否 | 尚未得到新整数 | 是，恢复后再丢弃错误行 |
| -1 | 是 | 否 | 不因范围错误而clear |
| 101 | 是 | 否 | 不因范围错误而clear |
| 80 | 是 | 是 | 否 |

clear恢复流状态；ignore丢弃仍留在输入中的坏文字。只clear会再次碰到abc；先ignore但不恢复失败状态，也无法按预期正常丢弃。EOF表示输入结束，应退出而不是要求无限重输。

### 热身F：最后一个数字不依赖换行才成立

空文件0个；无末尾换行的 `10 20 30` 为3个；有换行的版本也是3个，因为数字提取跳过空白； `10 bad 20` 成功读到10之后停止并报告非数字内容。

数值30可以在读到文件末尾时成功提取，此时可能只有eofbit，流转bool仍为真。把读取表达式放在while条件中能保留这次成功；预先检查good或eof会把“上次状态”和“本次是否读成”混在一起。

相对文件名相对于运行时工作目录，而不是保证相对于cpp文件。找不到文件时先确认工作目录和输入路径；可以用绝对路径把这个问题排除。

## 任务 2：正确条件

```cpp
score >= 60 && score <= 100
command == 'q' || command == 'Q'
n % 2 == 0 && n % 26 != 0
index >= 0 && index < size && values[index] == 0
!(a && b)                 // 等价于 !a || !b
```

数组检查依靠从左到右短路：下标不合法时不执行访问。链式比较先得到 0/1，不能表达区间；单独的 `'Q'` 是非零值，会令或条件总为真；先做除法再排除 0 无法保护除法。

### 为什么那三种错误条件看起来像对的

1. `60<=score<=100`先计算 `60<=score` 得到false或true，也就是比较时的0或1。它们都<=100，因此不能筛出正确区间。应把两个完整比较用&&相连。
2. `command=='q'||'Q'`右边不是“command等于Q”，只是字符常量Q；它是非零值，会转为true。应再次写出command的比较。
3. `12/d>2&&d!=0`在到达d的检查前就做了除法；d=0时无法靠短路补救。应先排除0。

数组条件也是同一思路：先保证index非负，再保证小于size，最后才访问values[index]。这里按题目约定两者都是int，避免把有符号负数与无符号长度直接混着比较。

## 任务 3：推演

- A 默认 bool 输出：`1 0 0`；第一项的左边为真，第二项的左边为假，都短路。
- B 输出 `AB`；匹配 a 后继续执行 b 的语句。a 分支末尾增加 break 才只输出 A。
- `while(in >> value)` 尝试读取，成功才进循环体。先用 `good()` 检查是检查上次状态，进入后可能读取失败；而用 `good()` 检查读完的状态，也可能把成功读取且带 eofbit 的末尾数字漏掉。原书做了简化说明，实际写程序应把读取表达式用作条件。

### A. 字符转换：一条输入队伍，逐个处理

完整程序：[ex1.cpp](代码/ex1.cpp)。处理顺序为：

```text
成功get一个字符
    是@？结束
    是数字？跳过本轮
    是大写？转小写
    是小写？转大写
    其他？原样输出
```

| 原字符 | 动作 | 正文输出 |
|---|---|---|
| A | 大写转小写 | a |
| b | 小写转大写 | B |
| 1 | 数字，continue | 无 |
| ! | 保持 | ! |
| 空格 | 保持 | 空格 |
| @ | break | 无，后面的tail不再读 |

因此 `Ab1! @tail` 得到 `aB! `。必须用get保留空白；逐词字符提取 `>>ch`会跳过空格、换行。分类函数前的unsigned char转换使参数符合函数要求，不是为了把文字改成数字正文。

不要把两次转换写成两个彼此独立的if：若先把A改为a，第二个if可能又把它变回A。参考代码用if/else if，让一个输入字符只走一个转换分支。

### B. 十笔数据：实际数量与数组容量分开

完整程序：[ex2.cpp](代码/ex2.cpp)。

| 收到的数据 | 存到下标 | count更新后 | total |
|---|---|---|---|
| 10 | 0 | 1 | 10 |
| 20 | 1 | 2 | 30 |
| 30 | 2 | 3 | 60 |
| x | 不存，读取失败 | 保持3 | 保持60 |

平均值60/3=20。第二次遍历只看下标0、1、2，严格大于20的是30，above为1。没收到的后七项不是数据，不参与平均值也不参加计数。

参考代码的 `data[count++]=value`先用旧count作为下标，再加1；初学时可以拆开：

```cpp
data[count] = value;
++count;
total += value;
```

这样更容易看出“先存进下一格，再增加已存数量”。循环条件先检查count<容量，满十项后不会再读第十一项，也不会访问下标10。

count=0时先输出没有数据再结束，避免除以0；一笔5平均5，高于平均的数量为0。负数或非有限数按题目规则报错，普通非数字则结束收集，两者的含义不同。

### C. 菜单：退出命令改变循环的决定

完整程序：[ex3.cpp](代码/ex3.cpp)。

| 命令 | switch动作 | running | 之后 |
|---|---|---|---|
| x | 未知命令提示 | true | 继续 |
| C | 课程信息 | true | 继续 |

### D. 分段计算：以前走完的段加当前段

完整程序：[ex4.cpp](代码/ex4.cpp)。练习提示给出了按上界从小到大的思路；参考代码按下界从大到小判断，也是互斥的四种情况。两种方向都可以，但相应公式必须匹配。

| 点数所在区间 | 计算 |
|---|---|
| 0–5000 | 0 |
| 超过5000、不超过15000 | (点数−5000)×10% |
| 超过15000、不超过35000 | 1000+(点数−15000)×15% |
| 超过35000 | 4000+(点数−35000)×20% |

6000得到100；16000得到1150；38000得到4600。超过35000之后，前面的两段已贡献1000+3000=4000，只给新增部分乘20%。

边界5000为0、15000为1000、35000为4000；取边界前后值应平滑连接，不会因换档突然把全部点数重算。

这是题目定义的点数数学模型。负数或非数字表示停止；它们不是要套入公式的新数据。浮点提取的能力与有限值检查是两层，参考代码在成功提取后再做isfinite检查。

### F. 文件计数：只给成功读取的字符加1

完整程序：[ex6.cpp](代码/ex6.cpp)。核心是：

```cpp
char ch;
while (in.get(ch)) {
    ++count;
}
```

这里in是已经成功打开的ifstream；char变量只有读取成功后才代表本次新字符。没有读到字符就不会进入体内，不需要预先猜是否到了EOF。

`A b`无末尾换行为3；有一个文本换行为4；空文件为0。文件打不开则报错，不输出“空文件0”，因为没有读到文件与文件确实为空是两个结果。

Windows文本模式可能把磁盘CRLF转换成一个换行；UTF-8中文字符可能占多个字节。因此这里说“文本流读到的字符数”，不把它宣称为磁盘字节数或中文文字个数。

getline能保留文件名中的空格。本题从getline开始，不需先ignore；只有之前的数字/词提取留了换行时，才需要按输入流程处理它。

## 任务 5：实现思路

参考完整程序：[pass_check.cpp](代码/pass_check.cpp)。

1. 用 `getline` 读取路径，用 `ifstream` 打开，失败立即返回。
2. `while(in >> value)` 驱动循环；遇到负数 continue，其他值计数、累加。
3. 循环后检查 bad，再看是不是正常 EOF；发现非数字则返回失败。
4. 不需平均值，所以空文件直接显示数量 0、合计 0。

本章的格式化数字读取接受数字前缀；检测完整文件的所有格式错误还需要更严格的解析。这里的练习约定普通整数，测试非数字项 `bad`，不把本程序宣称为任意文本的完整校验器。

### 用0、−2、7、3追踪过关程序

| 读取值 | 分支 | count | total |
|---|---|---|---|
| 0 | 保留，0也是非负数 | 1 | 0 |
| -2 | continue，跳过本轮累计 | 1 | 0 |
| 7 | 保留 | 2 | 7 |
| 3 | 保留 | 3 | 10 |
| 下一次读取失败于EOF | 不进入体内 | 3 | 10 |

continue不关闭文件，也不终止整个循环。最后的3即使没有换行，也应在一次成功提取后被累计。

`1 bad 2`不是正常EOF：读到1之后在bad处提取失败，应该报告内容不合约定；2未被处理。空文件则是正常EOF，数量与合计都为0。

能自己解释这张表，说明已把第5章的重复、第6章的选择和文件读取连在了一起。

## 常见修正

- 不是所有重复失败都需要 `clear()`：值已读成功但超范围，应调整业务分支；流已失败才恢复状态。
- `clear()` 不删除错误输入；`ignore()` 的行尾丢弃需要在状态恢复之后进行。
- `break` 不会一次跳出所有嵌套循环。
- 文件名 `my data.txt` 不能靠 `cin >> filename` 完整读取。
- 文件最后没有换行不是错误，不应漏掉最后一个成功读取的值。
