## 1. 口头题

### Q1 三种结构参数

| 原型 | 接收什么 | 是否通过参数修改原 Box | 调用 |
|---|---|---|---|
| show(Box box) | Box 值 | 不会因改副本而改原对象 | show(package) |
| update(`Box*` box) | Box 地址值 | 可以沿地址修改 | update(&package) |
| inspect(`const Box*` box) | 只读访问的地址值 | 不允许通过该参数修改 | inspect(&package) |

update 中把形参 box 设为 nullptr 只改指针副本，不删除 package。
普通局部对象不需要用 delete 手动销毁。

### Q2 原生数组与 array 按值

first 的数组形参调整为 `int*`，可以沿地址改到原第一项。
second 按值接收 array 对象，修改副本不改变原对象。

要改原 array 对象，可用：

```cpp
void second(std::array<int, 3>* values);
// main 有 std::array<int,3> data：调用 second(&data)
```

内部先得到对象，再访问项：`(*values)[0]`。不要把整个对象地址和第一项元素地址混淆。

### Q3 递归需要收敛

基本情形是 n==0，直接返回 1；缩小方式是 n-1；子调用返回后乘以当前 n，再返回。
factorial(0) 自身仍执行一次，只是没有后续自调用。

若先把负数转成 unsigned int，值会变成无符号范围内的数，无法再按原意判断是否负数。main 先用 int 接收和检查。

### Q4 地址与数值

square 在函数指针赋值等语境转换为函数地址，&square 显式取地址；square(3) 是调用，得到 double 数值 9。
`double (*pf)(double)` 是指针变量；`double* pf(double)` 是函数声明，函数返回 `double*`。
pf 指向有效 square 时，两种调用都返回 9。

int other(double) 返回类型不同，不能直接赋给上述 pf。值的普通转换规则不等于函数指针类型可以随意转换。

### Q5 函数返回的地址是另一层

函数指针保存函数地址；调用返回的 `const double*` 保存数据元素地址。result 不再指向函数。
若指向 main 的普通局部数组，不能 delete；数组销毁后，这个元素地址也不再可用于读取。

## 2. 手走题

### T1 时长

50+25=75；75/60=1；75%60=15；小时 1+2+1=4，所以结果 4 小时 15 分。
按值参数没有修改原第一段，其值仍为 1 小时 50 分。

### T2 进入与返回

```text
enter 2
enter 1
enter 0
leave 0
leave 1
leave 2
```

leave 0 前没有子调用；leave 1 前 trace(0) 返回；leave 2 前 trace(1) 返回。
若两条输出都放在自调用前，则先 enter 2、leave 2，再 enter 1、leave 1，最后 enter 0、leave 0。
顺序取决于语句放在调用之前还是之后。

### T3 规则表

8、2 的加减乘结果为 10、6、16。
operations[1] 是 subtract 的函数指针；`operations[1](8,2)` 已经执行减法，得到数值 6。
传给 calculate 的第三个参数应是函数指针，不是提前算出的值。

### T4 安全调用前提

成员访问要求指向有效、存活的 Box，不能用 nullptr。
函数调用要求指针已初始化为有效、签名匹配的函数，不能读取未初始化指针并调用。
空指针检查只能识别空值，不会自动识别所有悬空指针；调用者仍需保证对象寿命。

## 3. A：Box 体积

完整程序：[代码/ex1.cpp](代码/ex1.cpp)。

### 两个接口各管一件事

update_volume 接收 `Box*`，通过 `->` 找到原对象字段；show_box 接收 Box 值，显示副本中的所有成员。
maker 使用 string，所以 getline 可以保留名字里的空格，不需要自己计算字符数组容量。

### 顺序为什么是先检查再写入？

函数检查空指针、有限数和尺寸范围，全部成功后才计算 volume。
使用逻辑 || 的短路规则：box==nullptr 为真时，后面的 box->height 等表达式不执行。

```text
main：Box 的 volume 初始0
update_volume(&box)：读2、3、4 → 写volume=24 → 返回true
main：show_box(box) → 显示原记录的新体积
```

返回 bool 是状态，volume 是写回的业务结果，二者用途不同。
某项尺寸为 0 仍满足本题范围，乘积为 0。负数、1001、缺尺寸或空 maker 不进入成功显示。

常见错误：update 按值；调用时遗漏 &；对指针使用点号；把 bool 当体积；验证前就访问空指针成员。

## 4. B：结构里的四项开支

### 结构包着数组，如何访问？

`expenses->values[i]` 分两步：通过指针找 Expenses 对象，再从它的 values 成员数组取第 i 项。
整个记录只需一个地址参数，不用把四个值各传一次。

显示使用 `const Expenses*`，可以读数组项、累计局部 total，不修改原账单。
局部 total 可变与参数数据只读不冲突。

### 不完整账单为什么不显示？

fill 必须成功四次。只有三项时返回 false，main 输出错误并结束，不把剩下的初始 0 解释成冬季实际开支。

输入 100、200、300、400，总数 1000；四个零合法，表示四季都没有开支。

### 失败时已有写入怎么办？

参考实现逐项写入，失败时前面的项可能已更新。本题 main 放弃该记录，符合约定。
若希望原对象完全不变，可以先填临时对象，成功后整体赋值。这是更强的接口约定，需要明确提出并实现。

常见错误：show 也用可写指针且误改数据；fill 提前返回 true；遗漏空指针处理；标签和数组下标错位。

## 5. C：递归阶乘

完整程序：[代码/ex3.cpp](代码/ex3.cpp)。

### 缩小与返回必须都说明

```text
factorial(3) 等 factorial(2)，再乘3
factorial(2) 等 factorial(1)，再乘2
factorial(1) 等 factorial(0)，再乘1
factorial(0) 直接返回1
返回路线：1 → 1 → 2 → 6
```

每层 n 是独立的形参，子调用用 n-1，不是把上一层 n 改了。
`return n*factorial(n-1)` 要先拿到子结果，完成乘法后才能返回本层结果。

### 两种重复分工

main 的 while 反复读不同的 n；factorial 的递归只求当前这一个 n 的结果。
把输入放进 factorial 会改变任务，使递归层次与用户输入次数混在一起。

### 类型与上限

main 用 int 检查 0–20，再传入 unsigned int；返回 unsigned long long。
20! 为 2432902008176640000，参考程序与测试覆盖该上限。负数、21 以上立即报错，不能无限递减或放任结果溢出。

常见错误：0 返回 0；忘记基本情形；调用 n+1；用 int 返回大结果；先转 unsigned 才查负数。

## 6. D：完整记录才计数

完整程序：[代码/ex4.cpp](代码/ex4.cpp)。

### 为什么先用 candidate？

一条记录需要名字、爱好、合法等级。candidate 全部读成功后才复制到 students[count] 并增加 count。
若只有名字，返回 -1，不把半条记录当作有效学生。

```text
读名字 → 非空 → 读爱好 → 读等级并检查
         全部成功 → 存入students[count] → ++count
```

在开始新名字时 EOF 可返回已有 count；在一条记录中途 EOF 则是不完整输入。空名字是明确结束标记。

### 三种显示究竟有什么不同？

| 显示接口 | 调用 | 收到的数据 |
|---|---|---|
| display_value(Student) | students[i] | 一条记录的值 |
| display_pointer(`const Student*`) | &students[i] | 一条记录的只读地址 |
| display_all(const Student[],count) | students,count | 首项地址与有效项数 |

它们显示相同数据，目的是比较接口，而不是生成三份不同记录。
数组显示按 count 遍历，不显示尚未填写的剩余容量。

### 换行处理

>> 读取 level 后，ignore 丢弃到当前行换行；下轮 getline 才能正常接收下一位的名字。
名字与爱好连续使用 getline，之间不额外 ignore，否则可能误吞掉真正的一行。

display_pointer 检查 nullptr 后直接返回。普通数组 records 的元素地址是借用，不 delete。

常见错误：忘记清理等级行换行，提前结束；用 >> 读名字丢掉空格；count 在记录完成前增加；传 Student 值给指针参数；失败仍进入成功显示。

## 7. E：标签与原名字

完整程序：[代码/ex5.cpp](代码/ex5.cpp)。

### 副本负责改名，返回值负责提供新文本

make_label 按值接收 name，逐下标把副本里的空格改为下划线。
main 的 name 仍保留原文字；main 用 label 接住新结果。

```text
main name：Li Ming
函数 name 副本：Li_Ming
返回：[Li_Ming]
main 显示原name并数空格：1
```

空行直接返回 [anonymous]。两个空格并非空字符串，所以返回 [__]，空格数 2。

### string 管理存储

返回的是 string 值，调用者不 delete[]。这和返回借用的 `char*` 或新分配的 char[] 都是不同的接口。
下标循环使用 std::size_t，与 name.size() 的类型匹配；避免 int 与无符号大小比较产生警告。

常见错误：没接返回值；对原 name 直接替换使原名字也变；把只有空格当作 empty；遍历到 size() 本身；把所有空白计为题目指定的单个空格字符。

## 8. F：回调与规则表

完整程序：[代码/ex6.cpp](代码/ex6.cpp)。

### 类型别名先统一接口

Operation 表示指向“两个 double 参数、double 返回值”的函数。
add、subtract、multiply 都满足，才能放进同一个数组。

calculate 内部只写：

```cpp
return operation(first, second);
```

它不用知道规则的名字。main 按下标选函数，提供同一对数。

### 输入 2、3 的一次循环

| i | 传入 calculate 的第三项 | calculate 内调用 | 结果 |
|---|---|---|---|
| 0 | add 的地址 | add(2,3) | 5 |
| 1 | subtract 的地址 | subtract(2,3) | -1 |
| 2 | multiply 的地址 | multiply(2,3) | 6 |

三种规则都初始化为有效目标，所以参考接口按“非空且有效”前提调用。
如果接口允许空目标，需要另外定义失败处理，不能直接调用 nullptr。

### 输入协议与 A 不同

0、0 是合法一对，输出三项 0，不作为退出标记。
读首项非数字或 EOF 结束；读到首项却缺第二项报错；超范围报错。
选择退出条件是程序的任务约定，不能从上一题机械照搬。

常见错误：operations 中装 add(2,3) 的结果；返回类型与参数类型不匹配；把 operations[i] 写成越界下标；标签数量没同步；通过强转压下不匹配；calculate 没 return。
