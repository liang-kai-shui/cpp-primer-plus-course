## 一、任务 2 的 5 个实验

### 实验 A：删掉函数原型会怎样

**参考答案**

把 `04_ourfunc.cpp` 第 15 行的 `void simon(int);` 注释掉再编译，报错是：

```
04_ourfunc.cpp: In function 'int main()':
04_ourfunc.cpp:24:5: error: 'simon' was not declared in this scope
     simon(3);                // 调用 simon，把 3 传进去
     ^~~~~
```

这是**编译期错误**（编译错误），不是链接错误。关键词：**`was not declared in this scope`**（"在此作用域中未声明"）。

原因：编译器**从上往下**读代码，读到 `main()` 里的 `simon(3)` 时，它还没见过 `simon` 这个名字——
C++ 要求**先声明、后使用**。函数原型就是提前给编译器的一张"说明书"。
修好它有两条路：① 把原型加回来；② 把 `simon` 的整个定义挪到 `main()` 前面（函数一多就会乱，所以不推荐）。

**原始作答记录**

> 报错原文抄录为 `error: 'simon' was not declared in this scope`（第 24 行）；
> 错误类型填的是：**编译期**。

**核对结果**

- ✅ 报错原文抄得对，行号（24）也对得上。
- ✅ 错误类型判断正确：这是**编译期**错误，因为编译器在生成目标文件之前就停下了，根本没有 `collect2.exe` / `ld` 那一行。

> **补充说明**：原答案正确。可以再补一句判断口诀：**报错里出现 `error:` 且没有 `collect2` / `ld` / `undefined reference` → 编译期；出现 `undefined reference` / `ld returned` → 链接期。**

### 实验 B：函数定义后多加一个分号会怎样 ★ 重要

**参考答案**

按步骤做完（① 注释掉原型 ② 在函数定义的 `}` 后面加一个 `;`），得到的报错是：

```
04_ourfunc.cpp: In function 'int main()':
04_ourfunc.cpp:24:5: error: 'simon' was not declared in this scope
     simon(3);                // 调用 simon，把 3 传进去
     ^~~~~
```

**和实验 A 一模一样**。也就是说：**这个错误并不是那个分号造成的**，真正的成因是"原型被注释掉了"。
用两次对照编译就能把责任分清楚：

| 改动 | 结果 |
| --- | --- |
| 原型注释掉 + 定义后多一个 `;` | ❌ `error: 'simon' was not declared in this scope`（编译期） |
| 原型**保留** + 定义后多一个 `;`（原型后面再多一个 `;` 也一样） | ✅ **编译通过**，`-Wall -Wextra` 连一个警告都没有 |

原因：函数定义结尾 `}` 后面的 `;`，在 C++ 里是一条**空声明（empty declaration）**。
`;` 单独出现是合法的，编译器直接忽略它。所以"一个分号造成 `undefined reference`"这个说法**不成立**。

⚠️ **这一题要注意**：题目把"注释掉原型"和"多写一个分号"两个改动放在了一起，很容易让人把报错错记在分号头上。
要定位真正的原因，必须**一次只改一个地方**——这正是调试的基本功。

**原始作答记录**

> 编译时报错，其余不清楚

**核对结果**

- ✅ "编译时报错"说对了：确实是**编译期**错误，不是链接期错误（报错里没有 `undefined reference`）。
- ❌ "其余不清楚"——这一题的结论和题目的暗示正好相反，值得记一笔（见订正说明）。

> **订正说明**：原答案写的是「编译时报错，其余不清楚」，正确应为「这是**编译期**错误 `'simon' was not declared in this scope`；而且它**不是那个多余的分号造成的**——分号加在函数定义后面只是一条合法的空声明，编译器会忽略它，真正的原因是原型被注释掉了（见实验 A）。把"原型保留 + 同样多一个分号"再编译一次就能验证：能通过，且没有任何警告」，因为题目把两个改动放在一起做，报错看起来像是分号引起的；只要把两个变量分开单独测，就能发现分号是无辜的。

### 实验 C：原型和定义不一致会怎样

**参考答案**

先按题目的字面做——只把**返回类型**从 `void` 改成 `double`，原型写成 `double simon(int);`，定义不动。
这样得到的是**编译期错误**：

```
04_ourfunc.cpp:40:6: error: ambiguating new declaration of 'void simon(int)'
 void simon(int n)
      ^~~~~
04_ourfunc.cpp:15:8: note: old declaration 'double simon(int)'
 double simon(int);
        ^~~~~
```

关键词：**`ambiguating new declaration`**（含混的新声明）——参数列表相同、返回类型不同的两个声明互相冲突，
编译器在编译阶段就直接报错，**走不到链接那一步**。（返回类型不参与 C++ 的函数重载区分，所以这也不能算重载。）

如果改成**参数类型**也不一致，比如原型写成 `double simon(double);`（定义仍是 `void simon(int n)`），
得到的才是真正的**链接期错误**：

```
<TEMP>/ccXXXXXX.o:04_ourfunc.cpp:(.text+0x1a): undefined reference to `simon(double)'
<TEMP>/ccXXXXXX.o:04_ourfunc.cpp:(.text+0x4c): undefined reference to `simon(double)'
collect2.exe: error: ld returned 1 exit status
```

关键词：**`undefined reference`**（未定义的引用）。原因：`main()` 里调用的是 `simon(double)`，
而程序里只定义了 `simon(int)`——两个函数的**参数列表不同**，属于重载关系，是两个不同的函数，
链接器找不到 `simon(double)` 的函数体。

**原始作答记录**

> 报错原文是 `undefined reference to 'simon(double)'`（两个调用点各一条）；
> "这是哪类错误？关键词是什么？"填的是：`undefined reference`。

**核对结果**

- ✅ 报错原文和"关键词 `undefined reference`"能**互相对上**：抄下来的报错里参数类型是 `simon(double)`，说明当时改的是**参数类型**（不只是返回类型）。
- ⚠️ 但按题目字面（只改返回类型、参数仍是 `int`），实际得到的是**编译期**的 `ambiguating new declaration`，不是链接错误。

> **订正说明**：原答案写的是「`undefined reference`」——如果实验时确实把原型改成了 `double simon(double);`（连带改了**参数类型**），那这个答案是**对的，保留**；但如果严格按题目文字只改**返回类型**（`double simon(int);`），正确应为「**编译期**错误，关键词 `ambiguating new declaration`」，因为同名且参数列表相同的两个函数不能只有返回类型不同——编译器把它当成互相冲突的声明，在编译阶段就报错，根本到不了链接阶段。报错原文里的 `simon(double)` 恰好说明当时改的是参数类型。**建议对照教材附录 J 和题目原文，把这一题的改动步骤再核一遍**（是改返回类型，还是改参数类型）。

### 实验 D：`cin >>` 读字符串

**参考答案**

跑 `03_getinfo.cpp`，先输入 carrots 的数量，再在名字那里输入 `Li Ming`，实际输出是：

```
How many carrots do you have? 3
Here are two more. Now you have 5 carrots.
Enter your name: Li Ming
Hello, Li!
```

关键在最后一行：**`Hello, Li!`**——只读到了 `Li`，`Ming` 丢了。

原因：`cin >> name` 在读到**空白符**时就停止，只把已经读到的 `Li` 存进 `name`，
剩下的 `Ming` 还留在输入缓冲区里。`>>` 读 `char` 数组时读的是**一个"单词"**，不是一整行。
想读整行要用 `cin.getline()`（第 4 章讲）。

**原始作答记录**

> Li，因为空格被视为输入结束了

**核对结果**

- ✅ 正确，而且抓到了关键点：确实是**空白符**终止了这次读取。

> **补充说明**：原答案正确。更精确的说法：`>>` 遇到空白符就停，而**空白符不只有空格**——还包括制表符（Tab）和换行符。所以输入 `Li` 然后直接回车，行为是一样的。

### 实验 E：`-Wall` 抓到的 bug

**参考答案**

把 `02_carrots.cpp` 里的 `int garbage;` 保持**不初始化**（注意：示例代码里现在写的是 `int garbage = 0;`，
做本实验前要先去掉 `= 0`），用 `-Wall` 编译，警告原文是：

```
02_carrots.cpp: In function 'int main()':
02_carrots.cpp:30:56: warning: 'garbage' is used uninitialized in this function [-Wuninitialized]
     cout << "未初始化的变量是: " << garbage << "  <- 每次运行可能都不一样" << endl;
                                                        ^~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
```

注意这是 **warning（警告）而不是 error**：编译照样成功、照样生成 exe，只是程序里 `garbage` 的值是
内存里残留的"垃圾值"，**每次运行可能都不一样**。这正是"未初始化变量"这个 bug 的样子。

把 `int garbage;` 改成 `int garbage = 0;` 之后，警告**没有了**：变量有了确定的初值，
编译器再没有"使用了未初始化变量"的理由可报。

**原始作答记录**

> 警告原文抄录为 `02_carrots.cpp:30:56: warning: 'garbage' is used uninitialized in this function [-Wuninitialized]`；
> "如果把 `int garbage;` 改成 `int garbage = 0;`，警告还在吗？为什么？"填的是：**不在了，因为变量被正确地初始化了**。

**核对结果**

- ✅ 警告原文抄得对，行号列号（30:56）都对得上。
- ✅ 第二问结论和理由都正确。

> **补充说明**：原答案正确。可以再补一句：警告不等于错误，但**未初始化变量这类警告必须当错误处理**——它指向的 bug 会让程序行为不确定（同样的输入，两次运行结果可能不同），是最难查的一类 bug。
>
> ⚠️ 另外提醒：示例代码里这一份当前是 `int garbage = 0;`（已初始化版本），直接编译是**看不到**这条警告的，要先改回 `int garbage;`。

**原始作答记录**

> 答：让预处理器把这个头文件内容都展开复制过来

**核对结果**

- ✅ 正确，"展开复制过来"正是"包含（include）"这个动作的准确描述。

> **补充说明**：原答案正确。可以再补两个术语细节：① 它叫**预处理指令**，在**预处理阶段**完成，早于编译；② 它不以分号结尾（`#include <iostream>;` 里的分号是多余的，第 1 章的实验 C 专门试过这个）。

> **补充说明**：原答案正确。术语上它叫 **using 编译指令**；它的作用范围是**从它出现的位置到所在作用域结束**（放在函数里就只对这个函数生效，见任务 5.3）。

- ✅ 三条都正确，信息完整。

> **补充说明**：原答案正确。可以再概括成一句：函数原型提供三样信息——**返回类型、函数名、形参类型列表**（形参名如 `t`、`n` 写不写都行，编译器不看）。

### 第 10 题：定义函数时，在什么情况下不必使用关键字 `return`？

**参考答案**：当函数的**返回类型是 `void`**（也就是函数不返回值）时，函数体末尾不必写 `return`，
执行到函数体结束就自动返回。例如 `void rattle(int n)`。
在这种函数里写一个不带返回值的 `return;` 也可以，但不是必须的。

**原始作答记录**

> 答：不用返回数据时 比如 int rattle(int n)

**核对结果**

- ❌ 举的例子把返回类型写成了 `int`，恰好把条件说反了。

> **订正说明**：原答案写的是「不用返回数据时 比如 `int rattle(int n)`」，正确应为「当函数的**返回类型是 `void`** 时，例如 `void rattle(int n)`」，因为原答案举的例子 `int rattle(int n)` 的返回类型是 `int`——返回类型是 `int` 的函数**必须**写 `return`（漏写会得到一个不确定的返回值，编译器也会警告），它恰恰是"必须用 return"的典型。判断依据不是"要不要用到返回值"这种主观说法，而是**函数头里写的返回类型是不是 `void`**。

### 第 11 题：`cout` 是未知标识符——原因和 3 种修复方法

**参考答案**

**原因**：`cout` 不是 C++ 的关键字，它是标准库头文件 `iostream` 中、声明在 `std` 名称空间里的一个**对象**。
编译器报"未知标识符"，说明这个名字在当前位置对它不可见——最可能的原因是程序**没有写 `#include <iostream>`**；
或者是写了头文件，但**既没有 `using` 指令、也没有用 `std::` 限定**。

**3 种修复方法**：

1. **补上头文件**：在文件开头加上 `#include <iostream>`（前提是原本就缺这个头文件）。
2. **让 `std` 中的名字可见**：加 `using namespace std;`，或更精确地只加 `using std::cout;`。
3. **不加 `using`，直接写全限定名**：`std::cout << "Please enter your PIN: ";`

**原始作答记录**

> 原因：（空）
>
> 修复方法 1：std::cout
> 修复方法 2：using namespace std
> 修复方法 3：自己定义一个名为cout的函数

**核对结果**

- ❌ "原因"一栏是空的，没答。
- ✅ 方法 1（`std::cout`）**是正确的方法之一**——等价于标准答案的第 3 种：用全限定名。
- ✅ 方法 2（`using namespace std;`）正确。
- ❌ 方法 3（"自己定义一个名为 cout 的函数"）是错的。

> **订正说明**：原答案的第 3 种方法写的是「自己定义一个名为 `cout` 的函数」，正确应为「**直接用全限定名 `std::cout`**」（如果把原答案的方法 1、3 对调，就正好是标准答案的第 1、3 种方法），因为：① `cout` 是一个**对象**，不是函数，自己定义一个同名的东西并不能替代它；② 就算真定义了，也只是把标准库的名字**遮住**，不但解决不了"编译器不认识这个标识符"的问题，还会引入名称冲突这类新麻烦。另外原答案的"原因"一栏是**空的**，这里补上——报错的意思就是"编译器没见过 `cout` 这个名字"，也就是**头文件或名称空间限定缺失**。

### 5.1 写一个"两个函数 + 函数原型"的小程序

**参考答案**（一个求两数之和的版本）：

```cpp
#include <iostream>

int fun1(int x, int y);          // 函数原型

int fun1(int x, int y)
{
    return x + y;
}

int main()
{
    using namespace std;
    int num1, num2;
    cout << "输入两个数，会输出相加: ";
    cin >> num1 >> num2;

    int sum = fun1(num1, num2);
    cout << "相加结果: " << sum << endl;

    return 0;
}
```

输入 `3 4`，输出：

```
输入两个数，会输出相加: 相加结果: 7
```

**原始作答记录**

```cpp
#include <iostream>
int fun1(int x,int y)

int fun1(int x, int y) {
    return x + y;
}

int main() {
     using namespace std;
    int num1, num2;
    cout << "输入两个数，会输出相加: ";
    cin >> num1 >> num2;

    int sum = fun1(num1, num2);
    cout << "相加结果: " << sum << endl;

    return 0;
}
```

**核对结果**

- ✅ **思路完全对**：先写 `fun1`，`main` 里读入两个数、调用 `fun1` 求和再输出——结构正是题目要的"两个函数"。
- ✅ `using namespace std;` 放在了 `main` **内部**，这正是 5.3 推荐的做法。
- ❌ **这段代码编译不过**。第 2 行 `int fun1(int x,int y)` 后面**少了分号**，它不是一条完整的声明；紧接着第 4 行又出现了同样的函数头，编译器把两行连在一起解析，于是报错：

```
original.cpp:4:1: error: expected initializer before 'int'
 int fun1(int x, int y) {
 ^~~
original.cpp: In function 'int main()':
original.cpp:14:15: error: 'fun1' was not declared in this scope
     int sum = fun1(num1, num2);
               ^~~~
```

> **订正说明**：原答案第 2 行写的是 `int fun1(int x,int y)`（**没有分号**），正确应为「**要么删掉这一行，要么在行尾补上分号**」——补上分号它才是一条合法的**函数原型**，删掉也可以，因为后面第 4 行就是函数定义、且定义写在 `main` 之前，编译器已经先见过它了。原答案之所以一行报出 3 个错，是因为第一条错误（`expected initializer before 'int'`）让编译器没能登记 `fun1` 这个函数，于是 `main` 里调用 `fun1` 又引发了"未声明"的连锁错误——**看报错时要从第一条看起**，后面几条往往只是它的后果。

### 5.2 两条报错分别属于哪类错误？往哪个方向排查？

```
a) error: 'simon' was not declared in this scope
b) undefined reference to `simon(int)'
```

**参考答案**

| | 错误类型 | 关键词 | 往哪个方向排查 |
| --- | --- | --- | --- |
| a | **编译期错误** | `was not declared in this scope` | 名字在使用前没有声明：函数原型漏了 / 名字拼错 / 大小写不符 / 定义在别的作用域里 |
| b | **链接期错误** | `undefined reference` | 名字声明了但**没有定义**：函数体漏写 / 定义在别的 `.cpp` 里而那个文件没参与编译链接 / 定义的参数列表和调用的不一致（是重载，不是同一个函数） |

一句话区分：**a 是"编译器不认识这个名字"，b 是"编译器认识这个名字，但链接器找不到它的实现"。**

**原始作答记录**

> 答：a：函数没有提前声明，b：没有在main函数里定义函数头

**核对结果**

- ✅ a 说对了：就是"函数没有提前声明"（缺原型或声明在使用之后）。
- ❌ b 说错了：与"有没有在 `main` 里定义"无关。

> **订正说明**：原答案 b 写的是「没有在 `main` 函数里定义函数头」，正确应为「**函数只有声明、没有定义**（或者定义所在的源文件没有参与链接，或定义的参数列表与调用不一致）」，因为 `undefined reference` 是**链接器**报的错——它的意思是"我在所有目标文件里都找不到 `simon(int)` 这个函数的实体"。函数**定义在 `main` 外面**恰恰是最常见的正确写法（本章练习 3、5、6、7 全都是这么写的），所以"没在 `main` 里定义"根本不是问题所在。判断口诀：看到 `undefined reference` 就去找**函数体**，而不是去找它的声明位置。

### 5.3 `std::cout` 里的 `std::` 是干什么的？为什么推荐把 `using namespace std;` 放进函数内部？

**参考答案**

`std::` 里的 `std` 是**标准库的名称空间（namespace）**，`::` 是**作用域解析运算符**。
`cout`、`cin`、`endl` 这些名字都声明在 `std` 里面，所以写 `std::cout` 就是告诉编译器：
"我要用的是 **`std` 这个名称空间里的** `cout`，不是别的同名东西。"——`::` 相当于给名字加了一个"姓"，用来消除歧义。

把 `using namespace std;` 放在**函数内部**，作用范围就只限于**那一个函数**；放在文件顶部，则是**整个文件**都生效。推荐放函数内部，原因有两个：

1. **减少名字冲突**：一旦在文件顶部写了它，`std` 里的**所有**名字（`count`、`distance`、`data`、`swap`……成百上千个）都变得可见，很容易和你自己定义的、或别的头文件里的同名标识符撞车，而且报错信息往往指不到真正的原因。
2. **意图更清楚**：作用范围越小，读代码的人越容易看出"这个函数在用标准库的名字"；文件顶部一条 `using namespace std;` 会让整个文件的所有名字来源都变得模糊（教材 2.4.5 节讨论的就是这个取舍）。

**原始作答记录**

> 答：std::相当于一个名为std的大容器，里面存放了关于基础函数的声明，比如cout cin函数，直接在顶部用using namesapce std；相当于全局声明，后续如果自己创建了一个名叫cout的函数，在调用这个自己创建的函数时就会和iostream中的cout定义冲突了，如果使用，std::cout就表示使用iostram中的cout函数

**核对结果**

- ✅ **核心意思是对的**：`std::` 是"指明用 `std` 里的那个名字"，而把 `using namespace std;` 放顶部会扩大可见范围、可能和自己定义的同名东西撞车。
- ❌ 有两处术语不准：`std` 不叫"大容器"，它是**名称空间**；`cout`、`cin` 是**对象**，不是"函数"。另外 `std::cout` 的含义是"使用 `std` 里的 `cout` 对象"，不是"使用 `cout` 函数"。
- ❌ 两处拼写错误：`namesapce` → `namespace`，`iostram` → `iostream`。
- ⚠️ 还漏了推荐放函数内部的第二个理由：**缩小作用范围、让意图更清楚**。

> **订正说明**：原答案写的是「`std` 相当于一个名为 `std` 的大容器，里面存放了关于基础**函数**的声明，比如 `cout`、`cin` **函数**」，正确应为「`std` 是一个**名称空间**，`cout`、`cin` 是声明在其中的**对象**（`cout` 是输出流对象、`cin` 是输入流对象）」，因为名称空间的作用是给名字划分"姓氏"以避免重名，它本身不是容器；而 `cout` / `cin` 是**对象**——你写 `cout << x` 是在对一个对象做运算符操作（调用重载的 `<<`），并不是在调用一个叫 `cout` 的函数。这个区别在第 8 章讲类与对象时会变得很重要。另外原答案里 `namesapce`、`iostram` 两处拼写要改（写错了会直接编译报错）。

---

## 附：本章要记住的三句

1. **声明可以有多个，定义只能有一个。** 函数原型就是"提前给编译器一张说明书"；少了它，`main()` 里调用就会报 `was not declared in this scope`（编译期），而不是 `undefined reference`（链接期）。
2. **`cin >>` 遇到空白符就停。** 读 `char` 数组时只能读到一个"单词"（输入 `Li Ming` 只得到 `Li`），想读整行要用 `cin.getline()`（第 4 章）。
3. **`return` 不是必需的，只看返回类型。** 返回类型是 `void` 才不必写；返回类型是 `int` 之类的，必须写。
