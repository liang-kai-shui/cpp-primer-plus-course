# 摸底测试 · 说明

## 这是什么

`diagnostic.cpp` 是一份**独立的自动测试程序**，用来判断你的 C++ 基础在什么位置，
好决定后面的内容从哪里讲起、讲多细。

它**不是考试**，不计分，也没有及格线。

## 里面有什么

- **10 个函数的声明**（题目）——你只需要把**函数体**填上
- **一套自动测试程序**（已写好，不要改）——共 **28 项**检查
- 函数原型已经给好了，**不要改函数名、参数类型、返回类型**，只填 `{ }` 里的内容

| 题号 | 函数 | 难度 |
|---|---|---|
| 1 | `sum_to` | 基础 |
| 2 | `is_prime` | 基础 |
| 3 | `count_vowels` | 基础 |
| 4 | `swap_ints` | 探测（引用） |
| 5 | `average` | 基础 |
| 6 | `reverse_str` | 基础 |
| 7 | `find_max` | 基础 |
| 8 | `fib` | 进阶 |
| 9 | `sort_vec` | 进阶 |
| 10 | `find_ptr` | 探测（指针） |

## 怎么用

1. 用 VS Code 打开 `diagnostic.cpp`
2. 从上往下实现这 10 个函数，**实现一个就保存，然后运行一次**
   （`Ctrl+Alt+N`，或对着文件右键 → Run Code）
3. 看输出里 `[通过]` 的项数有没有变多
4. 全部做完、或者卡住了，就停下来看结果

## 初始状态是 35%，做不出来很正常

**你什么都不写、直接运行，结果会是「通过 10 项，未通过 18 项（正确率 35%）」。**

这 10 项**不是**你答对的，而是题目里本来就有的**边界情况**碰巧对上了——
比如 `sum_to(0)` 期望 `0`，而空的函数体返回的也正是 `0`；`is_prime(1)` 期望 `false`，
空函数体返回的也是 `false`。

**所以：**

- 35% 是**起点**，不是你的水平
- 做不出来**完全正常**，这里面有超过一半的内容是第 4 章、第 8 章才讲的
- 顶部标了 `[探测]` 的题目（引用、指针）不会做是**预期之内**的，直接跳过
- 卡住了就**空着**，测试会诚实地显示 `[未通过]`，这比随便填一个值有用得多

> 这份材料里，**空着**比**猜一个**有价值。因为它的用途就是找出边界在哪里。

## ⚠️ 绝对不要去问 AI 要答案

**不要**把这份文件贴给任何 AI、不要搜索"`fib` 怎么写"、不要找现成代码抄。

原因很简单：**这份测试唯一的用途，就是测出你真实的位置。**

- 你把 AI 生成的答案填进去 → 测出来的是「AI 会什么」，不是「你会什么」
- 后面就会按错误的起点安排内容 → 该补的基础被跳过 → 学到一半处处卡壳
- **浪费的是你自己的时间**

**空着不丢人，作弊才丢人。** 卡住的地方恰恰是这份测试最有价值的信息。

## 编译说明（可选）

程序开头是一个**中文控制台兼容处理**：Windows 上把控制台输出代码页切成 UTF-8，
避免中文变乱码；非 Windows 平台或没有这个头文件时，它会自动跳过，**不需要做任何额外配置**。

如果编译时提示找不到 `utf8_console.h`，说明你手上的版本是旧版，把 `#include <utf8_console.h>`
这一行删掉即可（程序照常运行，只是 Windows 控制台里的中文可能显示为乱码）。

编译命令（在 `diagnostic.cpp` 所在目录打开终端）：

```powershell
g++ -std=c++17 -Wall -g diagnostic.cpp -o diagnostic.exe
.\diagnostic.exe
```

> 提示：函数声明顺序在文件顶部集中列了一次，定义写在其后的注释块里，**按注释里的题号顺序做**最省事。
