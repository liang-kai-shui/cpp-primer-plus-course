# 错误分类实验 · 参考答案

> ⚠️ **先自己做预测、自己编译跑一遍再看这里。**
> 猜错才有收获——猜错了说明你的直觉需要修正，这正是这份实验的目的。

**标本文件位置**：`示例代码/01_错误分类实验/`（6 个 `.cpp`，可直接编译运行）

> 💡 **先说明一个容易混淆的点**：下文里「**标本编号 A–F**」只是文件的标签；
> 而讲义里另外讲了一套「**类型 A / B / C / D / E**」——那是**错误的分类**。
> **两套编号不是一一对应的**，读的时候以「类型」为准。

## 标本 A：`A_missing_semicolon.cpp` —— 漏了一个分号

**类型：编译错误（第 ①②③ 步出的问题）**

真实报错：

```
A_missing_semicolon.cpp: In function 'int main()':
A_missing_semicolon.cpp:7:38: error: expected ';' before 'return'
     std::cout << "hello世界" << std::endl
                                      ^
                                      ;
     return 0;
     ~~~~~~
```

- 生成 exe 了吗？**没有**
- **注意行号陷阱**：报错说 `7:38`，但第 7 行是 `return 0;`。**真正的错误在第 6 行末尾**——上一行漏了分号。
- 记住这个规律：**GCC 报错的行号，经常指向「发现错误的地点」，而不是「错误本身」**。
  当你看到 `expected ';' before X` 这类消息，先去检查 **X 的上一行末尾**。

## 标本 B：`B_undefined_function.cpp` —— 只有声明，没有定义

**类型：链接错误（第 ④ 步出的问题）**

真实报错：

```
C:\Users\...\Temp\a1b2c3d4.o:B_undefined_function.cpp:(.text+0x18): undefined reference to `add(int, int)'
collect2.exe: error: ld returned 1 exit status
```

- 生成 exe 了吗？**没有**
- 关键词：**`undefined reference to 'add(int, int)'`** = 「未定义的引用」
- 出现 `collect2.exe` / `ld` → 说明是**链接器**在报错，不是编译器

**注意报错里那个 `C:\Users\...\Temp\a1b2c3d4.o`** —— 这是编译器在临时目录里生成的目标文件
（就是第 ③ 步的 `.o`）。说明编译（①②③）**全部成功了**，问题只出在最后一步：
`add` 被调用，但全世界的目标文件和库里都找不到它的机器码。

> 📌 这种「在报错里找已经生成的目标文件路径」的方法很有用：
> **只要 `.o` 出现了，就说明编译三步全过了，问题一定在链接。**

**正确写法**：补上函数体

```cpp
int add(int a, int b)
{
    return a + b;
}
```

## 标本 C1：`C_type_mismatch.cpp` —— 类型不匹配

**类型：编译错误（类型问题，也在第 ①②③ 步）**

源码：
```cpp
#include <string>
int main()
{
    std::string s = 12345;      // 想用整数初始化 string
    return 0;
}
```

真实报错：

```
C_type_mismatch.cpp: In function 'int main()':
C_type_mismatch.cpp:9:21: error: conversion from 'int' to non-scalar type
'std::__cxx11::string' {aka 'std::__cxx11::basic_string<char>'} requested
```

- 生成 exe 了吗？**没有**
- 关键词：**`conversion from 'int' to ... requested`** = 「要求从 int 转换到 …，但不允许」
- `{aka 'std::__cxx11::basic_string<char>'}`：`aka` = 「also known as」，
  真实类型叫 `basic_string<char>`，`string` 只是个别名。**这个 `__cxx11` 前缀是 GCC 的旧 ABI 命名**，
  看到它不要慌，它就是在说「字符串类型」。

> 📌 **类型错误和语法错误都属于「编译错误」**（A 是少了符号，C1 是类型不兼容），
> 但它们的报错关键词不同：
> - 语法错 → `expected ';' before ...`（**编译器在找符号**）
> - 类型错 → `conversion ... requested` / `cannot convert`（**编译器在检查类型**）
>
> 处理方式一样：**去看报错定位的那一行，或者它的上一行。**

## 标本 C2：`C_extra_semicolon.cpp` —— `#include` 后面多写了分号

**类型：只是一个警告（warning），不是错误**

真实输出：

```
C_extra_semicolon.cpp:6:20: warning: extra tokens at end of #include directive
 #include <iostream>;
                    ^
```

- 生成 exe 了吗？**生成了！** 而且程序正常运行，输出「能跑吗」，退出码 0

**所以「`#include` 后面不能加分号」这句话的准确版本是**：

- 加了分号**不会报错**，程序照样跑
- 但编译器会**警告**你 `extra tokens at end of #include directive`（该指令末尾有多余的记号）
- 所以要**养成不加分号的习惯**——不是因为会崩，而是因为这是错的写法，
  在别的编译器上可能就真报错了

> 📌 **顺便注意行号**：报错说第 **6** 行，可 `#include` 明明在第 1 行。
> 因为 `#include` 是**预处理指令**，第 ① 步展开后你的代码在预处理结果里跑到第 6 行了。
> GCC 很聪明，它同时知道两种位置，这里报的是展开后的位置。
> **看到行号和你的文件对不上时，先想想是不是预处理（`#include`/`#define`）导致的。**

> 💡 **`warning` 和 `error` 的区别**：`error` 会让编译**停止**，不产出 exe；
> `warning` 会**继续编译**，产出 exe。但**警告往往就是未来的 bug**——
> 尤其在有几百行代码的项目里，一个小警告通常正是问题的起点。

## 标本 D：`D_divide_by_zero.cpp` —— 整数除以 0

**类型：运行时错误（前四步全部成功，跑起来才崩）**

真实结果：

| 项目 | 结果 |
|---|---|
| 编译器输出 | **什么都没有**（`-Wall -Wextra` 也没警告） |
| 生成 exe | **成功** |
| 程序输出 | 只有 `程序开始运行` 一行 |
| 退出码 | **-1073741676** |

**两个关键点：**

1. **`这一行会被打印吗？` 没有被打印** —— 说明程序在 `a / b` 那一行**直接崩掉了**，
   后面的代码一行都没执行。
2. **退出码 `-1073741676` 是什么？**
   换成十六进制是 `0xC0000094`，这是 Windows 的错误码
   `STATUS_INTEGER_DIVIDE_BY_ZERO` —— **整数除零异常**。
   （顺便记住：退出码 0 = 正常结束；**非 0 = 出问题了**。以后程序「没输出」的时候，先看退出码。）

> **为什么编译器和 `-Wall -Wextra` 都没发现？**
> 因为 `a` 和 `b` 是变量，**编译器在编译期不知道 `b` 的值是 0**。它没法预知。
> 这类「值在运行时才确定」的错误，编译器永远帮不了你——**这就是为什么你必须自己写测试**。

## 标本 E：`E_array_out_of_bounds.cpp` —— 数组越界

**类型：运行时错误 —— 而且是 C++ 里最危险的一类**

真实结果：

| 项目 | 结果 |
|---|---|
| 编译器输出 | **什么都没有**（`-Wall -Wextra` 也没警告！） |
| 生成 exe | **成功** |
| 程序输出 | `1 2 3 3 ` |
| 退出码 | **0（正常结束！）** |

**请仔细看这个结果：**

- `a` 只有 3 个元素，但循环访问了 `a[0]` `a[1]` `a[2]` **`a[3]`**
- `a[3]` 是**越界**的，它属于别的变量（甚至是别的函数的内存）
- 程序**没有崩溃**，**退出码 0**，输出 `1 2 3 3`
- 那个多出来的 `3` 是**内存里的垃圾数据**，这次恰好是 3，下次可能是一千万，也可能是负数

**这就是 C++ 最坑的地方**：

> **C++ 默认不检查数组越界。** 它相信你写的下标是对的，
> 直接把「`a` 的起始地址 + 3×4 字节」那个位置的内存给你。
> 这个行为叫 **未定义行为（undefined behavior, UB）**——
> 标准里说「这种情况下的行为不做任何保证」。
> 它可能：正常跑出错误结果 / 崩溃 / 有时对有时错 / 在某些编译器上跑得「看起来正常」。
> **全都是「合法」的。**

**为什么这个比标本 D 危险**：

- D 崩了 → 你**知道**出问题了
- E 没崩、退出码 0、看着像正常输出 → 你**以为**没问题，
  然后程序把错误的数据写进了数据库

**怎么防**：

1. 老老实实写 `i < size`，别写 `<=`
2. 用 `std::vector` 并用 `.at(i)` 访问（越界会抛异常；`[]` 不检查）
3. 打开编译器的检查开关（讲指针时可以用 `-fsanitize=address`）
4. **写测试，把边界情况都试一遍**

## 汇总表

| 标本 | 类型 | 属于哪一步 | 生成 exe? | 关键词 | 怎么排查 |
|---|---|---|---|---|---|
| A | 编译错误（语法） | **编译期** | ❌ | `error: expected ';' before ...` | 看报错行的**上一行** |
| B | 链接错误 | **链接期** | ❌ | `undefined reference to` / `ld returned` | 查函数定义、查参与编译的文件 |
| C1 | 编译错误（类型） | **编译期** | ❌ | `conversion ... requested` | 看报错行，检查类型是否兼容 |
| C2 | 警告（不是错误） | 预处理期 | ✅ | `warning: extra tokens` | 只是不规范，但养成好习惯 |
| D | 运行时错误（崩溃） | **运行期** | ✅ | 退出码 `-1073741676` | 崩了 → 看退出码 + 定位到出错行 |
| E | 运行时错误（静默） | **运行期** | ✅ | **无任何提示** | 最危险，只能靠测试和工具 |

> 💡 **D 和 E 都属于运行期错误，但 D 崩了、E 没崩。**
> 这两条放在一起看，才看得出「不崩溃」有时候比「崩溃」更麻烦。

## 你现在应该建立的条件反射

看到红色报错，**第一句话问自己**：

> **「有 exe 吗？」**

- **没有 exe**，报错里有 `error:` + `文件:行:列` → **编译错误**，去看行号处（或上一行）
- **没有 exe**，报错里有 `undefined reference` / `ld` / `collect2` → **链接错误**，
  去查函数定义和编译命令里漏掉的文件
- **有 exe** 但结果不对或崩了 → **运行时错误**，去写测试、打日志、上调试器

**这个分类框架，你在整个 C++ 学习过程中每天都会用到。**
