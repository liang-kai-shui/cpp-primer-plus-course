> 这一部分就是补上被跳过的地基。**如果你已经能不看资料默写一个 hello world 程序，可以直接跳到第 1 节**；否则请按顺序读完这 10 小节。

## 0.1 程序、源代码、编译（第 1 章的一句话回顾）

三个词，三句话：

| 词 | 白话解释 | 对应文件 |
|---|---|---|
| **程序** | 给计算机的一张**任务清单**，一行一个动作，计算机从上往下照着做 | —— |
| **源代码** | 你用文本写的那份清单（人能看懂的字母和符号） | `.cpp` 文件 |
| **编译** | 把这份清单**翻译**成机器能看懂的 0/1 | `.exe` 文件 |

**编译这一句就够用**（第 1 章讲过完整的四步：预处理 → 编译 → 汇编 → 链接）。这里只强调一个后果：

> ⚠️ **代码没编译成功，程序就不存在。** 编译器不通过，你连一个 exe 都拿不到，
> 也就谈不上"运行看看效果"。所以第 1 章那套错误分类（编译错误 / 链接错误 / 运行错误）
> 从这一章开始天天要用。

顺便记住两句结论，后面第 1、7 节会用到：

- **编译错误**：编译器"读不懂"你写的字。**代码根本没变成机器码。**
- **链接错误**：每个文件都读懂了，但"说好有的东西"找不到实物。关键词 `undefined reference`。

## 0.2 什么是语句？分号是干什么的？

**语句（statement）= 给计算机下的一条命令。**

写作文用句号"。"断句，写 C++ 用**分号 `;`** 断句。就这么简单：

```cpp
int carrots;                    // 语句 1：申请一个整数变量
carrots = 25;                   // 语句 2：把 25 放进去
cout << carrots << endl;        // 语句 3：把它打印出来
```

三条命令 → **三个分号**。少了分号，编译器就不知道一条命令到哪儿结束：

```cpp
int carrots = 25
std::cout << carrots << std::endl;   // ← 上一行漏了分号
```

实测报错（GCC 8.1.0）：

```
error: expected ',' or ';' before 'std'
```

翻译过来就是："我读到这里，本来期待一个 `,` 或 `;`，结果遇到了 `std`。" —— **凡是看到 `expected ... before ...`，第一反应就是"上一行的分号是不是漏了"。**

### 两条新手一定要知道的分号规矩

| 情况 | 要不要分号 | 说明 |
|---|---|---|
| 普通语句 | **要** | `int a = 5;`、`cout << a;` |
| 预处理指令 `#include <iostream>` | **不要** | 它不是 C++ 语句，是给"预处理器"的命令。加了会警告 `extra tokens at end of #include directive` |
| 函数头 + 函数体 `int main() { ... }` | **`}` 后面不要** | `}` 已经结束了函数，再加 `;` 是多写了一个"空语句" |
| 函数**原型** `void simon(int);` | **要** | 原型是一条语句，必须有分号（第 7 节详讲） |
| 复合语句 `{ ... }` 里面的每条语句 | **要** | 括号只是把语句包起来，不代替分号 |

### 一个反直觉但很重要的事实：C++ 不关心你换行

C++ 是**自由格式**语言——**换行、空格、缩进对编译器毫无意义，它只认分号。**下面这段代码照样能编译，输出 `5`：

```cpp
int main()
{
    int a
        =
        5
        ;
    std::cout << a << std::endl;
    return 0;
}
```

所以：

- **缩进和换行是写给"人"看的**（第 8 节讲风格），不是写给编译器看的；
- 但**分号是写给编译器看的**，一个都不能少。

## 0.3 什么是变量？为什么 C++ 必须先声明类型？

### 比方：内存是一排储物柜，变量是给柜子贴的标签

计算机的内存可以想象成一排**储物柜**。你想存东西，就得：

1. 挑一个（或几个）柜子 → `int carrots;`
2. 给柜子贴上一个标签 → 标签名 `carrots`
3. 说清楚这个柜子是放什么规格的东西 → 类型 `int`（整数）
4. 往里放东西 → `carrots = 25;`
5. 以后需要的时候，报标签名就能取出来 → `cout << carrots;`

**为什么需要变量？** 因为程序要**记住东西**。要记住用户刚才输入的数字、要记住运算的中间结果、要记住循环到第几轮了。没有变量，程序算完就忘，什么也做不了。

```cpp
#include <iostream>

int main()
{
    using namespace std;

    int carrots;                        // ① 声明：申请一个柜子，贴标签 carrots
    carrots = 25;                       // ② 赋值：把 25 放进柜子
    cout << "carrots = " << carrots << endl;

    carrots = 30;                       // ③ 同一个柜子，换个东西放（旧值被覆盖）
    cout << "carrots = " << carrots << endl;

    int total = carrots + 5;            // ④ 声明 + 初始化：读 carrots，加 5，放进新柜子 total
    cout << "total = " << total << endl;

    return 0;
}
```

输出：

```
carrots = 25
carrots = 30
total = 35
```

一句话总结：**变量就是一个"有名字、有类型、能反复改"的存储位置。**

### 为什么 C++ 必须先声明类型？

因为**柜子的规格不一样**：

- `int`（整数）：只装整数，比如 `25`、`-7`、`0`
- `double`（双精度浮点数）：装小数，比如 `3.14`、`-0.5`
- `char`（字符）：装单个字符，比如 `'A'`、`'7'`
- `bool`（布尔）：只装"真 / 假"

计算机内存里存的全是 0 和 1，**它自己看不出这串 0/1 到底是数字 65 还是字符 `'A'`**。类型就是"怎么解释这串 0/1"的说明书。所以 C++（**静态类型**语言）要求你**在编译期就把类型写清楚**：

```cpp
int a = 5;          // ✅ 说明"a 里是整数"
a = "hello";        // ❌ 编译错误：柜子装不下字符串
```

对比一下：有些语言（比如 Python）不用声明类型，因为它在**运行时**才去判断。代价是慢、而且错误要跑到那一行才暴露。C++ 选择"编译期就查清楚"，代价是你**必须多写一个类型名**。这笔交易在第 1 章已经算过一遍。

### 变量名的四条规矩（教材 p38 讲过）

| 规矩 | 例子 |
|---|---|
| 只能用**字母、数字、下划线** | `carrots2`、`my_count` ✅；`my-count` ❌ |
| **不能以数字开头** | `2a` ❌ → `error: expected unqualified-id before numeric constant` |
| **区分大小写** | `Carrots` 和 `carrots` 是**两个不同的变量** |
| **不能用保留字**（语言自己用的词） | `int`、`return`、`if`、`class` ❌ → `error: expected unqualified-id before '=' token` |

> 💡 保留字完整列表在教材**附录 B（p859）**。取名前对一眼，能省很多莫名其妙的报错。

**取名还有一条没有写在语法里的规矩**：名字要能说明它的用途。`count` 好过 `c`，`totalPounds` 好过 `tp`。三个月后的你读代码时，会感谢现在的你。

## 0.4 什么是函数？

### 最直白的解释

> **函数（function）= 一段有名字、可以被反复使用的代码块。它有输入，有输出。**

`main` 就是一个函数，`sqrt` 也是函数，你自己也能造函数。三个特征：

| 特征 | 术语 | 在代码里长什么样 |
|---|---|---|
| 有**名字** | 函数名 | `add` |
| 有**输入**（可以有 0 个、1 个或多个） | 参数（parameter） | `(int a, int b)` |
| 有**输出**（也可以没有） | 返回值（return value） | 前面那个 `int` |

### 比方：函数是一台榨汁机

| 榨汁机 | 函数 |
|---|---|
| 机器上写着"榨汁机" | 函数**名字**：`juice` |
| 你得往里放水果 | **参数**：放进去的原料 |
| 出来一杯果汁 | **返回值**：加工的结果 |
| 按下开关 | **调用**（call）：写 `juice(苹果)` |
| 榨一次、榨一百次都行 | **可复用**：写一次，到处调用 |
| 机器内部怎么转你不需要知道 | **黑盒**：你只需要知道"给它什么、它给你什么" |

**为什么需要函数？** 两个理由，都会在后面章节反复出现：

1. **不用重复自己**。同一段代码要用五次，就写一个函数调用五次；要改的时候只改一个地方。
2. **把大问题拆成小问题**。`main` 只负责"流程"，细节交给专门的函数（第 7.6 节展开）。

### 代码长什么样

```cpp
#include <iostream>

int add(int a, int b)        // ← 函数定义：返回类型 int，名字 add，两个 int 参数
{
    return a + b;            // ← return：把结果 a+b 交给调用者
}

int main()
{
    using namespace std;

    int x = 3;
    int y = 4;
    int sum = add(x, y);     // ← 调用：把 x、y 交给 add，等它算完，结果存进 sum
    cout << x << " + " << y << " = " << sum << endl;

    return 0;
}
```

输出：

```
3 + 4 = 7
```

把 `int add(int a, int b) { return a + b; }` 这一行拆开看，每一块都有名字：

| 部件 | 在这行里 | 作用 |
|---|---|---|
| 返回类型 | `int` | 函数算出来的结果是什么类型 |
| 函数名 | `add` | 调用时用的名字 |
| 参数列表 | `(int a, int b)` | 要喂给它什么：**类型 + 名字**，各写一遍 |
| 函数体 | `{ return a + b; }` | 真正执行的部分；`return` 把结果交出去 |

前三块合起来叫**函数头**（`int add(int a, int b)`），它同时也是这个函数的"规格"。

调用的时候，括号里放的是**实参**（实际给的值，这里是 `x`、`y`）；定义里括号里放的是**形参**（接收用的占位名字，这里是 `a`、`b`）。**实参和形参是两回事**：`x` 的值被"复制"给 `a`，改 `a` 不会动 `x`（教材第 7 章会细讲）。

### 三个词，一张表（看到就对应上）

| 术语 | 白话 | 例子 |
|---|---|---|
| 函数定义（definition） | "这机器**怎么做**的"——带 `{ }` 的实物 | `int add(int a, int b) { return a + b; }` |
| 函数声明 / 函数原型（prototype） | "有这么台机器，规格是这样"——一张说明书，**没有** `{ }` | `int add(int a, int b);` |
| 函数调用（call） | "开一下这台机器" | `add(3, 4)` |

> 📌 **"原型"是这一章的核心概念**，第 7 节会用一大节专门讲。
> 现在你只需要先记住：**原型是说明书，定义是实物，调用是使用。**

## 0.5 什么是注释？为什么注释很重要？

**注释（comment）= 写在代码里、但编译器完全忽略的文字。** 它只给人看。

C++ 有两种写法：

```cpp
// 单行注释：从 // 开始，到这行结束

/* 多行注释
   可以跨好几行。
   注意：它不能嵌套——第一个 */ 出现时，注释就结束了。 */
```

| | `//` | `/* ... */` |
|---|---|---|
| 范围 | 到行尾 | 到 `*/` 为止 |
| 能嵌套吗 | 无嵌套概念 | **不能嵌套**（第一个 `*/` 就结束了） |
| 推荐 | ✅ 日常用它 | 只在临时注释掉一大段代码时用 |

### 为什么注释很重要？

三个理由，按重要性排序：

1. **代码是写给"三个月后的自己"看的**。你一定会忘记当时为什么那么写。
2. **代码说明"是什么"，注释才能说明"为什么"**。程序里最贵的信息是意图。
3. **它是你调试的开关**。怀疑某几行有问题，用 `//` 注释掉，编译运行看现象——这是最常用的调试手段。

### 唯一一条原则

> **注释解释"为什么"，不解释"是什么"。**

```cpp
carrots = carrots - 1;    // ❌ 让 carrots 减 1        ← 废话，代码本身已经说了
carrots = carrots - 1;    // ✅ 吃掉一根              ← 说明业务含义
```

再看一个"好注释"的例子：

```cpp
cin.get();     // 等待用户按回车再退出，否则双击运行时窗口会一闪而过
```

这行代码本身看不出为什么要有；**注释把它存在的原因说清楚了**。这就是好注释。

> ⚠️ 反面教材：注释和代码**不一致**比没有注释更糟。改了代码不改注释，
> 下一个人（包括你自己）会被带进沟里。

## 0.6 `main` 函数为什么特殊？

### 它是程序的**入口**

一个 C++ 程序可以有很多函数，但**有且只有一个 `main`**。操作系统启动你的程序时，做的事就是：

> "找到 `main`，从这个函数的第一行开始执行。"

所以：

- **`main` 不是"第一个写的函数"，而是"第一个被执行的函数"**。你写在前面的其他函数，**如果没有被调用，一行都不会执行**。
- 名字必须是 `main`，**全小写**。写成 `Main` 或 `mian`（手滑）都不行。
- 返回类型必须是 `int`。

实测：一个文件里有函数但**没有 `main`**，编译器读得懂，但链接时找不到入口：

```
undefined reference to `WinMain'
collect2.exe: error: ld returned 1 exit status
```

（`Main`、`mian` 报的是同一条错。补充一句：Windows 上的 MinGW 工具链把"缺少控制台入口"报成 `WinMain`——`WinMain` 是 Windows 图形程序的入口名；教材上另一些环境报的是 `undefined reference to 'main'`。**两种都是"链接错误 + 少了入口函数"，含义完全一样。**）

### 四条规矩

| 规矩 | 说明 |
|---|---|
| 名字必须是 `main` | 全小写。写成 `Main` 或 `mian` → 链接错误 `undefined reference to ...`（见上） |
| 返回类型是 `int` | **不要写 `void main()`**。教材 p30 明确说：这不是标准选项，有些系统上跑不了。在这套 GCC 8.1.0 上实测直接报编译错误：<br>`error: '::main' must return 'int'` |
| `()` 里空着 | C++ 里 `int main()` 和 `int main(void)` **完全等价**（C 里不等价）。两种写法都能编译运行 |
| 必须有 `return` | `main` 是**唯一**可以省略 `return` 的函数（编译器自动补 `return 0`），写不写都能跑通，但**建议写**——显式写出来更清楚 |

### 骨架长这样

```cpp
#include <iostream>          // ① 预处理指令：把 iostream 的内容原样插进来（没有分号！）

int main()                   // ② 函数头：程序从这里开始执行
{                            // ③ 函数体开始
    using namespace std;     // ④ 让 std 里的名字可以直接用（第 2 节详讲）

    cout << "Hello!" << endl;

    return 0;                // ⑤ 返回给操作系统：0 表示"一切正常"
}                            // ⑥ main 的 } 后面不写分号
```

### `return 0` 到底是什么？

它是**返回给操作系统**的，叫**退出码**：

- **0 = 成功**；**非 0 = 出错**。
- 第 1 章的除零实验里看到 `-1073741676`，就是这个值。
- 以后写脚本、做命令行工具、让别的程序判断"你跑成功了没有"，全靠这个数。

在 Windows 命令行里可以自己验证：

```powershell
.\01_myfirst.exe
echo $LASTEXITCODE      # 输出 0
```

## 0.7 什么是头文件 `#include`？

**一句话：`#include` 是告诉预处理器"把那个文件的内容，原样抄到这一行的位置"。**

`#include <iostream>` 的意思就是："把系统里那个叫 `iostream` 的文件打开，内容整段复制粘贴到这里。"

- 为什么要这么做？因为 `cout`、`cin` 这些东西**不是你发明的**，是标准库提供的。它们在哪里"登记"？在 `iostream` 这个文件里。你抄过来，编译器才认识它们。
- 所以：**用 `cout` / `cin` 就必须 `#include <iostream>`**，反过来，如果不用它们，其实可以不加。
- 它是**预处理指令**，不是 C++ 语句：**行尾不加分号**，而且习惯写在文件最上面。
- "预处理"是编译的第一步，第 1 章的编译四步里讲过，细节回看第 1 章。

差别在于 `#include <iostream>` 和 `#include "myfile.h"` 的搜索路径不同（尖括号找系统目录，引号先找当前目录）——这是后面多文件工程（第 9 章）的内容，**现在不用管**。

具体细节和第 1.3 节一起看。

## 0.8 `cout` 到底是什么？为什么它能输出各种类型？

### 先讲"对象"是什么（白话版）

> **对象（object）= 一个"自带功能的数据包裹"。**

普通变量的比喻是"储物柜"：只存东西，不会做事。对象比它多一层：**它不光存着数据，还自带一堆"能对它做的操作"**。

比方：普通变量是一块**砖**；对象是一台**收音机**——收音机里也有零件（数据），但你还**能按按钮**（功能）。按钮在哪、怎么按，都写在它的"设计图"里。

### `cout` 就是这个东西

| 问题 | 答案 |
|---|---|
| `cout` 是什么？ | 一个**对象**，代表"标准输出"（默认就是屏幕） |
| 它的"设计图"（类型）是什么？ | `ostream` 类（**o**utput **stream**，输出流） |
| 它在哪儿登记？ | `<iostream>` 头文件里 |
| 它的名字在哪个箱子里？ | `std` 名称空间里，所以全名是 `std::cout`（第 2 节详讲） |
| 怎么用它？ | 用 `<<` 把东西"塞"进去 |

```cpp
#include <iostream>

int main()
{
    using namespace std;

    cout << "int:    " << 42 << endl;          // 输出 42
    cout << "double: " << 3.14 << endl;        // 输出 3.14
    cout << "char:   " << 'A' << endl;         // 输出 A
    cout << "字符串: " << "hello" << endl;      // 输出 hello
    cout << "表达式: " << 2 + 3 * 4 << endl;    // 输出 14（先算出 14 再输出）

    return 0;
}
```

输出：

```
int:    42
double: 3.14
char:   A
字符串: hello
表达式: 14
```

### 为什么它能输出各种类型？

因为 `<<` 不是一个符号，而是**一整套同名的操作**：给整数一个版本、给小数一个版本、给字符一个版本、给字符串一个版本……**你写 `<<`，`cout` 自己按右边东西的类型去挑合适的那个版本。**

所以你可以把 `cout` 想成一台"**会自己适应各种类型的输出器**"：你给它什么，它都能正确地打成文字。

> 📌 `<<` 的正式名字是**插入运算符**（insertion operator）。它能被这样"一个符号对应多种类型"，靠的是**运算符重载**（第 11 章会教你自己也给自己的类定义 `<<`）。**现在不用懂原理，只要会用。**

### 一个必须知道的后果

因为 `cout` 住在 `std` 里，**不写 `std::` 又不写 `using`，编译器就不认识它**：

```cpp
#include <iostream>
int main()
{
    cout << "Please enter your PIN: ";   // ← 没写 std:: 也没 using
    return 0;
}
```

实测报错：

```
error: 'cout' was not declared in this scope
note: suggested alternative: 'std::cout'
```

读法（很重要）：**`'xxx' was not declared in this scope`** 的意思是"`xxx` 这个名字我不认识，在我看的这个范围里找不到它"。而 GCC 还很贴心地补了一句 `suggested alternative: 'std::cout'`——**它已经告诉你正确写法了。报错信息要读到最后一行。**

> 💡 教材 p53 复习题第 11 题就是考这个场景，并且要求你写出**三种**修复方法。

## 0.9 `endl` 和 `\n` 是什么？为什么要换行？

### 计算机不会自己换行

`cout << "A"; cout << "B";` 的结果是 `AB` 粘在一起——**计算机只在你明确说"换行"的时候才换行。**

两个办法：

| 写法 | 是什么 | 效果 |
|---|---|---|
| `endl` | 一个**操纵器**（manipulator），来自 `std` | 换行 **+ 强制刷新输出缓冲区** |
| `'\n'` | **一个字符**：换行符（转义序列） | 只换行 |
| `"\n"` | 一个**字符串**，里面只有一个换行符 | 只换行，效果同上一行 |

三者实测：

```cpp
#include <iostream>

int main()
{
    using namespace std;

    cout << "A" << 'B' << "C";       // 没有换行 → 和后面粘在一起
    cout << "D" << endl;             // 换行，输出 ABCD
    cout << "E" << '\n';             // 换行
    cout << "F" << "\n";             // 换行
    cout << "G" << endl;

    cout << "制表:\tX" << endl;      // \t 是制表符（横向跳一格）
    cout << "反斜杠:\\" << endl;
    cout << "引号:\"" << endl;

    return 0;
}
```

输出：

```
ABCD
E
F
G
制表:	X
反斜杠:\
引号:"
```

### 为什么必须换行？

两个理由，都是**给人**的：

1. **可读性**。所有输出挤在一行，人根本没法看。
2. **提示和输入不会粘在一起**。比如 `cout << "Enter your age: ";` 后面不换行（故意的），
   光标就停在同一行等你输入，看起来才自然；而结果输出前要换行，否则会变成
   `Enter your age: 29 348 months.` 这种糊在一起的句子。

### 转义序列小表（反斜杠开头的"暗号"）

| 写法 | 含义 |
|---|---|
| `\n` | 换行 |
| `\t` | 制表符（对齐用） |
| `\\` | 一个反斜杠本身 |
| `\"` | 一个双引号（否则会提前结束字符串） |
| `\'` | 一个单引号（写字符字面量时用） |

### `endl` 和 `'\n'` 怎么选？（教材 p36 / p757）

| | 做什么 | 代价 |
|---|---|---|
| `endl` | 换行 **+ 刷新缓冲区** | 每次刷新都有一次系统调用开销 |
| `'\n'` | 只换行 | 快 |

**学习阶段随便用**，可读性优先（`endl` 名字更直白）。写大量输出（比如循环里几十万行）时改成 `'\n'` 会快很多。教材 p757 有更详细的讨论。

## 0.10 `cin` 怎么用？`>>` 在干什么？

`cin` 是 `cout` 的"镜像"：

| | `cout` | `cin` |
|---|---|---|
| 是什么 | 标准输出流对象 | 标准输入流对象 |
| 代表 | 屏幕 | 键盘 |
| 类型 | `ostream` 类 | `istream` 类 |
| 用的符号 | `<<` **插入**运算符 | `>>` **抽取**运算符 |
| 方向记忆 | 数据被**塞进** `cout`（流向屏幕） | 数据被**抽出** `cin`（从键盘流进变量） |
| 头文件 | `<iostream>` | `<iostream>`（同一个） |

**`>>` 在干什么？** 它像一根从键盘接过来的水管，`>>` 就是"舀一勺"：

```cpp
int hours;              // 先准备好柜子
cin >> hours;           // 从键盘的输入流里抽出一个数，按 hours 的类型理解，放进去
```

**箭头的方向就是数据的流向**：`cout << x` 是把 `x` 送出去，`cin >> x` 是把外面的东西抽进 `x`。记住这一点就不会写反。

完整例子（后面第 4 节还会细讲它的坑）：

```cpp
#include <iostream>

int main()
{
    using namespace std;

    int hours = 0, minutes = 0;                 // 顺便初始化，避免垃圾值（见 3.3）

    cout << "Enter the number of hours: ";      // ① 先提示，否则程序会"发呆"等输入
    cin >> hours;                               // ② 读一个整数

    cout << "Enter the number of minutes: ";
    cin >> minutes;

    cout << "Time: " << hours << ":" << minutes << endl;

    return 0;
}
```

运行（输入 9 和 28）：

```
Enter the number of hours: 9
Enter the number of minutes: 28
Time: 9:28
```

三条实用建议：

1. **先 `cout` 提示，再 `cin` 读**。程序不会主动跟你说"我在等你输入"，光秃秃的黑窗口会让人以为死机了。
2. **一次可以读多个**：`cin >> a >> b;` 等价于 `cin >> a; cin >> b;`（中间用空格或回车隔开都行）。
3. **⚠️ `cin >>` 遇到空白符就停**——这是个大坑，第 4 节专门讲。

# 1. 程序骨架（2.1，p29–37）

## 1.1 `main()` 的规矩（2.1.1，p30）

```cpp
int main()          // 返回类型是 int
{                   // 函数体开始
    ...
    return 0;       // 返回 0 表示"正常结束"
}                   // 结束
```

四条规矩：

| 规矩 | 说明 |
|---|---|
| 名字必须是 `main` | 全小写。写成 `Main` 或 `mian` → 链接错误 `undefined reference to 'main'`（在这套 MinGW 工具链上，报错原文是 `undefined reference to 'WinMain'`，原因见 0.6） |
| 返回类型是 `int` | **不要写 `void main()`**。教材 p30 明确说：这不是标准选项，有些系统上跑不了。GCC 8.1.0 实测直接报 `error: '::main' must return 'int'` |
| `()` 里空着 | C++ 里 `int main()` 和 `int main(void)` **等价**（C 里不等价） |
| 必须有 `return` | main 是**唯一**可以省略 `return` 的函数（编译器自动补 `return 0`），但**建议写** |

> ⚠️ **`main` 的 `}` 后面不要加分号。**
> 很多资料在这里会写"加了会报错"——**实测修正一下**：GCC 8.1.0 在 `-std=c++17` 下
> 会**默默接受**这个多余的分号（C++11 起标准允许"空声明"），只有加 `-pedantic` 才提示
> `warning: extra ';' [-Wpedantic]`。
> **但它依然是坏习惯**，而且会让你误以为"函数定义要加分号"，进而写出 7.3 节那个真正的坑。
> 结论不变：**`}` 后面不写分号。**

**`return 0` 到底是什么？** 它是返回给**操作系统**的。第 1 章实验 D（除零）里看到的退出码 `-1073741676`，就是这个值。**0 = 成功，非 0 = 出错**——以后写脚本、做命令行工具全靠这个。

## 1.2 注释（2.1.2，p32）

```cpp
// 单行注释，从 // 到这行结束

/* 多行注释
   可以跨行 */
```

**写注释的最高原则**（书上没直说，但这是行业共识）：

> 注释解释 **为什么**，不解释 **是什么**。

```cpp
carrots = carrots - 1;    // ❌ 让 carrots 减 1（废话，代码本身已经说了）
carrots = carrots - 1;    // ✅ 吃掉一根（说明业务含义）
```

再看一个"好注释"的真实例子——很多 Windows 控制台程序结尾都有这么一行：

```cpp
cin.get();                // 等一个回车再退出，否则双击运行时窗口一闪而过
```

`cin.get()` 这行本身看不出为什么要有，注释把**存在的原因**说清楚了。**这就是好注释。**

（第 0.5 节已经把注释的前因后果讲全了，这里只补教材的原文视角。）

## 1.3 预处理与头文件（2.1.3–2.1.4，p33）

复习第 1 章的结论：`#include <iostream>` 是**预处理指令**，把 `iostream` 的**内容**原样插进来。它是编译的第一步（预处理），和编译四步对得上。

**头文件名的新旧对比**（书 p33 讲了）：

| 旧式（C 风格，也能用） | 新式（C++ 风格，推荐） |
|---|---|
| `<iostream.h>` | `<iostream>` |
| `<math.h>` | `<cmath>` |
| `<string.h>` | `<cstring>` |

差别：新式头文件把名字放进 `std` 名称空间，旧式放在全局。**用新式**——这也是为什么下面那句话是必须的。

# 2. ⭐ 名称空间（2.1.5 p34 + 2.4.5 p50–52）

## 2.1 为什么会有 `std::`

C++ 标准库把**所有名字**都装进了一个叫 `std` 的"箱子"里（std = **st**andar**d**）。

**为什么非要装箱子？** 因为怕撞名。举个真实场景：

```cpp
// 你自己写了个函数叫 sort
void sort(int* a, int n) { ... }

// 标准库也有个 sort（在 <algorithm> 里）
// 如果不装箱子，编译器就分不清你要用哪个 → 报错
```

（上面这段是**示意片段**：`{ ... }` 表示函数体省略。）

有了名称空间就清楚了：

```cpp
::sort(a, n);          // 你的（:: 表示全局）
std::sort(a, a + n);   // 标准库的
```

**所以 `std::cout` 的完整意思是**："标准库箱子里的那个 `cout`"。
`::` 叫**作用域解析运算符**（教材 p34）。

### 撞名不是"可能发生"，是"一定会发生"——实测给你看

经常有人问："`using namespace std;` 我用了半年都没出过事，为什么说它危险？"
因为它的危险是**可复现**的，只是要等到你引入某个头文件的那一天。看：

```cpp
#include <iostream>
#include <algorithm>
using namespace std;          // ← 把 std 里的所有名字都倒进全局

int count = 0;                // ← 自己又定义了一个叫 count 的变量

int main()
{
    cout << count << endl;    // ← 灾难现场
    return 0;
}
```

实测报错：

```
error: reference to 'count' is ambiguous
note: candidates are: 'template<class _IIter, class _Tp> ... std::count(_IIter, _IIter, const _Tp&)'
note:                 'int count'
```

`ambiguous` = "有歧义，我不知道你要哪个"。**你的 `count` 和 `std::count` 撞上了，`using namespace std;` 把它们混在了同一层。** 这就是"污染"两个字的具体含义：不是你写错了什么，而是**你引入了太多本来不需要的名字**。

## 2.2 四种写法（教材 p52 总结）

看示例文件 **`示例代码/02_开始学习C++/06_namespace.cpp`**，四种写法都在里面，跑一遍对照着看。

| 写法 | 代码 | 影响范围 | 评价 |
|---|---|---|---|
| ① 全局 using | 文件顶部 `using namespace std;` | **整个文件**所有函数 | 最省事，最容易污染 |
| ② 函数内 using | 写在函数体内 | 只有该函数 | 小偷懒，挺好 |
| ③ 只引入需要的 | `using std::cout;` | 只引入指定的名字 | **推荐**，明确 |
| ④ 完全不用 | 每次写 `std::cout` | 无 | **最安全**，头文件里必须这样 |

跑一遍 `06_namespace.cpp` 的输出（四种写法依次命中）：

```
[写法③] using std::cout; 只引入需要的名字
[写法②] using namespace std; 写在函数内部，只影响本函数
[写法④] 每次都写前缀 std:: ，最明确、最安全
（这行用了 std::string，因为上面没 using std::string）
```

注意最后一行：写法 ③ 只引入了 `cout` 和 `endl`，**没有**引入 `string`，所以用 `std::string` 时还得把前缀写全。**这就是 ③ 和 ① 的区别：③ 的影响范围是你亲手点名的那些名字。**

## 2.3 给读者的具体建议

```
现在（学习阶段）  → 用 ②：把 `using namespace std;` 写在 main 里
L13（多文件工程）→ 头文件里绝对不能用 ①②，必须用 ④
代码超过 300 行   → 开始用 ③
```

> 📌 **为什么 ① 不好？** 教材 p52 也提到了这一点。假设你写了 `using namespace std;`，
> 然后自己定义了一个叫 `count` 的变量——但 `std` 里也有个 `std::count`。
> 平时没事，某天你 `#include <algorithm>` 之后就莫名其妙报错了（2.1 节有实测报错原文）。
> **② 的影响范围最小，是最适合学习阶段的选择。**

# 3. 语句（2.2，p38–40）

## 3.1 六种语句（教材 p52 总结）

| 语句类型 | 例子 | 作用 |
|---|---|---|
| 声明语句 | `int carrots;` | 定义变量的名称和类型 |
| 赋值语句 | `carrots = 25;` | 用 `=` 给变量赋值 |
| 消息语句 | `cout << "hi";` | 把消息发给对象，激发行动 |
| 函数调用 | `simon(3);` | 执行函数 |
| 函数原型 | `void simon(int);` | 声明函数的返回类型和参数 |
| 返回语句 | `return 0;` | 把一个值返回给调用者 |

> 📌 第 0.2 节讲过"语句就是一条命令，分号就是句号"。
> 这张表是把"命令"按**功能**分了六类——考试喜欢考分类，写代码时不必想分类。

## 3.2 声明 ≠ 定义（这是本课的隐藏主线）

| | 声明（declaration） | 定义（definition） |
|---|---|---|
| 是什么 | **说明书**："有个叫 X 的东西，长这样" | **实物**："X 具体怎么做" |
| 变量 | `extern int a;` | `int a;`（分配内存） |
| 函数 | `int f(int);` | `int f(int x) { return x; }` |
| 能有几个 | 可以有很多个 | **只能有一个** |

**这个区别会在三个地方咬你**：

1. 第 1 章的链接错误：只有声明没有定义 → `undefined reference`
2. 本课的函数原型：先给编译器一份说明书
3. 第 13 章的多文件工程：头文件放声明，`.cpp` 放定义

## 3.3 初始化 vs 赋值

```cpp
int a = 5;      // 初始化（创建时就给值）—— 推荐
int b;          // 只声明
b = 5;          // 赋值（之后才给值）
```

**不初始化的后果**：里面是内存里的**垃圾值**。看示例
**`示例代码/02_开始学习C++/02_carrots.cpp`**——它故意演示了这个，编译时会给你一个警告：

```
warning: 'garbage' is used uninitialized in this function [-Wuninitialized]
```

> 💡 **这个警告就是第 1 章讲的道理**：开了 `-Wall`，编译器主动帮你找 bug。
> 不加 `-Wall` 的编译命令，这类 bug 会静悄悄地溜过去。
>
> **动手实验**：把文件里那句 `int garbage = 0;` 改成 `int garbage;`（只声明、不赋值），
> 重新编译，警告就会出现；改回去，警告消失。
> （示例文件里为了"能直接跑出正常输出"，默认写成了 `= 0`，所以你要自己动手改一次才能看到警告。）

**为什么必须初始化？** 因为"声明"只是**要来一块内存**，它不会顺便帮你擦干净。那块内存上一个程序用过的内容还在里面，你读到的就是那些"没擦掉的残留"——每次运行可能都不一样。所以：

> **规矩：声明变量时顺手给它一个初始值。** 这一条能帮你避开后面几年里一大类"程序行为莫名其妙"的 bug。

# 4. `cin` 输入（2.3.1，p41）

```cpp
int carrots;
cin >> carrots;        // >> 叫"抽取运算符"，从输入流里抽出数据
```

（`cin` 和 `>>` 的白话解释见第 0.10 节。）

**`cin` 的两个特性**：

1. **智能转换**：你输入 `25`，它自动变成 `int` 存进 `carrots`。你输入 `25.7` 到 `int` → 只读 `25`，`.7` 留在缓冲区里（第 3 章细讲这个坑）
2. **⚠️ `cin >>` 读字符串遇到空白符就停**

第 2 点一定要亲手验证。跑 **`示例代码/02_开始学习C++/03_getinfo.cpp`**，输入 `Li Ming`，看输出。

```
Enter your name: Li Ming
Hello, Li!              ← 只读到了 "Li"！
```

**原因**：`>>` 把输入按"空白符"（空格、Tab、换行）切分，一次只取一个"词"。
**想读整行要用 `cin.getline()`**——第 4 章（p95）讲。

> 💡 想自己验证得更清楚：在 `Hello, Li!` 后面再加一句 `cin >> name;`，你会看到第二次读到的
> 是 `Ming`——因为 `>>` 只是"停下来"了，**没有把剩下的内容扔掉**，下一次读会接着从那里取。

# 5. `cout` 拼接（2.3.2，p41）

```cpp
cout << "Now you have " << carrots << " carrots." << endl;
```

`<<` 可以**串联**：每个 `<<` 把右边的东西插进 `cout`，然后返回 `cout` 本身，所以能接着 `<<`。
（本质是运算符重载，第 11 章讲。）

**拆开看完全等价**（这也是理解 `<<` 的最快方式）：

```cpp
cout << "Now you have ";
cout << carrots;
cout << " carrots.";
cout << endl;
```

两段代码输出一模一样。**为什么可以串起来？** 因为 `cout << a` 这个表达式的**结果还是 `cout`**，所以后面还能继续 `<<`。跟"`a + b + c` 从左往右连着算"是一个道理。

**`endl` vs `'\n'`**（书 p36 / p757）：

| | 做什么 | 代价 |
|---|---|---|
| `endl` | 换行 **+ 刷新缓冲区** | 每次刷新有系统调用开销 |
| `'\n'` | 只换行 | 快 |

**学习阶段随便用**，写大量输出时用 `'\n'` 更快。

# 7. ⭐⭐ 函数（2.4，p43–50）—— 本课核心

> 如果你跳过了第 0 部分，请先回去读 **0.4 什么是函数**——那里有"榨汁机"比方和"定义 / 原型 / 调用"三件套的完整解释。

## 7.1 有返回值的库函数：`sqrt()`（2.4.1，p43）

```cpp
#include <iostream>
#include <cmath>                    // sqrt 在这个头文件里
int main()
{
    double area = 100.0;
    double side = sqrt(area);        // 调用：算出结果，赋给 side
    std::cout << side << std::endl;  // 10
}
```

输出：

```
10
```

**观察这个模式**：函数调用**出现在赋值号右边**。函数"算出"一个值交给你。
**返回值类型**决定这个值是什么类型。`sqrt` 返回 `double`。

> 💡 注意这里用的是 `std::cout`（写法 ④）——因为 `sqrt` 在全局也有一份（来自 `<math.h>` 的历史遗留），
> 而 `cout` 只在 `std` 里。**这两种情况混在一个文件里时，老老实实写 `std::` 最不容易出错。**

## 7.2 函数变体（2.4.2，p46）

教材这里讲的是：同一个名字可能有多个版本，编译器按参数选（这就是**重载**，第 8 章细讲）。
现在只需知道：**看函数原型就知道怎么调用它**。

`sqrt()` 就是最好的例子：`sqrt(100.0)` 用的是 `double` 版本，`sqrt(100.0f)` 用的是 `float` 版本，
`sqrt(100)` 会先把 `int` 转成 `double` 再用 `double` 版本。**你只写一个名字，编译器替你挑版本**——但你得能从原型看出"有哪些版本可选"。

## 7.3 ⭐ 用户定义的函数 + 函数原型（2.4.3，p46–48）

看 **`示例代码/02_开始学习C++/04_ourfunc.cpp`**，这是本课最重要的一个文件。

```cpp
#include <iostream>

void simon(int);          // ★ 函数原型 ★

int main()
{
    simon(3);             // 调用
    return 0;
}

void simon(int n)         // ★ 函数定义 ★
{
    using namespace std;
    cout << "Simon says touch your toes " << n << " times." << endl;
}
```

**为什么必须有原型？**

> C++ 编译器是**从上往下**读代码的。读到 `main` 里的 `simon(3)` 时，
> 它还不知道 `simon` 是什么东西。**原型就是提前递给它的一张说明书。**

**删掉原型会怎样？** 自己试试，你会看到：

```
error: 'simon' was not declared in this scope
```

→ 这是**编译错误**（识别错误类型的能力，第 1 章学的，用上了）。

**原型告诉编译器三件事**（教材 p53 复习题第 9 题就是考这个）：

1. 函数**名字**
2. **返回类型**
3. **参数个数和类型**

**三个必须搞清的细节**：

| 细节 | 说明 |
|---|---|
| 原型末尾**有**分号 | `void simon(int);` |
| 定义末尾**没有**分号 | `void simon(int n) { ... }` ← `}` 后不加 `;` |
| 原型和定义的签名**必须一致** | 见下面两种真实报错 |

### ⚠️ "签名不一致"到底会发生什么？（实测修正）

很多资料写"原型写 `void simon(int)`，定义写成 `double simon(int)` → **链接错误**"。
**实测后发现要分两种情况**，而且两种情况都值得记住：

**情况 A：只有返回类型不同 → 编译错误**

```cpp
#include <iostream>

double simon(int);                        // 原型：返回 double

int main() { using namespace std; simon(3); return 0; }

void simon(int n) { cout << n << endl; }  // 定义：返回 void ← 和原型冲突
```

实测：

```
error: ambiguating new declaration of 'void simon(int)'
note: old declaration 'double simon(int)'
```

`ambiguating` 的意思是"这个声明让名字变得有歧义了"——**返回类型不算签名的一部分**，`double simon(int)` 和 `void simon(int)` 是同名同参数的两种说法，编译器不知道该信哪个。**这是编译错误，代码根本没生成机器码。**

**情况 B：参数类型不同 → 链接错误**

```cpp
#include <iostream>

void simon(double);                       // 原型：参数是 double

int main() { using namespace std; simon(3); return 0; }   // 调用点：只看得见 double 版本

void simon(int n)                         // 定义：参数是 int ← 这是另一个函数
{
    using namespace std;
    cout << n << endl;
}
```

实测：

```
undefined reference to `simon(double)'
collect2.exe: error: ld returned 1 exit status
```

为什么？**因为"同名不同参数"是两个完全不同的函数**（第 8 章的重载）：

- 调用点 `simon(3)` 前面只看得到 `simon(double)`，于是它决定调用 `simon(double)`；
- 但全文件里**没有** `simon(double)` 的**定义**（只有 `simon(int)` 的定义）；
- 于是链接器喊："说好的 `simon(double)` 在哪？"

> 📌 **两种情况的共同教训是一条**：**函数原型必须和函数定义严格一致**——返回类型、参数个数、参数类型，一个都不能差。
> 顺便记住一个更普遍的规律：**重载解析只看调用点之前可见的声明。** 定义写在后面，对前面的调用点毫无影响。

### ⚠️ 关于"函数定义后面多写了一个分号"

常见的说法是：定义后多一个 `;` 会被当成**声明**，导致链接错误 `undefined reference to 'simon(int)'`。
**实测结果如下（两层结论，都要知道）：**

**第一层：`}` 后多一个 `;` 本身不会出错。**

```cpp
void simon(int n) { std::cout << n << std::endl; };   // ← 多了一个分号
```

- `-std=c++17 -Wall -Wextra`：**完全没有任何提示，正常编译运行**
- 加 `-pedantic` 才提示：`warning: extra ';' [-Wpedantic]`

原因：`{ ... }` 已经是一个完整的函数定义，后面那个 `;` 只是一个"空声明"，C++11 起标准明确允许。

**第二层：真正会让你掉进链接错误坑的，是"分号吃掉了函数体"。**

```cpp
#include <iostream>
void simon(int);                                        // 原型（说明书：有这个东西）
int main() { using namespace std; simon(3); return 0; }
void simon(int n);                                      // ← 以为是定义，其实还是声明！
```

多写一个分号的**真实危险**在这里：你本来打算写定义，手一快写成了 `void simon(int n);`——
编译器认为它是**第二遍声明**（合法的），于是整个程序**只有声明、没有定义**：

```
undefined reference to `simon(int)'
collect2.exe: error: ld returned 1 exit status
```

**这才是第 1 章实验 B（`undefined reference`）的场景**，也是"声明 vs 定义"最经典的一次咬人。

**最终结论（比通常的说法更严格，也更好记）：**

> **函数定义的 `}` 后面一个符号都不要加。** 多写一个分号，轻则白写（被当成空声明），
> 重则让你把"声明"误认成"定义"，最后在链接阶段才炸。

## 7.4 有返回值的用户定义函数（2.4.4，p49–50）

看 **`示例代码/02_开始学习C++/05_convert.cpp`**：

```cpp
int stonetolb(int);              // 原型：接收 int，返回 int

int main()
{
    int stone = 10;
    int pounds = stonetolb(stone);     // ← 函数调用出现在赋值号右边
    cout << stone << " stone = " << pounds << " pounds." << endl;
    return 0;
}

int stonetolb(int sts)           // 定义
{
    return 14 * sts;             // 有返回值就必须有 return
}
```

输出：

```
10 stone = 140 pounds.
```

**`return` 干两件事**：① 把值交给调用者 ② **立刻结束这个函数**（后面的代码不执行）。

第 ② 点在后面写判断和循环时会天天用到：

```cpp
int check(int x)
{
    if (x < 0)
        return -1;      // 一到这儿，函数当场结束，下面的行不会执行
    return x * 2;       // 只有 x >= 0 才会走到这里
}
```

**教材 p50 的要点**：原型里可以省略参数名（`int stonetolb(int);`），但定义里**必须**写参数名，因为你要用它。

## 7.5 在多函数程序里怎么用 `using`（2.4.5，p50）

教材的结论（p52）：

> 只让**需要**访问 `std` 的函数访问它，是更好的选择。

所以**推荐把 `using namespace std;` 写在真正需要它的函数内部**，而不是文件顶部。

**这个"最小权限"思想非常重要**，它贯穿整个 C++：

- 变量：能用局部就不用全局
- 函数：能不暴露就不暴露
- `using`：能放局部就不放全局

> 💡 看 `04_ourfunc.cpp`：`main` 里没写 `using namespace std;`，而 `simon` 里写了——
> 因为 `main` 根本没用 `cout`。**这就是"谁需要谁写"的标准示范。**

## 7.6 为什么必须拆函数？

先看规模问题。一个 10 行的小程序全写在 `main` 里完全没问题；但随着功能增加：

| 程序规模 | 会怎样 |
|---|---|
| 40 行 | 全在 `main` 里还能看懂 |
| 第 5 章后（循环） | 100 行，开始难受 |
| 第 10 章后（类） | 500 行，改一处要读半小时 |
| 真实项目 | 10000+ 行，不拆函数**根本没法维护** |

**三条经验法则**（现在记住，第 10–12 章会反复练）：

1. **一个函数只做一件事**
2. **长度 10–30 行**，超过 50 行就该拆
3. **函数名要能说明它做什么**（`calculateTotal` 好过 `f1`）

> 📖 想提前看"未来的代码长什么样"？打开 **`示例代码/01_参考_代码重构示例/spiral_functions.cpp`**——
> 那里把一个 60 行的 `main` 拆成了三个函数。**现在不用看懂，只要有个印象：好代码要去的地方长这样。**

## 8.2 命名约定（教材 p52）


```
Three blind mice

See how they run
```

其中一个函数要调用两次，该函数生成前两行；另一个函数也被调用两次，并生成其余的输出。
> 💡 **这题是本课的核心**。设计思路：一共 3 个函数：`main()` + `f1()` + `f2()`；
> `f1()` 输出一行 `Three blind mice` → 在 `main` 里调用 **2 次**；

**练习 4.** 编写一个程序，让用户输入其年龄，然后显示该年龄包含多少个月，如下所示：


**练习 5.** ⭐ 编写一个程序，其中的 `main()` 调用一个**用户定义的函数**（以摄氏温度值为参数，并返回相应的华氏温度值）。该程序按下面的格式要求用户输入摄氏温度值，并显示结果：

```
Please enter a Celsius value: 20
20 degrees Celsius is 68 degrees Fahrenheit.
```

转换公式：**华氏温度 = 1.8 × 摄氏温度 + 32.0**
> 💡 **要点**：
> - 函数原型大概长这样：`double celsiusToFahrenheit(double);`
> - 返回类型用 `double`（**别用 `int`**，否则 20 → 68 是对的，但 21 → 69.8 会被截断）
> - **`1.8` 和小数点一定要写**：如果写成 `9 / 5 * c + 32`，`9/5` 会得到 `1` 而不是 `1.8`（整数除法！第 3 章细讲）。
>   实测：`9 / 5 * 20 + 32` 得到 `52`，而 `1.8 * 20 + 32` 得到 `68`。

**练习 6.** ⭐ 编写一个程序，其 `main()` 调用一个**用户定义的函数**（以光年值为参数，并返回对应天文单位的值）。该程序按下面的格式要求用户输入光年值，并显示结果：

```
Enter the number of light years: 4.2
4.2 light years = 265608 astronomical units.
```

天文单位是从地球到太阳的平均距离（约 150000000 公里或 93000000 英里），光年是光一年走的距离（约 10 万亿公里或 6 万亿英里）（除太阳外，最近的恒星大约离地球 4.2 光年）。请使用 `double` 类型（参见程序清单 2.4），转换公式为：**1 光年 = 63240 天文单位**
> 💡 验证：`4.2 × 63240 = 265608` ✓ 算出来正好对得上就说明你写对了。
> 注意 `double` 默认会打印成 `4.2`，但如果是 `4.0` 会打印成 `4`——第 3 章讲怎么控制。

**练习 7.** ⭐ 编写一个程序，要求用户输入小时数和分钟数。在 `main()` 函数中，将这两个值传递给一个 **`void` 函数**，后者以下面这样的格式显示这两个值：

# 10. 常见坑汇总

每条都尽量附上**真实报错原文**（在本套 GCC 8.1.0 + `-std=c++17 -Wall -Wextra` 上实测）。

| # | 坑 | 会出现什么 |
|---|---|---|
| 1 | `#include <iostream>;` 加了分号 | `warning: extra tokens at end of #include directive`（第 1 章实验 C 已验证） |
| 2 | `main` 的 `}` 后加了 `;` | 实测**能编译**（C++11 起允许空声明）；`-pedantic` 下 `warning: extra ';' [-Wpedantic]`。**但不要养成这个习惯**——它会让"定义"和"声明"在你脑子里糊成一团（见 9.2 实验 B / 7.3） |
| 3 | **函数定义后面加了 `;`** | 单独一个 `;` 无害；**真正的坑是它让你把 `void simon(int n);` 误当定义写下去** → 只算声明 → **链接错误** `undefined reference to 'simon(int)'` |
| 4 | 忘记写函数原型 | 编译错误 `'xxx' was not declared in this scope` |
| 5 | 原型和定义签名不一致 | 参数类型不同 → **链接错误** `undefined reference to 'simon(double)'`；仅返回类型不同 → **编译错误** `ambiguating new declaration of 'void simon(int)'` |
| 6 | `cin >> name` 想读全名 | 只读到第一个空格（示例 03） |
| 7 | 变量没初始化就用 | 警告 + 垃圾值（示例 02） |
| 8 | `sqrt(-1)` | 输出 `nan` 或 `-nan`（**不是负数**）；本套环境实测输出 `nan` |
| 9 | `3 / 2` 得到 `1` | 整数除法截断（第 3 章细讲） |
| 10 | 拼写错误：`iostram`、`kout`、`coot` | 各种诡异报错（教材 p30 专门讲过）。实测 `#include <iostram>`：`fatal error: iostram: No such file or directory`；写成 `cout` 但不写 `std::`：`error: 'cout' was not declared in this scope` + `note: suggested alternative: 'std::cout'` |

### 零基础读者额外要小心的 6 条

| # | 坑 | 会出现什么 |
|---|---|---|
| 11 | 语句漏了分号 | `error: expected ',' or ';' before 'xxx'`——先查**上一行行尾** |
| 12 | 变量名以数字开头 | `error: expected unqualified-id before numeric constant` |
| 13 | 把保留字当变量名（`int int;`） | `error: expected unqualified-id before '=' token` |
| 14 | 大小写写错：`Carrots` / `carrots` 混用 | `error: 'Carrots' was not declared in this scope`（它们是两个变量） |
| 15 | 没有 `main`，或写成 `Main` / `mian` | 链接错误 `undefined reference to 'WinMain'`（MinGW 上的说法，含义同"找不到入口 `main`"） |
| 16 | 写 `void main()` | 编译错误 `error: '::main' must return 'int'`（教材 p30 也提醒过不要这么写） |

> 💡 **看报错的三步法**：① 从**第一条**错误看起（后面往往是连带的）；② 看清是
> **编译错误**（`error:` + 文件名行号）还是**链接错误**（`undefined reference` + `ld returned`）；
> ③ 把最后一行 `note:` 也读完——那里常常直接写着正确答案。
