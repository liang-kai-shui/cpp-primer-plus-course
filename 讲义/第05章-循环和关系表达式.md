## 0. 本课怎么学

### 0.1 这课接在什么地方

前几课解决的是“数据放在哪里”：一个变量放一个值，数组放一排值，结构把一条记录的几个值放在一起。

现在要解决一个新的问题：**有了一排数据，怎样把每一项都处理一遍？**

例如你存了 30 个同学的成绩。你不应该为每个人抄一条加法语句，而应该告诉程序：从第一个开始，做相同的动作，直到最后一个。这就是本章的循环。

这一课不要求你“背下来三种循环的格式”就结束。更重要的是能在纸上回答：

1. 程序现在走到哪一行？
2. 变量现在是多少？
3. 下一步为什么回到前面，或为什么离开循环？

**会回答这三句，才算读懂了循环。** 看见 `for` 并不等于已经理解它。

### 0.2 先认几个词

| 词 | 先用一句话理解 | 类比 |
|---|---|---|
| 循环 | 根据条件重复做一段动作 | 按要求跑若干圈 |
| 循环体 | 每次重复时真正执行的代码 | 每一圈要做的动作 |
| 条件 | 一个能判定真假的问题 | “还没跑够吗？” |
| 迭代 | 执行一轮循环 | 跑一圈 |
| 遍历 | 按一定顺序访问一组数据 | 挨个打开一排储物柜 |
| 累加器 | 保存到目前为止的总和的变量 | 不断往里面放东西的篮子 |
| 哨兵 | 专门约定用来结束输入的值 | 队伍末尾的结束牌 |
| EOF | 输入来源已经到头 | 文件最后一页也翻完了 |

不用一次背完。下面每个词用到时都会再解释；“迭代”也没有比“重复一轮”多出神秘含义。

## 1. 循环：让同一套动作反复发生

打印五次问候，可以抄五条输出语句。但换成一千次，或次数来自用户输入，复制就行不通。**循环**就是“重复执行某段代码，直到条件不成立”。像跑步：每跑一圈，检查是否够了，再决定下一圈。

### 1.1 先看没有循环会怎样

```cpp
std::cout << "Hello\n";
std::cout << "Hello\n";
std::cout << "Hello\n";
```

这里输出三次，因为有三条输出语句。如果用户要五次，你得再改源码。循环让你写一次动作，把重复次数交给变量和条件控制。

把上面的三条改成下面的三次循环，输出的问候相同，但写法开始具有“次数可变”的能力：

```cpp
for (int i = 0; i < 3; ++i) {
    std::cout << "Hello\n";
}
```

先不要急着看懂 `++i`。把它暂时读成“让 i 增加 1”，第 3 节再拆开讲。

### 1.2 把 `for` 的一行分成四块

```text
for (int i = 0;    i < 3;    ++i) {
     └─ 起点 ─┘  └─ 判断 ─┘ └更新┘
    要重复的动作
}
```

| 部分 | 在这里是什么意思 | 什么时候执行 |
|---|---|---|
| `int i = 0` | 创建一个整数计数变量，让它从 0 开始 | 进入循环时只执行一次 |
| `i < 3` | 问“i 还小于 3 吗？” | 每次准备执行循环体之前 |
| `++i` | 把 i 加 1 | 本轮循环体执行完之后 |
| `{ ... }` | 每轮真正要做的动作 | 条件为真才执行 |

圆括号中的两处分号分隔三个部分；花括号中的分号结束一条条语句。它们位置不同，作用也不同。

`i` 只是程序员取的名字。你也可以叫 `round`、`index`，名字不会使变量自动变成计数器；它能计数，是因为你给它起点并每次加 1。

### 1.3 电脑不是按源码排版“从上往下读一次”

现在把循环体改成输出 i，方便看见变量怎样变化：

```cpp
for (int i = 0; i < 3; ++i) {
    std::cout << i << '\n';
}
```

`for (初始化; 条件; 更新)` 的顺序是：**初始化一次 → 检查条件 → 执行循环体 → 更新 → 再检查**。不能把更新当作第一次循环之前发生。

| 步骤 | `i` | 条件 `i < 3` | 动作 |
|---|---:|---|---|
| 初始化、首次检查 | 0 | 真 | 输出 0 |
| 更新后检查 | 1 | 真 | 输出 1 |
| 更新后检查 | 2 | 真 | 输出 2 |
| 更新后检查 | 3 | 假 | 退出，不再输出 |

也可以把路线画出来：

```text
创建 i，写入 0
      |
      v
检查 i < 3 -------- 假 --------> 循环后的下一条语句
      |
      真
      v
执行循环体：打印 i
      |
      v
执行 ++i
      |
      +-----------------------> 回到条件检查
```

注意三个经常猜错的地方：

- 创建 i **不在每一轮重新执行**，否则 i 每轮都变回 0。
- 第一轮打印的是 0，更新还没发生，不是 1。
- i 已经变成 3 时还会检查一次条件，但不会进入循环体。

所以“循环体执行 3 次”和“条件检查 4 次”可以同时正确。示例 01 会统计这两个数；它的条件里用逗号额外计数，第 3 节解释逗号后再回头读，不必在第一遍模仿这个技巧。

> **动手实验 A**：在自己的副本里，把 3 改成 1。打印什么？再改成 0。是否至少打印一次？先手写路线，再运行。

### 1.4 为什么常从 0 开始，不从 1 开始

循环不强制从 0 开始。要打印“第 1 圈、第 2 圈、第 3 圈”，可以这样写：

```cpp
for (int round = 1; round <= 3; ++round) {
    std::cout << "round " << round << '\n';
}
```

从 0 开始常见，是因为数组下标从 0 开始：长度为 3 的数组有下标 0、1、2。

```text
元素个数：    3
合法下标：    0       1       2
数组元素： [ 70 ]  [ 80 ]  [ 90 ]
                         这里之后没有第 3 号元素
```

因此两组搭配都可以得到三次循环：

| 起点 | 条件 | 循环体中看到的计数值 |
|---|---|---|
| `i = 0` | `i < 3` | 0、1、2 |
| `i = 1` | `i <= 3` | 1、2、3 |

问题不在“能不能用 <=”，而在**起点、条件和实际访问的下标是否对应**。用后一种 i 直接访问长度为 3 的 `a[i]`，就错过了 a[0] 并访问 a[3]。

### 1.5 变量活在哪：循环的作用域

在初始化处声明的 `i`，只能在这个循环的条件、更新、循环体中使用。若要退出后读它，应先在循环外声明。**作用域**就是名字能被使用的区域，像某个房间里的标签只在房间内有效。

数组 `int a[3]` 的下标是 0、1、2，所以遍历条件是 `i < 3`，写 `i <= 3` 会访问不存在的 `a[3]`。若每次加 3，条件 `i != 10` 可能永远不变成假；想控制上界通常应写 `i < 10`。

```cpp
for (int i = 0; i < 3; ++i) {
    std::cout << i << '\n';
}
// std::cout << i; // 不要取消注释：这里已经没有这个名字可用。
```

如果确实需要知道退出时的值，就在外面创建变量：

```cpp
int i = 0;
for (; i < 3; ++i) {
    std::cout << i << '\n';
}
std::cout << "after loop=" << i << '\n'; // 3
```

第一处分号前没有内容，因为初始化已在循环外完成；分号本身还必须保留。默认把计数变量放在循环里更容易管理，只有确实需要时才扩大它的作用域。

### 1.6 步长：每轮不一定只加 1

**步长**就是相邻两轮之间计数变量改变多少，像楼梯一次跨几级。

```cpp
for (int n = 0; n < 11; n += 3) {
    std::cout << n << ' ';
}
```

输出是 `0 3 6 9`，随后 n 变成 12。循环不会强制让 n 最后恰好等于 11；它只根据条件判断要不要下一轮。

若误写 `n != 11`，序列会是 0、3、6、9、12……，跳过 11，条件一直没按预期变假；继续下去还可能发生整数溢出。不要用“它迟早会到达上界”替代推演。

往回数也可以：

```cpp
for (int n = 3; n > 0; --n) {
    std::cout << n << ' '; // 3 2 1
}
```

> **动手实验 B**：打印 2、4、6、8、10。先写起点、条件、更新三个部分，再写输出。怎样做到包含 10，却不多打印 12？

### 循环体、语句和代码块

循环直接控制**一条语句**。花括号把多条语句打包成一条复合语句；缩进只是给人看的。

```cpp
for (int i = 0; i < 3; ++i) {
    std::cout << i;
    std::cout << "!\n";
}
```

`for (...);` 中的分号是一个空语句，循环体便为空，后面的代码不属于循环。块内新声明的变量退出块就不可使用；尽量避免在内层再声明同名变量遮住外层变量。

`x + 6` 只是计算一个值，不修改 `x`；`x = x + 6` 或 `x += 6` 才修改它。表达式算出值，语句要求程序做一步动作；不能看到运算就以为变量发生了变化。

### 1.7 循环里最常见的实际工作：累计总和

先不用数组，计算 1+2+3：

```cpp
int total = 0;
for (int n = 1; n <= 3; ++n) {
    total = total + n;
}
std::cout << total << '\n'; // 6
```

把 `total = total + n` 读成：“取出旧 total，加上这一轮的 n，再把结果存回 total。”等号是放回去的动作，不是数学里的恒等关系。

| 本轮 n | 本轮开始的 total | 计算 | 本轮结束的 total |
|---|---:|---|---:|
| 1 | 0 | 0+1 | 1 |
| 2 | 1 | 1+2 | 3 |
| 3 | 3 | 3+3 | 6 |

这时 total 就叫累加器。为什么从 0 开始？因为 0 加一个数，还是那个数，没有凭空多一笔数据。

把 total 放进循环体，每轮重新设成 0，会发生什么？

```cpp
for (int n = 1; n <= 3; ++n) {
    int total = 0; // 每轮创建新的 total，之前的累计没有保留下来。
    total += n;
    std::cout << total << ' '; // 1 2 3，不是累计的 1 3 6。
}
```

**要保留跨轮结果，累加器要在循环之前初始化。** 第 8 节按行统计时，你又会遇到“什么需要跨轮保留，什么应该每行重置”。

### 1.8 接到数组：让下标替你选数据

```cpp
int scores[3]{70, 80, 90};
int total = 0;
for (int i = 0; i < 3; ++i) {
    total += scores[i];
}
std::cout << "total=" << total << '\n';
std::cout << "average=" << total / 3.0 << '\n';
```

先看循环体：i 为 0 时取 scores[0]，为 1 时取 scores[1]，为 2 时取 scores[2]。循环本身不知道“这是成绩”，数据意义由你的变量和任务决定。

这里总和 240，平均 80。用 3.0 是为了浮点除法；如果改成总和不能整除的三个成绩，`total / 3` 的整数除法会丢掉小数。这个坑来自 第 3 章，不会因为用了循环就消失。

### 1.9 阶乘：累乘的初值为什么换成 1

原书程序清单 5.4 引出阶乘：`5!` 表示 1×2×3×4×5，不是 C++ 中可以直接写的一个运算符。

```text
0! = 1（约定）
1! = 1
2! = 1 × 2 = 2
3! = 2 × 3 = 6
4! = 6 × 4 = 24
5! = 24 × 5 = 120
```

它的规律是“当前阶乘 = 前一个阶乘 × 当前整数”。示例 02 用数组保存每一步：

```cpp
facts[0] = 1;
for (int i = 1; i <= 10; ++i) {
    facts[i] = facts[i - 1] * i;
}
```

为什么不是 `facts[0]=0`？因为任何数乘 0 都是 0，后面所有结果都会被变成 0。求和从 0 开始，求积从 1 开始，这两个初值要根据运算的含义来选。

阶乘增长很快，`long long` 也不是无限大的整数。示例只算到 10!；练习把上界扩到 100 时使用 `long double`，换来更大范围，同时接受浮点精度限制。

> **本节小检查**：不用运行，解释“循环体执行三次，条件检查四次”“数组长度 3，下标最大 2”“total 要放在循环外”这三句话。如果解释不出，回到执行表，不要急着学新语法。

## 2. 关系表达式：条件怎样得到真假

### 2.1 条件不是一段中文，必须能算出真假

电脑不认识“差不多做够了”“下一个同学应该还有数据”。你必须把要求写成明确的表达式。

例如“i 小于 3”写成 `i < 3`。“小于”这个符号连起两个值，计算结果只有两种：成立或不成立。C++ 用 `bool` 保存这种结果，两个值叫 `true` 和 `false`。

| 写法 | 读法 | 举例 |
|---|---|---|
| `a < b` | a 小于 b | 2<3 为真 |
| `a <= b` | a 小于或等于 b | 3<=3 为真 |
| `a > b` | a 大于 b | 2>3 为假 |
| `a >= b` | a 大于或等于 b | 3>=3 为真 |
| `a == b` | a 等于 b 吗 | 3==3 为真 |
| `a != b` | a 不等于 b 吗 | 3!=3 为假 |

`<=` 是两个字符组成的一个运算符，不能在中间插空格写成 `< =`。`!=` 也一样。

`<`、`<=`、`>`、`>=`、`==`、`!=` 比较两个值，结果类型是 `bool`。例如 `3 < 5` 为 `true`，`3 == 5` 为 `false`。默认输出 `bool` 是 1 或 0；`std::boolalpha` 可以输出文字 `true` / `false`。

数字用作条件时，0 转为假，非零转为真。`if` 的详细用法在下一课，本课先理解循环条件。

### 2.2 看见 0、1，不代表条件在“返回次数”

```cpp
std::cout << (2 < 3) << '\n';  // 1
std::cout << (2 == 3) << '\n'; // 0
std::cout << std::boolalpha;
std::cout << (2 < 3) << '\n';  // true
```

括号让 `cout` 先输出比较结果，避免输出运算与比较运算混在一起。1/0 只是默认的 bool 显示形式，条件没有告诉你“还要做一轮还是零轮”；它只告诉循环“这一次是否可以进去”。

下面的 n 就不是 bool，而是 int，但循环条件会把它转换成真假：

```cpp
int n = 3;
while (n) {
    std::cout << n << ' ';
    --n;
}
```

依次看到 3、2、1，最后 n 为 0 时退出。这里能结束，是因为 n 会到 0，不是因为“数字条件只能判断正数”。−1 也是非零，也会转换为真。初学时 `while(n > 0)` 比 `while(n)` 更明确地表达这个倒数任务。

### 2.3 `=` 和 `==`：只差一个字符，程序任务却变了

**`=` 是赋值，`==` 才是比较。** `while (x = 5)` 会不断把 5 赋给 `x`，条件一直为真。编译器警告值得检查，不要为了消除警告给错误赋值加括号。

| 表达式 | 是否修改 x | 提供给周围代码的值 |
|---|---|---|
| `x = 5` | 是，存入 5 | 赋值后的 x，即 5 |
| `x == 5` | 否 | 比较结果 true 或 false |

所以赋值也能被写到条件位置，不一定直接编译失败；它可能只是与你的意图不符。赋进去的 5 是非零，转为真，循环自然停不下来。

> **安全实验**：只写 `int x=2; std::cout << (x=5);` 和另一个独立片段的 `(x==5)`，比较 x 最后的值。不要为了“试一下”运行已经知道会无限循环的 while。

`for (;;) { ... }` 省略了条件，它相当于一直为真。先不要在不清楚退出方式时写这种循环。

## 3. `++`：先用旧值，还是先得到新值

### 3.1 它为什么出现在循环的更新位置

计数器每轮加 1，经常需要 `i = i + 1;`。`++i;` 是完成这件事的简洁写法。类似地，`--i;` 完成减 1。

先把两件事分开：**变量最终变成多少**，和**表达式这一次交给别人什么值**。后置/前置的区别在第二件事上。

`++` 把变量加 1；`--` 减 1。单独作为语句时，`++n;` 与 `n++;` 都把 `n` 加 1。区别在于**这个表达式提供给周围代码的值**。

```cpp
int n = 4;
int a = n++;  // a 得到旧值 4，n 变成 5
int b = ++n;  // n 先变成 6，b 得到新值 6
```

逐步记账：

| 正在执行的语句 | 执行前 n | 这次表达式提供的值 | 执行后 n | 接收变量 |
|---|---:|---:|---:|---|
| `int a = n++;` | 4 | 4 | 5 | a=4 |
| `int b = ++n;` | 5 | 6 | 6 | b=6 |

像给队员发号码：后置是“把旧号码递给你，自己的号码加 1”；前置是“自己的号码先加 1，把新号码递给你”。两种都真的修改号码，不能把后置理解为“只取值，不修改”。

如果整个语句就是 `n++;`，旧值没有被任何变量接收，但 n 仍加 1。在普通 `for` 的更新位置，返回旧值还是新值都没有被使用，所以两种写法在这里得到相同的计数变化。

### 3.2 自增放进条件，推演要多记一步

若 `j = 5`，条件 `++j < 9` 先把 `j` 加 1再比较；`j++ < 9` 使用旧值比较，但进入循环体前这次加 1已经完成。不要把“返回旧值”理解成“变量要等很久才修改”。

以这一段为例，只用于练习读代码，实际编程可以写得更直接：

```cpp
int j = 5;
while (++j < 9) {
    std::cout << j++ << ' ';
}
```

| 阶段 | j 怎样变化 | 发生什么 |
|---|---|---|
| 首次条件 | 5→6 | 6<9 为真，进入 |
| 首次输出 | 6→7 | 输出旧值 6 |
| 第二次条件 | 7→8 | 8<9 为真，进入 |
| 第二次输出 | 8→9 | 输出旧值 8 |
| 第三次条件 | 9→10 | 10<9 为假，退出 |

输出两个数字，j 却变了五次，最终为 10。**条件表达式自己也可能修改变量**，不能只看循环体里有几个 ++。

> **动手实验**：先预测 `int n=4; int a=n++; int b=++n;` 的三个最终值，再跑示例 03。只改一个 ++ 的位置，重新画表。不要同时改三处之后猜是哪处造成变化。

### 接回上一课的指针

| 表达式 | 意思 |
|---|---|
| `*p++` | 按 `*(p++)` 解释：取原来所指的值，再让指针移到下一元素 |
| `(*p)++` | 增加当前元素；指针不移动 |
| `*++p` | 先移动指针，再取新位置的值 |

这些操作仍要遵守数组边界。示例 03 把每种操作拆成单独语句，方便画出指针的位置。

先回忆指针：`p` 保存的是地址，`*p` 才是这个地址指向的元素。把示例中的数组画出来：

```text
开始：  [10] [20] [30]
         p

first = *p++：first 得到 10；p 移到第二个元素
        [10] [20] [30]
              p

(*p)++：把第二个元素加 1；p 不动
        [10] [21] [30]
              p

third = *++p：p 先移到第三个，再取值 30
        [10] [21] [30]
                   p
```

为什么 `*p++` 是给 p 加 1？后置 ++ 比一元 * 结合得更紧，解析为 `*(p++)`。给所指元素加 1，要用括号明确写出 `(*p)++`。读不顺时就拆成两条语句；知道这种写法的意思，不代表每个遍历都必须用它。

### 副作用与求值顺序

**副作用**是表达式除了算出值，还修改了程序状态，比如 `n++` 修改 `n`。知道运算符优先级，只能知道表达式怎样分组，不能据此断定所有子表达式从左到右执行。

```cpp
// 错误示意，只分析，不运行：
// int result = i++ + ++i;
```

上面两个修改没有规定的先后顺序，行为未定义，不能把某次运行的输出当作规则。把修改拆成多条语句最容易核对。原书 5.1.6 使用较早的标准背景，C++17 改变了部分求值顺序规则，因此不能把书中的赋值示例一概套用到所有标准；本课不靠复杂自增表达式完成实际任务。[标准的求值顺序规则](https://eel.is/c++draft/intro.execution)

### 复合赋值与逗号（5.1.9–5.1.11）

`+=`、`-=`、`*=`、`/=`、`%=` 把运算与赋值合起来。对于这里的简单整数变量，`total += value` 等价于 `total = total + value`；整数 `/=` 仍是整数除法，`%=` 用于整数。

逗号运算符先执行左边，再执行右边，整个表达式的值取右边：

```cpp
int x = 0;
int y = (x = 3, x + 2); // x 为 3，y 为 5
```

`int a = 1, b = 2;` 的逗号分隔声明，不是上面的逗号运算符。逗号可以放在 `for` 的更新部分同时更新两个变量，但初学时先用循环体内的两条语句，容易检查。

### 3.3 复合赋值先从你已经会的加法读起

```cpp
int total = 10;
total += 3; // total = total + 3，得到 13
total -= 2; // total = total - 2，得到 11
total *= 2; // total = total * 2，得到 22
total /= 4; // 整数除法，得到 5
total %= 3; // 5 除以 3 的余数，得到 2
```

这些不是“新的数学”，只是把“算完写回原变量”缩写了。先会读 `total = total + value`，再用 `+=`。

逗号示例 `int y=(x=3, x+2);` 也可以拆成：

```cpp
x = 3;
int y = x + 2;
```

示例 01 的 `(++checks, i < 3)` 同理：每次检查时先增加 checks，再把 `i<3` 的真假作为整个条件结果。因此连最后那次失败检查也被计数。

> **阅读层次**：循环计数、自增、复合赋值需要会写；指针组合表达式、逗号需要会读；复杂求值顺序先学会识别危险写法，不需要背所有标准规则。

## 4. 字符串：比较内容与遍历边界

### 4.1 “相同的文字”和“相同的地址”不是一个问题

回忆 第 4 章 A：`char a[]="hi";` 是一个字符数组，内容是 `'h'`、`'i'`、`'\0'`。最后的零字符表示字符串到这里结束，不是显示出来的数字 0。

```cpp
char a[] = "hi";
char b[] = "hi";
```

```text
a 的数组： [h] [i] [\0]    一块自己的存储空间
b 的数组： [h] [i] [\0]    另一块自己的存储空间

逐个看字符：相同
问“是不是同一个位置”：不同
```

像两个不同的文件都写着 hello：文件内容一样，不代表它们就是同一个文件。

两个字符数组用 `==`，通常会先转换成指针，比较的是地址，**没有逐个比较字符**。C 风格字符串比较内容，用 `<cstring>` 的 `std::strcmp(a, b)`：0 表示相等，小于 0 / 大于 0 表示顺序；不要依赖结果恰好是 −1 或 1。

`std::string` 已经提供内容比较，可以写 `word == "done"`，也可以用 `<` 比较字典顺序。字符串的字典顺序不是字符串中数字的数值顺序；例如 `"10" < "2"`。

### 4.2 `strcmp` 的返回值怎么读

```cpp
std::strcmp("hi", "hi") == 0  // 内容相同
std::strcmp("hi", "ho") < 0   // 第一个不同字符 i 排在 o 前面
std::strcmp("ho", "hi") > 0   // 第一个不同字符 o 排在 i 后面
```

`strcmp` 需要有效的、以 `\0` 结束的 C 风格字符串。如果数组没有结束符，它不会自动知道数组容量，可能一直往后读，所以不能随便把任意 char 数组交给它。

0 表示相等，这点和条件“非零为真”容易混：

```cpp
// 清楚地问“内容相等吗”：
bool same = std::strcmp(a, b) == 0;
```

直接拿 `strcmp(a,b)` 当条件，反而是在内容不同时为真。写出 `==0`，自己的意图更清楚。

### 4.3 `std::string` 为什么可以直接用 `==`

```cpp
std::string first = "hi";
std::string second = "hi";
bool same = first == second; // true，比较内容
```

`std::string` 是标准库提供的一种字符串类型，它已经实现了这些比较操作。现在只需会用，不需要先学会“运算符重载”的实现；后面第 11 章再解释类型怎样定义自己的运算。

字典顺序逐个字符找第一个不同位置。`"10"` 与 `"2"` 的第一位是 `'1'` 和 `'2'`，比较在这里就分出先后，不会自动把全文转换成整数 10 和 2。

### 4.4 正向访问：先认长度，再认下标

```cpp
std::string word = "cat";
for (std::size_t i = 0; i < word.size(); ++i) {
    std::cout << word[i] << ' ';
}
```

`word.size()` 是长度 3，合法下标是 0、1、2，依次读到 c、a、t。`std::size_t` 是用于表示大小和下标的无符号整数类型，常来自 `<cstddef>`；名字看起来长，仍然只是一个整数类型。

**长度不等于最后一个下标。** 对非空字符串，最后下标是长度减 1；对空字符串，根本没有“最后一个字符”。

### 4.5 反向访问：空字符串要先想清楚

反向遍历容易在空字符串时写错。`size()` 返回无符号长度，直接写 `word.size() - 1` 可能在长度为 0 时下溢。采用下面的形式：

```cpp
for (std::size_t i = word.size(); i > 0; --i) {
    std::cout << word[i - 1];
}
```

长度为 0，一次也不进入；长度为 3，访问下标 2、1、0。示例 04 用 `getline` 允许空行和空格。这里处理的是单字节 ASCII 文本；反转 UTF-8 中文的字节不能得到正确的中文字序。

| 进入条件检查时的 i | `i > 0` | 实际访问的 `i-1` | 字符 |
|---:|---|---:|---|
| 3 | 真 | 2 | t |
| 2 | 真 | 1 | a |
| 1 | 真 | 0 | c |
| 0 | 假 | 不访问 | — |

这相当于从“末尾后一格”开始，每轮读取前一格。先保证 i 大于 0，再做 i−1，就不会把 0 减 1 用作下标。

无符号整数不能用负数当倒数终点。这样的思路有问题：

```cpp
// 只分析，不运行：
// for (std::size_t i = word.size()-1; i >= 0; --i) { ... }
```

因为无符号 i 总是大于等于 0；减到 0 后再减会变成很大的无符号值，而不是 −1。不是把条件写得“包含 0”就安全了。

> **动手实验**：运行示例 04，输入 `cat`、空行、`a b`。每次先写出要访问的下标列表。再解释为什么反转一个中文字符串不属于本例的保证范围。

## 5. `while` 和 `do...while`：选择检查时机

### 5.1 什么情况下不能提前知道次数

打印十行，次数已知；但“用户会输入多少个数”通常不知道。你可以规定输入 0 结束，或者一直读到 EOF。循环要根据正在发生的事情决定是否继续，`while` 很适合表达它。

先从一个已知会结束的例子看语法，再换成输入任务：

**`while`** 先检查条件，真才执行；它适合“读到结束”“累计直到达到目标”等次数事先未知的事情。

```cpp
int n = 3;
while (n > 0) {
    std::cout << n << ' ';
    --n; // 缺少这一步，条件可能永远为真
}
```

拆开看：

- `while` 是关键字，表示“只要下面的条件成立就重复”。
- `(n > 0)` 每次进入循环体前检查。
- 花括号里是这一轮动作；这里的 `--n` 由你写，while 不会自动替你加减变量。

```text
n=3 → 检查真 → 打印3 → n=2
    → 检查真 → 打印2 → n=1
    → 检查真 → 打印1 → n=0
    → 检查假 → 离开
```

`for` 把起点、条件、更新集中在一行；`while` 只规定条件，起点和更新放在别处。它们都不是会自动懂你目标的计数机器。

### 5.2 结束不了，先检查“条件会不会改变”

```cpp
// 错误示意，不运行：
// int n = 3;
// while (n > 0) {
//     std::cout << n;
// }
```

循环体没有修改 n，条件一直看见 3，当然一直为真。找无限循环时，不要先责怪输出或编译器，先问：**有什么动作能让条件从真变假？那个动作真的执行了吗？**

常见原因包括更新漏写、更新方向反了、while 后多了分号，以及更新藏在没有进入的分支里。第 6 章的 continue 也可能跳过更新。

### 5.3 `do...while` 把检查放到动作之后

**`do...while`** 先执行循环体，再检查条件，正常执行时至少进入一次。像先问一次菜单，再决定要不要继续。结尾有必需的分号。

```cpp
int n = 0;
do {
    std::cout << n << '\n';
} while (n > 0);
```

上面仍打印一次 0；对应 `while (n > 0)` 则一次也不打印。三种循环并非互相替代的口号：固定次数优先考虑 `for`，输入驱动优先考虑 `while`，必须先做一次再判断时考虑 `do...while`。

把 n 初始为 0 的两个流程摆在一起：

```text
while：   检查 0>0 → 假 → 直接离开，没输出
do：      先输出 0 → 检查 0>0 → 假 → 离开
```

`do` 后的花括号是动作，末尾的 `while(...)` 是是否再做一次的问题。写完右花括号还没结束整个语句，最后那个分号必须有。

它常用于先显示一次菜单、先尝试一次操作等任务。若“没有数据就绝不应处理”，选择先检查的循环，不要为了保证执行一次而使用 do。

> **动手实验**：跑示例 05，比较 `zero while:` 后没有数字、`zero do:` 后有 0。再把 n 初值设为 1，逐条看条件检查的时机，而不只是看最终都输出了哪些数字。

### 原书的计时和类型别名（5.2.2）

`<ctime>` 中的 `std::clock()`、`std::clock_t` 与 `CLOCKS_PER_SEC` 用于估算程序消耗的处理器时间：两次读数的差除以每秒刻度，得到秒数；应检查 `clock()` 是否返回失败值。它不保证等同于现实经过的钟表时间。原书用循环等待演示 `while`，会持续占用处理器，不适合用作日常等待方案。

`typedef std::clock_t Tick;` 为已有类型取一个别名，像给同一人添昵称，没有创造新的不同类型；现代写法可用 `using Tick = std::clock_t;`。这些是阅读补充，不要求写计时程序。

## 6. 范围 `for`：从每个元素取值

### 6.1 为什么又多了一种 for

如果目标只是“把所有成绩逐个输出”，你不关心当前下标，只关心当前成绩。范围 for 替你进行逐项访问，不必手写长度判断，像对一篮水果说“每个都称一次”。

```cpp
int scores[]{70, 80, 90};
for (int score : scores) {
    std::cout << score << '\n';
}
```

冒号右边是要遍历的容器或数组；左边的变量依次得到元素。这里 `score` 是副本，修改它不会改数组。若写 `int& score`，它是当前元素的别名，修改它会改数组；这就是**引用**的最小用法，完整规则留到 L12。

### 6.2 值变量：拿一张复印件出来处理

```cpp
int scores[]{70, 80, 90};
for (int score : scores) {
    score += 5;
    std::cout << score << ' '; // 75 85 95
}
std::cout << scores[0];        // 原数组首项仍是 70
```

这里每轮创建的 score 接收当前元素的值，像拿出一张成绩单复印件。改复印件不会改原件，所以“循环里打印了加分后的数字”和“数组真的被修改”是两回事。

### 6.3 引用变量：给原元素添一个临时名字

```cpp
for (int& score : scores) {
    score += 5;
}
```

这里的 `&` 出现在类型后的声明位置，表示引用，不是表达式里的“取地址”。这一轮的 score 是原元素的别名，修改它就是修改那个元素。

```text
值变量：    scores[0]=70 → 复制到 score → score改成75，原件仍70
引用变量：  score 就是 scores[0] 的另一个名字 → 原件改成75
```

先把这个差别说清楚即可，完整的引用规则在 L12 学习。示例 06 先改副本，再改引用，所以能直接比较两种效果。

> **动手实验**：把引用循环中的 `int&` 改成 `int`，只改这一个地方。预测最后的数组输出；运行后解释为什么改掉一个符号就改变了数据是否被保存。

需要下标、跳过部分元素或同时操作两组数据时，普通 `for` 仍合适。范围循环不是“更短就永远更好”。

## 7. 文本输入：先区分“读什么”，再判断“读到了吗”

### 7.1 输入流和缓冲区：先画一条队伍

**输入流**是一条按顺序送来数据的通道。`std::cin` 通常连接键盘所在的终端，也可以通过重定向从文件取得数据。

**缓冲区**可以先理解为“已经输入、但程序还没读走的字符队伍”。你敲 `A b` 再回车，等待读取的内容可画成：

```text
下一个先读的位置
  |
  v
[A] [空格] [b] [换行 \n]
```

回车也带来一个换行符。它不是屏幕上可见的字母，但仍是输入中的字符。读取一次会按所用规则从这条队伍取走数据；不能把每次读取都想成“重新让用户输入一整份”。

第 4 章 A 中“读完数字后 getline 得到空行”的问题也来自这条队伍：数字读取留下了换行，下一个整行读取先遇见它。

### 7.2 `cin >> ch`：它默认先跳过空白

| 输入方法 | 空格、制表符、换行 | 成功判断 |
|---|---|---|
| `std::cin >> ch`（`char`） | 默认跳过 | 把提取表达式用作条件 |
| `std::cin.get(ch)` | 保留 | 把 `get(ch)` 的返回流用作条件 |
| `std::cin.get()` | 保留 | 返回字符或 EOF 标记，先检查再转换 |

```cpp
char ch;
std::cin >> ch;
std::cout << ch;
```

ch 的类型是 char，所以这里只想提取一个字符。输入 `A b\n`，第一次得到 A；第二次先跳过空格，得到 b；第三次跳过换行，继续等待后面的非空白字符。

这适合读取一个菜单命令，不适合“数文章有几个空格”“原样复制文字”，因为空白已经被跳过了。

### 7.3 `get(ch)`：把空白也作为正文取出来

```cpp
char ch;
while (std::cin.get(ch)) {
    std::cout << ch;
}
```

循环条件尝试读取一个字符，成功才进循环体，**不会在读取失败后重复使用旧的 `ch`**。`get(ch)` 与 `get()` 同名但参数和返回值不同，这是原书 5.5.3 引出的函数重载；这里只需按调用形式区别。

逐轮对照同一份 `A b\n`：

| 第几次成功读取 | `cin >> ch` 得到 | `cin.get(ch)` 得到 |
|---|---|---|
| 1 | A | A |
| 2 | b | 空格 |
| 3 | 需要下一个非空白字符 | b |
| 4 | — | 换行 |

`get(ch)` 的 ch 是输出参数：读到的字符被存入它。`get(ch)` 自己返回的是输入流对象，因此放到 while 条件里的问题是“读取成功了吗”，**不是“这个字符的数字值是不是非零”**。

这一步很重要：即使某个读取成功的字符值是 0，也不应该因此认定流读取失败。我们检查的是流状态，字符内容是另一件事。

### 7.4 哨兵：读到了，但约定不再处理它

可以规定 `#` 表示结束。把“已经读到字符”和“不是结束牌”两个条件连起来：

```cpp
char ch;
int count = 0;
while (std::cin.get(ch) && ch != '#') {
    ++count;
}
std::cout << count;
```

输入 `A b\n#` 时：A、空格、b、换行分别进循环体，count 从 0 到 4；读到 # 时，第二个条件为假，# 不进循环体，不计数。

这里 `&&` 表示“并且”。它先检查读取成功；读取失败后不会再去比较一个并非新读到的 ch。完整规则在下一课讲，这里先按“先读到，再检查内容”理解。

若正文中需要保存 #，这种哨兵协议就不合适，应采用 EOF 或其他明确的格式。结束方式是你与输入使用者的约定，不是所有文本程序都会自动认 #。

### 7.5 EOF：来源结束，不是有人敲了 E、O、F

**EOF** 表示输入结束，不是正文里某个可见字符。无参数 `get()` 返回的类型需要同时容纳字符和结束标记；若先保存到 `char`，可能丢掉区别。示例 09 用 `std::char_traits<char>::int_type` 接住返回值，与 `eof()` 比较，确认有字符后才转成 `char`。原书使用 `int` 与 `EOF` 演示同一思路，别直接硬编码 −1。

不要写 `while (!std::cin.eof())` 再在循环体内读：**EOF 状态通常在尝试读取后才更新**，检查过早会多做一次。输入失败还可能是类型不匹配，不只有 EOF；下一课详细讲处理。

键盘终端可以一直等待下一次输入，文件则有明确末尾。读取到文件末尾后还要再读，流才知道“这次没有任何字符可交给你”。

这就是为什么读取动作放在条件里：

```text
尝试读一个字符
   |
   +-- 成功：处理这次的新字符 → 再尝试读取
   |
   +-- 失败：不处理旧变量 → 离开循环
```

错误的 `while(!eof())` 顺序是“先问上次有没有到头，再尝试这次读取”。例如文件只有 AB：

| 轮次 | 读取前 EOF 状态 | 这次读取 | 若无检查就 count++ |
|---|---|---|---|
| 1 | 尚未到头 | 成功读到 A | 计一次 |
| 2 | 尚未到头 | 成功读到 B | 再计一次 |
| 3 | 尚未记录结束 | 读取失败，发现末尾 | 错误地再计一次 |

因此它可能把两个字符数成三个。不要拿“我已经先检查过了”代替检查这一次读取是否成功。

### 7.6 无参数 `get()` 为什么不能先装进 char

下面两个函数调用名字相同，但使用方式不同：

```text
cin.get(ch)：把字符放进 ch，调用的返回结果是流
cin.get()：没有 ch 可写，把字符或结束标记作为返回结果交出来
```

后者必须用能容纳“所有字符值”和“另一个结束标记”的类型。原书用 int 接住，再与 `<cstdio>` 提供的 EOF 比较。本课示例 09 用标准字符流提供的类型和标记：

```cpp
using Traits = std::char_traits<char>;
Traits::int_type value;
while ((value = std::cin.get()) != Traits::eof()) {
    char ch = Traits::to_char_type(value);
    std::cout.put(ch);
}
```

名字比较长，第一遍把它按四步读：

1. 给标准库的一组字符规则起个简短名字 Traits。
2. value 用它提供的、能够保留结束标记的整数类型。
3. 尝试读取，先问结果是不是结束标记。
4. 确定有字符后，再转成 char 输出。

`put(ch)` 向输出流送出一个字符。这里引入这些名字是为了完整说明无参数版本；你自己的初学程序优先使用 `while(cin.get(ch))`，不需要先学模板才能完成字符统计。

### 7.7 让文本输入实验能重复

示例 07、08 以 `#` 为结束哨兵（专门约定的结束字符，不计入统计）；09 读到 EOF。给 07、08 输入 `A b`、换行、`#`，07 数到 2，08 数到 4：一个空格和一个换行也算字符。

示例条件中的 `&&` 表示“并且”：先成功读到字符，再检查它不是哨兵，才进入循环体。若读取失败，后面的字符比较不会执行；完整的逻辑运算和短路规则在 第 6 章 展开。

Windows 交互终端通常可以在空行按 `Ctrl+Z`、再回车产生 EOF，具体由终端决定。也可以用文件输入获得可重复的结果：

```powershell
g++ -std=c++17 -Wall -Wextra -pedantic 示例代码/05_循环和关系表达式/09_get_eof.cpp -o example.exe
cmd /c "example.exe < 示例代码\05_循环和关系表达式\text_sample.txt"
```

PowerShell 自己不支持这种 `<` 输入重定向，所以这里由 `cmd` 执行。统计文本字符时，本课按文本流读出的字节计数；Windows 文本模式会把文件中的 CRLF 换行转换为 `\n`，结果不一定是磁盘文件字节数。

不要用“按键次数”推算字符数：回车是否产生正文换行、结束控制键怎样处理，与终端和文本模式有关。固定一份文本文件后再测试，才能准确对比两种读取方法。

也不要把汉字数直接与 char 数量画等号：UTF-8 的一个汉字通常占多个字节，本课统计的是流送来的字节字符。英文实验先把空白、读取成功和结束条件理解清楚，再学多字节编码。

> **本节检查**：输入 `A b\n#`，为什么示例 07 是 2，08 是 4？没有 # 而输入直接结束，为什么仍能停止？能回答这两句，再去做单词计数练习。

## 8. 嵌套循环与二维数组

### 8.1 先从表格开始，不从括号开始

假设我们记录两家店连续三天的销量：

| 店铺 / 天 | 第 0 天 | 第 1 天 | 第 2 天 |
|---|---:|---:|---:|
| 第 0 家店 | 10 | 20 | 30 |
| 第 1 家店 | 40 | 50 | 60 |

一维数组像一排柜子，只用一个编号。二维数组像几排柜子：先选第几排，再选排里的第几个，因此要两个下标。

```cpp
int sales[2][3]{{10, 20, 30}, {40, 50, 60}};
```

| 写法 | 本例中的意思 | 值 |
|---|---|---:|
| `sales[0][0]` | 第 0 家店、第 0 天 | 10 |
| `sales[0][2]` | 第 0 家店、第 2 天 | 30 |
| `sales[1][0]` | 第 1 家店、第 0 天 | 40 |
| `sales[1][2]` | 第 1 家店、第 2 天 | 60 |

两个 3 和 2 不能随意交换：`sales[2][0]` 的第一下标越界，虽然第二下标 0 合法。

### 8.2 为什么一层循环不够

**嵌套**就是一个循环体里面再放一个循环。像班级点名：外层选班级，内层逐个点这个班的学生。每换一个班，内层要从第一个学生重新开始。

只写 `for(row=0;row<2;++row)`，每轮只确定了店铺，没确定当天的数据。我们需要在每家店内部，再走三天：

```text
外层 row=0
    内层 col=0 → 访问 [0][0]
    内层 col=1 → 访问 [0][1]
    内层 col=2 → 访问 [0][2]
    内层 col=3 → 条件为假，内层结束

外层 row=1
    重新创建 col=0 → 访问 [1][0]
    内层 col=1   → 访问 [1][1]
    内层 col=2   → 访问 [1][2]
    内层 col=3   → 条件为假，内层结束

外层 row=2 → 条件为假，全部结束
```

内层循环不是只在第一次外层迭代执行一次；**每次外层进入，都重新执行整个内层循环**。本例循环体里的数据处理共 2×3=6 次。

### 8.3 每行合计，哪些变量放里、哪些放外

```cpp
int sales[2][3]{{10, 20, 30}, {40, 50, 60}};
for (int row = 0; row < 2; ++row) {
    int row_total = 0;
    for (int col = 0; col < 3; ++col) {
        row_total += sales[row][col];
    }
    std::cout << row_total << '\n'; // 60、150
}
```

`int sales[2][3]` 是两个“含三个 `int` 的数组”组成的数组。第一个下标选行，第二个选列；这里行只允许 0–1，列只允许 0–2。花括号可以按行初始化，缺少的元素会被置零。

`row_total` 在外层循环体里初始化，每行重新从 0 开始；如果放到外面却不重置，第二次输出会是前两行累计。要算每一列，则外层遍历列，内层遍历行，仍访问 `sales[row][col]`，不能为了换遍历顺序就随意交换下标。

```text
第 0 行：row_total 从0开始 → 10 → 30 → 60
第 1 行：row_total 从0开始 → 40 → 90 → 150
```

若把 row_total 放在外面只初始化一次：

```text
第 0 行结束：60
第 1 行开始：接着60 → 100 → 150 → 210
```

210 是总计，不是第二行本身的合计。变量没有算错加法，**错的是你让它保存了不该保留的上一行结果**。

要同时计算行合计和总计，可以放两个变量：

```cpp
int total = 0;               // 全表保留，只初始化一次
for (int row = 0; row < 2; ++row) {
    int row_total = 0;       // 每行重新开始
    for (int col = 0; col < 3; ++col) {
        row_total += sales[row][col];
    }
    total += row_total;
}
```

### 8.4 列合计：访问顺序变了，下标含义没变

第 0 天要把两家店相加，得到 50；第 1 天为 70；第 2 天为 90：

```cpp
for (int col = 0; col < 3; ++col) {
    int col_total = 0;
    for (int row = 0; row < 2; ++row) {
        col_total += sales[row][col];
    }
    std::cout << col_total << '\n';
}
```

外层现在选天，内层选店铺，但数组仍然是 `sales[店铺][天]`。遍历顺序可以变，数据定义不能跟着被误读。

### 8.5 初始化与长度的两个小规则

```cpp
int zeros[2][3]{};                 // 所有元素为 0
int partial[2][3]{{1}, {2, 3}};    // 每行没给出的元素为 0
```

partial 的内容是第一行 `1 0 0`，第二行 `2 3 0`。花括号按行分组，有助于核对对应关系。

普通内置数组的长度应是编译期常量。本课用固定的 2、3；不要把用户读入的 n 直接放到 `int data[n][3]` 中当作标准 C++ 的通用写法。有些编译器扩展允许这种形式，但 `-pedantic` 会提醒；动态长度可以以后用合适的容器处理。

> **动手实验**：在示例 10 的副本里，把 sales[1][2] 从 60 改成 0。第二行合计、第三列合计、全表总计各减多少？你应该先手算三个结果，再运行。

### 8.6 打图形也是嵌套循环

二维数据不是嵌套循环的唯一用途。例如打印两行、每行三个星号：

```cpp
for (int row = 0; row < 2; ++row) {
    for (int col = 0; col < 3; ++col) {
        std::cout << '*';
    }
    std::cout << '\n';
}
```

```text
***
***
```

换行应在内层结束后发生：打印完一整行再换行。如果把换行放进内层，会变成一个星号占一行。练习中的右对齐三角形再加一个想法：每行打印的点号数与星号数随 row 改变，合起来仍等于总宽度。

## 9. 这课的检查清单

### 9.1 遇到循环错误，按这个顺序查

| 现象 | 先检查哪里 | 为什么 |
|---|---|---|
| 一次都没输出 | 第一次条件是否已经为假 | 先检查的循环可以零次 |
| 多做或少做一次 | 起点、`<` / `<=`、更新位置 | 边界决定哪些轮次进入 |
| 一直停不下来 | 更新有没有执行、方向是否对 | 条件必须有机会变假 |
| 数组结果怪或崩溃 | 每个下标有没有超范围 | 编译器通常不替你检查 [] |
| 累计只剩最后一项 | 累加器是不是每轮重新设为0 | 之前的结果被抹掉 |
| 字符数偏少 | 是否用了跳过空白的 `>>` | 空格和换行被跳过 |
| 字符数多一次 | 是否先检查 `!eof()` 再读 | 失败的那次也被处理 |
| 第二行合计变成总计 | 行合计有没有按行重置 | 上一行数据被继续累加 |

找错误时挑一个最小输入，比如三个数、两个字符、一个空字符串。能手算的输入最适合看出哪一轮不对；一上来输入 100 个值，反而难追踪。

### 9.2 三个层次的完成标准

1. **会读**：能给定初值，在纸上推演每一轮。
2. **会改**：改变上界、步长或一个元素，预测结果如何变化。
3. **会写**：没有示例也能写出区间求和、单词计数和二维统计。

只做到第一层就去抄参考答案，很容易把“看得懂”误认为“自己写得出”。做练习时先写下输入、循环条件和要保留的变量，再补语法。

- [ ] 能解释 `< length`、`<= length` 和空循环体的区别。
- [ ] 不靠猜编译器输出解释未定义行为。
- [ ] 空字符串反向遍历不产生非法下标。
- [ ] 能根据是否保留空白选输入方法，并把读取成功放在循环条件。
