## 0. 学习顺序和示例入口

### 0.1 上一课会重复了，这一课开始会选择

第 5 章 的循环能把每个成绩处理一遍，但还不能仅靠“重复”完成这些要求：

- 及格的显示通过，没及格的提示重学。
- 输入不是数字，提醒用户再输入。
- 用户选课程、进度或退出，执行不同动作。
- 文件没打开成功，说明原因并结束。

这些任务的共同点是：**不是所有代码都应该每次执行，程序要根据情况选一条路。** 这种选择叫分支。

像学校办事窗口：手续完整就办理，缺材料就让你补材料。窗口的规则需要说清“什么情况”“做什么”，程序也一样。

本课顺序是：先学一条条件，再连接多个条件，再做菜单，最后把规则用于输入与文件。后面的完整程序会用到前面的积木；如果读文件代码卡住，先确认 if 和 while 的执行顺序是否已懂。

## 1. `if`：程序到这里，选哪条路

### 1.1 先把“选择”写成中文

我们要处理分数，先不急着写符号：

```text
如果分数达到60分：显示通过
否则：显示需要再练习
```

这句话有三个部分：一个问题、问题成立的动作、不成立的动作。对应到 C++：

```text
if   (问题)   { 成立时的动作 }
else          { 不成立时的动作 }
```

if 的意思是“如果”，else 是“否则”；它们是语言提供的关键字，不是我们声明的变量。

以前的程序顺着往下走，现在要根据数据决定动作。**分支**就是“满足条件走一条路，否则走另一条路”，像根据天气决定是否带伞。

```cpp
if (score >= 60) {
    std::cout << "Pass\n";
} else {
    std::cout << "Try again\n";
}
```

条件先转换为真假；真执行 `if` 块，假执行 `else` 块，只选一边。没有 `else` 时，条件为假就跳过这块。和循环一样，**花括号决定范围，缩进不决定**。

### 1.2 第一次看完整程序，逐行拆开

```cpp
#include <iostream>

int main()
{
    int score = 0;
    std::cout << "Score: ";
    if (!(std::cin >> score)) {
        std::cout << "Please enter an integer.\n";
        return 1;
    }

    if (score >= 60) {
        std::cout << "Pass\n";
    } else {
        std::cout << "Try again\n";
    }
    std::cout << "Finished\n";
    return 0;
}
```

先看 score 后面的分支，不懂输入检查那行时，暂时读作“没有成功读到整数，就说明原因并结束”，第 7 节会拆开它。

| 代码 | 负责什么 |
|---|---|
| `int score = 0;` | 准备一个整数变量 |
| `std::cin >> score` | 从输入里尝试读一个整数放进去 |
| `score >= 60` | 得到 bool：分数是否至少为60 |
| if 中的输出 | 条件为真才做 |
| else 中的输出 | 条件为假才做 |
| 最后的 Finished | 在整个选择完成后继续做 |

输入 75：读入 75，比较为真，输出 Pass，跳过 else，再输出 Finished。

输入 50：比较为假，跳过 if，执行 else，再输出 Finished。

```text
来到条件检查
    |
    +-- score>=60 为真 --> 输出 Pass --------+
    |                                       |
    +-- score>=60 为假 --> 输出 Try again ---+
                                            |
                                            v
                                      输出 Finished
```

**分支选完之后会汇合，继续执行后面的语句。** 它不会自动结束整个程序；上面的输入失败分支之所以结束，是因为写了 return。

### 1.3 没有 else 时，“不成立”就是跳过

```cpp
if (score == 100) {
    std::cout << "Perfect!\n";
}
std::cout << "Thank you\n";
```

100 分打印两行，其他分数只打印 Thank you。没有 else 不代表语法不完整，也不代表“不成立会报错”，只是没有额外动作。

用 `==` 比较是否相等；`=` 是赋值。第 5 章 已经说明：赋值可能仍能用作条件，但做的是另一件事，所以不要把“能编译”当作“条件写对了”。

### 1.4 花括号与那个多出来的分号

```cpp
if (score >= 60) {
    std::cout << "Pass\n";
    std::cout << "Next lesson\n";
}
```

两个动作都需要在通过时做，就都放到 if 的花括号里。若第二行跑到右花括号之外，它就不再受这个条件控制。

```cpp
// 错误示意：
// if (score >= 60);
// {
//     std::cout << "Pass\n";
// }
```

if 后的分号变成受控制的空语句，下面的块独立执行。效果是无论分数多少都打印 Pass，不是“分号帮你结束这一行而已”。这个错误与 while 后多分号类似，但表现可能更隐蔽：程序能很快运行完，只是选择失效了。

### 多个 `if` 与 `else if` 是两种需求

```cpp
if (score >= 90) { /* A */ }
else if (score >= 80) { /* B */ }
else if (score >= 60) { /* C */ }
else { /* D */ }
```

这里按顺序检查，命中第一个真条件后，后面的分支不再检查。把阈值从高往低排：若先检查 `>=60`，95 分也会立刻进入最低通过档。

两条独立的 `if` 会各自检查，可能都执行。例如一个数字既大于 0 又为偶数，两个提示都需要显示，就用独立 `if`。只允许选一个等级，使用 `else if` 链。

### 1.5 用同一个分数看清两种写法

独立检查：

```cpp
int score = 95;
if (score >= 60) {
    std::cout << "Passed\n";
}
if (score >= 90) {
    std::cout << "Excellent\n";
}
```

95 满足两个条件，因此两行都打印。表示“既通过、又优秀”时，这正是我们想要的结果。

互斥选择：

```cpp
if (score >= 90) {
    std::cout << "A\n";
} else if (score >= 60) {
    std::cout << "Passed\n";
} else {
    std::cout << "Not passed\n";
}
```

95 命中第一项，后面不再检查，只有一行输出。这才适合“给一个等级”。不是哪种语法更高级，而是需求是否允许多个动作同时发生。

### 1.6 条件排列顺序要能覆盖边界

以示例 01 的四档为例：

| 输入 | `>=90` | 接着 `>=80` | 接着 `>=60` | 最终选择 |
|---:|---|---|---|---|
| 95 | 真 | 不再检查 | 不再检查 | A |
| 85 | 假 | 真 | 不再检查 | B |
| 75 | 假 | 假 | 真 | C |
| 59 | 假 | 假 | 假 | Not passed |

在第二项里，不需要再写 score<90，因为能走到它就已经说明第一项不成立。这就是从高往低排阈值的好处。

重点测试 59/60、79/80、89/90。写 `>60` 会把正好 60 排除；写 `>=60` 才包含边界。人的“及格”习惯不会替你修正程序里的比较号。

嵌套条件中，没有花括号的 `else` 会匹配最近的尚未匹配的 `if`；不要靠缩进猜。课程代码统一给分支加花括号，先让结构清楚。

输入分数应先检查读取成功，再检查 0–100 的范围。**类型正确不等于业务范围正确**：`-5` 能读成整数，但不是有效分数。

### 1.7 为什么范围检查要在等级判断前面

如果直接按 >=90 评 A，150 也会得到 A；如果不排除负数，−10 可能被当成一个普通未通过分数。

程序要按三层检查：

```text
能读成整数吗？ → 不能：说明输入错误，结束
在0到100之间吗？→ 不在：说明范围错误，结束
属于哪个档？   → 只在数据有效之后评级
```

示例 01 就是这个结构。练习题中的“读入”“校验”“计算”也可以按这个顺序拆开，不要把非法输入硬塞进正常计算过程。

### 1.8 嵌套 if 的 else 跟谁配

这里用两个 bool 变量表示“是否有票”和“是否为学生”。试验前先声明，例如 `bool has_ticket=true; bool is_student=false;`，再放入下面的片段。

```cpp
// 容易误读的写法：
if (has_ticket)
    if (is_student)
        std::cout << "Student price\n";
    else
        std::cout << "Regular price\n";
```

else 匹配最近的尚未匹配的 if，也就是 is_student 那个，不是 has_ticket。虽然文字排版看起来像在外层，语言仍按语法规则匹配。

把结构明确写出来：

```cpp
if (has_ticket) {
    if (is_student) {
        std::cout << "Student price\n";
    } else {
        std::cout << "Regular price\n";
    }
}
```

没有票时整个外层块跳过，不能误以为会打印 Regular price。

> **动手实验**：在自己的测试文件里给 score 依次设 59、60、95。比较两条独立 if 与 else if 链输出几行，再在纸上圈出“哪个条件从未被检查”。

## 2. 逻辑运算：把问题拆成几个条件

### 2.1 单个条件够用了，为什么还需要连接起来

假设要求“分数不低于 60，且不高于 100”。只写 score>=60 会接受 200；只写 score<=100 会接受 −5。两个条件都必须通过才算有效。

可以写嵌套 if，但逻辑运算让这两个真假结果组合成一个结果，再交给 if 或 while。这里的运算对象是“是否成立”，不是把两个分数相加。

`&&` 是“并且”，两边都真才为真；`||` 是“或者”，至少一边真就为真；`!` 是“取反”。它们像门禁规则：证件有效并且预约有效，才能进入。

| A | B | A && B | A \|\| B |
|---|---|---|---|
| 假 | 假 | 假 | 假 |
| 假 | 真 | 假 | 真 |
| 真 | 假 | 假 | 真 |
| 真 | 真 | 真 | 真 |

表里的 A、B 表示两条真假条件，不是固定的变量名。比如把 A 换成 `score>=60`、B 换成 `score<=100`，整个 AND 结果就表示“在这个闭区间内”。

### 2.2 `&&`：每一道要求都通过

```cpp
bool allowed = score >= 60 && score <= 100;
```

| score | >=60 | <=100 | 两项并且 |
|---:|---|---|---|
| 50 | 假 | 真 | 假 |
| 80 | 真 | 真 | 真 |
| 120 | 真 | 假 | 假 |

“一项通过就算通过”不是 AND。像进考场同时要求带证件和准考证，缺任何一个都不满足规则。

### 2.3 `||`：至少一种情况符合

菜单允许小写 q 或大写 Q 退出，要写两个完整比较：

```cpp
bool quit = command == 'q' || command == 'Q';
```

读成“command 是 q，或者 command 是 Q”。任何一项为真即可；两项都为真也会为真，逻辑 OR 不是“恰好一个条件为真”。

这里的 `||` 是两个竖线，键盘通常用 Shift 加反斜杠键输入；不要把字符 1、字母 l 或单个 `|` 写进去。

### 2.4 两个看起来像中文的错误条件

判断闭区间应写 `low <= value && value <= high`。数学里的 `low <= value <= high` 在 C++ 中先把第一个比较算成 bool，再用 0 或 1 与 high 比较，意思完全不同。

```cpp
bool in_range = 10 <= value && value <= 20;
bool quit = command == 'q' || command == 'Q';
```

`command == 'q' || 'Q'` 是错误条件：第二部分只有非零字符值，它本身就为真；两边必须各写完整比较。

把链式比较拆开就看清问题了。假设 score 是 50：

```text
60 <= score <= 100
第一步：60<=50 → false
第二步：false 转成0，再算 0<=100 → true
```

结果竟然为真，不是因为 C++ 觉得 50 及格，而是你问了另一个问题。用两个完整比较，再用 && 连接。

另一种错误也能拆开：

```text
command=='q' || 'Q'
左边：可能为真，也可能为假
右边：'Q' 的字符数值非零，转成真假就是真
所以整个 OR 一直为真
```

**连接符两边各自应该是一个完整的问题。** 不要省略第二次的变量名和比较号。

### 短路求值：有时右边根本不执行

**短路**就是左边已经足以确定结果时，省掉右边的计算：

- `A && B`：A 为假，不执行 B。
- `A || B`：A 为真，不执行 B。

顺序很关键：`denominator != 0 && 12 / denominator > 2` 先排除除数为 0，再做除法。反过来就失去保护。数组访问也应先检查下标范围，再读元素。

```cpp
int calls = 0;
bool result = false && (++calls > 0); // calls 仍为 0
```

示例 02 打印右边是否发生，帮助你看见短路。它适用于这里的内置逻辑运算符；不要拿按位 `&` / `|` 替代 `&&` / `||`，两类运算的目的和求值规则不同。

### 2.5 短路的实际作用：先过安全检查

```cpp
int denominator = 0;
bool useful = denominator != 0 && 12 / denominator > 2;
```

运行过程：左边问“不是 0 吗”，答案是假。AND 已经不可能为真，右边不执行，因此根本没有做除以 0 的运算。

换成 denominator=3，左边真，右边才算 12/3>2，得到真。**不是逻辑运算符把一次错误除法修好了，而是它没有让那次除法发生。**

数组也可以按同样顺序保护：

```cpp
int values[3]{0, 10, 20};
int index = 3;
bool is_zero = index >= 0 && index < 3 && values[index] == 0;
```

第二个条件为假，最后的数组访问被跳过。如果先写 `values[index]==0` 再检查范围，已经越界，再多的后续判断也救不回来。

### 2.6 用一个计数变量看见右边有没有执行

示例 02 用 `++calls` 在右侧留下记录；每次执行才多一次：

| 当前组合 | 右边是否执行 | 示例中累计 calls |
|---|---|---:|
| `false && ...` | 否 | 0 |
| `true && ...` | 是 | 1 |
| `true || ...` | 否 | 1 |
| `false || ...` | 是 | 2 |

这不是让你把所有条件都写成带副作用的复杂表达式，而是一个观察求值过程的实验。实际规则判断尽量读起来清楚；如果某个动作必须执行，不要藏在可能被短路的位置。

### 优先级、取反和另一套拼写

关系比较通常先于 `&&`，`&&` 先于 `||`。仍建议对混合条件加括号，例如 `(age >= 18 && has_ticket) || is_staff`。

`!n` 得到 bool，并非把数字改成相反数；`!!7` 为 true，不会恢复为整数 7。`!(a && b)` 等价于 `!a || !b`，`!(a || b)` 等价于 `!a && !b`，可用于检查“全部通过”与“有一项失败”。

原书 6.2.6 的 `and`、`or`、`not` 是 `&&`、`||`、`!` 的替代拼写，C++ 中不需额外头文件。本课程统一用符号，以便对照常见代码。

### 2.7 `!`：把一个问题的答案反过来

```cpp
bool finished = false;
bool keep_going = !finished; // true
```

finished 不变；`!finished` 产生相反的真假结果，不是在给 finished 重新赋值。

```text
!true  → false
!false → true
!0     → true   （0先转换为假）
!7     → false  （7先转换为真）
!!7    → true   （仍是bool，不是整数7）
```

别把逻辑取反 ! 与算术负号 − 混淆：`-7` 是整数 −7，`!7` 是 bool false。

### 2.8 括号先帮助人读，再帮助编译器分组

```cpp
bool allowed = (age >= 18 && has_ticket) || is_staff;
```

表示“成年且有票，或者是工作人员”。换成 `age>=18 && (has_ticket || is_staff)`，则工作人员也必须成年；分组不同，规则不同。

不用一次背完整优先级表，遇到混合 AND、OR，先把中文规则写出来，然后用括号标明哪两项一起判断。

取反一整组也要括号：`!(a&&b)` 表示“不是同时成立”，可以拆成“a不成立或b不成立”。如果写成 `!a&&b`，只取反 a，问题已经变了。

> **动手实验**：假设 age=16、has_ticket=false、is_staff=true，手算上面两个分组的结果。再运行验证。差异来自条件结构，不来自随机输入。

## 3. `cctype`：判断字符，先明确输入范围

### 3.1 先区分“字符 3”与“整数 3”

```cpp
char ch = '3';
int number = 3;
```

ch 保存数字字符 `'3'` 的编码值，number 保存用于计算的整数 3。判断 ch 是否为数字字符，是问“它是不是 0到9这些符号之一”，不是问它的数值是否小于10。

要把 `"123"` 整串解析成整数，那是数字输入/转换的任务。`isdigit` 一次只分类一个字符，并不会把字符串变成数。

**字符分类函数**替你判断“这是字母吗、数字吗、空白吗”。不必每次写一串字符范围比较，像把逐项检查交给一个分类员。

| `<cctype>` 函数 | 用途 |
|---|---|
| `std::isalpha` | 是否为字母 |
| `std::isdigit` | 是否为数字字符 |
| `std::isspace` | 是否为空白，如空格、换行、制表符 |
| `std::isalnum` | 是否为字母或数字 |
| `std::ispunct` | 是否为标点 |
| `std::islower` / `std::isupper` | 是否为小写 / 大写字母 |
| `std::tolower` / `std::toupper` | 转小写 / 大写，不能转换的字符保持不变 |

分类函数返回整数，**非零**表示真，不应硬写 `isalpha(ch) == 1`。

### 3.2 这些函数为什么比一长串比较方便

如果只判断某些英文大写字母，你可以检查字符范围；但空白不止一个普通空格，还可能是换行、制表符等。库函数已经把分类规则装好，你只需问它。

```cpp
char ch = 'A';
unsigned char byte = static_cast<unsigned char>(ch);
bool letter = std::isalpha(byte) != 0;
bool digit = std::isdigit(byte) != 0;
```

letter 为真，digit 为假。`std::` 仍表示使用标准库里的名字；`#include <cctype>` 告诉编译器这些函数的声明在哪里。

不必写 `!=0` 才能放到 if 条件，因为 if 会把非零值当真；示例写成 `if(std::isalpha(byte))` 就是这个意思。

### 3.3 转换函数提供一个结果，不会自动改原变量

```cpp
char ch = 'a';
unsigned char byte = static_cast<unsigned char>(ch);
char upper = static_cast<char>(std::toupper(byte));
```

upper 得到 A，ch 仍然是 a。如果希望 ch 本身改变，需要把结果赋回 ch：

```cpp
ch = static_cast<char>(std::toupper(byte));
```

像把一张小写字母卡交给窗口，窗口递回大写版；你不接住结果，桌上的原卡并不会自己变样。原书复习题也提醒“计算出的值”和“修改变量”是两件事，这与上一章的表达式概念相连。

### 3.4 程序中那两个 `static_cast` 是在做什么

当字符已放在 `char` 中，安全用法是先转换为 `unsigned char` 再传入：

```cpp
unsigned char byte = static_cast<unsigned char>(ch);
if (std::isalpha(byte)) {
    char upper = static_cast<char>(std::toupper(byte));
    std::cout << upper;
}
```

原因是有的平台 `char` 带符号，高位字节可能成为负数；这些函数要求参数是能用 `unsigned char` 表示的值，或 EOF。无参数 `get()` 返回值要先检查 EOF，再按字符处理，不能把 EOF 转成 unsigned char 后当正文。[微软字符分类函数的参数说明](https://learn.microsoft.com/en-us/cpp/c-runtime-library/reference/isalnum-iswalnum-isalnum-l-iswalnum-l?view=msvc-170)

本课不改变区域设置，示例按常见英文字符分类。`std::string` 里的 UTF-8 中文可能由多个字节组成，逐字节 `isalpha` 不是中文分词或 Unicode 字符分类。

初学时把安全写法记成两个动作即可：

```text
从char变量取出字节 → 转成unsigned char → 交给分类/转换函数
转换函数返回的整数结果 → 转成char → 存入字符变量或输出
```

第一个转换是避免带符号 char 的负值进入不接受它的接口；第二个是把函数返回的整数结果按字符保存。完整的字符编码和区域设置是补充阅读，当前先用 A、b、1、空格和标点进行实验。

### 3.5 跟着示例 03 逐个分类

输入一行 `A b1!` 后回车，再结束输入：

| 读到的字符 | 命中哪个分支 | 计数变化 | 是否输出字符 |
|---|---|---|---|
| A | isalpha | letters+1 | 输出A |
| 空格 | isspace | spaces+1 | 不输出 |
| b | isalpha | letters+1 | 转大写输出B |
| 1 | isdigit | digits+1 | 不输出 |
| ! | 最后的else | others+1 | 不输出 |
| 换行 | isspace | spaces+1 | 不输出 |

正文输出 AB，统计是字母2、数字1、空白2、其他1。不要把它理解为“原样复制整个输入”：示例选择只输出字母，其他字符只做分类统计。

这是 else if 链的又一个用途：每个字节选一个分类，避免同一项被重复统计。若需求是独立统计可能重叠的类别，比如“字母数量”和“字母或数字数量”，才考虑独立 if。

> **动手实验**：把输入改为 `ab 12!`，手算四个计数。再用没有末尾换行的文本文件做一次，解释空白数为什么少1。

## 4. `?:`：只在两个值中选一个

### 4.1 分支还能直接给出一个值

已经会用 if 选择动作，接下来要解决“选出的结果要存入变量”。比如求 a、b 中较大的数：

```cpp
int larger;
if (a > b) {
    larger = a;
} else {
    larger = b;
}
```

只有一个简单结果要选择时，条件运算符把它写成一个表达式。

**条件运算符**的格式是 `条件 ? 真时表达式 : 假时表达式`，它产生一个值；只求值被选中的那一边。

```cpp
int larger = a > b ? a : b;
std::cout << (score >= 60 ? "Pass" : "Fail");
```

第二行的括号帮助明确输出的是整个选择结果。若分支中要做多件事或条件很长，用 `if...else` 更易读；不必为省行数套多层 `?:`。

### 4.2 拆开问号和冒号

```text
int larger = (a > b) ? a : b;
              问题    真  假
```

- 先判断 a>b。
- 为真，整个表达式的结果是 a。
- 为假，整个表达式的结果是 b。
- 把选出来的值赋给 larger。

如果 a=3、b=8，larger 为8；如果两者都4，条件为假，选 b 的4，结果仍然4。

左右两边不是都执行再丢掉一边。这里只求值选中的表达式；但不要利用这点堆叠很多自增和输出动作，保持“选一个简单值”的用途即可。

条件运算符有三个操作数，所以也叫三目运算符。这个术语只是在数：条件、真时结果、假时结果，一共三项。

> **小检查**：`score>=60 ? "Pass" : "Fail"` 得到的是哪种用途的结果？它自己会不会打印？答案是选出文本，只有交给 cout 才输出。

## 5. `switch`：按离散命令选择动作

### 5.1 先看一个普通字符菜单

我们约定 c 继续学习，p 查看进度，q 退出。输入的是字符，因此用户敲 q，程序通过 `char command; cin>>command;` 得到的是 `'q'`，不是整数编号。

用 if...else 也能写这个任务：

```cpp
if (command == 'c') {
    std::cout << "Continue\n";
} else if (command == 'p') {
    std::cout << "Progress\n";
} else if (command == 'q') {
    std::cout << "Quit\n";
} else {
    std::cout << "Unknown command\n";
}
```

switch 把“同一个值与多个固定值比较”的结构集中写出来。先认字符版，再读枚举标签，不需要第一步就写很多新类型。

如果输入只可能是 `'c'`、`'p'`、`'q'` 等菜单命令，一串相等比较可以改为 `switch`，像按按钮编号找到对应功能。

```cpp
switch (command) {
case 'c':
case 'C':
    std::cout << "Continue\n";
    break;
case 'q':
case 'Q':
    std::cout << "Quit\n";
    break;
default:
    std::cout << "Unknown command\n";
}
```

匹配到一个 `case` 后从那里开始执行，**不会自动在下一个 case 停下**。`break` 才离开 `switch`；`default` 处理没有匹配的输入。两个大小写 case 连续写、共用一个动作，是有意合并分支；执行完一个动作却忘写 break，常是错误。

### 5.2 每个部件叫什么、做什么

| 写法 | 作用 | 容易漏什么 |
|---|---|---|
| `switch(command)` | 先计算这次要选择的值 | 圆括号与整个块 |
| `case 'c':` | 标记字符c对应的入口 | 冒号、字符单引号 |
| 标签后面的语句 | 从入口往下执行的动作 | 不会自动停止 |
| `break;` | 离开当前switch | 分号 |
| `default:` | 无case匹配时的入口 | 它不是必须有，但菜单通常需要 |

`case` 是标签，不是一个自动包住代码的 if 块。正是这个区别带来了“贯穿到下一个标签”的行为。

### 5.3 漏 break，为什么打印了两种结果

```cpp
char command = 'a';
switch (command) {
case 'a':
    std::cout << "A";
case 'b':
    std::cout << "B";
    break;
default:
    std::cout << "?";
}
```

执行路线：匹配 a → 输出A → 没有break，继续往下 → 输出B → 遇到break退出。所以输出 AB，而不是 A。

执行进入 a 后，**并没有再次问“command是不是b”**，b 标签只是被路过。理解这点，才能解释贯穿。

如果 a 末尾有 break，则只输出 A。如果想多个值共用同一动作，可以有意把几个空标签写在一起，例如 c/C；不要把两种情况混为一谈。

### 5.4 什么情况用 if，什么情况用 switch

条件通常是整数、字符或枚举值；case 标签是不同的编译期整型常量。不能直接 `switch(std::string)`，也不能写 `case score >= 60:` 表示区间。区间用 `if`，若干固定值用 `switch`。

| 需求 | 合适的写法 | 原因 |
|---|---|---|
| 分数是否>=60 | if | 是范围比较 |
| 成年且有票 | if | 是组合条件 |
| 命令是c、p、q中的一个 | switch或if链 | 比较同一个字符与几个固定值 |
| 字符串是否等于done | if | switch不能直接接std::string |

如果希望在某个 case 中声明局部变量，可以用块明确它的作用域：

```cpp
case 'p': {
    int completed = 2;
    std::cout << completed;
    break;
}
```

### 5.5 枚举标签：给状态编号起名字（回顾 第 4 章 B）

```cpp
enum Action { Continue, Progress, Quit };
Action action = Progress;
switch (action) {
case Continue: std::cout << "Continue\n"; break;
case Progress: std::cout << "Progress\n"; break;
case Quit: std::cout << "Quit\n"; break;
}
```

枚举量背后有整数值，switch 可以用它作标签。这里不是拿英文字串 Progress 去比较，而是拿枚举值作选择。与字符菜单相同的入口/贯穿/break 规则仍然适用。

这一小节只把旧知识接起来；示例 05 使用直接的字符菜单，先把它独立跑通即可。

## 6. `break` 与 `continue`：影响哪个结构

### 6.1 循环条件之外，还可以提前结束

第 5 章 已经会在 while 的条件为假时结束循环。有时进入这一轮后才发现“这里就是结束标记”，break 可以马上离开，不必把所有处理都塞到一个很长的循环条件里。

continue 则没有结束整个循环，它只是放弃这一轮剩下的处理。要在脑子里分清“这件工作结束”和“这个样本跳过”。

`break` 离开最内层循环或 `switch`，像提前结束这场比赛；`continue` 结束本次循环体的剩余动作，继续下一轮，像跳过一个不符合要求的样本。

```cpp
int number;
int sum = 0;
while (std::cin >> number) {
    if (number == 0) break;
    if (number < 0) continue;
    sum += number;
}
```

输入 `5 -2 7 0 100`，只累计 5 和 7，得到 12。循环被 0 结束，100 不再读取处理。

### 6.2 每轮发生了什么

| 读到 number | 先看是不是0 | 再看是不是负数 | 累加动作 | 下一步 |
|---:|---|---|---|---|
| 5 | 否 | 否 | sum变5 | 再读 |
| −2 | 否 | 是 | 被continue跳过 | 再读 |
| 7 | 否 | 否 | sum变12 | 再读 |
| 0 | 是 | 不检查 | 被break跳过 | 结束循环 |
| 100 | 没有再读取 | — | — | — |

所以“输入里有100”和“程序处理了100”不是一回事。结束协议告诉程序从哪里停止，它不会自动把所有已经写在文件里的数据都处理完。

在 `for` 中 `continue` 会转到更新表达式，然后检查条件；在 `while` 中转到条件。因此若 `while` 的更新放在体尾，却在它之前 continue，可能不更新并陷入死循环。

嵌套 `switch` 中的 break 只离开 `switch`，不会顺带离开外层菜单循环。示例 05 另用 `running` 控制外层循环，收到退出命令就设为 false。

### 6.3 为什么菜单要单独有一个 running

**标志变量**就是保存某个状态的变量。`bool running=true;` 表示菜单目前还运行。

```cpp
bool running = true;
char command;
while (running && (std::cin >> command)) {
    switch (command) {
    case 'q':
        running = false;
        break;
    default:
        std::cout << "Try another command\n";
        break;
    }
}
```

遇到 q：先把 running 设成 false，break 离开 switch，来到 while 的下一次条件检查。running 已为假，于是外层循环结束。

若只写 break 而不改变 running，会离开这次 switch，随后 while 仍会再等待命令，看起来就像“q没有退出”。**break 离开最内层能接收它的循环或switch，不是退出程序的万能按钮。**

示例 05 支持大写与小写。读取用 >> char，默认跳过空格和换行，适合一个字符的命令；如果输入 hello，它会被当成 h、e、l、l、o 五次输入，而不是一个完整菜单命令。

### 6.4 continue 会不会漏掉更新

先看普通 for：

```cpp
for (int i = 0; i < 3; ++i) {
    if (i == 1) continue;
    std::cout << i; // 输出0、2
}
```

continue 之后仍会走 for 的更新 ++i，再检查条件。因此它不会因为跳过输出就卡在 i=1。

但 while 的更新如果写在体尾，continue 可以跳过它：

```cpp
// 危险示意，不运行：
// int i=0;
// while(i<3) {
//     if(i==1) continue;
//     ++i;
// }
```

i 变成1后，continue 一直让程序回到条件，永远到不了 ++i。修正办法是调整更新位置或使用本来就适合计数的 for，而不是随便再添一个 break 掩盖循环设计问题。

> **动手实验**：把示例 06 的输入设为 `0`、全为负数、`5 -2 7 0 100`。分别预测 sum，指出哪些数据读到了但被跳过、哪些根本没处理。

## 7. 数字输入：失败是状态，需要处理

### 7.1 “不在范围内”和“读不成数字”是两个问题

```cpp
int number;
std::cin >> number;
```

假设程序只接受0–100：

| 用户输入 | 能否按int提取 | 业务上能否接受 | 要做的事 |
|---|---|---|---|
| 80 | 可以 | 可以 | 使用它 |
| −1 | 可以 | 不可以 | 提示范围错误 |
| 101 | 可以 | 不可以 | 提示范围错误 |
| abc | 失败 | 没有有效的本次整数 | 处理流失败 |
| EOF | 没有新数据 | 输入已经结束 | 正常退出输入循环 |

输入 −1 不会因为你的程序规定“不接受负数”就使 cin 自动失败。库负责解析类型，程序自己负责数据规则。

### 7.2 先成功读入，才可以处理这个新值

`std::cin >> number` 尝试把输入解释成数字。如果用户输入 `hello`，提取失败，流进入失败状态；此后直接继续读，通常仍会失败。像录入系统卡在一条无法解析的记录上，必须先恢复状态再移走这条记录。

第 5 章 已经用到这种条件：

```cpp
while (std::cin >> number) {
    // 这里只处理成功读到的新整数。
}
```

`cin>>number` 的返回结果是输入流，用作条件时会根据状态判断是否成功。它不是 number 本身，所以成功读到整数0，条件仍然可以为真。

再看一次读取时的错误分支：

```cpp
if (!(std::cin >> number)) {
    // ! 把“读取成功”取反，这里只在读取失败时进入。
}
```

括号里的提取先发生，! 再取反。不能理解成“先把 number 取反再输入”。遇到这种有括号的表达式，先把最里面要做的动作说成一句话，再往外读。

### 7.3 失败标志和错误文字，分别还留在那里

输入 abc 后，可以画成两个问题：

```text
流的状态：这次提取失败了，以后的读取会先受这个状态影响
等待读取的文字：abc和行尾还需要被丢弃或重新处理
```

只修正其中一个，另一个问题仍存在。教材 6.7 展示的 clear 加丢弃输入，正是在处理这两层。

示例 07 接受 **0–100 的整数**，不合格就重新询问；EOF 正常结束。

```cpp
int number;
if (!(std::cin >> number)) {
    if (std::cin.eof()) { /* 输入结束 */ }
    else if (std::cin.bad()) { /* 底层读取错误 */ }
    else {
        std::cin.clear();
        std::cin.ignore(std::numeric_limits<std::streamsize>::max(), '\n');
        // 重新询问；先 clear，再 ignore
    }
}
```

`clear()` 清除状态标志，**不会自动删掉缓冲区里的错误文字**；`ignore` 丢弃到行尾，需要 `<limits>`。这里只忽略出错的那一整行，所以 `hello 80` 的 80 也被放弃，下一行再输入。

### 7.4 两行恢复代码按顺序看

```cpp
std::cin.clear();
std::cin.ignore(std::numeric_limits<std::streamsize>::max(), '\n');
```

第一行：把流恢复到可以继续尝试读取的状态。

第二行：从输入中丢弃字符，直到碰到换行或达到指定数量。这里给足够大的数量，就是为了让整条错误行都被丢弃，换行本身也被取走。

`std::streamsize` 是流使用的计数类型；`std::numeric_limits<...>::max()` 取得这个类型能表示的最大值，需要 `<limits>`。这些尖括号是标准库的用法，完整模板知识后面学；当前可以把整行当成“丢弃剩余一行”的工具写法，重点理解何时调用和先后顺序。

| 错误修复 | 为什么还可能失败 |
|---|---|
| 只clear | 失败状态解除，但下一次又遇见同一条abc |
| 只ignore | 流仍处于失败状态，丢弃操作通常不能按预期继续 |
| 先clear，再ignore | 先能读取，再移走坏输入，下一行可以重新尝试 |

### 7.5 输入结束时，为什么不能继续叫用户重输

如果来源已经结束，clear 只能清除状态，不能创造新数据。下一次读取又失败，再clear……，会反复提示而停不下来。

示例 07 区分 EOF、底层读取错误、可恢复的格式错误。**EOF 是结束约定，格式错误才需要在这个程序里重问**。

`bad()` 表示底层读写出现严重错误，比如数据来源不能正常工作；它与用户输入了一个字母不同，不应简单清掉后无限重试。

### 7.6 把示例 07 用固定输入追踪一遍

依次每行输入 abc、−1、101、80，然后 EOF：

| 这次输入 | 哪个分支 | 状态或数据处理 | 是否继续 |
|---|---|---|---|
| abc | 提取失败、非EOF | clear后丢弃这行，显示Not an integer | 是 |
| −1 | 提取成功、范围无效 | 显示Out of range，不需要clear | 是 |
| 101 | 提取成功、范围无效 | 同上 | 是 |
| 80 | 成功且有效 | 显示accepted=80 | 是 |
| EOF | 提取没有新数据 | 显示End of input，break | 否 |

这段程序把第1节的 if、第2节的逻辑、第6节的 continue/break 都接起来了。第一次读看表，第二次读在源码中圈出每个分支，第三次再自己敲一个简化版。

原书 6.7 还示范“遇到非数字就结束”的输入循环；这是另一种明确的结束约定，不一定需要纠错。选择停止还是重问，取决于程序任务。

注意：格式化提取可读取合法的数字前缀，输入 `12abc` 时可能先读到 12，剩下 `abc` 影响下一次读取。示例 07 **不是整行格式校验器**。如果要严格要求整行只有一个整数，可先 `getline` 再解析；完整流工具在第 17 章再展开。

例如你希望“一行只输入一个整数”，但 `>>int` 实际做的是“先按整数格式提取能取的那部分”。这也是为什么本课不能说“能提取就证明整行完全合法”。先认识这种边界，不必在第6章同时做一个复杂的文本解析器。

> **动手实验**：输入 `hello 80` 在同一行，再输入下一行的90。观察恢复策略丢弃了哪一部分。随后单独输入12abc，说明为什么可能先接受12，再对剩余文字报错。

### 流转 bool 不等于 `good()`

流用作条件，检查的是没有 `failbit` 或 `badbit`；`good()` 则要求所有状态位都未设置。成功读到最后一个数字时，可能同时到达 EOF：数字有效，流转 bool 仍为真，但 `good()` 已为假。原书在文件示例附近将两者作简化等同，本课采用 `while (in >> value)`，避免漏掉末尾没有换行的最后一个数字。[标准的流状态定义](https://eel.is/c++draft/basic.ios.members)

这是**补充阅读**。第一次学只记住“把读取表达式放在循环条件”即可，不必背状态位的每种组合。

| 名字 | 当前只需理解为 |
|---|---|
| eofbit | 输入来源到头了 |
| failbit | 这次提取没有按要求完成 |
| badbit | 底层读写出了严重问题 |

标志可以同时存在，所以不能把三种名字想成互斥的三个单选等级。最后一个合法数字可能成功读到，同时发现EOF；成功数据仍应该处理一次。正文中的标准链接用于解释原书简化处，不要求你先读完标准草案。

## 8. 文件输入输出：换一个数据来源

### 8.1 屏幕显示过，不代表磁盘保存过

`cout<<total` 把结果送到终端显示，程序里的变量在进程结束后也不会自动变成一份文件。如果希望明天还能打开结果，必须明确写入文件。

文件流使用熟悉的 `<<`、`>>`，所以你不需要换一整套输出语法。改变的是流连接到哪里：

```text
std::cout  ---- 输出 ----> 终端屏幕
std::ofstream 对象 ----> 磁盘中的文本文件

std::cin   <--- 输入 ---- 终端或重定向来源
std::ifstream 对象 <--- 磁盘中的文本文件
```

### 8.2 文本文件里到底存了什么

```text
10
20.5
-3
```

这是字符形式的数字：字符1、字符0、换行……。读取到 double 时，流再按数字格式解释它们。文本文件不是简单把 double 在内存里的那几个字节直接抄到磁盘；二进制文件是另一类话题，第17章再展开。

文件扩展名 `.txt` 是帮助人识别用途的名字部分，不是 C++ 判断能否读取数字的魔法开关。关键仍是打开能否成功、内容是否符合读取格式。

### 8.3 第一次创建输出文件，逐行读

终端关闭后，变量里的数据就没了。**文件流**让程序把数据写到磁盘，或从磁盘读入；可以把它理解为 `cout` / `cin` 换了一根连接到文件的管道。需要 `<fstream>`。

```cpp
std::ofstream out("numbers.txt");
if (!out) { /* 打开失败，停止 */ }
out << 10 << '\n' << 20 << '\n';
```

`ofstream` 默认打开普通输出文件时会截断已有内容；本课只写示例文件 `course_numbers.txt`，不要把路径换成自己的重要文件。若要追加，显式使用 `std::ios::app`，追加是否合适由数据格式决定。

把完整例子的动作拆开：

```cpp
#include <fstream>
#include <iostream>

int main()
{
    std::ofstream out("course_numbers.txt");
    if (!out) {
        std::cerr << "Cannot open output file\n";
        return 1;
    }
    out << 10 << '\n' << 20.5 << '\n' << -3 << '\n';
    out.close();
    if (!out) {
        std::cerr << "Write or close failed\n";
        return 1;
    }
    std::cout << "Wrote course_numbers.txt\n";
    return 0;
}
```

| 代码 | 人话 |
|---|---|
| `std::ofstream` | 标准库的输出文件流类型 |
| `out` | 我们给这条输出管道取的变量名 |
| `("course_numbers.txt")` | 创建对象时，告诉它要连接哪个文件 |
| `if(!out)` | 问“刚才打开失败了吗” |
| `out << ...` | 把内容送往文件，而不是cout的屏幕 |
| `out.close()` | 结束这次文件写入，关闭连接 |

这里的括号是在创建文件流对象时给出文件名，不是每行都重新打开一次。后面 `out<<...` 使用同一个已打开的流。

`cerr` 是错误输出流，也常显示在终端；用它表达诊断信息。`return 1` 表示程序以失败状态结束，不是向文件写入数字1。

### 8.4 文件到底写到哪个文件夹

**相对路径**从程序的当前工作目录出发，不是自动从 `.cpp` 所在目录出发。在课程根目录编译运行，生成文件就在课程根目录；从其他目录启动同一个 exe，文件位置可能不同。用 `Get-Location` 确认所在目录，调试配置也可能指定工作目录。

| 启动前所在位置 | 程序使用的相对文件名 | 实际查找的位置 |
|---|---|---|
| 本课目录 | course_numbers.txt | 本课目录里的该文件 |
| 本课目录/my_code | course_numbers.txt | my_code里的该文件 |
| 另一个文件夹 | course_numbers.txt | 那个文件夹里的该文件 |

“我的 `.cpp` 在 code 文件夹里”并不能证明文件也在 code 中。编译所在目录、可执行文件所在目录、运行时工作目录是三件可以不同的事。

手动验证时，先在终端执行 `Get-Location`，再运行程序。不要一边从编辑器按钮运行、一边到另一个目录找文件，然后以为程序没写入。

路径含空格时：终端命令中的路径要按 shell 规则用引号包住；程序用 getline 读入的文件名，则直接输入路径文字，不需要把两侧引号也当文件名输进去。

### 8.5 打开成功，后面写入仍要检查

示例 08 写入 10、20.5、−3，然后显式 close 并检查状态；即使打开成功，也仍可能在写入或关闭时失败。局部文件流通常在离开作用域时自动关闭，显式关闭便于本课检查结果。

原书先教打开和常规写入，我们的示例再把失败分支写清楚。现在先掌握三个检查点：

1. 打开后：文件能否作为输出目标？
2. 写入时：内容有没有正常送出？
3. 结束时：关闭/提交剩余输出有没有失败？

写完可以用记事本打开 `course_numbers.txt`，应看见三行数据。没有看见文件时先查工作目录，文件为空时再看是否真的执行到写入语句。

### 8.6 输入文件流，用熟悉的 `>>` 读数字

### 读取、累计与区分结束原因

```cpp
std::ifstream in(filename);
if (!in.is_open()) { /* 文件不存在或无法打开 */ }
double value;
while (in >> value) {
    total += value;
    ++count;
}
```

不要写 `while (!in.eof())` 先进入体内，再读取。也不要在 `while(in >> value)` 后再把最后一次 value 累加，读取失败时它不是新的有效数据。

`std::ifstream` 表示输入文件流类型；in 是我们取的变量名，filename 是保存路径的字符串。`in.is_open()` 问文件连接是否已打开。

然后用 `in >> value` 替换从终端读取的 `cin >> value`。每次成功提取一个数字，total 加上它，count 加1：

| 成功读到 | 之前total | 更新后total | 更新后count |
|---:|---:|---:|---:|
| 10 | 0 | 10 | 1 |
| 20.5 | 10 | 30.5 | 2 |
| −3 | 30.5 | 27.5 | 3 |

没有第四个数字，下一次读取失败，循环退出，不会再次加上 −3。

### 8.7 空文件也应该是一个明确结果

```cpp
if (count == 0) {
    std::cout << "No data\n";
} else {
    std::cout << total / count << '\n';
}
```

空文件能打开成功，但是零次成功读取。**打开成功不代表里面至少有一个数字。** count 为0时直接说明无数据，不算平均值。

这里 total 是 double，除法是浮点除法，不是两个int相除。如果以后把 total 改成整数，平均值的小数问题又要重新考虑。

### 8.8 循环停了，问清楚为什么停

停止后区分：`bad()` 是底层读取错误；`eof()` 通常表示到达文件末尾；否则 `fail()` 可能意味着遇到非数字。它们是状态位，可以同时存在。这里接受由空白分隔的普通有限十进制数；示例 09 发现非数字就报告失败，不伪装成完整统计。

本课解析仍采用格式化提取：如果末尾出现一个不完整数字，比如只有 `1e`，可能同时设置 failbit 和 eofbit，单看 EOF 无法证明整份文本格式严格正确。严格格式验证留待后续；练习至少用 `10 bad 20` 检验非数字路径。

第一次学可以用三份小文件建立直觉：

| 文件内容 | 应看到什么 | 要理解什么 |
|---|---|---|
| 空文件 | count=0、No data | 没数据不能求平均 |
| `10 20 30`，末尾无换行 | count=3、total=60 | 最后一个数字仍要处理 |
| `10 bad 20` | 报非数字数据错误 | 停止不一定意味着正常读完 |

原书演示文件处理的基本流程；“任意格式都能严格验证”是更大的任务。本课把接口能做什么、暂时没有做什么讲清楚，不要求第一次学文件就解决所有解析问题。

### 8.9 完整走一遍写入再读取

没有有效数据时，不计算 `total / count`，否则除数为 0。空文件应显示 `count=0`、`No data`。

先运行写入程序，再运行读取程序，输入 `course_numbers.txt`，应得到数量 3、合计 27.5、平均约 9.16667。文件名用 `getline` 读取，允许路径含空格。也测试空文件、不存在的文件、文件最后一个数字后没有换行。

具体操作：

```powershell
g++ -std=c++17 -Wall -Wextra -pedantic 示例代码/06_分支语句和逻辑运算符/08_write_file.cpp -o write_demo.exe
./write_demo.exe
g++ -std=c++17 -Wall -Wextra -pedantic 示例代码/06_分支语句和逻辑运算符/09_read_file.cpp -o read_demo.exe
./read_demo.exe
```

read_demo 提示 `File name:` 时，输入 `course_numbers.txt` 再回车。不是输入 `.cpp` 文件名，也不是输入 write_demo.exe；我们要读的是刚才生成的数据文件。

预期主要输出：

```text
count=3 total=27.5
average=9.16667
```

接着把文件副本改成空文件，再运行读取程序；再填入 `10 bad 20`，观察错误分支。先在副本里实验，可以保留原来成功的数据做对照。

### 8.10 为什么文件名用 getline

`cin>>filename` 默认读到空白结束，输入 `my data.txt` 只会拿到 my。`getline(cin,filename)` 读取整行，才能把含空格的路径保存进去。

本课文件示例独立运行，在读取路径之前没有读过数字，所以没有“数字后残留换行”的问题。若把它接到菜单或数字输入后面，就要回顾 第 4 章 A：上一条提取有没有留下换行，下一次 getline 会先读到什么。

> **动手实验**：新建名为 `my data.txt` 的文件，填入三个数字。用示例 09 读它，说明为什么文件名中的空格保留下来了；随后换到另一个工作目录，再用相对路径，解释查找位置的变化。

## 9. 过关标准

### 9.1 看见现象，先定位是哪一层

| 现象 | 先检查什么 |
|---|---|
| 95分得到最低通过档 | else if的阈值排列顺序 |
| 未通过也显示Pass | if后是否多分号、输出是否在块外 |
| 任意命令都退出 | 是否写了 `command=='q' || 'Q'` |
| 按q后菜单仍继续 | break只离开switch，外层状态是否改变 |
| abc后一直报错 | clear和丢弃坏行有没有都做 |
| −1后没法继续 | 读取成功但超范围，不要误当流失败 |
| 找不到刚写的文件 | 实际工作目录、相对路径 |
| 最后一个数丢了或多算一次 | 是否把读取本身放在循环条件 |
| 空文件平均值异常 | count=0是否单独处理 |

### 9.2 写程序之前，先写四句计划

拿“文件统计”作为例子：

```text
我需要哪些输入：一个整行文件名，文件中是数字。
输入有效的条件：路径能打开，每次数字提取成功。
我每次保留什么：到目前为止的总和与数量。
什么情况结束：正常文件末尾；打不开或遇坏数据则说明错误。
```

再把每句分配给 getline、if、while、累加器。程序不是先背一串符号，再猜能完成什么；是先确定任务，再选择恰好表达任务的语句。

如果独立写不出完整程序，可以先只做“读一个分数并评级”，再做“反复读取”，最后再换成文件来源。把几个已经跑通的小步骤连起来，比一次抄最长的程序容易理解。

- [ ] 能解释独立 `if` 和 `else if` 的区别，正确覆盖边界值。
- [ ] 能写完整的区间和大小写退出条件，说出短路跳过哪一边。
- [ ] 字符分类前处理 `char` 的符号问题，不把 EOF 当正文。
- [ ] 菜单处理非法命令，退出时确实结束外层循环。
- [ ] 能解释 clear 与 ignore 各自做什么，EOF 不会触发无限重问。
- [ ] 能读写文本文件，正确处理空文件和没有末尾换行的数据。
