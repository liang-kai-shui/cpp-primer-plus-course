💡 文件名已经暗示了问题所在——但这不是重点。 你要判断的是：它属于哪一类错误？会不会生成 exe？报错里会出现什么关键词？

做法（顺序很重要，不要跳步）

对每一个文件，严格按这三步：

  1. 先预测：只看代码，填下面的表——「我猜这是哪类错误？」
  2. 再验证：在 VS Code 里打开这个 .cpp，运行（或用终端 g++ 命令）
  3. 后对照：去打开 参考答案/第01章/错误分类实验-答案.md，看真实结果

💡 为什么必须先预测？ 因为「看一眼就知道是啥错」这个能力，靠的是预测→打脸→修正这个循环。 直接看答案的话，下次还是不会。

✅ 任务 5：找 bug 练习（思考题）

下面这段凯撒密码程序：输入 abc 输出 def，看着很正常。 但输入 XYZ 时，它输出的是 [\]，而不是 ABC。

// 片段：把每个大写字母往后偏移 3 位
for (int i = 0; i < s.size(); ++i)
{
    if (s[i] >= 'A' && s[i] <= 'Z')
        s[i] = 'A' + (s[i] - 'A' + 3);   // 问题出在这里
}

这道题不是在考你写代码，而是拿现成的代码当"找 bug"的练习素材—— 读别人的代码并找出问题，是一项独立且很重要的能力。

  • [ ] 找出这个 bug 的根本原因（提示：'X' - 'A' + 3 等于多少？'A' + 26 是哪个字符？）
答：
  • [ ] 这个 bug 属于讲义里的哪一类错误？（编译/链接/运行时）
答：
  • [ ] 为什么只看"输入 abc 输出 def"发现不了它？如果重新给你一次机会，你会多测哪几个输入？
