一、任务 2 的 4 个实验

实验 A：忘了结构声明后面那个分号

参考答案

新建文件，故意写成：

struct Point
{
    int x;
    int y;
}                       // ← 故意不加分号

int main() { return 0; }

编译（g++ -std=c++17 -Wall -Wextra 文件名.cpp -o 文件名），报错原文：

文件名.cpp:6:2: error: expected ';' after struct definition
 }                       // ← 故意不加分号
  ^
  ;

属于编译期错误。（编译器在把源码翻译成机器码的阶段就发现了语法问题， 根本还没到链接那一步，更没有运行。）

GCC 还做了什么来帮你？ 报错下面那个 ^ 指着出错的位置， 再下面单独印了一个 ;——它直接把"你该在这里加一个分号"画出来了。 照抄就行。

讲解：为什么分号不能少？

C++ 里，结构声明本身是一条完整的"语句"，而 C++ 规定语句要以分号结尾。 这个分号不是"结构的结束符号"，而是"这条声明语句到此结束"的意思。

💡 两个值得记住的点： 1. 这是一条很清晰的错误，不会级联。 你改完这一处，程序就通了， 不会因为它冒出十来个莫名其妙的错误。"错误能一眼看懂"的情况要珍惜。 2. 新手对这个分号的怨念主要来自函数和结构长得像： cpp void f() { } // 函数定义后面【不需要】分号 struct P { }; // 结构声明后面【必须】有分号 记法：函数是"动作"，结构是"给一种数据起名"，起名这件事得用分号结句。

实验 B：结构能整体赋值，数组不能

参考答案

报错原文：

文件名.cpp:9:9: error: invalid array assignment
     b = a;                   // 数组：会怎样？
         ^

一句话解释：为什么结构可以、数组不行？

数组名在多数场合会"退化成地址"，而地址不能当值赋给另一个数组； 结构是一个完整的值，所以能整体复制。

把 b = a; 注释掉还能不能编译通过？

能。 把那一行注释掉以后，程序 0 错误 0 警告通过。 这说明：

  • b = a; 那一行确实是唯一的问题——编译器是精确地指着它报的错；
  • 而它上面那行 p2 = p1;（结构整体赋值）完全合法，编译器没意见。

讲解：为什么会有这个差别？

  • 数组：int a[3]; 里的 a，在大多数用到它的地方， 编译器会把它当成"第一个元素的地址"来用，而不是当成"装着 3 个整数的盒子"。 地址是一个位置编号，你没法把「一个位置」整个塞进「另一个位置」， 所以 b = a; 被直接拒绝。 （这也是为什么数组不能"整体赋值"、不能"整体当函数参数传进去"—— 传进去的其实是地址。）
  • 结构：Point p1; 里的 p1 不是地址，它是一个实实在在的盒子， 里面装着 x 和 y。盒子可以整个搬走，所以 p2 = p1; 合法， 编译器会逐个成员帮你复制过去。

而且这是复制，不是"两个名字指向同一份数据"：

p1 = (3, 4)
p2 = (3, 4)   <- 从 p1 复制来的

把 p2.x 改成 100 之后：
  p1.x = 3    <- 没变
  p2.x = 100

📌 地址这件事，是第 4 章 C「指针与自由存储空间」的核心内容。 现在记住结论就够了：数组名 ≈ 地址，结构名 = 一整个值。 如果这里只是死记硬背，到了指针那一课会很吃力—— 建议现在就把它当成一个"待解释的疑问"存着，那正是下一课要回答的问题。

实验 C：struct 和 union 的内存差别

参考答案

程序（成员完全相同，只换关键字）：

#include <iostream>

struct S { int i; double d; char c[16]; };
union  U { int i; double d; char c[16]; };

int main()
{
    std::cout << "sizeof(S) = " << sizeof(S) << "\n";
    std::cout << "sizeof(U) = " << sizeof(U) << "\n";
    return 0;
}

实测输出（GCC 8.1.0 / MinGW-w64）：

sizeof(S) = 32
sizeof(U) = 16

为什么不一样？分别算一遍：

计算 结果
各成员大小相加 4 + 8 + 16 28
最大成员大小 max(4, 8, 16) 16
struct S 实测 28 再对齐 → 32
union U 实测 = 最大成员 → 16

sizeof(S) 里"多出来的东西"是什么？

是内存对齐留下的空隙。 struct S 里三个成员要各自落在"整齐"的位置上：

struct S { int i; double d; char c[16]; }
大小 = 4 + 8 + 16 = 28，对齐后 = 32

  ┌──────────────┐ 偏移 0
  │  int  i      │  4 字节
  ├──────────────┤
  │  （填充 4）  │  ← 对齐用的空隙：让 double 从 8 的倍数处开始
  ├──────────────┤ 偏移 8
  │  double d    │  8 字节
  ├──────────────┤ 偏移 16
  │  char c[16]  │  16 字节
  └──────────────┘

int i 占 0–3。double d 要求从 8 的倍数开始，所以不能放在偏移 4， 于是偏移 4–7 这 4 个字节就空着了——这就是"多出来的 4 字节"。 （整体大小还要是最大对齐要求的整数倍，这里 28 → 32 正好也满足。）

用一句话说出 struct 和 union 的根本区别：

struct 的成员各占一块内存（大小 = 各成员之和 + 对齐空隙）； union 的成员共用一块内存（大小 = 最大成员）。

再补一个对比图：

union U { int i; double d; char c[16]; }
大小 = max(4, 8, 16) = 16

  ┌──────────────┐ 偏移 0
  │              │
  │  int i  ────┐│
  │  double d ──┤│ ← 三个成员的【起始地址相同】
  │  char c[16]─┘│
  │              │
  └──────────────┘

怎么在代码里亲眼看到"起始地址相同"？

取 &u.i、&u.d、&u.c[0] 打印出来，三个地址是完全一样的 （示例代码/04_结构共用体枚举/05_union.cpp 里打印了 &v.i 和 &v.d， 实测都是 0x61fe48）。

⚠️ 提醒：sizeof(struct S) 里的那个 32 是本机、本编译器的实测值。 换个编译器或平台可能不同（对齐规则不完全是语言规定的）。 所以不要拿结构大小去写死数字。

实验 D：枚举的取值范围怎么影响它的大小

参考答案

实测输出（GCC 8.1.0 / MinGW-w64）：

sizeof(E1) = 4
sizeof(E2) = 4
sizeof(E3) = 8

这说明了什么？

它正好对应教材 4.6.2（p113–114）那条取值范围规则，逐条对：

枚举 最大枚举量 按规则算出的取值范围 需要多大空间 实测
E1 { a1, a2 } 1 上限 = 2¹−1 = 1，下限 0 → 0..1 1 个比特就够 4 字节
E2 { b1, b2 = 1000 } 1000 上限 = 2¹⁰−1 = 1023 → 0..1023 2 字节够 4 字节
E3 { c1, c2 = 5000000000LL } 5000000000 上限 = 2³³−1 → 需要 64 位 8 字节 8 字节

结论：枚举的大小由"装得下它的取值范围"决定， 而取值范围由"最大（和最小）枚举量"按那条规则推出来。

  • E3 里的 5000000000 已经超出了 32 位 int 能表示的范围 （int 最大约 21 亿），所以编译器必须给它一个 64 位的底层类型 → sizeof 变 8。 这就是题目特意让你写 LL 后缀的原因。
  • E1 / E2 都只需要 32 位以内，所以都是 4 字节。

追问：既然 E1 里的最大值只有 1，为什么它没有变成 1 字节？

因为"能装下"只是必要条件，编译器还有选择余地。 C++ 只要求"底层类型必须能表示所有枚举量的值"，没有要求"必须选最小的那个"。 GCC 在这里统一选了 unsigned int（4 字节）。

📌 所以：不要用 sizeof(枚举) 做任何假设。 如果你确实需要一个 1 字节的枚举（比如要往文件里写固定格式的数据）， C++11 允许你显式指定底层类型： cpp enum class Priority : unsigned char { low, mid, high }; // 明确要求 1 字节 （示例代码/04_结构共用体枚举/06_enum.cpp 里也打印了 sizeof(Color) 和 sizeof(Week)， 实测都是 4。）

二、任务 3：复习题（教材 p123）

第 8 题：设计一个描述鱼的结构声明

题目：设计一个描述鱼的结构声明。结构中应当包括品种、重量（整数，单位为盎司）和长度（英寸，包括小数）。

参考答案

struct fish
{
    char variety[20];   // 品种：用 char 数组存一串文字
    int  weight;        // 重量：整数，单位是盎司
    double length;      // 长度：英寸，包括小数
};

或者用 std::string 来存品种：

#include <string>

struct fish
{
    std::string variety;   // 品种（C++ 风格的写法）
    int         weight;    // 盎司
    double      length;    // 英寸
};

讲解：两种写法各有取舍

写法 好处 代价
char variety[20]; 不依赖任何库；内存占用固定（20 字节）；可以直接写进二进制文件 长度写死了，超过 19 个字符（要留一个位置给结束符 '\0'）就存不下；赋值不能整体赋，要用 strcpy
std::string variety; 想多长就多长，会自己增长；复制 / 赋值直接 = 就行 需要 #include <string>；对象本身占的空间比 char[20] 大（本机实测 sizeof(std::string) = 32 字节）；不适合直接当二进制数据写文件

⚠️ char variety[20] 能存几个字符？ 最多 19 个。 因为 C 风格字符串要在最后留一个位置放结束符 （就是编号为 0 的那个字符，写作 '\0'），用来标记"字符串到这里为止"。 所以声明成 20，实际能装 19 个字符——这是很常见的差一错误。

而且因为数组不能整体赋值（实验 B 刚验证过）， 你没法写 myFish.variety = "carp";，得用 strcpy(myFish.variety, "carp"); 或者 cin.getline(myFish.variety, 20);。这也是 std::string 更省心的原因。

结构里的"顺序"很重要：大括号初始化时，值是按成员出现的先后顺序对上去的。 本答案的顺序是 variety → weight → length，第 9 题的初始化就必须照这个顺序写。

📌 这一题本身只要求"结构声明"，也就是那张"模板"。 注意：写到这里为止，一个字节的内存都还没分配—— 声明一个结构不占内存，要到第 9 题 fish myFish; 才真的分配。

第 9 题：声明该结构的变量并初始化

题目：声明一个问题 8 中定义的结构的变量，并对它进行初始化。

参考答案

fish myFish = {"carp", 5, 12.5};

讲解

  • fish 是第 8 题声明的类型名；myFish 是变量名（自己起，合法即可）。
  • 这一行才真正分配内存——这也正是本课最重要的那个区分： 「结构声明」画模板不占内存，「结构变量」才占内存。
  • 三个值按 variety → weight → length 的声明顺序对上去：
  • "carp" → 品种（鲤鱼）
  • 5 → 5 盎司
  • 12.5 → 12.5 英寸
  • 这一行同时完成了定义（把变量造出来）和初始化（造出来的同时就把值写上）。 两种概念的区别见讲义 1.3。

几种合法的等价写法

// ① C++98 老写法（带等号）
fish myFish = {"carp", 5, 12.5};

// ② C++11 新写法（省略等号，和数组一样）
fish myFish{"carp", 5, 12.5};

// ③ 先定义、再逐个赋值 —— 这也合法，但这是【赋值】不是【初始化】
fish myFish;
myFish.weight = 5;
myFish.length = 12.5;
// 用 char 数组时品种得用 strcpy；用 std::string 时可以直接写：
// myFish.variety = "carp";

⚠️ 一个容易踩的坑：顺序写反。 cpp fish myFish = {5, 12.5, "carp"}; // ❌ 值对错了格子 这一行会直接编译报错（实测）：因为 "carp" 塞不进 int， 12.5 也塞不进 int，还会触发 -Wnarrowing。 类型不一样的时候，编译器会替你挡住——这是好事。

⚠️ 但别因此就觉得"顺序无所谓"。真正危险的是成员类型完全相同的情况： cpp struct Point3 { int x; int y; int z; }; Point3 p = {100, 3, 4}; // 本意是 (3, 4, 100)，手滑写反了 这一行实测 0 错误 0 警告，p 就变成了 x=100, y=3, z=4—— 数据悄悄错了，程序照常跑，等到结果不对时已经很难查了。 记住：大括号里的值，是照结构里"从上往下"的顺序发的号码牌。

💡 只初始化一部分时，编译器会提醒你： Student s4 = {"Only Name"}; 用 -Wall -Wextra 编译会给出 warning: missing initializer for member 'Student::age' [-Wmissing-field-initializers]。 这就是为什么编译时一定要带 -Wall -Wextra。

⚠️ 另一个细节：5 到底该理解为 5 盎司还是 5 英寸？ 光看 {5, 12.5} 是看不出来的，必须回到结构声明去对。 这也说明了结构成员命名的重要性——如果嫌 weight / length 不够清楚， 可以起更明确的名字（比如 weight_oz、length_in），让单位写在名字里。

第 10 题：用 enum 定义一个名为 Response 的类型

题目：用 enum 定义一个名为 Response 的类型，它包含 Yes、No 和 Maybe 等枚举量，其中 Yes 的值为 1，No 为 0，Maybe 为 2。

参考答案

enum Response { No = 0, Yes = 1, Maybe = 2 };

⚠️⚠️ 这一题的关键：必须显式赋值，不能靠默认递增

题目的列举顺序是 Yes, No, Maybe，要求的却是 1, 0, 2：

枚举量 题目要求的值 如果按列举顺序默认递增会得到
Yes 1 0 ❌
No 0 1 ❌
Maybe 2 2 ✅（碰巧对了）

枚举量的默认规则是"第一个从 0 开始，后面依次 +1"， 所以如果只写 enum Response { Yes, No, Maybe };，得到的是 Yes=0, No=1, Maybe=2 ——Yes 和 No 全反了。

所以这一题必须一个一个把值写出来。

那为什么参考答案里把顺序换成了 No, Yes, Maybe？

因为这样就刚好可以用默认递增（0, 1, 2），一行更短：

enum Response { No, Yes, Maybe };        // No=0, Yes=1, Maybe=2 —— 值完全正确

两种写法值完全等价，选哪个都行：

enum Response { No = 0, Yes = 1, Maybe = 2 };   // 显式写值，意图最清楚
enum Response { No, Yes, Maybe };               // 靠默认递增，但【顺序必须改】

📌 该选哪个？推荐显式写值的那种。 理由：

  1. 意图清楚：读代码的人不用去数"这是第几个"。
  2. 顺序可以自由：显式赋值以后，枚举量的书写顺序和数值顺序解耦了。 题目给的是"先 Yes 后 No"，那就照着题目的顺序写，值单独标出来—— 这样和题目一一对应，改起来也不会牵一发动全身。
  3. 不容易被后来的人改坏：如果哪天有人在 No 前面插了一个新枚举量， 靠默认递增的那份代码所有值都会往后挪一位，而显式赋值的那份纹丝不动。

⚠️ 一个特别容易混的点：题目里 Yes 在 No 前面，值却是 1 比 0 大。 这说明 "书写顺序"和"数值大小"是两件独立的事—— 只有在你不写值的时候，编译器才会硬把"书写顺序"翻译成"递增的数值"。 一旦你显式写了值，两者就没关系了。

顺便：这个 Response 用起来是什么样

Response answer = Yes;

if (answer == Yes)
    std::cout << "回答是肯定的\n";

std::cout << answer << "\n";              // 打印出来是 1（数字，不是 "Yes"）
std::cout << Maybe - No << "\n";          // 2 - 0 = 2（参与运算时退化成 int）

⚠️ 注意：打印 answer 出来的是 1，不是 Yes。 因为枚举量在编译之后只剩数字了，名字只存在于源码里。 想打印出 "Yes" 这样的文字，得自己写 switch 或查表来转换。

这里也顺便解释一下「枚举量」和「变量」的区别

  • Yes、No、Maybe 是枚举量（enumerator），它们不是变量， 不能给它们赋值（Yes = 5; 是错的）。 它们更像"给常量起的名字"。
  • Response answer; 里的 answer 才是变量，可以赋值、可以比较、可以改。

再提醒一个以后的坑：名字作用域

enum Response { No, Yes, Maybe };
enum Answer   { No, Yes };      // ❌ 报错！

普通 enum 的成员名会跑到外层作用域里，所以上面这样写会报 error: 'red' conflicts with a previous declaration 那一类错误 （本机实测同名成员就是这个报错）。 解决办法是 C++11 的 enum class：

enum class Response { No, Yes, Maybe };
enum class Answer   { No, Yes };

Response r = Response::Yes;              // 必须带前缀 Response::
Response a = Response::Yes;              // 不冲突了
std::cout << static_cast<int>(r);        // 想打印数字必须显式转换

代价是不能直接打印、也不能直接和 int 比，必须 static_cast<int>。 两个好处（名字不冲突、不会隐式转 int）对一份要认真维护的代码通常更值。

💡 为什么枚举量的名字会"跑出去"？ 回到讲义 1.4 节的"作用域"： 普通 enum 的成员名是"跑到大街上喊的名字"， 所以别的地方再喊一声同样的名字就撞车了。 enum class 的名字老老实实待在自己里面，要访问就得报门牌号（Response::）。

三、附：本课的三句核心

  1. 「结构声明」不分配内存，「结构变量」才分配内存。 struct Student { ... }; 只是画了一张表格模板； Student s1; 才是照着模板印出一张真表格。 这一条就是以后「类 vs 对象」的地基。

  2. 数组不能整体赋值，结构可以。 int b[3]; b = a; → error: invalid array assignment； Point p2; p2 = p1; → 完全合法，而且是复制不是共享。 原因：数组名在多数场合会退化成地址，结构是一整个值。 （地址到底是什么，第 4 章 C 会讲透。）

  3. struct 各占一块，union 共用一块。 同一批成员 int i; double d; char c[16];： struct 是 32 字节（28 + 4 对齐空隙），union 是 16 字节（最大成员）。 而 union 读"不是最后写入的那个成员"不会报错，只会给垃圾值。
