一、任务 2 的 5 个实验

实验 A：亲手制造一次"越界"

参考答案

把 01_array_basics.cpp 里那个遍历循环从 i < 5 改成 i <= 5 之后：

  • 编译没有任何报错，也没有警告（-std=c++17 -Wall -Wextra 实测）。
  • 运行输出会在原有的 5 个成绩后面多出一个值，也就是第 6 个输出：

5 个成绩：90 85 78 92 88 0

这个 0 不是"数组的第 6 个元素"——scores 只有 5 个元素， 它根本不存在第 6 个。它是越界读到的那块内存里碰巧躺着的东西。 - 为什么编译器不管？ 因为 scores[i] 在编译期被翻译成"起点地址 + i 格"的算术， 编译器不看 i 的值（而且 i 的值要到运行时才知道）。这不是编译器"偷懒"， 而是 C++ 刻意的设计选择：为了速度，不做检查（教材 p122 讲了这一点）。 它属于运行时的行为，标准把它归为未定义行为： 可能拿到垃圾值、可能算错、可能崩溃。

📌 一个必须记住的细节：这次读出来的是 0，看起来"多一个 0 好像也没事"。 千万别把"这次没事"当成"这样写没事"——那块内存里是什么，每次运行都可能不同。

原始作答记录

  • 编译有报错或警告吗：没有报错或者警告
  • 运行输出：90 85 78 92 88 0，多出来第六个元素，值为 0
  • 为什么编译器不管：因为这是运行时错误，cpp编译器不管越界

核对结果

  • 编译无报错无警告 ✅ 正确（实测确认）。
  • 输出数据 ✅ 正确。
  • 原因 ⚠️ 方向对、说法要改（见订正说明）。

订正说明：原答案说「这是运行时错误」，这个说法不准确。 越界访问在 C++ 里不是"运行时错误（runtime error）"—— 运行时错误指的是"程序跑起来才发现的错误，而且一定能被发现（比如除以 0、数组越界在 Java 里会抛异常）"。 越界访问在这里根本不会被发现，所以它属于未定义行为（undefined behavior）： 标准没规定结果，编译器也不插检查，可能什么都没发生。 准确表述应为：「这是未定义行为，编译器不做检查—— 因为 scores[i] 只是地址算术，编译器在翻译时不知道 i 会是多少； C++ 为了速度刻意不做边界检查」。区别在于：未定义行为不一定报错，这才是它危险的地方。

实验 B：sizeof vs strlen

参考答案

8 7
20 7
  • s1 是用双引号初始化的数组，编译器按内容的长度自动决定大小： "bubbles" 是 7 个字母 + 1 个 '\0' = 8 字节，所以 sizeof(s1) = 8。
  • s2 是你自己写死了 20 的数组，sizeof 量的是"这排柜子总共多大"， 所以是 20，和里面装了几个字无关。
  • strlen 数的是"到 '\0' 之前有几个字符"，两个数组装的内容一样，所以都是 7。

一句话：sizeof 量柜子有多大（和装了什么无关），strlen 数装了几个字。

原始作答记录

8 7 20 7 因为 s1 是编译器自动规划的数组大小，自动为字符数 +1； 而 s2 为手动定义了 20 个大小的数组，所以占用的内存大小不一样

核对结果

  • 数据 ✅ 完全正确。
  • 原因 ✅ 正确，保留。

订正说明：这一条原答案是对的。只补两点更准确的说法： ① sizeof 是运算符、在编译期就把结果算好了；strlen 是函数（<cstring> 里）， 要运行时一个字符一个字符地数——两者"什么时候算"不一样； ② 对字符串来说两者永远差 1（sizeof 含结尾的 '\0'，strlen 不含）。 这个"差 1"并不普遍成立：对 int a[10] 用 strlen 是无意义的（它不是字符串）。

实验 C：数组能不能整体赋值

参考答案

报错原文（g++ 8.1.0 / MinGW-w64 实测，-std=c++17 -Wall -Wextra）：

error: invalid array assignment
     b = a;
         ^

属于编译期错误。

为什么？ 因为 C++ 里数组不是一个"值"。a 这个名字在参与表达式时， 会退化成"第一个元素的地址"（一个门牌号），而"给一排柜子赋值"在语法上没有意义， 所以编译器在编译阶段就直接拒绝（不是链接期，也不是运行期）。

想复制内容，只能逐个元素复制：

for (int i = 0; i < 3; ++i) b[i] = a[i];

（或者用 <cstring> 里的 memcpy；再或者干脆用 std::string / std::vector， 它们是可以整体赋值的。）

原始作答记录

  • 报错原文：error: invalid array assignment（含文件路径与行号）
  • 属于哪类错误：编译期

核对结果

  • 报错原文 ✅ 正确（关键那一行 error: invalid array assignment 抄对了）。
  • 分类 ✅ 完全正确，保留。

订正说明：这一条原答案是对的。只补一句"为什么"： 报错发生在编译期而不是运行期，是因为编译器在语法层面就知道这件事不合法 （数组名会退化成地址，而地址不能被赋给一串变量）， 它根本不需要等到程序跑起来。编译器能帮你拦住的错误都是好错误。

实验 D：混合输入的陷阱

参考答案

跑 06_mixed_input_trap.cpp 的"错误示范"部分：

Enter the year: Enter the address:   year    = 2026
  address = ""   <- 空的！
  • address 读到的是一个空字符串（长度为 0）。
  • 原因：cin >> year 读到数字 2026 后，在遇到换行符时停下，但没有把换行符取走—— 那个 '\n' 还留在输入缓冲区里。紧接着 cin.getline(address, 80) 去读， 看到的第一个字符就是换行符，于是它判定"这一行是空的"，读了个空串就返回了。
  • 用解法 2 复现，关键那一行就是：

cpp (cin >> year).get();

它的意思是"先读年份，然后在同一个 cin 对象上再调用 get() 把换行符取走"。 （cin >> year 的返回值就是 cin 本身，所以可以接着写 .get()。）

原始作答记录

读到了 \0，因为用 cin 时候按下的回车不会被 cin 读取走， 而停留在了输入队列中，导致 getline 读取到了换行，而直接结束了

关键那一行：(cin >> year).get();

核对结果

  • 现象 ✅ 正确（address 确实读成了空的）。
  • 原因 ✅ 正确，而且抓住了要点：「回车留在输入队列里，getline 读到换行就直接结束」。
  • 修法 ✅ 解法 2 抄对了。

订正说明：这一条原答案是对的，只改一处措辞： 原答案说"读到了 \0"——严格说 getline 读到的不是 '\0' 这个字符， 而是一个空字符串（字符串长度为 0）。'\0' 是结果： getline 发现第一个字符是换行、判定这是空行， 于是它按规矩给数组的第 0 格写上 '\0'（保证结果是个合法字符串），然后就返回了。 所以"读到空串"和"数组第 0 格是 '\0'"两件事都对，但因果顺序是 先遇到换行 → 才写入 '\0'。

补充一个第四种组合（原答案没提到）： 如果下一个操作是 cin >>，就完全不会出问题， 因为 cin >> 会自动跳过开头的空白符，把残留的换行当分隔符跳过去。 "只读整行的操作（getline / get）才会被咬"——这正是本课最该记住的一句话。

实验 E：C 风格字符串的 ==

参考答案

0
1

（std::cout << (a == b) 输出 0 表示 false；(strcmp(a, b) == 0) 输出 1 表示 true。）

  • 第一个 a == b 比的是两个数组的地址，不是它们装的内容。 a 和 b 是两块不同的内存，门牌号不一样，所以比较结果是"不相等"。 （这就是"数组名参与表达式时会退化成地址"的直接后果。）
  • 第二个 strcmp(a, b) == 0 才是比较内容：strcmp 会一个字符一个字符地比， 内容相同就返回 0。

注意这个约定的别扭之处：strcmp 用 0 表示"相等"，而 0 在 if 里是"假"。 所以 if (strcmp(a, b))（没写 == 0）的意思正好相反—— 一定要把 == 0 写上。

原始作答记录

0 1 因为第一个是直接比较内存地址，地址肯定不一样，所以为 0

核对结果

  • 两个输出 ✅ 正确。
  • 原因 ✅ 完全正确，保留。

订正说明：这一条原答案是对的。只补两句： ① 既然 a == b 比的是地址，那它永远不可能用来判断内容是否相同， 这不是"碰巧错"，而是语法层面就错了； ② 与之对照，std::string 的 == 是被专门定义过的（重载）， 所以 std::string a, b; 时 a == b 比的才是内容—— 这也是 std::string 存在的理由之一。

第 1 题：如何声明下述数据？

参考答案

小题 要求 答案
a actor 是由 30 个 char 组成的数组 char actor[30];
b betsie 是由 100 个 short 组成的数组 short betsie[100];
c chuck 是由 13 个 float 组成的数组 float chuck[13];

语法模板：类型 名字[元素个数]; 方括号里写的是元素个数（不是"最后一个下标"），所以要 30 个就写 [30]。

原始作答记录

a. char actor[30]; b. short betsie[100]; c. float chuck[13]; d. long double dipsea[64];

核对结果

  • 四小题 ✅ 全部正确，保留。

第 3 题：声明一个包含 5 个元素的 int 数组，并将它初始化为前 5 个正奇数

参考答案

int x[5] = {1, 3, 5, 7, 9};

前 5 个正奇数是 1、3、5、7、9。 用花括号列出来，编译器会按顺序填进去；写了 5 个值、数组也是 5 格，正好装满。

原始作答记录

int x[5] = {1, 3, 5, 7, 9};

核对结果

  • ✅ 完全正确，保留。

订正说明：这一条原答案完全正确。 顺便记两个容易混的变体： ① 如果只写 int x[5] = {1, 3};，后面三格会自动补 0（不是垃圾值）； ② 如果写 int x[] = {1,3,5,7,9};（不写大小），编译器会自己数出 5。 本题写死 [5] 最清楚，也最贴合题意。

第 4 题：把数组第一个元素和最后一个元素的和赋给 even

参考答案

int even = x[0] + x[4];

推导：第 3 题的数组是 int x[5] = {1, 3, 5, 7, 9};

  • 第一个元素 → 下标 0 → x[0]（值 1）
  • 最后一个元素（一共 5 个）→ 下标 5 − 1 = 4 → x[4]（值 9）
  • 所以 x[0] + x[4] = 1 + 9 = 10

原始作答记录

最初写的是 int even = x[1] + x[-1]; 后来改成了 int even = x[0] + x[4];

核对结果

  • 最终答案 ✅ 正确。
  • 但最初那一版两个下标都错了，而且错得很有代表性，见下面的专项说明。

⚠️ 订正说明（本课最重要的一条）

原答案最初写的是 int even = x[1] + x[-1];，这里同时犯了三类错误：

  1. "差一"错误：第一个元素的下标是 0，不是 1。 （"第 1 个"和"下标 1"是两件事——下标是偏移量，第 1 个的偏移量是 0。）
  2. "差一"错误：最后一个元素的下标是 4，不是 −1。 （len − 1 = 5 − 1 = 4。−1 是别的语言里"从末尾数"的写法，C++ 的数组下标不支持负数。）
  3. 越界：x[-1] 不只是"取错了元素"，它是访问数组前面那块不属于它的内存， 属于未定义行为——可能读到垃圾值，也可能直接让程序崩溃。 ⚠️ 而且 x[-1] 通常连编译错误都不会有，编译器不会拦你， 这才是它比"差一"更危险的地方。

正确的推理链只有一句话： 第 n 个元素的下标 = n − 1；最后一个元素的下标 = 长度 − 1。

⭐ 专项：「下标差一」这个错误，一张表讲透

数组下标就是偏移量（"离起点走了几格"），所以"第几个"和"下标几"永远差 1：

你想要的东西 偏移 / 下标 一个 5 元素数组 int x[5] 里的实际写法
第 1 个元素 偏移 0 x[0]
第 2 个元素 偏移 1 x[1]
第 3 个元素 偏移 2 x[2]
第 n 个元素 偏移 n − 1 x[n-1]
最后一个元素（长度 len） 偏移 len − 1 x[len-1]（本题 x[4]）
❌ 长度为 len 时写 x[len] 超出范围 x[5] ✗ 越界
❌ 写 x[-1] 想"从末尾数" 负偏移 x[-1] ✗ 越界

三条能防住这类错误的习惯：

  1. 问自己"我要的是第几个"，然后减 1 得到下标；
  2. 循环遍历数组永远写 i < len，别写 i <= len；
  3. 别写负数下标——C++ 数组不支持"从末尾数"（Python 那种 x[-1] 在 C++ 里是越界）。

📌 复习题第 5 题考的是同一件事（"第 2 个元素"→ 下标 1）。 这两题一起看，就能把"差一"这个错误彻底钉住。

第 5 题：显示 float 数组 ideas 中第 2 个元素的值

参考答案

cout << ideas[1];

推导：题目要的是第 2 个元素，而下标是偏移量，所以要 2 − 1 = 1。 即 ideas[1]（不是 ideas[2]）。

原始作答记录

最初写的是 ideas[2]，后来改成了 cout << ideas[1];

核对结果

  • 最终答案 ✅ 正确。
  • 最初那一版 ❌ 差一错误（见订正说明）。

订正说明：原答案最初写的是 ideas[2]，正确应为 ideas[1]， 因为题目问的是「第 2 个元素」，而下标是偏移量： 第 1 个的偏移是 0、第 2 个的偏移是 1、第 n 个的偏移是 n − 1。

⚠️ 和上一题不同的是：ideas[2] 不越界（如果数组至少有 3 个元素）， 所以它不会报错、不会崩溃，只会安静地打印第 3 个元素—— 这种"结果合法但答非所问"的错误，比越界更难发现。 做题时把"第几个"和"下标几"分开想，是唯一的防法（对照上一题那张表）。

另外两个细节：教材附录 J 的官方答案就是 cout << ideas[1] << endl;； 如果要按题目原样比较，加不加 << endl 都不影响正确性。

第 6 题：声明一个 char 数组，并初始化为字符串 "cheeseburger"

参考答案

char s[] = "cheeseburger";

要点：用双引号初始化时，编译器会自动在末尾补一个 '\0'， 并且不写方括号里的数字时，它会按 字符数 + 1 自动算好大小 （这里是 12 个字母 + 1 = 13 字节）。

如果非要写死大小，最小合法值是 13：

char s[13] = "cheeseburger";     // ✅ 12 个字母 + '\0'
char s[12] = "cheeseburger";     // ❌ 装不下 '\0'，编译器报错

原始作答记录

char s[] = "cheeseburger";

核对结果

  • ✅ 完全正确，保留。

订正说明：这一条原答案完全正确，且用了最省心的写法（[] 让编译器自己数）。 补充一句常见错法的报错原文，便于以后认出来： char s[12] = "cheeseburger"; 会得到 error: initializer-string for array of chars is too long—— 因为字符串字面量自带一个 '\0'，所以数组大小必须是"字符数 + 1"。

第 7 题：声明一个 string 对象，并初始化为 "WaldorfSalad"

参考答案

std::string s = "WaldorfSalad";

（如果文件上方已经有 using namespace std;，也可以直接写 string s = "WaldorfSalad";。）

要点：

  • std::string 是 C++ 标准库提供的字符串类型，要用它必须 #include <string>。
  • 它不用写大小（自己管内存），所以写法比 char 数组更简单。
  • 注意大小写：题目给的字符串是 "WaldorfSalad"（W 和 S 都是大写，中间没有空格）， 不是 "Waldorf Salad"。

原始作答记录

string s = "WaldorfSalad";

核对结果

  • ✅ 正确，保留。

第 16 题：把 cin.getline(address, 80); 换成 cin >> address; 会有什么影响？

参考答案

把读整行的 cin.getline(address, 80); 换成按单词读的 cin >> address;， 会带来两个影响：

  1. 读不到空格，也读不到整行。 cin >> 在遇到第一个空白符（空格 / Tab / 换行）时就停， 所以像 "123 Main Street" 这样的地址只会读到 "123"，后面全丢了。 （getline 不会这样，它会把整行连同空格一起读进来。）
  2. 换行符会留在输入队列里。 cin >> 只取走它需要的字符，不取走后面那个换行符； 于是这个 '\n' 残留在缓冲区中，影响下一次读取—— 如果下一个操作是 cin.getline(...) 或 cin.get(...)， 它会读到"空行"（看上去就像程序跳过了一次输入）。

📌 一句话总结：cin >> address 能读，但只读一个词，而且还留下一颗地雷 （残留的换行符）给后面的读整行操作。

原始作答记录

  1. 不能读取到空格，不能读取到整行，换行符会留在输入队列中

核对结果

  • ✅ 完全正确，保留。 三个要点（读不到空格、读不到整行、换行符残留）全说到了。

订正说明：这一条原答案是对的。只把第 3 点的因果说完整一点： "换行符留在输入队列里"这件事本身不是问题，问题是"谁会去读它"。 如果下一个操作是 cin >>，它会自动跳过空白，你看不出任何异常； 只有当下一个操作是 getline / get（要读整行）时， 它才会读到空行、让你以为"程序吞了一次输入"。 也就是说：同一段代码，换个读法就从"没事"变成"出事"—— 这一点在第 4 章 A 的讲义第 5.4 节有一张四种组合的对照表。

附：本章要记住的四句

  1. 下标是偏移量，从 0 开始：第 1 个 → [0]，第 n 个 → [n-1]，最后一个 → [len-1]。 "差一"和"负数下标"是最高频的两个错误，而负数下标还是越界。
  2. C 风格字符串 = 以 '\0' 结尾的 char 数组。 '\0' 是"句号"；sizeof 含它、strlen 不含它，所以对字符串永远差 1。
  3. 换行符是上一个 cin >> 留下的：只要下一个操作是 getline / get， 就会读到空行。修法：cin >> x; 之后补 cin.get();。 下一个操作若是 cin >>，则看不出问题（它自己跳空白）。
  4. C++ 不做数组边界检查：越界读拿到的是垃圾值， 越界写会破坏别的变量，而且两种都可能不报错、不崩溃——这属于未定义行为， 不是"运行时错误"。
