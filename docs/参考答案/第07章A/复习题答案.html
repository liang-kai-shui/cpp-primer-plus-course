第 7 章 A 参考答案：函数基础与数组参数

配合 练习 使用。这里解释本课整理的问题，不替代自备教材中的完整复习题与编程题。 先做自己的版本，再比较“接口、处理顺序、边界”，不要求变量名和参考程序相同。

1. 口头题

Q1 原型、调用、定义

第一行是原型，告诉编译器函数名字、返回类型与参数类型；第二行含调用，传入 3.5，将返回值保存到 result；第三行是定义，提供函数体。

原型是一条声明，用分号结束；普通函数定义由函数体结束，不需要在结束花括号后添加这个声明分号。 调用之前若已有完整定义，该定义也完成了声明作用，不必重复写独立原型。

本课统一使用“文件前部原型、main、后部定义”，是为了容易读，不是说原型只能写在那里。块内函数声明可以合法，普通函数定义则不能嵌套在 main 内。

Q2 返回值与写回是两种操作

输出仍是 8。next 得到 number 的值，在自己的 value 上计算 9，再把 9 交回；调用者没有使用结果。

number = next(number);

这次是 main 的赋值把返回结果写进 number。不能只靠“函数运行过了”判断调用者变量是否改变。

Q3 地址值复制，目标对象可以相同

++data 改的是形参指针自己的地址值，不改变调用者保存起点的指针变量。 data[0]=99 沿形参指针找到元素并写入；地址有效、目标可写时，会改到原数组。

所以“形参按值传递”并不等于“函数无法改变任何外部数据”。看它是否沿地址写目标。

Q4 count 才是已输入项数

show、mean 使用 3。容量 10 表示最多可写多少，不表示已经有多少有效成绩。 零初始化是让剩余位置有确定的初值；它没有制造七份用户输入。

数组形参的 [10] 不保证容量，形参仍调整为指针。调用者和被调用函数必须遵守长度约定。

Q5 范围与字符串

  • [values,values+4) 有 4 项，end 是末尾后一个位置，不允许读取 *end。
  • 起点等于终点是空范围，循环零次。
  • const int* 不允许通过 p 写元素，可以改变 p 指向的位置，例如 ++p。
  • 空字符串是有效的字符序列，第一个字符就为零；nullptr 没有指向可读取的字符序列。
  • n 个可见字符加一个终止零字符，需要 n+1 项。若约定函数返回由 new[] 创建的字符数组，调用者使用结束后 delete[]。

返回借用的原数组地址则不能因此 delete[]，必须区分来源与约定。

2. 手走题与找错

T1 参数按位置对应

subtract(9,2) 是 7；subtract(2,9) 是 -7。 第一个实参给 first，第二个给 second。参数名只在函数内部起作用，不会自动在 main 中搜索同名变量。

T2 整数运算已先发生

(3+4)/2 使用整数操作数，先得到整数 3，再转换为 double 的 3.0。 可写 (first+second)/2.0，这个小例子得到 3.5。关键是让除法发生时已有浮点操作数，不是只改返回类型。

T3 第三次访问已经越界

起点是 values+2，访问的原数组下标依次是 2、3、4。数组有效下标只有 0–3，下标 4 越界。 合法调用是起点 values+2、长度 2。不要把原数组总容量 4 当作任何子范围都能使用的长度。

T4 局部数组不会因返回地址而延寿

text 在函数结束后不再存活，返回它的地址是悬空地址。 本章方案之一是 new char[...] 创建结果并补零，返回后由调用者 delete[]；另一种在 第 7 章 B 学到的方案是返回 string 值，由对象管理字符存储。

不能以“这次恰好显示 hello”证明错误版本安全。

3. A：调和平均数

完整程序：代码/ex1.cpp。

计算为什么单独做？

harmonic_mean 只负责公式：

return 2.0 * first * second / (first + second);

main 负责接题、结束、报错和显示。以后换成文件输入时，公式函数不需要跟着改。

一轮执行过程

步骤 输入 2、6 时
读 first 2，成功
读 second 6，成功
检查结束 两者都不是 0
检查范围 正数、有限、不超上限
调函数 24/8=3
输出 mean=3

这一轮结束后，程序回到下一次读取。首项非数字是结束协议；第二项缺失是半对输入，程序明确报错。

范围限制使演示公式不必处理任意巨大值。零标记在有效范围检查前处理，所以 0 8 结束，不误报“正数范围错误”。

常见错误：写整数参数导致精度损失；不检查 second 是否读成功；调用后没使用返回值；在退出条件前先除法。

4. B：成绩数组

完整程序：代码/ex2.cpp。

fill 为什么返回 count？

main 只知道数组容量 10，不知道输入成功多少项。fill 在每次合法存入后增加 count，再把 count 返回。 main 保存这个结果，后面两个函数才能只处理有效数据。

容量10，输入10 20 30 x
写入下标0、1、2
遇到x停止 → 返回3
show处理3项 → mean累加60，除以3 → 20

数组以地址交给 fill，因此写入可以留在 main 的数组中。count 自身是局部整数，需要返回交给调用者，不能假设 main 自动得到它。

空输入怎么处理？

count=0 时仍可调用 show，它的循环不进入。但 mean 要求 count>0。 main 在调用 mean 前检查，输出 No scores，避免 0 作除数。 输入一个 0 时 count=1，平均值为 0，是一份有效成绩。

错误与正常停止

非数字或 EOF 是正常停止，返回当前 count；读到数字却超范围，返回 -1。 main 必须在把 count 传给成功流程之前识别 -1，不应对失败输入输出平均值。

常见错误：遍历 capacity 导致初始零参加平均；mean 用 int 累加小数；把 0 当成结束标记；写完第 11 项才检查容量。

5. C：两次反转

完整程序：代码/ex3.cpp。

一次反转只交换一半的位置

left 从 0 到 count/2 之前，right=count-1-left。 count=5 时交换 (0,4)、(1,3)，下标 2 不变。

temporary 保存左边旧值，否则先把右值写到左边后，就会丢掉需要放到右边的旧左值。

中间部分仍然用同一个函数

第一次是 reverse_values(values,count)。 第二次在 count>2 时调用 reverse_values(values+1,count-2)。

1 2 3 4 5
5 4 3 2 1       全部反转
5 2 3 4 1       只反转中间三项

第二次传入的起点不同，所以函数内下标 0 对应原数组下标 1。 无需另写“反转中间”函数，接口的起点与长度已经描述了需要处理的子范围。

边界

count 为 0、1 时没有交换；为 2 时只反转全部，随后中间操作跳过。 先判断 count>2 再构造中间调用，避免为不存在的中间范围计算负长度。

常见错误：遍历所有 left，结果又反回来；right 写成 count-left；中间长度误用 count-1；尝试返回整个原生数组。

6. D：指针区间

完整程序：代码/ex4.cpp。

返回 current 的含义

每次写完 *current 就 ++current，所以三项存完时 current 指向下标 3。 这个位置是下一次可填的位置，也是已填半开范围的终点。

[begin,current) = 三项
current-begin = 3
最后一个已填元素 = current-1（仅在非空时才讨论）

返回 current-1 会让后面按半开范围遍历时遗漏最后一项，空输入时还会构造错误位置。

空范围与错误不同

没有数据时 current==begin，这是一个有效空范围；sum 初始为 0，循环零次，返回 0。 范围错误返回 nullptr。main 先判 nullptr，因此不对错误返回做指针减法或遍历。

指针差只适用于这里同一数组内的有效位置。这个函数也不分配空间，不需要 delete 返回值。

常见错误：show 使用 <=end，读到终点；把空范围当作失败；在检查 nullptr 前输出 used_end-begin；把返回指针理解成新的独立数组。

7. E：二维数组

完整程序：代码/ex5.cpp。

列数决定如何找下一行

const int values[][3] 调整为指向三项 int 数组的指针。 values[row][column] 先定位整行，再定位该行的一项。原生二维数组不是 int**。

sum_matrix 的两个循环覆盖每行每列；sum_column 只改变 row，column 固定。

1 2 3
4 5 6
总和：(1+2+3)+(4+5+6)=21
各列：5、7、9

输出使用 long long 累加。每项范围与固定六项也足以约束本题结果，不宣称支持无限大小矩阵。

const 可以使用

课程使用 C++17，const int[][3] 的只读接口经过编译验证。 教材相关说明沿用了“指针的指针”解释，容易使人误以为这里不能加 const；实际类型是指向固定宽度行数组的指针。

常见错误：省略需要的第二维；行列循环写反；列循环从 1 开始遗漏第 0 列；少读一项仍开始统计。

8. F：字符串替换

完整程序：代码/ex6.cpp。

先找到有效字符的结束位置

循环条件是 text[i]!='\0'。遇到结尾零字符就停止，不改它、不计数。 banana 的下标 1、3、5 都是 a，所以替换后为 bonono，返回 3。

调用者已握有 text 数组，函数沿地址写入即可；返回值用于提供额外的匹配数量。

为什么 a 换成 a 仍计 3？

题目约定统计匹配位置，不是统计最终发生变化的字节数量。每个匹配位置都执行指定替换，aaa 中有三个匹配。 只要约定一致，这种情况不会让函数的计数含义含糊。

输入容量

char[201] 可存最多 200 个文本字节以及结尾零字符。 cin.getline 的状态检查识别超长或读取失败；后面两个字符也必须读成功。 空行是成功读入的空字符串，与 EOF 前完全没有输入一行不同。

常见错误：用字符串字面量作为可写数组；用 capacity 遍历到尾部未使用位置；把终止零字符覆盖；忘记 count 返回值；把字节上限说成汉字数上限。

9. 如何判断自己的程序完成了？

不要求输出排版逐字一致，但结果、接口意图和停止策略要与练习约定相符。

检查正常值、空输入、容量上限、范围错误。特别确认：没有有效数据时不除以零；子数组调用没有把总容量当成剩余长度；返回地址的对象仍存活。

参考代码中的数值输入用格式化提取，不是严格的逐字校验器。按练习约定输入正常数字，学习重点是函数的数据流。
