0. 先把任务分开：传数据、重复调用、传算法

上一课，你已经把一个程序拆成了几件小事：读入、计算、显示。 这课继续问三个问题：

  1. 如果数据是一整条记录，函数该怎么接收？
  2. 如果一个大问题能缩成同一种小问题，函数能不能再调用自己？
  3. 如果计算步骤相同、计算规则不同，能不能把“规则”也交给函数？

对应的工具是结构参数、递归、函数指针。不要一次把三个工具全塞进同一题。

0.1 开始前要会的五件事

  • 看懂 double f(double x); 的返回类型、名字和参数。
  • 知道调用后要用变量或表达式接住返回值。
  • 知道普通按值形参是独立的值，指针形参也是地址值的副本。
  • 能区分 p、*p 和 &object。
  • 能解释数组参数为什么另外需要长度。

如果其中一项说不清，先回到 第 7 章 A 对应小节。函数指针并不要求你先背复杂声明。

0.2 本课术语，用一句话解释

名字 人话解释 想解决的问题
结构参数 把同一条记录的几个字段一起交给函数 避免名字、尺寸、体积各传各的
按值传递 函数得到一个独立的值 函数内部可以改副本
指向结构的指针 保存一条记录的地址 让函数找到并修改原记录
递归 一个函数在执行中再次调用自身 把任务缩成同一种更小的任务
基本情形 可以直接得出答案，不需要继续调用的情形 让递归停下来
函数指针 保存一个函数的地址的变量 运行时选择要调用的函数
回调 一个函数调用由调用者提供的另一个函数 把具体计算规则交给调用者决定
类型别名 给一个已有类型取一个简短名字 少写复杂声明，方便阅读

生活类比可以帮你入门：结构像一张完整登记表，递归像“先处理更小的一叠表格”，函数指针像记录某位办事人的联系方式。但最终要以实际代码的参数、调用和寿命为准。

0.3 建议分三轮学习

第一轮：数据。 阅读 1–5 节，运行示例 01–05，做练习 A、B、D、E。

第二轮：递归。 阅读 6–8 节，手写调用过程，再运行示例 06–08，做练习 C。

第三轮：选择算法。 阅读 9–11 节，运行示例 09–10，做练习 F。示例 11 是教材复杂声明的拆解，可留到第二遍。

每轮都先预测输出，再运行。预测错了，就在纸上找第一次与程序不同的那一步。

1. 结构可以作为一个完整的值交给函数

教材 7.6 先用时长说明结构参数。设一段视频长 1 小时 50 分，另一段长 2 小时 25 分。我们需要把两段时长相加。

如果用四个整数参数，很容易把顺序写错。把“小时、分钟”放进同一种结构，函数的意思更清楚。

1.1 先定义一种记录的格式

片段：

struct Duration {
    int hours;
    int minutes;
};

Duration 是类型名，表示这种记录的格式。first 才是一个具体对象：

Duration first{1, 50};

first.hours 是 1，first.minutes 是 50。点号表示“取这个对象里面的成员”。

1.2 把原型读成一句话

Duration add_duration(Duration first, Duration second);

从左到右读：add_duration 接收两个时长值，算好后返回一个时长值。

部分 意思
最左边 Duration 返回结果是一条时长记录
add_duration 函数名
Duration first 第一个按值形参
Duration second 第二个按值形参

结构类型要先声明，后面的函数原型才能使用这个名字。把 struct Duration 放在这些原型之前。

1.3 用纸算清楚进位

先加分钟：50 + 25 = 75。

75 分钟包含 1 个完整小时，还剩 15 分钟：

75 / 60 = 1       整数除法：完整的小时数
75 % 60 = 15      余数：不足一小时的分钟数
1 + 2 + 1 = 4    小时总数
结果：4 小时 15 分

示例 01 的定义把这个过程写出来：

Duration add_duration(Duration first, Duration second)
{
    int minutes = first.minutes + second.minutes;
    return {first.hours + second.hours + minutes / 60,
            minutes % 60};
}

return { ... }; 按返回类型创建结果记录。你也可以先声明 Duration result{...};，再 return result;，结果含义相同。

这里演示的是正常、非负的小数值时长，不把它当作可以接收任意整数的时间库。

1.4 调用时，哪一条记录归谁？

main 的 first：  {1,50} ──提供值──> add_duration 的 first
main 的 second： {2,25} ──提供值──> add_duration 的 second
                                      │
                                  算出 {4,15}
                                      │ 返回值
main 的 total：  {4,15} <───────────────┘

函数中的 first 和 main 中的 first 恰好同名，仍是不同作用域中的对象。 函数内部改副本，不会通过这个按值参数改动 main 的记录。

示例 01 输出：

4h 15m
1h 50m

第二行专门检查原记录。

动手改一处： 把函数里相加前的 first.hours 设为 0。预测总时长和第二行，再运行。总时长会改变，main 的 first 仍是 1 小时 50 分。

1.5 返回局部结构值为什么可以？

函数可以返回一条记录的值。结果对象的值交给调用者，不依赖已经结束的局部对象继续存活。

这和返回局部对象的地址不同：地址只告诉你“它原来在哪儿”，不会延长对象寿命。

编译器可能省去某些实际复制，直接构造返回结果。本课先掌握语义：返回值可作为独立结果使用；局部对象的地址不能当作长期有效的数据地址。

2. 想修改原结构，就把地址交给函数

假设一个箱子有长、宽、高，体积字段还没算。我们希望函数把算出的体积写回原箱子。

2.1 同一任务为什么有两种接口？

片段：

struct Box {
    double length;
    double width;
    double height;
    double volume;
};

void show_box(const Box* box);
bool set_volume(Box* box);

显示只需读取，使用 const Box*；计算后写回需要修改，使用 Box*。

bool 返回值表示操作是否成功。体积通过地址写回，因此返回值不必再装体积。

2.2 三个位置各写一个不同的符号

Box package{2, 3, 4, 0};
set_volume(&package);
位置 写法 作用
调用处 &package 取原箱子的地址
原型和定义的参数 Box* box 声明接收该地址的指针变量
函数体 box->volume 找到这个地址上的箱子，再取体积成员

不要把三种符号混在一起记。问清楚“我现在在取地址、声明指针，还是访问成员”。

2.3 箭头是两步操作的简写

box->volume = box->length * box->width * box->height;

box->volume 等价于 (*box).volume。

  1. *box 找到指针所指的对象。
  2. .volume 取这条记录的体积。

括号很重要。*box.volume 会先尝试取指针变量的 volume，指针本身没有这个成员。

2.4 先判断空指针，再访问

bool set_volume(Box* box)
{
    if (box == nullptr) return false;
    box->volume = box->length * box->width * box->height;
    return true;
}

nullptr 表示没有指向对象。拿不到对象，就不能解引用。这个函数用 false 告诉调用者没完成任务。

空指针检查并不能识别所有坏地址：指向已经销毁的对象，或凭空构造的地址，也不允许使用。调用者仍负责提供存活的对象。

示例 02 用正常尺寸得到 24，并检查 set_volume(nullptr) 返回 false。

2.5 地址的副本，为什么仍能改到原对象？

main：package ────────────────────┐
                                │ 同一个箱子
main 调用时提供 &package          │
函数：box 保存该地址的副本 ────────┘

副本是“地址值”，并没有把整个箱子复制进去。 修改 box->volume 是沿地址找到原箱子；把 box = nullptr 则只改变函数里的指针变量。

纸上判断： 在 set_volume 末尾写 box = nullptr;，main 的 package 是否消失？不会。只是函数中的地址变量改变了。

2.6 const 在这里限制什么？

const Box* box 限制通过这个指针修改成员，仍可读取成员。它并没有把所有其他访问途径一并冻结。

显示函数最容易出现的错误是写成可修改指针，后来不小心把 == 写成 =。使用只读参数，让编译器帮助发现误写。

本节过关： 独立写出“声明结构、声明原型、取地址调用、箭头修改成员”四步；并解释为什么这里不需要 delete。package 是普通局部对象，函数没有用 new 创建它。

3. 结构还可以装下一种坐标，返回另一种坐标

教材 7.6.2 用直角坐标转极坐标展示结构的输入和返回。本节数学公式直接给出，重点是数据如何经过函数。

3.1 两种记录对应两种描述

struct Rect { double x; double y; };
struct Polar { double distance; double angle; };
Polar to_polar(Rect point);

Rect 用横向位置 x 和纵向位置 y 描述点。Polar 用“距原点多远、朝哪个方向”描述同一点。

返回类型不必与参数类型相同。转换函数接收 Rect，返回 Polar，正好表达“从一种表示转换成另一种”。

3.2 手算点 (3,4) 的距离

横向 3，纵向 4
距离的平方 = 3×3 + 4×4 = 25
距离 = √25 = 5

程序使用 <cmath> 的 std::sqrt 求平方根。

方向角使用 std::atan2(y, x)。注意参数顺序是 y 在前、x 在后。 它会利用两个坐标确定方向，包括 x 为零、位于不同象限的情况。

不要随手改成 std::atan(y/x)：x 为零时除法有问题，单独一个比值也不足以区分所有方向。

3.3 弧度先存，显示时再换成角度

atan2 的结果是弧度。可以把它理解为另一种角度单位：半圈是 π 弧度，也是 180 度。

角度数 = 弧度数 × 180 / π

示例 03 使用 std::acos(-1.0) 得到 π，避免依赖某些编译器特有的 M_PI 宏。 输入 3 4，距离应为 5.000，角度约 53.130 度。

输入 0 1，距离 1、方向 90 度；输入 -1 0，方向接近 180 度。

3.4 原点没有唯一方向

点 (0,0) 距离原点为 0，你无法说它朝着某个唯一方向。 示例专门识别这个输入，报告方向未定义，不把一个计算结果解释成几何上唯一的方向。

程序限制坐标是 [-1000000,1000000] 内的有限数，避免演示过程中极端数值干扰计算。 “公式正确”与“任意输入都适合计算”是两件需要分别检查的事。

3.5 这一节真正要记住的接口

读入 Rect → 检查输入 → 调用 to_polar → 接收 Polar → 显示

输入输出留在 main，转换函数只做转换。以后要把同一转换用于文件数据或图形界面，就能复用它。

4. string 是对象，按值传递可以得到独立副本

第 7 章 A 的 const char* 参数接收字符序列的地址。 std::string 则把字符串作为对象管理，可以记录长度、赋值、拼接，并作为返回值使用。

4.1 先写最容易读的接口

std::string make_greeting(std::string name);

意思是：接收名字值，返回问候语值。调用片段：

std::string name = "Li Ming";
std::string greeting = make_greeting(name);

示例 04 在函数副本中拼接 Hello,。问候语改变，原名字仍为 Li Ming。

值 属于哪里 调用后用途
main 的 name 调用者 继续保留原名字
函数的 name 被调用函数 可在局部修改
返回的问候语 结果 保存到 greeting

4.2 返回新 string 不需要手动 delete[]

string 对象自己管理字符存储。 你按对象的规则使用它，不对普通 string 执行 delete[]，也不用为返回值手动补终止零字符。

这和 第 7 章 A 返回 new char[n+1] 的示例有不同的管理约定。先辨认返回类型，再决定如何使用结果。

对象按值传递可能有复制成本。第 8 章会介绍引用，让只读函数更方便地接收对象。本课先把按值语义讲清楚。

4.3 string 数组仍然是数组参数

教材 7.7 还显示一组 string。片段：

void show_names(const std::string names[], int count);

这里数组形参仍会调整成 const std::string*，不会因为元素类型是 string 就自动把整个数组按值复制。

区别在于：每个元素是一个 string 对象。names[i] 取一个对象，其 .size() 是这一项字符串的长度，不是整个 names 数组的项数。

4.4 混用 >> 和 getline，要处理换行

std::cin >> level 读完数字，行末换行常常还留在输入中。 接着 std::getline 可能立即读到这个换行，得到空行。

学生登记练习在读取数字后使用：

std::cin.ignore(std::numeric_limits<std::streamsize>::max(), '\n');

需要 <limits>。意思是丢弃当前行剩下的内容，直到换行，包括这个换行。

这不是“每次输入后都加一遍”的口诀。先问上一次使用什么输入函数、它留下了什么。连续两次 getline 通常不需要额外清理。

5. std::array 对象与原生数组的参数规则不同

教材 7.8 演示 array 对象。第 4 章见过它，这次重点观察它经过函数时的行为。

5.1 这个类型把容量写进类型里

std::array<int, 3> values{10, 20, 30};

需要 <array>。int 是元素类型，3 是元素个数。这个对象的 .size() 为 3。 std::array<int,4> 是另一种类型，不能直接当作 std::array<int,3> 传给固定接收后者的函数。

5.2 比较两种原型

void change_raw(int values[], int count);
void zero_copy(std::array<int, 3> values);
接口 实际形参 直接改元素的结果
原生数组形参 指向元素的指针 改到调用者的相应元素
array 按值形参 一个 array 对象值 改的是函数副本

这张表解释的是这两个具体声明，不能泛化成“所有数组都复制”或“所有数组都不复制”。

示例 05 把副本全设为零，打印副本，再打印 main 的对象：

copy: 0 0 0
 10 20 30

5.3 要改整个对象，用指向对象的指针

bool add_five(std::array<int, 3>* values);

调用是 add_five(&values)。 这里接收的是整个 array 对象的地址，和接收第一个 int 元素地址不同。

函数内部访问元素：

(*values)[i] += 5;

分两步读：先 *values 得到 array 对象，再 [i] 取它里面的元素。 *values[i] 的结合顺序不同，会先进行指针下标访问，不能作为同义写法。

修改后 main 的对象变为 15、25、35。空指针返回 false。

5.4 三种数据接口整理

任务 本课可用接口 是否会修改原数据
显示 Box const Box* 不能通过该参数修改
计算并写回 Box 体积 Box* 可以
生成问候语 std::string 按值，返回 string 不会因改形参而改原名字
原生数组求和 const int* 加长度 不修改元素
array 副本清零 std::array<int,3> 按值 不修改原对象
array 原对象加五 std::array<int,3>* 可以

停下来做一次： 不看表，给“读取一个结构”“修改一个结构”“返回一个新结构”各写一个原型，并解释调用处该给值还是地址。

6. 递归：调用自己后，当前这一层还没结束

递归是教材 7.9 的主题。最常见的误解是：遇到自调用，就“跳回函数开头，之前的内容都没了”。

实际发生的是一次新的函数调用。当前这次调用暂停，等新的调用返回，才继续后面的语句。

6.1 先看不带计算的完整程序

#include <iostream>

void trace(int level);

int main()
{
    trace(3);
}

void trace(int level)
{
    std::cout << "enter " << level << '\n';
    if (level > 0) trace(level - 1);
    std::cout << "leave " << level << '\n';
}

示例 06 在此基础上增加深度输入和 0–8 范围检查。

6.2 手走 trace(3)，不要只背输出

trace(3) 打印 enter 3，调用 trace(2)，等待
  trace(2) 打印 enter 2，调用 trace(1)，等待
    trace(1) 打印 enter 1，调用 trace(0)，等待
      trace(0) 打印 enter 0，不再调用，打印 leave 0，返回
    trace(1) 从调用之后继续，打印 leave 1，返回
  trace(2) 从调用之后继续，打印 leave 2，返回
trace(3) 从调用之后继续，打印 leave 3，返回 main

得到：

enter 3
enter 2
enter 1
enter 0
leave 0
leave 1
leave 2
leave 3

每一层的 level 都是自己的形参值，分别为 3、2、1、0。 trace(level-1) 不会把上一层的 level 减成新的值。

6.3 把等待位置写成表

当前调用 调用更小问题前 更小问题返回后
trace(3) enter 3 leave 3
trace(2) enter 2 leave 2
trace(1) enter 1 leave 1
trace(0) enter 0；不继续调用 leave 0

“调用记录”保存这一次的参数、局部状态和返回后继续执行的位置，常用栈来组织。 本课不用研究栈的机器布局，先记住后来进入的调用先返回。

6.4 三个必须回答的问题

  1. 何时直接解决？ level 为 0 时不再递归。
  2. 下一次是否更接近停止？ 每次减少 1，正数最终到 0。
  3. 小问题返回后做什么？ 打印当前层的 leave。

如果把 level-1 改成 level+1，正数会远离停止条件。 如果删除条件，level 即使到 0 也继续调用，不能正常结束。

这是纸上找错，不需要真的制造无限递归。

6.5 深度 0 不等于调用次数 0

trace(0) 仍会进入一次函数，打印 enter 0、leave 0，只是没有进一步的递归调用。 对这个程序，trace(n) 在合法范围内共有 n+1 次函数调用。

示例限制最大深度 8 是为了容易观察。真实程序的可用调用深度受资源影响，不能把递归当作无限容量的工具。

动手改一处： 把 leave 的输出移到自调用之前。再预测输出。你会看到顺序来自代码位置，而不是“递归天然就会倒序”。

7. 用递归算阶乘：先拿到小问题的结果

阶乘表示从 n 一直乘到 1。例如 4! = 4×3×2×1 = 24。 规定 0! = 1，这既是数学定义，也是递归停止的答案。

7.1 把大问题缩小一步

4! = 4 × 3!
3! = 3 × 2!
2! = 2 × 1!
1! = 1 × 0!
0! = 1，可以直接返回

每次 n 减 1，不是提前算出所有乘法，而是先等待小问题给出结果。

7.2 函数定义很短，理解不能省略

unsigned long long factorial(unsigned int n)
{
    if (n == 0) return 1;
    return n * factorial(n - 1);
}

输入先用能表示负数的整数接收并检查，再传入这个函数。不要先把负数转换成无符号数，才问它是否小于零。

本函数约定调用者传入 0–20。unsigned long long 至少能表示 64 位无符号整数的范围，20! 可以容纳；本课不继续算 21!，也不宣称该类型可表示任意阶乘。

7.3 3! 的返回路线

等待的调用 收到的小结果 自己返回
factorial(0) 不等待 1
factorial(1) factorial(0) 是 1 1×1=1
factorial(2) factorial(1) 是 1 2×1=2
factorial(3) factorial(2) 是 2 3×2=6

main 最后得到 6。函数里 return 不会直接把所有层一次性跳过，每一层都要完成自己等待的乘法。

7.4 返回类型也要能装下结果

如果局部计算用大整数，函数却声明 int factorial(...)，返回时仍需要转换成 int，可能丢失结果。 返回类型是接口的一部分，不是函数内部算完以后可忽略的装饰。

示例 07 只计算一次；练习 C 要求反复读入，直到读不到下一项为止。循环负责重复接题，递归负责解一题，两种重复有各自的用途。

7.5 递归和循环怎样选？

阶乘也可以用循环累计，从 1 乘到 n。对这个小任务，循环通常更直接；递归版本用于观察“问题缩小、结果返回”的过程。

会递归不代表以后每个循环都要改写成递归。选择能把任务表达清楚、且资源可控的实现。

8. 两次递归调用：左右分开处理

教材 7.9.2 画刻度尺。我们用一个固定长度字符序列观察同一个思路。

8.1 先准备字符，不要把字符串边界忘了

示例 08 使用 char ruler[18]：

  • 下标 0–16 共 17 个可见字符。
  • 下标 17 是 \0，表示 C 风格字符串结束。
  • 可见字符先填 .，两端 0、16 改成 |。

初始输出：

|...............|

终止零字符不参与画刻度，也不打印出来。

8.2 一次处理一个区间

void subdivide(char ruler[], int left, int right, int depth)
{
    if (depth <= 0 || right - left <= 1) return;
    int middle = left + (right - left) / 2;
    ruler[middle] = '|';
    subdivide(ruler, left, middle, depth - 1);
    subdivide(ruler, middle, right, depth - 1);
}

left、right 在这里是两端刻度的下标，不同于 第 7 章 A 的半开指针范围。函数修改的是两端之间的中点。 调用者提供 0≤left<right≤16；depth 限制在 0–4。

8.3 depth=2 的执行过程

subdivide(0,16,2)：标 8
  subdivide(0,8,1)：标 4
    subdivide(0,4,0)：停止
    subdivide(4,8,0)：停止
  subdivide(8,16,1)：标 12
    subdivide(8,12,0)：停止
    subdivide(12,16,0)：停止

先把左侧调用及其子调用处理完，才执行右侧调用。程序没有启动并行任务。

最后 0、4、8、12、16 为刻度：

|...|...|...|...|

8.4 为什么各层画到同一条尺子上？

ruler 是原生数组形参，实际接收字符地址。各层得到同一字符存储的地址副本，因此可以向同一条尺子写不同中点。

left、right、depth 是普通按值参数，每层各有自己的值。 不能笼统地说“递归里的所有变量共享”或“所有数据复制”：分别看每个参数的类型和操作。

8.5 调用总数和同时等待的层数不同

depth=2 时，上图有 7 次函数调用，包括 4 次直接停止的调用。 在长度足够继续划分的情况下，深度 d 的调用总数可达到 2^(d+1)-1。

但左侧处理完就返回，右侧才开始。不会同时保留所有节点的调用记录。 同时活跃的递归层数随深度增长，而不是等于整棵调用树的节点数。

固定尺子还有“区间太短就停止”的条件，这也会限制继续划分。

动手检查： depth=0 时只保留两端；depth=1 增加一个中点；depth=4 时可见位置全部成为刻度。不要把结尾 \0 也改成 |。

9. 函数指针：让变量记住“下一次找谁计算”

教材 7.10 用函数指针把算法选择交给调用者。先从两个简单函数开始，不急着看复杂数组声明。

9.1 两个具有相同接口的函数

double square(double value) { return value * value; }
double half(double value) { return value / 2; }

两者都接收一个 double，返回一个 double，因此可以用同一种函数指针指向它们。

如果直接写 square(4)，计算规则固定是平方。 我们希望保存“这次使用 square、下次使用 half”的选择，调用代码保持 operation(4)。

9.2 分清地址和调用结果

写法 这里的含义
square 在给函数指针赋值等语境中，转换为该函数的地址
&square 显式取该函数的地址
square(4) 现在调用函数，得到数值 16

保存地址和马上算出数值，不能混用。函数指针不能用数值 16 初始化。

9.3 从普通原型一步步构造声明

普通函数原型：

double square(double);

函数指针变量：

double (*operation)(double) = square;

读法：operation 是一个指针，它指向“接收 double、返回 double”的函数。

声明片段 管什么
(*operation) operation 是指针变量
右边 (double) 所指函数的参数列表
最左边 double 所指函数的返回类型

括号把 *operation 绑在一起。下面这个声明含义完全不同：

double* operation(double);

它声明一个函数，接收 double，返回 double 指针。不是函数指针变量。

9.4 调用有两种等价写法

double first = operation(4);
double second = (*operation)(4);
operation = half;
double third = operation(4);

前两项为 16，第三项为 2。(*operation)(4) 显式说明“找到指向的函数，然后调用”；operation(4) 更简洁，C++ 允许两种写法。

函数指针也仍然是一个有类型的变量。给它换目标，不会修改 square 或 half 的函数体。

9.5 签名必须匹配

这里需要“double 返回类型、一个 double 参数”的函数。

int wrong(double value);        // 返回类型不同
double also_wrong(int value);  // 参数类型不同

不能因为 int 平时可以转换为 double，就把这些函数随便装进上述指针。 普通调用中的数值转换，不等于函数指针类型之间可以这样转换。

不要用强制转换压下类型不匹配的错误；先把函数接口改成你确实需要的类型。

9.6 没有目标时不能调用

nullptr 可以表示函数指针没有目标，但是不能对它执行调用。

本课示例把指针初始化为已声明、已定义且签名匹配的函数，再调用。 如果设计一个允许空回调的接口，必须明确检查并规定失败处理。不要只声明一个未初始化指针就立即调用。

本节过关： 不看答案写出一个“接收两个 double、返回 double”的函数指针声明，并指出其中每个 double 的作用。

10. 回调：把函数地址当作参数传进去

回调不是一种神秘的运行机制。本课就是把一个函数地址交给另一个函数，后者在合适的位置调用它。

10.1 先给类型取个名字

using UnaryOperation = double (*)(double);
double apply(double value, UnaryOperation operation);

using 取别名，不创建新算法。 也可用教材中的 typedef 写法：

typedef double (*UnaryOperation)(double);

两种写法为这里同一类型取名。课程示例采用 using，读起来更容易拆成“名字 = 类型”。

10.2 apply 的定义只有一次转交

double apply(double value, UnaryOperation operation)
{
    return operation(value);
}

这个接口约定 operation 指向有效函数。 它不需要知道目标到底叫 square 还是 half，只要目标遵守同一个参数和返回接口。

10.3 手走 apply(3, square)

main 提供数值 3 和 square 的地址
  apply 的 value 得到 3
  apply 的 operation 得到 square 的地址副本
  operation(value) 调用 square(3)
    square 返回 9
  apply 收到 9，再返回 9
main 接收最终的 9

换成 apply(3, half)，同一个 apply 定义返回 1.5。

常见错误是写 apply(3, square(3))。第二个参数就变成了数值 9，而原型要求函数地址。编译器应该拒绝这个类型不匹配。

10.4 从一元运算扩展到二元运算

using Operation = double (*)(double, double);
double calculate(double first, double second, Operation operation);

函数定义：

double calculate(double first, double second, Operation operation)
{
    return operation(first, second);
}

calculate 负责接收两个数并转交，不在内部用 if 猜运算种类。add、subtract、multiply 分别负责一个实际规则。

这就是本章编程练习 10 的核心。练习 F 会加上重复输入和函数指针数组。

11. 函数指针数组：一张可以逐项调用的规则表

普通数组装数值，这个数组装函数地址。所有元素仍然必须属于同一种类型。

11.1 先用别名写清楚元素类型

using Operation = double (*)(double, double);
Operation operations[]{add, subtract, multiply};
const char* names[]{"add", "subtract", "multiply"};

operations 有三项函数指针，names 有三项对应标签。下标相同的两项组成一组。 本课采用固定三项；改数组内容时也要检查标签数量与循环范围。

下标 operations 中保存什么 输入 2、3 的结果
0 add 的地址 5
1 subtract 的地址 -1
2 multiply 的地址 6

调用片段：

for (int i = 0; i < 3; ++i) {
    double result = calculate(2, 3, operations[i]);
    std::cout << names[i] << '=' << result << '\n';
}

operations[i] 是选出来的函数指针；operations[i](2,3) 则已经是一次调用。 传给 calculate 的应是前者。

11.2 暂时去掉别名，看原来的形状

等价声明：

double (*operations[3])(double, double) = {add, subtract, multiply};

从名字向外读：operations 先是大小为 3 的数组；每项是指针；指针目标是接收两个 double 的函数；函数返回 double。

会使用别名版本，就已经能写练习。复杂版本用于看懂教材和别人的代码，不要求靠猜测背下来。

11.3 补充：指向函数的指针，目标函数还返回指针

教材后半段把“函数指针”“函数指针数组”“指向该数组的指针”组合起来。先分层，再看示例 11。

const double* first_value(const double values[], int count);
using Selector = const double* (*)(const double*, int);
Selector selectors[]{first_value, last_value};

这里有三个不同的东西：

东西 类型/用途
selectors[0] 函数指针，保存 first_value 的地址
selectors[0](values,3) 调用函数，返回一个元素地址
*selectors[0](values,3) 沿返回的地址读取那个 double

先拆开写，比一口气塞进输出语句更容易检查：

Selector select = selectors[0];
const double* result = select(values, 3);
if (result != nullptr) std::cout << *result << '\n';

values 是 10、20、30 时，first_value 返回第一项地址，last_value 返回最后一项地址。 没有元素时返回 nullptr，必须先检查，再读取。

11.4 返回的元素地址归谁管理？

它指向调用者的 values 数组，不是函数通过 new 分配的新空间。 不执行 delete，也不能在调用者数组销毁后继续使用这个地址。

“返回指针”本身没有说明所有权。必须看函数的行为和约定：指向原有数据、静态数据、还是新分配的数据？第 7 章 A、第 7 章 B 的例子故意分别展示这些区别。

11.5 补充：指向整个函数指针数组

auto table = &selectors;

这次 &selectors 取整个数组的地址，不是只取第一项。 如果显式写类型：

Selector (*table)[2] = &selectors;

使用时先得到整个数组，再选下标：

const double* result = (*table)[1](values, 3);

拆解顺序：

*table          得到 selectors 数组
(*table)[1]     取其中第二个函数指针
(values,3)      调用这个函数
result          接住函数返回的元素地址
*result         在 result 非空且有效时读元素

示例 11 的 via table=30 验证这条路线。 auto 是让编译器根据初始化表达式推断变量类型，不会替你保证地址有效，也不会替你检查下标。

读到这里觉得吃力很正常：回到简单指针的“保存地址、沿地址找目标”，每次只解开一层。

12. 把函数接口当作一张任务说明书

本课引入的工具多，选接口时先问任务，而不是先决定“今天要用递归”。

12.1 写程序前填四行

例如箱子体积：

输入：指向一个存活 Box 的指针，可以是 nullptr
输出：bool 表示是否完成
修改：成功时写 box->volume
失败：nullptr 返回 false，不访问成员

例如 calculate：

输入：两个已检查的数、一个有效的二元函数指针
输出：这个函数的 double 结果
修改：不修改输入变量
前提：回调的参数和返回类型匹配，不能是空目标

这四行能帮助你决定返回类型、const、值还是地址，也让 main 知道如何处理结果。

12.2 常见问题，先检查最接近原因的位置

现象 先检查
改完结构，main 还是旧值 参数是不是按值；有没有接住返回结果
p.member 报错 p 是对象还是指针；指针成员访问用 ->
字符串读成空行 前一次 >> 是否留下换行
array 改了副本 参数是否按值，需要写原对象时是否传地址
递归一直不结束 基本情形、输入范围、下一次是否接近基本情形
返回顺序预测错 自调用前后的语句分别在何时执行
大阶乘错误 输入上限、运算类型和返回类型是否都合适
函数指针赋值失败 返回类型和每个参数类型是否匹配
第二个参数要求指针却收到数字 是否把函数名误写成了一次函数调用
返回指针后读取错误 空值、所指对象寿命、有效长度

12.3 验收时别只测顺利情况

结构测试正常尺寸、零尺寸、空指针策略；字符串测试空行、含空格；递归测试基本情形、普通值、上限；回调测试每一种规则。

对于危险代码，只在纸上指出错误。不能把一次越界或悬空地址读取“恰好输出正常”当作正确证据。

本课输入例子使用普通数值输入，>> 的格式化提取不是逐字符严格校验器，例如数字后夹字母可能先提取数字部分。练习测试使用约定格式的数值，不把这些示例当成生产环境的完整输入验证库。
