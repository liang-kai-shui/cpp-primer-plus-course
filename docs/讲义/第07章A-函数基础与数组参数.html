0. 本课怎么学

0.1 从“把代码写出来”走到“把事情分清楚”

前两课已经能读一组数、用循环处理、根据条件输出结果。程序变长以后，你可能把输入、求和、平均、打印都放在 main 中。

它能运行，但修改一处规则时，必须在很多行里找对应的代码。相同的计算再做一遍，又要复制一套循环。

函数就是一段有名字、能被调用来完成某项工作的代码。 像厨房里的几个工作站：收材料、烹饪、装盘各有职责，负责人按顺序安排它们。

函数不只用来减少复制。它也让你能分别回答：

  1. 这一步要接收什么？
  2. 这一步负责做什么？
  3. 它把什么结果交回来？
  4. 它是否允许修改传入的数据？

本课先从一个数的计算开始，再把前几课的数组统计拆成函数。

0.2 名词先用一句话解释

名词 人话 你会在哪里看到
函数原型 提前说明函数怎样使用 double cube(double value);
函数定义 这项工作具体怎样做 有函数体的那一整段

实参 调用时真正交过去的值 上面的3.0
形参 函数里接收输入的变量 上面的value
返回值 函数交给调用方的结果 立方得到27

副作用 除返回结果以外还改变了什么 输出文字、修改原数组

不用一下背完。下面每个词都与具体的代码一起出现。

1. 原型、调用、定义：三个地方，各做一件事

1.1 先看一个完整程序

下面没有交互输入，3.0直接写在代码里，先把注意力放在执行顺序。

#include <iostream>

double cube(double value); // 原型

int main()
{
    double answer = cube(3.0); // 调用
    std::cout << answer << '\n';
    return 0;
}

double cube(double value) // 定义
{
    return value * value * value;
}

输出27。函数的定义写在 main 后面，不代表它会在 main 结束后自动执行。只有执行到调用，程序才进入这个函数。

1.2 把一行原型拆开

double   cube   (double value)   ;
  |        |          |         |
返回类型  名字     输入参数    声明结束
部分 告诉调用方什么
第一个double 会交回来一个double结果
cube 用这个名字调用它
圆括号里的double 要接收一个double输入
value 输入的说明性名字，可在原型中省略
最后分号 到这里是一条声明，没有函数体

double cube(double);也是同一个原型。为了方便读，我们尽量在原型里保留有意义的参数名。

1.3 定义多了什么

定义有花括号里的实现：

double cube(double value)
{
    return value * value * value;
}

value在函数中是一个变量。return先算出乘积，再把结果交回去，并结束这一次调用。

原型的分号不能原样留在定义的函数头后面：

// 错误片段：这里已经用分号结束声明，后面的块不是函数体。
double cube(double value);
{
    return value * value * value;
}

把错误片段当作“原型后接一段全局裸代码”理解，就知道编译器为什么不接受。

1.4 调用时不再写参数类型

double answer = cube(3.0);

这里把3.0作为输入，拿到返回值后初始化answer。调用写值或表达式，定义/原型才写参数类型。

cube(double 3.0)不是正确调用。也不要把调用写成 double cube(double value);，后者只是在声明函数。

想做的事 应写的形式
提前说明函数存在 double cube(double value);
给出实现 函数头后接 { ... }
用变量side调用 cube(side)
接住计算结果 double volume = cube(side);

1.5 为什么先让编译器看见声明

编译到调用的位置时，编译器需要知道函数的输入数量、类型和返回类型。它也可能在编译当前文件时根本看不到另一个文件里的实现。

因此先写原型，再调用，再在后面定义，是本课程统一采用的布局。

另一种合法布局是先给出完整定义，再写main；定义本身也提供声明。不是每个函数都必须另外抄一条原型，要求是在使用之前有合适的声明可见。

动手实验：在副本中删除cube的原型，定义仍留在main后。观察“未声明”之类的编译错误。再把完整定义移到main之前，确认这时无需单独原型也能编译。

2. 一次调用怎样进去，又怎样回来

2.1 暂停的是调用方的当前位置

以 double answer=cube(3.0); 为例：

main走到cube(3.0)
     |
     +-- 创建本次调用的value，初值3.0
              |
              +-- 计算3.0×3.0×3.0
              |
              +-- return交回27.0
     |
     +-- answer获得27.0
     |
     +-- 执行下一条输出

可以把它想成读文章时看脚注：记住刚才的位置，读完脚注后回来继续。

2.2 不是从函数后面重新开始main

示例01专门加入了三条输出。顺序是：

Before call
Inside cube
answer=27

Inside cube属于被调用函数，但出现在main的两条输出之间。这说明控制流程确实从调用位置进去，再回到该位置后面。

若main调用cube两次，每次都会完成一次独立调用；不会“记住上次局部变量的值继续算”，除非函数另外使用了有持续状态的数据，本课不这样设计。

2.3 返回值要被使用才完成你的目的

cube(3.0);                    // 调用，但没有使用返回的27
double answer = cube(3.0);     // 调用，把27保存起来
std::cout << cube(3.0);       // 调用，把27交给输出

第一行也会执行函数。若函数只有计算，它的结果在这条语句后就被丢弃。若函数里面还输出文字，那些输出仍会发生；丢弃返回值不会撤销已发生的动作。

计算结果不会自动改成某个外部变量的值。 这是本课要反复练的地方。

动手实验：把示例01里接结果的赋值改成单独的 cube(3.0);。不要继续输出不存在的answer。观察函数里面的文字仍会打印，但结果没有被你保存。

3. return和void：交回结果，还是只做动作

3.1 return结束哪一段

int larger(int first, int second)
{
    if (first > second) return first;
    return second;
}

第一次return只结束larger本次调用，不结束整个程序；main还会继续。main中的return才结束main，并把退出状态交给运行环境。

larger里如果first>second，执行第一条return后就不会继续执行第二条。

3.2 普通有返回值函数不能遗漏正常路径

// 不完整：first<=second时走到末尾，却没有提供结果。
int larger(int first, int second)
{
    if (first > second) return first;
}

编译器可能先警告“并非所有路径都有返回值”。不要忽略警告再猜一个输出，这条正常返回路径是不正确的。

本课所有有返回值函数都让正常路径明确return。main是一个特殊情况：走到末尾相当于return 0，不能拿它推导出普通int函数也能省略。

3.3 void不是返回一个“空数字”

打印一排字符的任务，可以只做动作，不返回数据：

void print_chars(char symbol, int count)
{
    for (int i = 0; i < count; ++i) std::cout << symbol;
    std::cout << '\n';
}

void的意思是没有返回值。因此这样调用：

print_chars('*', 3);

不能写 int result=print_chars('*',3);，因为没有一个int结果可接。

void函数可以写不带值的 return; 提前结束，也可以正常走到函数体末尾。

3.4 返回类型与返回的值

函数声明返回double，就应该提供符合意思的double结果。可转换的类型有时会被自动转换，但“能转换”不表示不会丢失信息。

int wrong_average(int first, int second)
{
    return (first + second) / 2;
}

用3和4调用得到3，因为整数除法先丢掉小数。仅把返回类型改成double仍得到3.0。要使计算本身采用浮点除法，例如 /2.0，并选double返回类型。

动手实验：用3和4比较“只改返回类型”和“同时改除数为2.0”。先预测3、3.0、3.5分别来自哪一步。

4. 按值传递：把值交过去，不把变量搬过去

4.1 实参与形参不是同一个变量

void change_copy(int number)
{
    number = 99;
}

如果main中有 int original=8;，调用 change_copy(original);，情况是：

main里的original [8]
          |
          +-- 取出值8，初始化形参
                         |
change_copy里的number [8] → 改为[99]

main里的original仍为[8]

两处变量可以名字不同，也可以都叫number。名字相同不会把它们变成同一块数据。

4.2 用返回值更新原变量

int next_value(int number)
{
    return number + 1;
}

下面三步的区别很大：

语句 main中的number，起初8
change_copy(number); 仍为8，函数改的是形参
next_value(number); 仍为8，9被交回但丢弃
number=next_value(number); 变为9，调用方显式赋值

示例02把它们放在一起验证。注意“函数计算出了9”和“main保存了9”是两件事。

4.3 每次调用有自己的局部变量

函数中的形参、普通局部变量通常在这次调用中存在。调用结束后，不能在main里直接使用函数的局部变量名。

double square(double value)
{
    double result = value * value;
    return result;
}

main拿到的是返回结果，不是直接获得了名为result的局部变量。下次再调用square，会有新一次的value和result。

这里只描述普通局部变量；static、全局状态在后续课程讲。实际编译器可能优化掉某些存储，但不会因此让按值参数随意修改调用方变量。

4.4 本课采用的函数摆放方式

原型和定义都放在文件作用域，与main并列。不要把另一个函数的定义塞进main的花括号里，C++不允许普通函数定义这样嵌套。

原型可以在块内声明，但为了让后续函数也看到统一的声明，本课程不采用那种布局。不要把“课程建议放外面”误写成“块内声明一定违法”。

同样，main里的 using namespace std; 只覆盖它所在的范围，不会让另一个函数里的cout自动可见。示例统一写std::，减少这个混淆。

5. 多个参数：逐个交代，每个都有类型

5.1 顺序决定谁接收哪个值

void print_chars(char symbol, int count);

print_chars('*',3)把字符*交给symbol，把整数3交给count。参数名不会替你按名字配对，配对由位置决定。

调用：print_chars('*', 3)
                  |    |
形参：         symbol count

示例03的times是3；函数内部循环使用count完成打印，返回后times仍为3。

5.2 即使类型相同，也逐个写类型

double area(double width, double height); // 正确
// double area(double width, height);     // 错误

参数列表不是普通变量声明 double width,height; 的写法。

两个参数类型相同尤其要起好名字。例如width和height、begin和end、capacity和count，名字能帮助人检查意思；编译器通常无法知道你把两个同类型实参交换了。

5.3 转换不替你检查业务规则

若参数要求int，把3.7传进去可能转换成3；若要求double，整数3可转成3.0。原型会做类型检查，但不会知道“人数不能为负”“数组长度不能超过容量”。

不要依赖转换把任意大浮点数塞进整数。先明确输入类型与可接受范围，再调用函数。

5.4 两参数计算：组合数的小模型

原书7.2.2用概率计算展示多个参数和局部累乘。本课示例05换成“从n个同学中选k个人，不区分选出的顺序”，只练组合数。

从5人选2人，共10种组合。逐轮乘除为：

轮次i 当前操作 result
起点 还没乘任何因子 1
1 乘5，再除1 5
2 乘4，再除2 10

示例把“检查0≤k≤n≤100”留给main，把计算留给函数。内部用long double，避免5/2这种整数除法破坏中间结果。

它用于理解参数与局部变量，不要求先精通概率论。k=0时循环零次，result=1，表示一种“什么也不选”的方案。

结果很大时浮点数未必保留每一个整数位；输出是数值近似，不能宣称这是无限精度的组合数工具。

动手实验：输入5 2、5 0、5 5。再输入2 5，确认main在调用计算前拒绝。写出哪些是类型检查，哪些是范围检查。

6. 数组参数：复制的是地址，元素仍在原处

6.1 先写一项常见工作：求和

long long sum_values(const int data[], int count)
{
    long long total = 0;
    for (int i = 0; i < count; ++i) total += data[i];
    return total;
}

调用 sum_values(values,4)：告诉函数从哪组数据开始，以及读几项。count没有自动与数组绑定，它只是一个由调用方提供的整数。

6.2 参数里的[]有一条特殊规则

在函数参数声明这个位置，const int data[]被调整为 const int* data。

long long sum_values(const int data[], int count);
long long sum_values(const int* data, int count);

两行声明的是同一种函数参数类型。不是两个重载，也不是把整个数组复制了一遍。

而在main中 int values[4]仍是数组，int* pointer仍是指针，不能把“参数处调整”扩大成“任何位置数组和指针都是一样的”。

6.3 看一张地址图

main的values： [2] [4] [6] [8]
                ^
                |
函数里的data：保存同一个起始地址的副本
函数里的count：保存整数4的副本

从技术上说，指针参数仍按值传递：复制一个地址值。之所以可以接触原数组，是因为复制后的地址仍指向原来那组元素。

因此有两种不同的修改：

函数内动作 影响
++data 移动形参指针，不移动调用方的指针变量
对可写参数执行 data[0]=99 修改该地址上的原元素

const参数不允许第二种写入；第9节再把const拆开讲。

6.4 长度必须另给，而且要给对

长度4的数组，传count=2可以让函数只处理前两项；传count=5不是“多算一次”，而是要求读不存在的元素，越界。

int data[100]写在函数参数里，也不会自动要求调用方一定给100项，更不会把100当作可以查询的运行时长度。

这里的接口约定是：count非负，起点后至少有count个有效int元素。函数只拿到指针和count，通常无法自行验证原数组到底有多大。

纸上找错：values有4项，分析 sum_values(values+2,3) 为什么越界。不要实际运行越界来“看看会打印什么”。

6.5 sizeof不会帮函数恢复丢失的长度

在main里，sizeof values得到整个数组的字节数；在函数里，data已经是指针，sizeof data得到指针本身的字节数。

具体字节数取决于实现，常见环境中int为4字节、指针为8字节；不要把这两个数写成C++永远保证的事实。

示例04先打印整个数组的字节数，接着在四次调用中分别打印指针字节数，最后统一打印四个求和结果。先计算、再输出标签，让诊断信息和结果容易区分。

正确求有效项数量的方法是调用方保存并传入count。到了第 7 章 B，std::array会把固定长度作为对象类型的一部分携带过来。

6.6 起点不一定是第一项

sum_values(values, 4);     // 四项全算
sum_values(values, 2);     // 前两项
sum_values(values + 2, 2); // 后两项

函数里面的data[0]表示“本次传进来起点上的第一项”，第三次调用时就是main的values[2]。

本地编号重新从0开始，但数据没有复制或搬家。

调用 函数看到的两项 总和
前两项 2、4 6
后两项 6、8 14
空段，count=0 不访问任何项 0

动手实验：只改示例04里其中一次调用的起点和数量，取中间两项。先手算4+6，再运行。数量不能超过起点后剩下的项数。

7. 把一个数组任务拆成三个函数

7.1 谁输入、谁显示、谁修改

示例06将事情分成：

int fill_values(double data[], int capacity);
void show_values(const double data[], int count);
void scale_values(double data[], int count, double factor);
函数 是否改原数组 返回什么
fill_values 是，写入输入值 实际收到的数量
show_values 否，只有输出动作 无返回值
scale_values 是，每项乘系数 无返回值

fill的容量是“最多可装几项”；返回的count是“实际装了几项”。两者必须分清。

7.2 main只负责安排顺序

double data[5]{};
int count = fill_values(data, 5);
show_values(data, count);
scale_values(data, count, 1.1);
show_values(data, count);

读这五行就能知道整个流程。具体的读取、显示、修改循环各在自己的函数里。

main仍要保存数组，因为它是整次流程的数据。不能把数组放在fill的局部作用域里，再假装后续函数还能拿那个局部数组使用。

7.3 只收两项时怎样走

示例约定负数、非数字、EOF结束；有限数超过1000000也停止收集，不存入数组。缩小数值范围用于保证演示中的乘法有明确范围。

输入 10 20 -1：

输入 动作 count 已有效的区间
10 存data[0] 1 前1项
20 存data[1] 2 前2项
-1 约定的结束标记，不存 2 仍是前2项

之后显示10、20，修改成11、22，再显示。后面的三个零初值不算用户数据。

7.4 返回数量也是函数结果

返回值不必是平均数这样的计算结果，也可以是“成功做了多少”“是否成功”的信息。

若忽略fill的返回数量，直接对容量5项求平均，就把未使用的格子混进了数据。程序可能没有编译错误，结果却不符合题目。

7.5 输入结束协议要先写清

本示例收集结束后不再询问其他数字，因此非数字留下失败状态也不会造成后续重读问题。若收集之后还要输入系数，就要按第 6 章处理失败状态和残留文字，并在EOF时结束。

不要照抄原书里“清除后一直读到换行”的循环而遗漏EOF：没有换行且输入已结束时，错误的恢复循环可能永远停不下来。

动手实验：测试立即-1、立即EOF、两项后非数字、五项全部填满。记录fill返回多少，show遍历多少，哪些格子被scale修改。

8. 两个指针表示区间：包含开头，不包含结尾

8.1 为什么还有第二种接口

“起点+数量”告诉函数处理哪段；“起点+结束位置”也能表达同一件事。

long long sum_range(const int* begin, const int* end);

本课约定区间是 [begin,end)：包括begin指向的元素，不包括end指向的位置。

8.2 超尾位置不是一个可读取的元素

values： [1] [2] [3] [4] [5]   超尾
           ^                   ^
         begin              values+5

最后元素是values[4]，结束位置是values+5。

可以构造同一数组的超尾指针，用于比较和表示结尾；不能对它解引用读取，也不能继续移动到更远的位置。

8.3 一轮一轮走

long long sum_range(const int* begin, const int* end)
{
    long long total = 0;
    for (const int* current = begin; current != end; ++current) {
        total += *current;
    }
    return total;
}

sum_range(values,values+3)的过程：

current位置 是否等于end 读取 total
values+0 否 1 1
values+1 否 2 3
values+2 否 3 6
values+3 是 不读取 保持6

若begin==end，就是空区间：一项也不访问，总和0。

8.4 指针必须属于有效的同一个范围

调用方要保证两个位置在同一个数组范围内（允许超尾），begin不在end后面。

把两个不同数组的指针凑成区间，或者把begin、end传反，不属于这个函数的合法输入。它不会自动发现错误并把数组重排。

end-begin计算同一数组内相隔的元素数，不是相隔字节数。只在这个前提满足时使用。

8.5 填充函数返回的“结束”是哪一格

若只填了两项，返回 data+2，表示有效区间 [data,data+2)。它是下一格的地址，不是最后成功填入的data[1]的地址。

原书7.13第7题的中文“最后被填充的位置”容易让人误解；与后续作为区间终点的用途连起来，应按最后成功项的后一格实现。

动手实验：示例07取 [values+1,values+4)，手算2+3+4=9。然后把两个终点设成同一个位置，确认空段结果为0。

9. const：限制从这条路能做什么

9.1 显示函数为什么写const

void show_values(const double data[], int count);

它承诺不通过data修改元素。如果误写 data[0]=0;，编译器会拒绝，让显示函数不小心清空数据的错误提早暴露。

原数组不一定真的是const。调用方仍可以通过其他可写路径改变自己的数组；const限制的是这个参数提供的访问方式。

9.2 指向只读数据，与指针本身固定

const int* reader = &first;
int* const writer = &first;
const int* const fixed_reader = &first;
声明 能把指针指向别处吗 能经它改元素吗
const int* 能 不能
int* const 不能 能
const int* const 不能 不能

第一种把“读到的int”视为只读；第二种把“保存的地址”固定。先记具体动作，再记英文名称。

9.3 参数中的const不是自动复制整个数组

无论可写的double*还是只读的const double*，传的都还是地址。增加const不是为了避免数组副本，而是为了限制写入并清楚表达意图。

需要修改原数组的fill或scale，不应把参数声明为const再强行去掉const。直接把接口设计成可写参数。

9.4 可写数据能交给只读函数

普通int数组与const int数组，都能交给接受const int*的只读函数；真正的const int数组不能交给要求int*的可写函数。

这是“能读的范围更宽”与“写入权限受限”两个方面。

不要把一级指针的规则直接照搬到int**与const int**。原书在这一节演示为什么简单加const会不安全；第一遍理解“多一级需要重新看类型”即可，不必实际运行违规修改。

动手实验：跑示例08，观察reader换了位置仍只能读、writer没换位置却能改值。在副本中分别尝试违反两种限制，只看编译错误，改回正确版本。

10. 二维数组参数：列数藏在行的类型里

10.1 先把一行当成一个元素

int matrix[2][3]{{1, 2, 3}, {4, 5, 6}};

matrix是有两项的外层数组，每一项又是含3个int的行数组。

外层第0项： [1] [2] [3]
外层第1项： [4] [5] [6]

把matrix作为参数时，得到的是指向第一行的指针。每次前进一行，要跳过3个int，不能仅凭int*猜步长。

10.2 先使用好读的写法

long long sum_matrix(const int matrix[][3], int rows);

第一个[]的长度没有写，用rows告诉函数有几行；第二个[3]写明每一行有3项。

在参数处，等价的指针写法是：

long long sum_matrix(const int (*matrix)[3], int rows);

先读成“matrix指向一行，每行是3个只读int”。不用第一遍就熟背括号拼法。

10.3 为什么不是int**

int**是指向int指针的指针，通常需要实际存放指针的结构；这里原始二维数组连续存的是int，并没有存放一张“各行指针表”。

两种类型不能靠强制转换假装一样。参数类型不同，访问下一行所需的动作也不同。

10.4 两个循环仍与上课一样

long long sum_matrix(const int matrix[][3], int rows)
{
    long long total = 0;
    for (int row = 0; row < rows; ++row) {
        for (int column = 0; column < 3; ++column) {
            total += matrix[row][column];
        }
    }
    return total;
}

示例09得到总和21、第一行6、零行0。列数固定为3，不代表行数也固定为2；函数能处理其他合法行数的三列数组。

10.5 与原书一个说明的区别

原书7.4末尾把二维数组参数说成“指向指针的指针”，并据此说不能加const。对于这里的原始二维数组，这个说法不准确。

本课程C++17环境可以使用 const int matrix[][3]，通过它只读元素。示例09已采用这种写法；把它误记成int**会影响后面的函数设计。

动手实验：把输入数组改为三行三列，并只把rows实参改成3；修改函数里的循环不需要增加“第三行专用语句”。再尝试给它四列数组，观察类型不匹配，别强制转换。

11. C风格字符串参数：用结尾字符确定何时停

11.1 字符数组什么时候才是字符串

char text[]{'h', 'i', '\0'};

最后的零字符表示文字结束。没有可访问的 \0 的普通字符数组，不能交给要求C字符串的函数任意往后读。

本课count_char的接口前提是：text非空指针，指向一个有效的、以零字符结束的字符串。

11.2 读字符直到零

std::size_t count_char(const char* text, char wanted)
{
    std::size_t count = 0;
    while (*text != '\0') {
        if (*text == wanted) ++count;
        ++text;
    }
    return count;
}

需要 <cstddef> 声明std::size_t。它是标准库用于长度和数量的无符号整数类型，不需要先知道它具体占几字节。

11.3 用banana追踪指针

指向字符 是否为零字符 是否等于a count
b 否 否 0
a 否 是 1
n 否 否 1
a 否 是 2
n 否 否 2
a 否 是 3
\0 是 不进入体内 保持3

每轮移动的是形参指针text。main保存的字符串起始指针仍指向b，文字内容也没有改变；示例10输出original=banana验证。

11.4 三种输入来源，与只读类型

char array[] = "hello";
const char* pointer = "hello";
count_char(array, 'l');
count_char(pointer, 'l');
count_char("hello", 'l');

字符数组、指向字符串的指针、字符串字面值都能用于只读接口。字符串字面值在C++中是const字符数组；不能用 char* p="hello"; 获得合法的可写文字。

不要沿用旧式示例中把字面值给char*的写法。需要修改文字时，先创建自己的可写char数组。

11.5 空字符串不是空指针

""仍有一个可读的零字符，循环零次；nullptr没有可解引用的字符，不能先读 *text。

我们的count_char没有把nullptr设计成空字符串。调用时应遵守有效C字符串前提，或者另设计空指针分支，两种接口不能混着猜。

动手实验：用banana分别数a、n、x，再用空字符串。不要把无结尾字符的数组或nullptr拿来运行这个函数。

12. 返回字符串地址：结果在哪里，谁负责释放

12.1 返回一个值，与返回它的地址

函数能返回int、double等值，也能返回指针；但返回地址以后，那个地址上的数据必须仍有效。

// 危险写法，仅分析，不能拿来使用。
char* wrong_text()
{
    char text[] = "hi";
    return text;
}

局部数组在函数结束后不再存活；返回它的地址不会把它搬到main，后续访问不正确。不能用“刚才还能打印”来证明数据寿命足够。

12.2 按原书思路，用new[]建立结果

示例11的核心：

char* build_text(char symbol, int count)
{
    char* text = new char[count + 1];
    for (int i = 0; i < count; ++i) text[i] = symbol;
    text[count] = '\0';
    return text;
}

调用前main已经检查0≤count≤80。这里为了展示与原书一致的机制使用new[]，小范围不代表内存分配永远不可能失败；普通new分配失败会抛出异常，异常处理在后续章节学习。

12.3 多出来的一格干什么

count=3、symbol=*时：

下标：       0    1    2      3
内容：      '*'  '*'  '*'   '\0'
文字字符数：3
分配格数：  4

count=0也要分配一格，写入零字符，得到有效空字符串。不能分配count格再把终止字符写到text[count]，那会越界。

12.4 指针变量结束，动态数组还存在

函数的局部指针text结束时不再作为局部变量存在；new[]得到的字符数组不会自动随它消失。函数把地址值交给调用方，让调用方仍能找到数组。

char* result = build_text('*', 3);
std::cout << result << '\n';
delete[] result;

在这个接口中，build_text创建，main用完后delete[]。不要在返回前释放，也不要忘记释放，更不要再次释放同一块。

12.5 判断返回指针的三个问题

  1. 它指向局部数据、动态分配数据，还是调用方本来拥有的数据？
  2. 使用期间数据是否仍存活？
  3. 如果需要释放，由谁、在什么时候释放？

返回指针不总表示“调用方必须delete”。例如返回调用方数组里某一项的地址，就不能擅自delete它。第 7 章 B会再用这样的例子区分。

12.6 下一课的string会更好管理文字结果

std::string可以按值返回，调用方不需要为了这段普通文字手动new/delete。本节学习原书的C字符串机制，是为了理解地址和寿命；日常文字处理可优先用string。

动手实验：示例11输入 * 0、* 3、x 80；检查方括号里有几个字符。输入−1或81应在分配前被拒绝。

13. 过关：能设计，而不是只会抄函数头

13.1 先在纸上写接口

要写平均值函数，先回答：

输入：哪组成绩？实际有几项？
输出：一个double平均值
是否修改原成绩：不修改，所以参数只读
空数据：由main先判断，不调用除法

再写原型、main的调用、函数定义。按这个顺序，不会先写几十行才发现返回类型根本不合任务。

13.2 看见症状，定位是哪一环

现象 先检查
调用处说函数未声明 原型是否可见，名字是否拼对
找不到函数的实现 定义是否存在，参数类型是否与声明对应
函数里改了数，main没变 改的是按值形参，还是显式接了返回值
平均值不对 是否用了实际count，是否在整数除法后才转double
显示函数把数组改了 只读接口是否加const，修改是否放错职责
字符串打印乱码或多出字符 有无有效零字符，地址上的数据是否仍存活
二维参数类型不匹配 列数是否相同，有无误写成int**
