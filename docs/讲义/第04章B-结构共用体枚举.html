本课目标

学完这一课，你要能做到下面 6 件事：

  1. 说清楚「结构声明」和「结构变量」的区别——哪一个会真正分配内存。 这是本课最重要的一个概念，也是以后学「类」的地基。
  2. 知道结构是什么、为什么需要它，能自己写一个含 3 个不同类型成员的结构并打印出来。
  3. 说清楚结构和数组的两个关键差别：成员是不是同类型；能不能整体赋值。
  4. 说清楚 struct 和 union 在内存上的根本区别（各占一块 vs 共用一块）。
  5. 认识位字段这种写法，知道它装不下时会发生什么、编译器会不会提醒你。
  6. 会用 enum 给一串数字起名字，知道 enum class 为什么更值得推荐。

这一章表面上在讲三种「打包数据的方式」，实际上讲的是「内存里的东西怎么摆放、一个名字代表多少内存」。 把这一课吃透，后面学指针、学类都会轻松很多。

第 0 部分 · 零基础补白：先把几个词说清楚

这一部分（第 1 节）是给零基础读者的地基。 如果你已经知道「内存」「变量」「类型」「初始化」大概是怎么回事，可以快速翻过，直接看第 2 节。

1. 五个你必须先认识的词

1.1 内存、比特、字节

内存（memory）：可以把内存想象成一长排极小的储物格，每个格子只有两种状态——「开着」或「关着」。

  • 比特（bit，也叫「位」）：就是一个这样的格子。它的内容只能是 0 或 1（关 / 开）。 单独一个比特能表达的信息极少，所以实际操作时都是好几个一起用。
  • 字节（byte）：8 个比特捆成一组，约定叫 1 个字节。 可以想成「一排 8 个开关」，一共能表示 2⁸ = 256 种不同的组合。

💡 为什么老要数字节？ 因为内存是有价格的——格子就那么多。 写程序时说的「这个东西占几字节」，意思就是「它占用几个储物格」。 本课讲的 struct / union / 位字段，本质上都在讨论占用几个格子、格子怎么分。

1.2 变量、类型、值

  • 变量（variable）：你给某个（或某几个）储物格起的名字。 真正的数据存在内存里，name 这样的名字只是一张标签。
  • 类型（data type）：告诉编译器「这个格子里的 0/1 该怎么解读、要占几个格子」的说明书。 int 和 double 的区别就在这里：占的格子数不同，解读方式也不同。
  • 值（value）：格子里面真正存着的东西。比如 int age = 19; 里，19 就是值。

1.3 声明、定义、初始化、赋值——这四个词是本课的关键

这四个词在第 4 章里反复出现，而且意思不能混。先用一张表分清：

词 一句话解释 生活化的例子
声明（declaration） 告诉编译器「有这么个东西，它叫什么、长什么样」 在纸上画好一张表格的模板（表头写上"姓名 / 年龄 / 成绩"）
定义（definition） 真的把这块地方留出来、造出来 印出一张空白表格，随时可以填
初始化（initialization） 一边造出来、一边就把第一个值写上 表格印出来的同时，第一行已经填好了
赋值（assignment） 东西已经存在了，现在擦掉旧内容、写上新的 表格已经在这了，把某一格的内容改掉

⚠️ 本课会反复用到这组词的区别，尤其是「声明」和「定义」。 下面第 3 节会用结构来把这件事讲得非常具体。

📌 一个提醒：C++ 里「声明」和「定义」的界线，对变量和对类型是不一样的。 - 对变量：int a; 既声明了 a、也定义了 a（真的留出了格子）。 所以日常说「声明一个变量」，通常就是指「定义」。 - 对类型：struct Student { ... }; 定义了一个类型， 但一个变量都没有造出来。这就是本课的坑所在。

本课说的「结构声明」用的是「声明一个类型」这层意思： 它确实定义了一种类型（所以 sizeof(Student) 合法）， 但它没有分配任何装数据的格子（所以里面一个值也没有）。 关键要记住的是最后一件事：结构类型定义好了 ≠ 有变量了 ≠ 占内存了。

1.4 作用域

作用域（scope）：一个名字「在哪些地方还认得出来」的范围。 出了这个范围，编译器就不认识这个名字了。

打个比方：你在自己家里喊「妈」，你妈会答应；出了门在街上喊「妈」，别人不知道你喊谁。 「妈」这个称呼的作用域就是你家里。

本课讲枚举的时候会大量提到作用域：普通 enum 的成员名作用域很大（跑到外面去了）， 所以容易撞名；enum class 的成员名老老实实待在自己里面，所以更安全。

2. 为什么需要「结构」：从一个具体问题出发（教材 4.4，p105–108）

2.1 先看问题：怎么描述一个学生？

要描述一个学生，至少需要三样信息：

姓名（一串文字） + 年龄（整数） + 成绩（小数）

麻烦来了：这三种是不同类型的数据。

如果你之前学过数组，会知道数组有个硬性规定——所有元素必须是同一种类型。 int 数组只能装 int，装不了「一会儿文字、一会儿整数、一会儿小数」。 所以数组装不下这三样东西。

2.2 一个笨办法：开三个数组

有人会想：「那我就开三个数组嘛——一个存姓名、一个存年龄、一个存成绩， 用同一个下标表示同一个人。」

// 三个数组「平行」存储
std::string names[3]  = {"Li Ming", "Wang Fang", "Zhang Wei"};
int         ages[3]   = {19, 20, 18};
double      scores[3] = {92.5, 88.0, 95.5};

// 想给王芳加分，你必须自己记住「她都在下标 1」
names[1]  = ...;    // 万一哪天删了一个人，下面三行的下标全要改
ages[1]   = ...;
scores[1] = ...;

能跑，但很脆弱。问题在于：三个数组之间没有任何机制保证它们对齐。 你一旦改了某一个数组的顺序，另外两个就跟人错位了——改错了还不会报错，只是数据悄悄乱掉。

2.3 结构：把三样东西打包成一个整体

结构（structure，关键字 struct）就是解决这个问题的：它允许你把几个不同类型的数据 捆在一起，当成一个整体来使用。

💡 生活化的比方：结构 = 一张学生信息卡 设想学校给每个学生发一张卡片：卡片上有三个格子，分别印着「姓名」「年龄」「成绩」。 这张卡片是一个整体——你拿着它，就等于同时拿到了这个人的三项信息。 你不可能只把卡片上的「成绩」那半张撕下来交给别人，要交就是整张交。 这就是结构：几样不同的信息，装在一个盒子里，一起搬、一起用。

        一个「学生」结构
   ┌──────────────────────┐
   │  name  : "Li Ming"   │
   │  age   : 19          │
   │  score : 92.5        │
   └──────────────────────┘
   一个变量，三个成员，永远绑在一起

2.4 结构里的每个格子叫「成员」

成员（member）：结构里面每一个被命名的格子，就叫这个结构的一个成员。 上面那张卡片有 3 个成员：name、age、score。

💡 如果你熟悉表格：结构就像一张表的「列定义」，每个成员就是一列。

访问成员用的是「点」，叫成员运算符，写作 .：

s1.name     // 取 s1 这个结构的 name 成员
s1.age      // 取 age 成员

读作「s1 的 name」。这一点和「学生的姓名」是一个道理，很自然。

💡 一句话记住它和数组的区别： 数组是「同类型的东西横着排成一排」，结构是「不同类型的东西竖着打包成一包」。 而且这两者可以叠加——结构数组（每个元素都是一个结构）就是它们叠在一起，见第 7 节。

3. ⭐⭐ 本课最重要的一节：结构「声明」≠ 结构「变量」

3.1 写一个结构要分两步

// ---------- 第一步：声明一个「结构模板」 ----------
struct Student          // struct 是关键字，Student 是这个新类型【名字】
{
    std::string name;   // 成员 1
    int         age;    // 成员 2
    double      score;  // 成员 3
};                      // ⚠️ 这个分号不能少！

// ---------- 第二步：用这个类型定义变量 ----------
Student s1;             // 现在才真正分配内存

第一步那一整段，叫「结构声明」（structure declaration）。第二步那一行，叫「定义结构变量」。

3.2 ⭐ 关键点：声明不分配任何内存

这是本课最要命、也最爱被考的一点：

struct Student          // ← 这一整段【不占用一个字节的内存】
{
    std::string name;
    int         age;
    double      score;
};

它只是告诉编译器一句话：

「以后我说到 Student，指的就是长这样的一种数据：先是名字，再是年龄，再是成绩。」

它没有造出任何真实的数据，所以不占内存。

💡 生活化的比方：表格模板 vs 填好的一行数据 - struct Student { ... }; 就是一张空白表格的模板—— 上面印好了表头「姓名 / 年龄 / 成绩」，但一张纸都没印出来，当然不占地方。 - Student s1; 才是照着模板真印出一张空白表， 从此你就有了一张自己的表（这时候才真的占地方）。 - Student s2; 再印一张，又占一份。

模板本身永远不占地方，占地方的是照模板印出来的每一份。

Student s1;             // ← 这一行才真正分配内存
Student s2;             // ← 又分配一份，和 s1 完全独立

实测（示例代码/04_结构共用体枚举/01_struct_basics.cpp）： sizeof(Student) 在本机是 48 字节，s1 和 s2 各占一份。

📌 为什么 sizeof(Student) 是合法的？ 因为 Student 是类型名，问「这种类型占多少字节」是正当的问题。 但如果你写 Student = 5;，编译器就会报错——因为 Student 是类型，不是变量， 类型不能拿来当左值装东西。这个对比能帮你一眼分清「类型」和「变量」。

3.3 为什么这个概念这么重要？

因为以后学「类」的时候，一模一样的事情会再来一遍：

本课 以后（第 10 章起）
struct Student { ... }; 结构声明 class Student { ... }; 类定义
Student s1; 结构变量 Student s1; 对象（实例）
模板不占内存 类不占内存
s1 占一份内存 对象占一份内存

「模板 vs 实例」这个思想就是面向对象编程的地基。 现在把这一层想通了，后面会省很多力气。

⚠️ 报错时会看得更清楚：如果你忘了结构声明后面那个分号，GCC 会明确告诉你 text error: expected ';' after struct definition 而且它还会用箭头指出该在哪里加，甚至把 ; 给你画出来。照着改就行，不用怕。

4. 结构变量的初始化（教材 4.4.1–4.4.2，p106–108）

4.1 什么叫「初始化」

上面第 1.3 节说过：初始化 = 一边把变量造出来、一边就把第一个值写上。 对结构来说，写法就是用一对大括号 { } 把各个成员的值按顺序排好。

4.2 三种写法

// ① C++98 老写法：可以带等号
Student s2 = {"Wang Fang", 20, 88.0};

// ② C++11 新写法：可以省略等号（和数组一样）
Student s3{"Zhang Wei", 18, 95.5};

// ③ 只初始化一部分 → 剩下的自动补 0 / 空
Student s4 = {"Only Name"};        // age = 0，score = 0（string 补成空字符串）

这三种都是初始化，因为它们都发生在「变量刚被造出来」的那一刻。

4.3 ⚠️ 顺序必须和声明一致

大括号里的值，是按成员在结构里出现的先后顺序一个个对上去的：

struct Student
{
    std::string name;    // 第 1 个 → 大括号里第 1 个值
    int         age;     // 第 2 个 → 大括号里第 2 个值
    double      score;   // 第 3 个 → 大括号里第 3 个值
};

所以 Student s = {"Wang Fang", 20, 88.0}; 是正确的； 如果把顺序写成 {20, "Wang Fang", 88.0}，编译器会直接报错—— 因为 20 塞不进 std::string。这是好事：类型不一样，编译器就替你挡下来了。

⚠️ 真正危险的是另一种情况：几个成员的类型完全相同。 ```cpp struct Point3 { int x; int y; int z; };

Point3 p = {100, 3, 4}; // 本意是 (3, 4, 100)，手滑写反了 `` 这一行**编译器一声不吭**（实测 0 错误 0 警告），p的值就变成了x=100, y=3, z=4`——数据悄悄错了，程序照常跑。 这正是「顺序必须和声明一致」这条规矩真正的分量所在。

💡 记法：大括号里的值，是照结构里「从上往下」的顺序发的号码牌。 别靠记，靠看——写初始化的时候，眼睛盯着结构声明从上往下对一遍。

💡 顺便一个好消息：如果你只写了一部分（比如 Student s4 = {"Only Name"};）， 用 -Wall -Wextra 编译时，GCC 会给出 warning: missing initializer for member 'Student::age' [-Wmissing-field-initializers] ——它会提醒你"还有格子没填"。 这就是为什么编译时一定要带上 -Wall -Wextra：能自动提醒你的错误，就别靠人眼去查。

4.4 赋值和初始化不一样，别混

Student s1;                    // 定义（造出来）
s1.name  = "Li Ming";          // ← 这是【赋值】：格子已经在了，往里写
s1.age   = 19;
s1.score = 92.5;

上面这四行完全合法，效果和「声明时直接初始化」差不多。 但注意区别：先把变量造出来、再一个个往里写，那是赋值，不是初始化。 题目如果说「要求在声明时初始化」，那就是要你写成 Student s1 = {"Li Ming", 19, 92.5}; 这种一行搞定的样子。

⚠️ 有一类数据必须先初始化、不能等后面赋值，例如 const 成员和引用成员 （这些以后会学到）。所以「初始化」和「赋值」的区别不只是措辞问题。

5. ⭐ 结构可以整体赋值——和数组对比（教材 4.4.4，p108–110）

这一节是本课第二个重点，也是最能体现「结构是个完整的值」的地方。

5.1 先看对比：数组不行，结构行

int a[3] = {1,2,3};
int b[3];
b = a;              // ❌ 编译错误！

实测报错原文（GCC 8.1.0）：

error: invalid array assignment

而结构：

Point p1 = {3, 4};
Point p2;
p2 = p1;            // ✅ 完全合法！逐成员复制一份

跑 示例代码/04_结构共用体枚举/02_struct_assign.cpp，实测输出：

p1 = (3, 4)
p2 = (3, 4)   <- 从 p1 复制来的

把 p2.x 改成 100 之后：
  p1.x = 3   <- 没变
  p2.x = 100
  ^ 是「各有一份」，不是「指向同一份」

⚠️ 注意区分「复制」和「共享」： p2 = p1 是复制——之后改 p2 不影响 p1。 两个变量各占一块自己的内存，只是内容一开始相同。 （「共享」是另一个东西，本课第 9 节的 union 才是真共享。）

5.2 ⭐ 为什么数组不行、结构行？

这一句解释要记牢：

数组名在多数场合会「退化成地址」，而地址不能当值赋给另一个数组； 结构是一个完整的值，所以能整体复制。

拆开来说：

  • 数组：int a[3]; 里的 a，在大多数用到它的地方，编译器会把它当成"第一个元素的地址"来用， 而不是当成"装着 3 个整数的那个盒子"。 地址是个位置编号，你没法把「一个位置」整个塞进「另一个位置」里， 所以 b = a; 编译器直接拒绝。
  • 结构：Point p1; 里的 p1 不是地址，它是一个实实在在的盒子， 里面装着 x 和 y。盒子可以整个搬走，所以 p2 = p1; 合法， 编译器会逐个成员帮你复制过去。

📌 地址这件事，是第 4 章 C「指针与自由存储空间」要讲透的核心内容。 现在只需要记住这个结论：数组名 ≈ 地址，结构名 = 一整个值。 到了那一课你会彻底明白为什么。

5.3 「值语义」是个好东西

「结构是完整的值」带来一串好处，这就是教材 4.4.4 想说的： 结构变量用起来和普通变量几乎一样。

能力 普通变量 int 结构变量 Point
定义 int a; Point a;
赋值 a = b; a = b; ✅
当函数参数 f(a) f(a) ✅（按值传递，会复制一份）
当函数返回值 int f() Point f() ✅
放进数组 int arr[3] Point arr[3] ✅
放进另一个结构 — ✅
当 union 的成员 ✅ ✅

💡 「按值传递」值得先记住：把结构传给函数时，默认是把整个结构复制一份给函数。 结构大的时候这样很浪费（比如 48 字节的结构，每次调用都复制 48 字节）。 所以第 7、8 章会教「传引用」来避免复制。 现在知道"默认是复制一份"就够了。

6. 结构里能放什么（教材 4.4.3，p108）

6.1 教材专门回答的那个问题：能放 string 吗？

教材 p108 专门用一小节回答：「结构可以将 string 类作为成员吗？」

答案：可以。 而且 C++11 起还能直接用 {...} 初始化：

struct Person
{
    std::string name;      // ✅ 完全可以
    std::string city;
    int         age;
};

Person p = {"Li Ming", "Zhengzhou", 19};   // ✅ C++11

💡 std::string 是什么？ 它是 C++ 标准库提供的一种能装一串文字的变量类型。 相比老式的 char 数组，它的好处是：自己知道怎么复制、怎么增长、怎么释放内存， 长度也不必提前写死。所以拿它当结构成员特别省心。

跑 示例代码/04_结构共用体枚举/04_struct_string_bitfield.cpp，还能看到整体复制也正常：

Person q = p; 再改 q.name 之后：p.name = Li Ming, q.name = Wang Fang   <- 各有一份

6.2 成员几乎可以是任何类型

结构成员几乎可以是任何类型：基本类型、数组、string、另一个结构、指针……

struct Date { int y, m, d; };

struct Student
{
    std::string name;
    Date        birthday;      // ← 结构里嵌结构，完全合法
};

// 访问时一层层点下去：
s.birthday.y                   // s 的生日 的 年

💡 生活化的比方：学生信息卡上有一栏叫「出生日期」， 而这一栏本身又是一张小卡片，上面分了「年 / 月 / 日」三格。 想拿到年份，就要先打开大卡片找到"出生日期"，再打开小卡片找"年"—— 这就是 s.birthday.y 里那两个点的意思。

7. 结构数组：天然的一张表格（教材 4.4.5，p110–111）

7.1 结构和数组叠加起来

结构和数组可以叠加：每个数组元素本身就是一个结构 → 天然的「表格」。

跑 示例代码/04_结构共用体枚举/03_struct_array.cpp：

Student group[3] = {
    {"Li Ming",   19, 92.5},
    {"Wang Fang", 20, 88.0},
    {"Zhang Wei", 18, 95.5},
};

注意初始化用了两层大括号：外面那层是数组（3 个元素）， 里面每个大括号是一个结构（一个学生的三项信息）。

💡 这就等于一张表格： - 外面那层数组 = 有几行 - 结构里的成员 = 有几列

group[1] 就是「表格的第 2 行」，group[1].name 就是「第 2 行、姓名那一列」。

7.2 访问方式：先下标，再点

group[i].name      // 先取第 i 个元素（是个结构），再取它的 name 成员

实测输出：

姓名            年龄    成绩
--------------------------------
Li Ming         19      92.5
Wang Fang       20      88
Zhang Wei       18      95.5
  ^ group[i] 是第 i 个结构，再 .name 取它的成员 —— 「先下标，再点」

平均分: 92
最高分: Zhang Wei (95.5)

⚠️ 读法要记牢：先算 group[i]，再算 .name。 写 (group[i]).name 和 group[i].name 完全等价。 但不能写成 group[i.name]——那是拿 i 的 name 成员当下标，完全不是一回事。 口诀：先下标，后点。

7.3 遍历找最高分（经典套路，值得背下来）

int best = 0;                                  // 先假设第 0 个最高
for (int i = 1; i < 3; ++i)
    if (group[i].score > group[best].score)
        best = i;                              // 发现更高的就把记住的编号换掉
cout << group[best].name;

思路：手里先拿一个「目前最高的人」的编号，然后一个一个比过去， 谁更高就把编号换成谁。比完一遍，手里的编号就是最高的那个。 （这叫「打擂台」，以后找最大 / 最小值都用这一招。）

8. 位字段：让一个成员只占几个比特（教材 4.4.6，p111）

这一节教材标的是「略读」——你只需要认识这种写法，能读懂别人的代码就够了。 但里面有个对比特别有教学价值，所以这里还是讲一讲。

8.1 什么是位字段

位字段（bit field）：规定某个成员"只占几个比特"，用来省内存。

先复习一下第 1.1 节：1 字节 = 8 比特（8 个开关）。 所以「占几个比特」= 「用几个开关来存这个数」。

假设你要存「日期」，用三个普通 int 存年月日，要 12 字节。 可实际上：

  • 日最大 31 → 5 个比特就够（2⁵ − 1 = 31）
  • 月最大 12 → 4 个比特就够（2⁴ − 1 = 15）
  • 年到 4095 都用得上 → 12 个比特够（2¹² − 1 = 4095）

用位字段写出来就是：

struct Date
{
    unsigned int day   : 5;    // 5 位 -> 0..31，够表示日期
    unsigned int month : 4;    // 4 位 -> 0..15，够表示月份
    unsigned int year  : 12;   // 12 位 -> 0..4095，够表示年份
};

语法就是：类型 成员名 : 位数;

实测（示例代码/04_结构共用体枚举/04_struct_string_bitfield.cpp）：

sizeof(Date) = 4 字节
  若用三个普通 int 存，要 12 字节

5 + 4 + 12 = 21 比特，一个 4 字节（32 比特）的 unsigned int 就装得下，所以是 4 字节。

💡 生活化的比方：位字段就像一份表格里留出"几格"给某一项。 明明只需要填「0～31」这么小的数，你却给它留了一整页纸，是浪费； 位字段就是「按需留格子」。

8.2 位字段有三个坑

坑 说明
不能取地址 &d.day 是错的（因为它不是一个完整的内存格子，没法给出地址）
布局依赖编译器 同样的代码换个编译器，比特怎么排可能不同 → 可移植性差
装不下会截断 见下一节

8.3 ⭐ 一个有意思的实测发现：位字段溢出会报警告

我们本来以为位字段溢出是「静默截断」（就是悄悄给你改掉、什么都不说）。 实测：编译器会警告。

Date d2 = {0, 0, 0};
d2.day = 40;              // 5 位最大只能到 31

warning: conversion from 'unsigned int' to 'unsigned char:5'
         changes value from '40' to '8' [-Woverflow]

值被截断成 8（40 − 32），而且编译器提前提醒了你。

💡 这条警告怎么读？ 三句话： 1. conversion from 'unsigned int' to 'unsigned char:5' ——「你往一个只有 5 比特的格子里塞一个 unsigned int」； 2. changes value from '40' to '8' ——「这个值会被从 40 改成 8」； 3. [-Woverflow] ——「这属于 overflow（溢出）这一类警告」， 以后想单独关掉或打开它，就用这个名字。

8.4 ⭐ 和「数组越界」对比：一个会警告，一个连警告都没有

这个对比很有教学价值：

情形 编译器会不会提醒
位字段装不下 会，给出 -Woverflow 警告，还告诉你值会变成多少
数组越界 不会（连警告都没有 —— 这才是最危险的）

实测：int a[3]; a[7] = 100; 用 -Wall -Wextra 编译，一条警告都没有， 程序照常跑，结果只是数据悄悄坏掉。

📌 结论：警告不是噪音，是编译器在帮你。 而且注意——-Woverflow 这一类警告就算你不加 -Wall 也照样会出现， 因为它是 GCC 默认就开的基本警告。 所以你看到警告时，先别急着忽略，读一读它说了什么。

8.5 要不要用位字段？

日常几乎用不到。 你只需要认识这种写法，能读懂别人的代码就够了。 真正需要精确控制「每个字节怎么用」的场合（比如网络协议、嵌入式）才会用到它。

9. 共用体 union：几个成员共用一块内存（教材 4.5，p111–112）

9.1 一句话说明

共用体（union）是一种「多个成员共享同一块内存」的结构。

union Value
{
    int    i;
    long   l;
    double d;
    char   bytes[8];
};

写法和 struct 长得一模一样，只是关键字换成了 union。

💡 生活化的比方：共用体 = 一个柜子，几个人轮流用 一个柜子只有那么大，单位里几个人共用它：今天张三放东西，明天李四放。 柜子的大小取决于东西最大的那个人（能放下最大的那件就行）， 而不是「张三的东西 + 李四的东西 + 王五的东西」加起来的面积。 而且一次只能有一个人的东西在里面——张三的东西放进去，李四的东西就没地方了（或者被覆盖）。 这就是 union：位置只有一块，谁用谁占。

9.2 实测：大小等于最大的那个成员

跑 示例代码/04_结构共用体枚举/05_union.cpp，实测：

sizeof(int)         = 4
sizeof(double)      = 8
sizeof(char[8])     = 8
--------------------------------
sizeof(union Value) = 8
  ^ 等于【最大那个成员】的大小，而不是各成员之和！     ← 这就是和 struct 的根本区别

9.3 ⭐ struct 和 union 的内存差别（必须看懂的图）

同一批成员，用 struct 和用 union 装，内存长得完全不一样：

struct S { int i; double d; char c[16]; }        union U { int i; double d; char c[16]; }
大小 = 4 + 8 + 16 = 28，对齐后 = 32               大小 = max(4, 8, 16) = 16

  ┌──────────────┐ 偏移 0                          ┌──────────────┐ 偏移 0
  │  int  i      │  4 字节                         │              │
  ├──────────────┤                                 │              │
  │  （填充 4）  │  ← 对齐用的空隙                  │  int i  ────┐│
  ├──────────────┤ 偏移 8                          │  double d ──┤│ ← 三个成员
  │  double d    │  8 字节                         │  char c[16]─┘│   起始地址相同
  ├──────────────┤ 偏移 16                         │              │
  │  char c[16]  │  16 字节                        │              │
  └──────────────┘                                 └──────────────┘
  各成员【各占一块】                                 各成员【共用一块】
  总大小 = 32 字节                                   总大小 = 16 字节

实测数据（本机 GCC 8.1.0）：

定义 sizeof 为什么
struct S { int i; double d; char c[16]; }; 32 4 + 8 + 16 = 28，再加 4 字节对齐空隙
union U { int i; double d; char c[16]; }; 16 等于最大成员 char[16] 的 16 字节

💡 「内存布局」是什么？ 指各个成员分别放在内存的哪个位置、从第几字节开始、占几个字节。 上面那两张图就是「内存布局图」——把看不见的内存画出来，一眼看清谁在哪。 写 C++ 的时候，能画出内存布局图，就说明你真懂了。

9.4 什么是「内存对齐」

你在上面看到了「填充 4 字节」和「28 变成 32」——这多出来的空隙就是内存对齐造成的。

内存对齐（memory alignment）：编译器会故意在成员之间插入一些空字节， 让每个成员从这个数据类型"习惯的"整数倍位置开始。

💡 生活化的比方：停车场的车位是划好的。 一辆小车不一定要停在车位正中间，但必须停在自己的车位线以内， 这样进出才快。内存也一样——让数据从整齐的位置开始， CPU 取数据的速度更快。代价就是会浪费一点空隙。

所以：

⚠️ sizeof(结构) 不一定等于各成员大小之和。 比如 sizeof(Student) 是 48 字节（这是本机实测值，std::string 本身占 32 字节）， 里面除了三个成员，还包括对齐留下的空隙。 换一个编译器、换一个平台，这个数字可能不同， 所以不要拿结构的大小去写死数字。

9.5 共用体的核心特点：写一个，覆盖其他

union 的内存布局（sizeof = 8）：

   ┌────────────────────────────┐
   │  i / l / d / bytes 全在这里  │   ← 所有成员的【起始地址相同】
   └────────────────────────────┘

实测证明了这一点：

v.i = 65   （写入 int）
  读 v.i = 65
  读 v.d = 3.21143e-322   <- 垃圾值（同一块内存被当成 double 解释）

v.d = 3.14159   （写入 double，覆盖了刚才的 i）
  读 v.d = 3.14159
  读 v.i = -266631570   <- 已经不是 65 了

&v.i = 0x61fe48
&v.d = 0x61fe48
  ^ 地址完全相同 —— 这就是「共用」的含义

💡 「垃圾值」不是随机的，是"同一块内存被换了种读法"。 你写进去的是 65 的二进制，却让程序按 double 的规则去解读它， 得到的当然是一个莫名其妙的小数——那块内存没变，变的是"说明书"。 （0x61fe48 这种写法是十六进制的地址，你可以先把它当成"格子的门牌号"。）

9.6 ⚠️ 共用体不记录「现在存的是哪个类型」

union 不记录「当前哪个成员是有效的」。
你读一个不是最后写入的成员，它【不会报错】，只会给你垃圾值。
所以正确用法是：自己用一个额外的变量记住「现在存的是什么类型」。

⚠️ 这是 union 最危险的地方：读错了成员，编译器不会拦你，程序也不会崩， 只是给你一个看着像数、其实是垃圾的结果。这种错最难查。

9.7 常见用法：union + 一个标签

struct Variant
{
    char tag;                      // 标签：'i' 表示存的是 int，'d' 表示存的是 double
    union { int i; double d; };    // 匿名共用体，成员直接叫 .i / .d
};

Variant a;  a.tag = 'i';  a.i = 42;
Variant b;  b.tag = 'd';  b.d = 2.718;

这种写法叫「带标签的联合」——多花一个字节存个小标签，用来记住是哪一种。 在文件格式解析、网络协议、脚本引擎里很常见。

💡 生活化的比方：柜子里现在放着谁的东西，柜门上贴一张纸条写着"张三"。 纸条（tag）不能告诉你里面是什么，但能告诉你该按谁的规矩去拿。

9.8 要不要学 union？

学习阶段几乎用不到。 它的价值是「省内存」和「看同一块内存的不同解释」。 现代 C++ 里很多场景被 std::variant 替代了。 现在只需要认识它、知道它和 struct 的区别就够了。

📌 本课要背下来的一句话： struct 的成员各占一块内存（大小 = 各成员之和 + 对齐空隙）； union 的成员共用一块内存（大小 = 最大成员）。

10. 枚举 enum：给一串数字起好记的名字（教材 4.6，p112–114）

10.1 为什么需要枚举

先对比两段代码：

int  today = 3;            // 3 是星期几？读代码的人得去查文档
Week today = Wed;          // 一眼就懂

枚举（enumeration，关键字 enum）就是给一组整数起"有意义的名字"。

💡 生活化的比方：枚举 = 给遥控器的按键贴标签 遥控器里面，每个键其实就是一个编号。 如果说明书上写「按 7 号键」，你每次都要翻说明书； 但按键上贴着「音量 +」，你就一眼就懂。 枚举就是给那些编号贴上名字。 注意：按下去，机器收到的还是 7 号——名字只是给人看的。

10.2 基本用法

enum Color { red, green, blue };                    // red=0, green=1, blue=2

拆开看这句话：

  • enum —— 关键字，表示「我要定义一个枚举」。
  • Color —— 这个枚举类型的名字。
  • red, green, blue —— 三个枚举量（enumerator），也就是「贴上标签的那几个编号」。

枚举量默认从 0 开始，依次 +1。

💡 「枚举量」是什么？ 就是枚举里列出来的每一个名字（red、green、blue）。 每个枚举量对应一个整数，它不是变量——你不能给 red 重新赋值。

跑 示例代码/04_结构共用体枚举/06_enum.cpp，实测：

red=0 green=1 blue=2
Mon=1 Wed=3 Sun=7
none=0 low=1 high=10 extra=11   <- extra 是 high+1

10.3 自己指定值（教材 4.6.1，p113）

enum Week { Mon = 1, Tue, Wed, Thu, Fri, Sat, Sun };   // Mon=1 .. Sun=7
                       ↑ 后面的自动接着 +1

enum Level { none = 0, low = 1, high = 10, extra };    // extra = 11
                                    ↑ 只指定一部分也行

规则很简单：你给了值就用你给的；没给的，就接着前一个 +1。

💡 为什么要自己指定？ 举个真实场景： 如果这套编号要和别的东西对表（比如某个文件格式规定「1 表示星期一」）， 那就必须显式写出来，不能靠默认从 0 开始。

10.4 枚举量就是整数

实测：

Week today = Wed;
  打印 today 出来是: 3   <- 枚举量打印出来是【数字】，不是名字
  if (today == Wed) 成立
  today + 1 = 4   （Wed 是 3，加 1 得 4）

三个要点：

  1. 打印枚举变量，输出的是数字，不是名字（因为计算机里存的就是数字， 名字在编译完以后就"没了"）；
  2. 可以比较（today == Wed）；
  3. 参与运算时会退化成 int（就是"变回普通整数"的意思）。

10.5 枚举的取值范围与「底层类型」（教材 4.6.2，p113–114）

先说什么叫「底层类型」

枚举本身是个类型，但它内部是用某个整数类型来存值的， 这个「内部真正用来存值的整数类型」就叫底层类型（underlying type）。

💡 比方：遥控器的按键上贴了「音量 +」的标签（枚举量名）， 但按键底下接的还是第 7 号线路（底层类型）。 标签是给你看的，线路是机器真正用的。

取值范围规则

规则（教材讲的）：

上限 = 「大于最大枚举量的最小 2 的幂」减 1
       例：最大是 7   →  2³-1 = 7
           最大是 10  →  2⁴-1 = 15
下限 = 若最小枚举量 ≥ 0，则是 0；否则是 -(2ⁿ - 1)

这条规则算出来的「取值范围」，决定了编译器最少要用多大的整数才装得下这些枚举值。 换句话说：枚举的大小是由"取值范围"倒推出来的，不是由"有几个成员"决定的。 （注意：规则只规定"必须装得下"，并不要求编译器非得选最小的那个类型。 所以下面实测里，取值范围只要 1 的枚举照样占 4 字节。）

实测：

sizeof(Color) = 4 字节
sizeof(Week)  = 4 字节

⚠️ 别假设枚举一定是 4 字节。 同样的枚举换个编译器 / 平台可能不一样。 要精确控制大小，C++11 可以显式写出底层类型：

cpp enum class Priority : unsigned char { low, mid, high }; // 底层类型定为 1 字节

: unsigned char 这一段就是在说「内部请用一个 unsigned char 来存」。

10.6 ⚠️ 一个要注意的地方：名字污染

enum Color { red, green, blue };
enum Other { red, yellow };        // ❌ 报错！red 重定义了

实测报错原文（GCC 8.1.0）：

error: 'red' conflicts with a previous declaration
note: previous declaration 'Color red'

原因：普通 enum 的成员名会跑到外层作用域里 （相当于在全局定义了三个名字 red、green、blue）。 不同枚举想用同一个名字就冲突了。

💡 回到第 1.4 节「作用域」： 普通 enum 的成员名是「跑到大街上喊的名字」， 所以别的地方再喊一次「red」就撞车了。

⚠️ 顺带说一个容易误导的说法：枚举量名冲突不是"值冲突"。 Color::red 和 Other::red 的值都是 0，值一样完全没关系， 真正冲突的是"名字"——编译器不认识两个同名的东西。这一点别记混。

10.7 C++11 的解法：enum class

enum class Direction { north, south, east, west };
Direction dir = Direction::north;      // ⚠️ 必须写 Direction::

Direction::north 里的 :: 读作「的」——「Direction 的 north」。

普通 enum enum class
名字作用域 跑到外层（会冲突） 关在自己里面
转成 int 自动 必须显式 static_cast<int>(dir)
能和 int 直接比较吗 能 不能，要显式转换
打印 直接 cout << today 不能直接打印，要转型

实测：

Direction dir = Direction::north;   <- 必须带前缀
  好处 1：名字不冲突（Color::red 和 Other::red 可以共存）
  好处 2：不会隐式转换成 int，更安全
  代价 1：不能直接打印，要转型：
          cout << static_cast<int>(dir) = 0

💡 static_cast<int>(dir) 是什么？ 就是「请把 dir 这个值当成 int 来用」——一次显式的类型转换。 因为 enum class 故意不允许自动转换（那正是它更安全的原因）， 所以你想要数字时，必须自己开口要。

实测：enum class Color { red, ... }; 和 enum class Other { red, ... }; 同时存在 完全可以编译通过，两者各是各的 red。

📌 推荐：新代码用 enum class。 普通 enum 只在「要和 C 语言的老代码对接」或「教材里的旧写法」时用。 （第 10 章「类作用域」会再讲一次。）

11. 本课常见坑汇总

每条都有实测证据（GCC 8.1.0 / MinGW-w64）：

# 坑 后果
1 结构声明后忘了分号 error: expected ';' after struct definition。GCC 还会把该加的 ; 画出来。是一条清晰的错误，不会级联出一堆
2 以为「声明结构」就分配了内存 不分配。Student 是类型，Student s1; 才是变量
3 初始化时成员顺序写反 成员类型各不相同时：编译报错（编译器替你挡住了）。成员类型完全相同时：编译器一声不吭，数据悄悄错（最危险）
4 student.name 写成了 student->name -> 是给指针用的（第 4 章 C 讲），现在用不上
5 以为结构不能整体赋值 可以。p2 = p1; 合法（数组不行，invalid array assignment）
6 写成 group[i.score] 错。应该是 group[i].score（先下标，后点）
7 位字段溢出没注意 有 -Woverflow 警告，值被截断（40 → 8）
8 对位字段成员取地址 &d.day 编译错误
9 读 union 里「不是最后写入」的成员 不报错，但给你垃圾值
10 两个 enum 用了同名成员 error: 'red' conflicts with a previous declaration
11 用 enum class 却忘了写前缀 north 未定义，必须写 Direction::north
12 直接 cout << 一个 enum class 变量 编译错误，要先 static_cast<int>
13 拿 sizeof(结构) 当固定值用 里面有对齐空隙，换个编译器 / 平台会变
