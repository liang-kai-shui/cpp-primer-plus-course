第 6 章讲义：分支语句和逻辑运算符

教材：《C++ Primer Plus（第 6 版）》第 6 章，PDF 第 183–219 页（书页 165–201）；正文 183–215，复习题 216–217，编程练习 217–219。 先修：L08 的循环和读取成功判断，L04 的字符串与混合输入，L05 的枚举。 目标：写出互斥且完整的条件分支，理解短路求值，处理错误输入，读写简单文本文件。 材料说明：按原书 6.1–6.8 编写；课程示例独立实现，原书程序清单 6.1–6.16 可对照。示例使用 C++17；字符分类按单字节英文文本讲解。

1. if：程序到这里，选哪条路

以前的程序顺着往下走，现在要根据数据决定动作。分支就是“满足条件走一条路，否则走另一条路”，像根据天气决定是否带伞。

if (score >= 60) {
    std::cout << "Pass\n";
} else {
    std::cout << "Try again\n";
}

条件先转换为真假；真执行 if 块，假执行 else 块，只选一边。没有 else 时，条件为假就跳过这块。和循环一样，花括号决定范围，缩进不决定。

多个 if 与 else if 是两种需求

if (score >= 90) { /* A */ }
else if (score >= 80) { /* B */ }
else if (score >= 60) { /* C */ }
else { /* D */ }

这里按顺序检查，命中第一个真条件后，后面的分支不再检查。把阈值从高往低排：若先检查 >=60，95 分也会立刻进入最低通过档。

两条独立的 if 会各自检查，可能都执行。例如一个数字既大于 0 又为偶数，两个提示都需要显示，就用独立 if。只允许选一个等级，使用 else if 链。

嵌套条件中，没有花括号的 else 会匹配最近的尚未匹配的 if；不要靠缩进猜。课程代码统一给分支加花括号，先让结构清楚。

输入分数应先检查读取成功，再检查 0–100 的范围。类型正确不等于业务范围正确：-5 能读成整数，但不是有效分数。

2. 逻辑运算：把问题拆成几个条件

&& 是“并且”，两边都真才为真；|| 是“或者”，至少一边真就为真；! 是“取反”。它们像门禁规则：证件有效并且预约有效，才能进入。

A B A && B A || B
假 假 假 假
假 真 假 真
真 假 假 真
真 真 真 真

判断闭区间应写 low <= value && value <= high。数学里的 low <= value <= high 在 C++ 中先把第一个比较算成 bool，再用 0 或 1 与 high 比较，意思完全不同。

bool in_range = 10 <= value && value <= 20;
bool quit = command == 'q' || command == 'Q';

command == 'q' || 'Q' 是错误条件：第二部分只有非零字符值，它本身就为真；两边必须各写完整比较。

短路求值：有时右边根本不执行

短路就是左边已经足以确定结果时，省掉右边的计算：

  • A && B：A 为假，不执行 B。
  • A || B：A 为真，不执行 B。

顺序很关键：denominator != 0 && 12 / denominator > 2 先排除除数为 0，再做除法。反过来就失去保护。数组访问也应先检查下标范围，再读元素。

int calls = 0;
bool result = false && (++calls > 0); // calls 仍为 0

示例 02 打印右边是否发生，帮助你看见短路。它适用于这里的内置逻辑运算符；不要拿按位 & / | 替代 && / ||，两类运算的目的和求值规则不同。

优先级、取反和另一套拼写

关系比较通常先于 &&，&& 先于 ||。仍建议对混合条件加括号，例如 (age >= 18 && has_ticket) || is_staff。

!n 得到 bool，并非把数字改成相反数；!!7 为 true，不会恢复为整数 7。!(a && b) 等价于 !a || !b，!(a || b) 等价于 !a && !b，可用于检查“全部通过”与“有一项失败”。

原书 6.2.6 的 and、or、not 是 &&、||、! 的替代拼写，C++ 中不需额外头文件。本课程统一用符号，以便对照常见代码。

3. cctype：判断字符，先明确输入范围

字符分类函数替你判断“这是字母吗、数字吗、空白吗”。不必每次写一串字符范围比较，像把逐项检查交给一个分类员。

<cctype> 函数 用途
std::isalpha 是否为字母
std::isdigit 是否为数字字符
std::isspace 是否为空白，如空格、换行、制表符
std::isalnum 是否为字母或数字
std::ispunct 是否为标点
std::islower / std::isupper 是否为小写 / 大写字母
std::tolower / std::toupper 转小写 / 大写，不能转换的字符保持不变

分类函数返回整数，非零表示真，不应硬写 isalpha(ch) == 1。

当字符已放在 char 中，安全用法是先转换为 unsigned char 再传入：

unsigned char byte = static_cast<unsigned char>(ch);
if (std::isalpha(byte)) {
    char upper = static_cast<char>(std::toupper(byte));
    std::cout << upper;
}

原因是有的平台 char 带符号，高位字节可能成为负数；这些函数要求参数是能用 unsigned char 表示的值，或 EOF。无参数 get() 返回值要先检查 EOF，再按字符处理，不能把 EOF 转成 unsigned char 后当正文。微软字符分类函数的参数说明

本课不改变区域设置，示例按常见英文字符分类。std::string 里的 UTF-8 中文可能由多个字节组成，逐字节 isalpha 不是中文分词或 Unicode 字符分类。

4. ?:：只在两个值中选一个

条件运算符的格式是 条件 ? 真时表达式 : 假时表达式，它产生一个值；只求值被选中的那一边。

int larger = a > b ? a : b;
std::cout << (score >= 60 ? "Pass" : "Fail");

第二行的括号帮助明确输出的是整个选择结果。若分支中要做多件事或条件很长，用 if...else 更易读；不必为省行数套多层 ?:。

5. switch：按离散命令选择动作

如果输入只可能是 'c'、'p'、'q' 等菜单命令，一串相等比较可以改为 switch，像按按钮编号找到对应功能。

switch (command) {
case 'c':
case 'C':
    std::cout << "Continue\n";
    break;
case 'q':
case 'Q':
    std::cout << "Quit\n";
    break;
default:
    std::cout << "Unknown command\n";
}

匹配到一个 case 后从那里开始执行，不会自动在下一个 case 停下。break 才离开 switch；default 处理没有匹配的输入。两个大小写 case 连续写、共用一个动作，是有意合并分支；执行完一个动作却忘写 break，常是错误。

条件通常是整数、字符或枚举值；case 标签是不同的编译期整型常量。不能直接 switch(std::string)，也不能写 case score >= 60: 表示区间。区间用 if，若干固定值用 switch。

L05 的枚举值可作标签：示例 05 先把字符命令转换成 enum Action，再切换枚举。若在某个 case 中声明局部变量，可用 { ... } 为它划出自己的块，避免跨 case 的初始化问题。

6. break 与 continue：影响哪个结构

break 离开最内层循环或 switch，像提前结束这场比赛；continue 结束本次循环体的剩余动作，继续下一轮，像跳过一个不符合要求的样本。

int number;
int sum = 0;
while (std::cin >> number) {
    if (number == 0) break;
    if (number < 0) continue;
    sum += number;
}

输入 5 -2 7 0 100，只累计 5 和 7，得到 12。循环被 0 结束，100 不再读取处理。

在 for 中 continue 会转到更新表达式，然后检查条件；在 while 中转到条件。因此若 while 的更新放在体尾，却在它之前 continue，可能不更新并陷入死循环。

嵌套 switch 中的 break 只离开 switch，不会顺带离开外层菜单循环。示例 05 另用 running 控制外层循环，收到退出命令就设为 false。

7. 数字输入：失败是状态，需要处理

std::cin >> number 尝试把输入解释成数字。如果用户输入 hello，提取失败，流进入失败状态；此后直接继续读，通常仍会失败。像录入系统卡在一条无法解析的记录上，必须先恢复状态再移走这条记录。

示例 07 接受 0–100 的整数，不合格就重新询问；EOF 正常结束。

int number;
if (!(std::cin >> number)) {
    if (std::cin.eof()) { /* 输入结束 */ }
    else if (std::cin.bad()) { /* 底层读取错误 */ }
    else {
        std::cin.clear();
        std::cin.ignore(std::numeric_limits<std::streamsize>::max(), '\n');
        // 重新询问；先 clear，再 ignore
    }
}

clear() 清除状态标志，不会自动删掉缓冲区里的错误文字；ignore 丢弃到行尾，需要 <limits>。这里只忽略出错的那一整行，所以 hello 80 的 80 也被放弃，下一行再输入。

原书 6.7 还示范“遇到非数字就结束”的输入循环；这是另一种明确的结束约定，不一定需要纠错。选择停止还是重问，取决于程序任务。

注意：格式化提取可读取合法的数字前缀，输入 12abc 时可能先读到 12，剩下 abc 影响下一次读取。示例 07 不是整行格式校验器。如果要严格要求整行只有一个整数，可先 getline 再解析；完整流工具在第 17 章再展开。

流转 bool 不等于 good()

流用作条件，检查的是没有 failbit 或 badbit；good() 则要求所有状态位都未设置。成功读到最后一个数字时，可能同时到达 EOF：数字有效，流转 bool 仍为真，但 good() 已为假。原书在文件示例附近将两者作简化等同，本课采用 while (in >> value)，避免漏掉末尾没有换行的最后一个数字。标准的流状态定义

8. 文件输入输出：换一个数据来源

终端关闭后，变量里的数据就没了。文件流让程序把数据写到磁盘，或从磁盘读入；可以把它理解为 cout / cin 换了一根连接到文件的管道。需要 <fstream>。

std::ofstream out("numbers.txt");
if (!out) { /* 打开失败，停止 */ }
out << 10 << '\n' << 20 << '\n';

ofstream 默认打开普通输出文件时会截断已有内容；本课只写示例文件 course_numbers.txt，不要把路径换成自己的重要文件。若要追加，显式使用 std::ios::app，追加是否合适由数据格式决定。

相对路径从程序的当前工作目录出发，不是自动从 .cpp 所在目录出发。在课程根目录编译运行，生成文件就在课程根目录；从其他目录启动同一个 exe，文件位置可能不同。用 Get-Location 确认所在目录，调试配置也可能指定工作目录。

示例 08 写入 10、20.5、−3，然后显式 close 并检查状态；即使打开成功，也仍可能在写入或关闭时失败。局部文件流通常在离开作用域时自动关闭，显式关闭便于本课检查结果。

读取、累计与区分结束原因

std::ifstream in(filename);
if (!in.is_open()) { /* 文件不存在或无法打开 */ }
double value;
while (in >> value) {
    total += value;
    ++count;
}

不要写 while (!in.eof()) 先进入体内，再读取。也不要在 while(in >> value) 后再把最后一次 value 累加，读取失败时它不是新的有效数据。

停止后区分：bad() 是底层读取错误；eof() 通常表示到达文件末尾；否则 fail() 可能意味着遇到非数字。它们是状态位，可以同时存在。这里接受由空白分隔的普通有限十进制数；示例 09 发现非数字就报告失败，不伪装成完整统计。

本课解析仍采用格式化提取：如果末尾出现一个不完整数字，比如只有 1e，可能同时设置 failbit 和 eofbit，单看 EOF 无法证明整份文本格式严格正确。严格格式验证留待后续；练习至少用 10 bad 20 检验非数字路径。

没有有效数据时，不计算 total / count，否则除数为 0。空文件应显示 count=0、No data。

先运行写入程序，再运行读取程序，输入 course_numbers.txt，应得到数量 3、合计 27.5、平均约 9.16667。文件名用 getline 读取，允许路径含空格。也测试空文件、不存在的文件、文件最后一个数字后没有换行。

9. 过关标准

  • [ ] 能解释独立 if 和 else if 的区别，正确覆盖边界值。
  • [ ] 能写完整的区间和大小写退出条件，说出短路跳过哪一边。
  • [ ] 字符分类前处理 char 的符号问题，不把 EOF 当正文。
  • [ ] 菜单处理非法命令，退出时确实结束外层循环。
  • [ ] 能解释 clear 与 ignore 各自做什么，EOF 不会触发无限重问。
  • [ ] 能读写文本文件，正确处理空文件和没有末尾换行的数据。
