第 0 部分 · 零基础补白：数组到底是什么

这一节是给零基础读者的地基。 如果你已经知道"什么叫数组、什么叫下标"，可以跳到第 1 节。

0.1 先说一个真实的难题

假设老师让你写个程序，存一个学生 5 门课的成绩。你可以这样写：

int score1, score2, score3, score4, score5;

但如果要存 100 个学生的成绩呢？ 写 100 个变量名？不可能。

而且这 100 个变量名之间毫无联系，你想"把所有人的成绩加一遍"都写不出来—— 你只能老老实实写 100 行 sum = sum + scoreNN;。

数组就是来解决这个问题的：

数组（array）：一组同类型的、在内存里连续存放的变量， 它们共用一个名字，靠下标（也叫索引）区分彼此。

打个比方——一排连号的储物柜：

普通变量 数组
像什么 一栋独栋房子，有自己的门牌号 一排连号的储物柜
共同点 — 所有柜子一样大（同类型）、紧挨着（连续内存）
怎么找 用名字 用柜子所在的那一排的名字 + 柜门号：scores[3]

一排 5 个柜子、名字叫 scores，柜门号就是 0 1 2 3 4：

第 0 号柜   第 1 号柜   第 2 号柜   第 3 号柜   第 4 号柜
  90         85         78         92         88
 scores[0]  scores[1]  scores[2]  scores[3]  scores[4]

为什么这个比方好用？ 因为它顺便解释了后面所有的坑：

  • 柜门号从 0 开始数 → 下标从 0 开始；
  • 柜子数量必须装修时就定好，不能住进去再改 → 数组大小必须是编译期常量；
  • 你拿第 7 号柜门的钥匙，去开一个只有 5 个柜子的柜子 → 数组越界；
  • 你跑到柜子外面去翻别人的东西 → 越界访问会拿到不属于你的数据，甚至弄坏别人的东西。

0.2 补一句：什么是"内存""地址"

后面会反复提到"内存""地址"，这里先用人话解释一遍。

  • 内存（memory）：计算机里一长排极小的格子，每个格子只能存 0 或 1。
  • 地址（address）：每个格子的门牌号（一个数字，通常用十六进制写，比如 0x61fe30）。 程序想知道"东西放在哪"，靠的就是这个号。
  • 字节（byte）：8 个格子打包成一组，是内存里最小的"取用单位"。 一个 int 通常占 4 字节，也就是 4 组这样的格子。

所以"数组在内存里连续存放"的意思是： 5 个 int 占 20 字节，它们住在门牌号连着的 20 个字节里 （第 1 个从 0x61fe30 开始，第 2 个就在 0x61fe34——正好差 4 字节）。

这一点是可以当场看到的。 跑一下 示例代码/04_数组与字符串/01_array_basics.cpp，它会打印每个元素的地址：

5 个成绩：90 85 78 92 88

sizeof(scores)      = 20 字节
sizeof(scores[0])   = 4 字节
所以元素个数 = 5

各元素的内存地址（注意每个差 4 字节 = sizeof(int)）：
  scores[0] 的地址 = 0x61fe30
  scores[1] 的地址 = 0x61fe34
  scores[2] 的地址 = 0x61fe38
  scores[3] 的地址 = 0x61fe3c
  scores[4] 的地址 = 0x61fe40
  ^ 连续！这就是「数组」这个名字的由来

📌 不用背上面这些地址（每次运行都不一样），只要记住它们是一个挨着一个的就够了。 后面理解"下标是什么""指针是怎么回事"，全靠这个事实。

0.3 本课出现的新词（先混个眼熟）

看到术语就懵是正常的。下面这些词本课都会第一次出现，每个词在第一次出场时都会有白话解释， 这里先列个清单让你心里有数：

名词 一句话解释
下标 / 索引 柜门号。第几个元素，从 0 开始数
偏移量 "离起点走了几格"。下标其实就是偏移量
编译期常量 程序还没运行、编译器就已经知道值的量（比如 const int kSize = 4;）
缓冲区 一块临时堆放输入数据的小盆。键盘敲的字先掉进这个盆，程序再从盆里取
字符串字面量 代码里用双引号直接写出来的那段文字，比如 "hello"
转义字符 用 \ 开头、表示"没法直接打出来的字符"的写法，比如 '\0'、'\n'
未定义行为 C++ 标准没规定结果的操作。可能没事、可能算错、可能崩溃——三种都可能
栈空间 程序给函数里的局部变量预留的一块内存区域（本课只需要知道"数组住在这里"）
垃圾值 一块没人清理过的内存里原来的东西。不是 0，也不是随机数，就是"上一个住户留下的"

1. 数组的声明与访问（4.1，p87–90）

1.1 语法：三件事

类型  名字[元素个数];        // 声明：开一排柜子
名字[下标] = 值;             // 赋值：往某个柜子里放东西
名字[下标]                   // 取值：把某个柜子里的东西拿出来

int scores[5];              // 声明：5 个 int
scores[0] = 90;             // 第一个元素的【下标是 0】
scores[1] = 85;
scores[2] = 78;
scores[3] = 92;
scores[4] = 88;             // 最后一个元素的下标是 4 = 5-1

✅ int scores[5]; 这句话要这样读： 「给我 5 个能装整数的柜子，这一排柜子叫 scores」。 注意 [5] 里写的是柜子的个数，不是"最后一个柜门号"。

1.2 ⭐ 铁律一：下标从 0 开始

5 个元素的数组，合法下标是 0 1 2 3 4，没有 5。

这是初学者最容易犯错的地方，而它背后有个非常合理的原因：

下标其实表示"偏移量"——也就是"离起点走了几格"。

内存里的样子（每个格子 4 字节）：

  scores:  [ 90 ][ 85 ][ 78 ][ 92 ][ 88 ]
  偏移量:    0     1     2     3     4
  下标:      0     1     2     3     4
             ↑
        scores 这个名字，代表【这一排柜子的起点位置】
        scores[3] 的意思是：从起点【往后走 3 格】，打开那个柜子

所以 scores[0] = "往后走 0 格" = 第一个元素。下标就是"距离起点的距离"：

  • 第 1 个元素 → 偏移 0（一步都不用走）
  • 第 n 个元素 → 偏移 n − 1
  • 最后一个元素（一共 len 个）→ 偏移 len − 1

💡 这个理解在后面学指针时会变得极其重要： 数组名 scores 本质上代表"第一个元素的地址"（地址就是门牌号，见 0.2）， 而 scores[i] 等价于 *(scores + i)——"从那个门牌号往后走 i 格，然后打开柜子取东西"。 这就是下标从 0 开始的真正原因。

📌 这一条考试很爱考，而且"差一"是最高频的错误： 题目问"第 2 个元素"，写 ideas[2] 是错的，正确是 ideas[1]。 复习题第 4、5 题考的就是这个，答案里有一张专门的对照表。

1.3 铁律二：数组大小必须是编译期常量

const int kSize = 4;
int good[kSize];            // ✅ 合法：kSize 是编译期常量

int n;
cin >> n;
int bad[n];                 // ❌ 标准 C++ 不允许"变长数组"

先解释一下"编译期常量"是什么： 程序从一段文字变成能运行的程序，要经过两步——先编译（编译器把你的代码翻译成机器能懂的指令）， 再运行。编译期就是"还没运行的那一步"。 编译期常量就是"编译器在翻译的时候就已经知道它的值、并且这个值不会再变"的量。

为什么数组大小必须是编译期常量？ 因为数组要在编译的时候就确定"要占多少内存、住哪一段地址"，编译器得提前把位置排好。 n 要等程序跑起来、用户敲了键盘才知道，编译器没法提前给它预留位置。

📌 如果大小真的非要等运行的时候才知道，怎么办？ 用 new（第 4 章 C 讲）或 std::vector（第 4 章 D 讲）。 这两个是本章后面要介绍的"数组替代品"。

⚠️ 一个容易误导人的细节（实测过）： 有些编译器（比如本机用的 GCC/MinGW）默认会把变长数组当扩展放行， 所以 int bad[n]; 可能编译通过、还能跑对。 但这不代表它合法——换一个编译器（比如 MSVC）或者加上 -pedantic-errors 就会直接报错。 写标准 C++ 就别这么写。

1.4 铁律三：数组没有边界检查（教材 4.1 p89 / 4.10 p122）

这是 C++ 最著名的坑。 scores[i] 只是"起点地址 + 往后 i 格"的算术， 它完全不检查 i 是否越界——就像储物柜管理员根本不查你的钥匙对不对。

跑 示例代码/04_数组与字符串/03_array_no_bounds_check.cpp，你会看到：

合法范围：squares[0] ~ squares[4]
squares[4]   = 25   (合法，最后一个)
squares[5]   = 0   <- 越界读，垃圾值
squares[100] = 0   <- 越界 100 个，垃圾值
  ^ 不报错、不崩溃，只是给你一块【不属于你的内存】的内容

注意这里的现象：越界读出来的两个值都是 0。 它们不是"数组的下一个元素"（数组根本没有第 6 个元素）， 而是那块内存里碰巧躺着的东西。这次是 0，下次可能是别的数—— 这就是"未定义行为"的意思：C++ 标准不规定会发生什么。

先解释一下"垃圾值"：内存就像一块可以反复擦写的白板。 你声明 int a[3]; 时没有给它初值，白板上上一个程序留下的字迹还在， 你读出来的就是那些旧字迹。它不是 0，也不是随机数，就是"上一个住户留下的"。

更可怕的是"写越界"——它会破坏别的变量的数据：

内存布局（示意）：
  [scores[0]][scores[1]][scores[2]][scores[3]][scores[4]][ 别的变量 ]
                                        ↑
                              你写 scores[5] = 100
                              就把「别的变量」给改了！

🔁 通用对照：如果你做过第 1 章「错误分类实验」里的 E（数组越界）， 当时 a[3]（数组只有 3 个元素）输出了 1 2 3 3，退出码还是 0，看起来"一切正常"。 那就是越界读——和上面 squares[5] 是同一件事。

先解释一下"未定义行为（undefined behavior）"： 它不是说"程序一定会崩"，而是说 C++ 标准没有规定这里应该发生什么。 所以编译器可以随便处理：可能没事、可能算出莫名其妙的结果、可能崩溃、可能今天是好的明天就坏了。 看到"未定义行为"四个字，就当它是"随时可能爆炸的地雷"，不要去赌。

教材 p122 讲了解决办法：vector 和 array 对象提供了成员函数 at()：

a2.at(1) = 2.3;      // 安全版本：会检查下标
a2[1]    = 2.3;      // 中括号版本：不检查

at() 会在运行的时候发现非法下标、并中断程序（报一个异常，比默默改坏数据好得多）。 代价是慢一点点——这就是 C++ 给你两种选择的原因："不为你不需要的东西付费"。

🛡️ 本课你要养成的三个习惯 1. 循环遍历数组，老老实实写 i < n，别写 i <= n（这是最高频的低级错误）； 2. 需要安全访问时用 vector 的 .at()； 3. 拿不准的时候，用下面 1.5 的办法把数组长度"算"出来，而不是手写一个数字。

1.5 一个好用的技巧：用 sizeof 求数组长度

写 for (int i = 0; i < 5; ++i) 的时候，那个 5 是手写的。 哪天你把数组改成 8 个元素，却忘了改循环里的 5，就立刻越界了。

C++ 里经典的求数组长度写法是：

int len = sizeof(scores) / sizeof(scores[0]);   // 20 / 4 = 5

意思很好懂：

  • sizeof(scores) = 整个数组占多少字节（5 × 4 = 20）；
  • sizeof(scores[0]) = 一个元素占多少字节（4）；
  • 两者一除，就是元素个数。

（sizeof 到底是什么，下一节就会讲清楚。）

2. 数组的初始化规则（4.1.2–4.1.3，p90–91）

跑 示例代码/04_数组与字符串/02_array_init_rules.cpp，六条规则：

# 写法 结果
1 int a[3]; 垃圾值（内存里上一个住户留下的东西）
2 int a[5] = {1, 2}; 1 2 0 0 0 ← 剩下的自动补 0 ⭐
3 int a[5] = {0}; 0 0 0 0 0 ← 全部清零的常用技巧
4 int a[] = {1,2,3,4}; 编译器自己数出 4 个
5 int a[3]{7,8,9}; C++11：可以省略等号；int a[3]{}; 全 0
6 int a[kSize]; 大小必须是编译期常量

实测输出：

int a1[3];                -> 0 66 0   <- 垃圾值（每次运行可能不同）
int a2[5] = {1, 2};       -> 1 2 0 0 0   <- 后面三个自动变 0！
int a3[5] = {0};          -> 0 0 0 0 0   <- 全部是 0
int a4[] = {10,20,30,40}; -> 编译器数出 4 个元素
int a5[3]{7, 8, 9};       -> 7 8 9
int a6[3]{};              -> 0 0 0  (全 0)

⚠️ 规则 2 特别重要：{1, 2} 只给了两个值，剩下的三个自动是 0。 很多新手以为剩下的是垃圾值——不是。 只有"完全不初始化"（规则 1）才是垃圾值。

"只给一部分值"叫部分初始化。 规则是： 只要你写了 = {...}，没写到的元素一律被填 0；一个都不写，才是不清理。

顺带一个实用结论：想快速把整个数组清零，写 int a[100] = {0}; 就行—— 只要写了 {0}，后面 99 个也会被填 0。这是最常用的清零技巧。

📌 规则 5 的 int a[3]{}; 是 C++11 才有的写法（花括号替代等号加初值）。 看到它不要惊讶，它和 int a[3] = {}; 是一回事，都是"全部清零"。

2.1 ⭐ 一个必须知道的事实：数组不能整体赋值

int a[3] = {1, 2, 3};
int b[3];
b = a;                  // ❌ 编译错误！

实测报错（教科书式的一行）：

error: invalid array assignment

为什么？ 因为 C++ 里数组不是"一个值"，它是"一串变量共用一个名字"—— 就像"一排柜子"不是一个能搬走的东西。

a 这个名字在大多数场合会退化成"第一个元素的门牌号（地址）"， 而"给一排柜子赋值"这件事在语法上根本没有意义，所以编译器直接拒绝。

📌 "退化成地址"是什么意思？ 名字 a 本来代表"整排柜子"，但 C++ 规定：在大多数用到它的地方，它会被当成"第一个柜子的门牌号"来用。 这个"从一整排降级成一个门牌号"的过程，就叫退化（decay）。 本课只需要知道有这么回事，第 4 章 C 讲指针时会彻底讲透。

想复制数组内容，只能逐个元素复制（或者用 memcpy）：

for (int i = 0; i < 3; ++i) b[i] = a[i];      // ✅ 这样才行

💡 这也正是 std::string 和 vector 存在的理由之一—— 它们可以直接赋值，因为它们内部帮你处理了这件事（见第 7 节）。

3. ⭐⭐ C 风格字符串的本质（4.2，p91–94）—— 本课最重要的概念

3.1 一句话定义

C 风格字符串 = 以 '\0' 结尾的 char 数组。

这里的每个词都要拆开讲：

  • char：专门用来存一个字符的类型（'a'、'5'、' ' 都是 char）。
  • char 数组：一排 char 柜子，比如 char s[100]; 是 100 个格子，每个格子放一个字符。
  • '\0'：一个特殊的字符，它的数值是 0（不是字符 '0'，那个的数值是 48）。
  • "以 '\0' 结尾"：这一排格子里，有效字符后面必须紧跟着放一个 '\0'。

先解释一下"转义字符"是什么。 有些字符你没法直接写在代码里——比如"换行"，你总不能真的在引号中间敲一下回车吧？ 于是 C++ 规定：用 \ 开头写一个代号。这类写法就叫转义字符。常用的有：

写法 含义 数值
'\n' 换行 10
'\t' 制表符（Tab） 9
'\0' 字符串结束标记 0
'\\' 一个反斜杠本身 92

所以 '\0' 读作「反斜杠零」，它是一个字符，但在内存里存的数值就是 0。

3.2 为什么需要 '\0'？

因为数组不知道自己的内容有多长！

char s[100];         // 100 个字节的空间
strcpy(s, "hello");  // 只用了 5 个字符

现在问题来了：读 s 的时候，怎么知道该读到第 6 个字节就停？ 数组本身只知道"我有 100 格"，不知道"我装了 5 个字符"。

所以 C/C++ 定了一个约定：

在有效字符后面放一个数值为 0 的特殊字符 '\0'， 读到它就说明"字符串到此结束"。

char s[100] = "hello";

  'h' 'e' 'l' 'l' 'o' '\0'  ?  ?  ?  ...
   ↑                    ↑
  s[0]                 s[5]  <- 结束标记
  （后面那些格子没用到，内容是垃圾）

打个比方：'\0' 就是一句话末尾的句号，告诉程序"到此为止"。

  • 没有句号，读的人就不知道这句话在哪儿结束，会一直往下念，念到别人的稿子上；
  • 有了句号，读到它就知道"这句完了"。

这也是为什么下面这件事会发生：

char s[5];                 // 只有 5 格
s[0] = 'h'; s[1] = 'e'; s[2] = 'l'; s[3] = 'l'; s[4] = 'o';
cout << s;                 // ❌ 危险！没有 '\0'，它会一直往后念

3.3 ⭐ 字符数组 ≠ 字符串

跑 示例代码/04_数组与字符串/04_cstring_basics.cpp：

char dog[8] = {'b','e','a','u','x',' ','I','I'};    // ❌ 没有 '\0'，不是字符串
char cat[8] = {'f','a','t','e','s','s','a','\0'};   // ✅ 有 '\0'，是字符串

用逐个字符的方式初始化数组时，编译器不会自动帮你加 '\0'。 dog 没有结束标记，所以 cout << dog 会一直往后读，直到碰巧遇到某个 0 才停。

实测输出：

char dog[8] = {'b','e','a','u','x',' ','I','I'};  (无 \0)
  当成字符串输出 -> beaux II   <- 后面是垃圾内容，因为找不到结束标记

char cat[8] = {...'a','\0'};  (有 \0)
  当成字符串输出 -> fatessa   <- 正常

⚠️ 这里有一个"看起来很正常"的陷阱，特别值得说清楚。

dog 打印出来的刚好是 beaux II——8 个字符一个不多一个不少，看起来完全正常。 但它是错的：dog 里根本没有 '\0'，程序只是运气好， 读到第 9 个字节时那里恰好是 0 才停下来。

换台机器、换个编译器、甚至同一台机器上改动一下别的代码，输出就可能变成一串乱码。 这就是"未定义行为"最讨厌的地方：它不一定当场出错，而是让你以为代码是对的。

判断标准永远是"数组里有没有 '\0'"，不是"这次打印得对不对"。

记住：是 '\0' 让一个 char 数组成为"字符串"。

3.4 字符串字面量自动带 '\0'

先解释一下"字符串字面量"：代码里用双引号直接写出来的那段文字，比如 "bubbles"。 叫"字面量"是因为它就"字面上摆在那里"，是一个写死的值。

char fish[] = "bubbles";        // 用双引号初始化，编译器会自动加 '\0'

用双引号初始化（而不是用 {...} 逐个字符写），编译器会自动补上 '\0'。 这也是最省事、最不容易漏的写法。实测：

sizeof(fish) = 8      <- 7 个字母 + 1 个 '\0'
strlen(fish) = 7      <- 只数有效字符

★ 考试最爱考的考点：sizeof vs strlen ★

先解释这两个东西是什么：

  • sizeof 是一个运算符（不用 #include 任何东西）， 它问的是"这个东西占多少字节"。它在编译期就把答案算好了。
  • strlen 是一个函数（住在 <cstring> 头文件里，得先 #include <cstring>）， 它问的是"从这串字符的开头数起，到 '\0' 之前有几个字符"。它得运行的时候一个一个数。
sizeof strlen
是什么 运算符，编译期求值 函数（在 <cstring> 里），运行时数
数什么 数组占的总字节数 有效字符数，不含 '\0'
"bubbles"（char fish[] = "bubbles";） 8 7
对 int arr[10] 40（10×4） 无意义（只能用于字符串）

两者永远差 1（对字符串而言）——因为 sizeof 把结尾的 '\0' 也算上了， 而 strlen 明确不含 '\0'。

一句话记忆：sizeof 量的是柜子有多大，strlen 数的是柜子里装了几个字。

3.5 陷阱：数组太小放不下 '\0'

char bad[4] = "abcd";      // ❌ "abcd" 需要 5 个字节（4 个字母 + '\0'）

C++11 起编译器直接报错：

error: initializer-string for array of chars is too long [-fpermissive]

所以安全的做法是：数组大小 ≥ 字符数 + 1。 或者干脆用 std::string（第 7 节）。

📌 这个错误比它看起来的好：编译器直接拦住了你，总比运行时偷偷改坏别人的数据强。 凡是编译器能拦住的错误，都是好错误。

3.6 ⭐ 埋一个引子：数组名参与算术时，代表的是地址，不是内容

这一小节只是埋个引子，第 4 章 C（指针那一课）会彻底讲透。现在只要看懂现象。

char letter_grade[5] = "B";

cout << letter_grade;          // 输出：B
cout << letter_grade + 1;      // 输出：（空字符串！）

为什么 letter_grade + 1 不是"内容加一"、也不是 C？

因为数组名 letter_grade 在参与算术时，代表的是"第一个字符所在的门牌号（地址）"， 而不是"数组里装的内容"。

  • letter_grade 代表 'B' 所在的那个门牌号；
  • letter_grade + 1 代表"往后挪一格"的那个门牌号；
  • 而 "B" 这个字符串在内存里是 'B' 后面紧跟着 '\0'：
  letter_grade[0]  letter_grade[1]
       'B'              '\0'
        ↑                 ↑
   letter_grade    letter_grade + 1

所以 letter_grade + 1 指向的是 '\0' 所在的位置， cout 从这个位置开始打印——第一个字符就是结束标记，于是它打出了一个空字符串。

"内容加一"的正确写法是给某个元素加：

letter_grade[0] = letter_grade[0] + 1;   // ✅ 'B' 变成 'C'（char 本质就是小整数）

📌 第 4 章 C 会讲清楚：为什么数组名会"退化成地址"、 为什么 letter_grade[i] 和 *(letter_grade + i) 是一回事。 现在记住结论就行：数组名参与算术 = 挪门牌号，不是改内容。

4. 字符串输入：三种方式（4.2.3–4.2.4，p94–98）

跑 示例代码/04_数组与字符串/05_string_input.cpp 对照着看。

方式 行为 换行符 能限长吗
cin >> s 遇空白符（空格 / Tab / 换行）就停 留在队列里 ❌ 不能（危险！）
cin.getline(s, n) 读一整行 丢弃 ✅ 最多 n−1 个字符
cin.get(s, n) 读一整行 保留 ✅ 最多 n−1 个字符

先解释两个词：

  • 空白符：看不见的"分隔符"，包括空格、Tab、换行。 它们的共同点是"看起来是一片空白"，程序用它们来区分"一个词说完了"。
  • 输入队列 / 缓冲区："缓冲区"就是一块临时堆放输入数据的小盆。 你从键盘敲进去的字，不是直接被程序取走的，而是先掉进这个盆里； 程序再从盆里一个一个取。盆里剩下的东西，会影响下一次取。 （水龙头一直开着，盆里的水没人接就会留着——这就是本课所有"奇怪现象"的总根源。）

4.1 cin >> s 的两个问题

char name[20];
cin >> name;              // 输入 "Li Ming"
// name 里只有 "Li"
  1. 遇空格就停 —— 读不到带空格的名字（只拿到第一个词）
  2. 不能限制长度 —— 如果用户输入 100 个字符，而数组只有 20， 它照样往后写 → 缓冲区溢出

⚠️ 什么是"缓冲区溢出"？为什么它是最危险的坑？

缓冲区就是上面那个"接水的盆"，在这里指 char name[20] 这 20 个格子的空间。 缓冲区溢出就是：往一个 20 格的盆里倒了 100 格的水，多出来的 80 格溢到了桌子上 ——也就是写到了数组后面的内存里，把别人的数据覆盖掉了。

最危险的地方在于：它可能不崩溃、看起来还正常。 实测（本机 g++ 8.1.0）：

cpp char name[20]; cin.getline(name, 80); // ❌ 第二参数必须 ≤ 数组大小！

这段代码用 -std=c++17 -Wall -Wextra 编译一个警告都没有； 输入 60 个字符，程序正常跑完、没有崩溃。 但此时数组后面的内存已经被写坏了——今天是别的变量被改，明天可能是程序崩溃， 后天可能是段错误。这就是它比"直接报错"危险得多的原因。

✅ 正确写法：第二个参数必须 ≤ 数组大小（习惯上直接写数组大小）：

cpp char name[20]; cin.getline(name, 20); // ✅ 最多读 19 个字符，剩下 1 格留给 '\0'

记住这条规则：cin.getline(数组, n) 里的 n 绝对不能大于数组的真实大小。 因为函数只信你给的这个数字，它不会去查数组到底多大。

4.2 cin.getline(s, n) —— 最省心的选择

char name[20];
cin.getline(name, 20);    // 最多读 19 个字符，剩下的空间留给 '\0'
  • 读一整行（空格也读进来）
  • 自动丢掉结尾的换行符 → 下次读输入不会被干扰
  • 自动加 '\0' → 保证结果一定是合法字符串

为什么最多是 n−1 个字符？ 因为要留一格放 '\0'。 cin.getline(name, 20) = "这排柜子有 20 格，你最多往里放 19 个字，最后一格我要留着放句号"。

4.3 cin.get(s, n) —— 差别就在换行符

char a[20], b[20];
cin.get(a, 20);           // 读完 "Li Ming"，但换行符【还留在盆里】
cin.get(b, 20);           // 一读就遇到换行 → b 是空的！

实测（05_string_input.cpp 的"方式三"）：

【方式三 cin.get】请输入你的全名:   第一次读: "2026 Somewhere Lane"
  紧接着再读一次: ""  <- 空的！因为换行符还在队列里

所以用 get 的时候，末尾要手动再吃一个换行符：

cin.get(a, 20);
cin.get();                // 吃掉换行符（不接参数 = 只取走一个字符）

为什么会有 get 这么"别扭"的函数？ 因为它能让你知道为什么停：是读满 n−1 个字符了，还是遇到换行符了？ cin.get(a, 20) 遇到换行符时不会提取它，你可以用 cin.get() 单独处理。 这个"更细的控制"在某些场景是必要的（比如你要自己判断这一行有没有读完整）。

4.4 一个有用的技巧：getline 的返回值

cin.getline() 返回的是 cin 这个对象本身， 而 cin 在"流状态"下可以直接当 bool（真/假）用：

while (cin.getline(buf, 80))     // 读失败（比如读到文件末尾）时循环结束
{
    // 处理 buf
}

先解释一下"流状态"：cin 除了装数据，还随身带着一个"状态标签"， 记录"上一次读取成功了没有"。读成功了它算"真"，读失败了（比如输入没了）它算"假"。 所以 while (cin.getline(...)) 读作："只要还能读进来一行，就继续循环"。

📌 这个写法本课不要求掌握，看到能认出来就行。

5. ⭐⭐ 混合输入数字和字符串的陷阱（4.2.5，p98–99）

这是 99% 的 C++ 初学者都会踩的坑，而且现象非常诡异： 程序好像"吞掉"了一次输入。跑 示例代码/04_数组与字符串/06_mixed_input_trap.cpp 亲手体验。

5.1 问题现象

int year;
char address[80];

cout << "Enter the year: ";
cin >> year;                        // 输入 2026 然后按回车
cout << "Enter the address: ";
cin.getline(address, 80);           // ← 它【跳过】了你的输入！

cout << "address = \"" << address << "\"";   // 输出：address = ""

实测输出：

Enter the year: Enter the address:   year    = 2026
  address = ""   <- 空的！

5.2 原因：换行符还留在输入队列里

关键是要理解"你按的那个回车，也是一个字符"。 你在键盘上按回车，敲进去的不是"什么都不输入"，而是敲了一个换行符（'\n'）。

你输入：  2 0 2 6 \n
          └──┬──┘  └┬┘
      cin >> year   └── 这个换行符【没人取走】，留在盆里
     只取走了 2026

接下来 getline 一看：盆里第一个字符是 '\n'
  → "哦，这一行是空的" → 于是它读了个空字符串，直接返回

图示：

输入缓冲区（那个"盆"）：  [2][0][2][6][\n]
                         ↑
                   cin >> year 只吃到这里

缓冲区：      [\n]                    ← 换行符还在
                ↑
          getline 一读就看见换行 → 读到空行

注意 cin >> year 的行为：它读到 6 之后，遇到的第一个非数字字符是 \n， 它认为"这个数字到此为止"，于是把 6 取走就收工了——那个 \n 它留在盆里没动。

5.3 三种解法

// ---- 解法 1：读完数字后，手动吃掉换行符 ----
cin >> year;
cin.get();                          // ← 就这一行（不接参数 = 取走一个字符）
cin.getline(address, 80);

// ---- 解法 2：把两步连起来写 ----
(cin >> year).get();                // cin >> year 返回 cin，再对它调 get()
cin.getline(address, 80);

// ---- 解法 3：全部用 getline，数字自己转 ----
char buf[80];
cin.getline(buf, 80);
year = atoi(buf);                   // 字符串 → 整数（atoi 在 <cstdlib> 里）
cin.getline(address, 80);

💡 推荐：解法 1 最直观；解法 2 写熟了更简洁。 学会 std::string 后，解法 3 会更常用（用 stoi() 代替 atoi()， stoi 在 <string> 里，用法一样是把字符串转成整数）。

关于什么"吞掉"之类的怪现象，一句总结就够了：

🔑 换行符是「上一个 cin >> 读数字」留下的，所以要在「下一个读整行的操作」之前清掉它。

📌 教材 p98 用了一整节讲这个，因为它是每个人都会遇到的真实问题。 一定要亲手跑一遍，光看是记不住的。

5.4 ⚠️ 这个陷阱只在特定情况下才咬你

这一条非常重要，因为初学者常常"今天遇到、明天遇不到"，越试越糊涂。

cin >> year;
cin.getline(address, 80);      // ❌ 被换行符骗了 → address 是空的

但如果是这样：

cin >> year;
cin >> age;                    // ✅ 没问题！

为什么第二个没事？ 因为 cin >> 会自动跳过开头的空白符（空格、Tab、换行）， 所以残留在盆里的那个换行符，被它当"分隔符"跳过去了——它压根不在乎前面有几个空白。

四种组合，一张表看懂：

上一个操作 下一个操作 会出问题吗 为什么
cin >> year cin.getline(...) ❌ 会 getline 不跳空白，看到换行就当"空行"
cin >> year cin.get(...) ❌ 会 同上
cin >> year cin >> age ✅ 不会 >> 自己会跳过前面的空白
cin.getline(...) cin.getline(...) ✅ 不会 getline 会把自己那一行的换行符丢掉
cin.get(...) cin.get(...) ❌ 会 get 会把换行符留着，下一次又撞上
cin.getline(...) cin >> age ✅ 不会 >> 自己跳空白

🔑 一行总结： 只有当"下一个操作是 getline / get（要读整行）"时，残留的换行符才会咬你； 如果下一个是 cin >>，它自己会跳过空白，你根本看不出问题。

⚠️ 也正因为"看不出问题"，这个坑最坑： 同样的写法，一处报错、一处正常，很多人就以为是自己"运气不好"。

一个省心的习惯（在"先读数字、再读整行"这种场景下）： 每次 cin >> 读完数字 / 单个字符之后，顺手接一个 cin.get(); 把这个换行符吃掉。 多写这一行不会有害，但能同时防住上面那两种会出问题的情况。

⚠️ 但这个习惯有边界，别到处乱加： cin.get(); 是"取走一个字符"，它并不检查那个字符到底是不是换行符。 - 在"先读数字、再读整行"的场景里，盆里下一个必然是那个换行符，所以安全、推荐； - 但如果你的程序是逐个字符处理输入的循环（比如一个一个读字符做统计）， 那个 cin.get(); 会误吃掉一个本该被处理的字符，反而制造 bug。

一句话：知道自己在清什么，再清。

6. std::string 类（4.3，p99–105）

6.1 C 风格字符串的三大痛点

# 痛点 例子
1 要手动管大小，写小了就溢出 char s[5] = "hello!"; 装不下
2 不能整体赋值 s1 = s2; ❌ 编译错误
3 不能用 == 比较内容 s1 == s2 比的是地址，不是文字

第 3 点特别坑。实测（示例代码/04_数组与字符串/07_std_string.cpp）：

char ca[] = "apple";
char cb[] = "apple";
ca == cb                 // 结果是 false（打印出来是 0）！
strcmp(ca, cb) == 0      // 这才是比较内容，结果是 true（打印出来是 1）

为什么 ca == cb 是 false？ 因为数组名参与比较时，代表的是"地址"（和 3.6 节那个 letter_grade + 1 是同一件事）。 两个数组是两块不同的内存，门牌号当然不一样，所以比较的结果是"不相等"—— 哪怕它们装的内容一模一样。

要比较内容，得用 strcmp()（住在 <cstring> 里）：

  • strcmp(a, b) == 0 → 两个字符串内容相同
  • strcmp(a, b) < 0 → a 排在 b 前面（按字符编码比较）
  • strcmp(a, b) > 0 → a 排在 b 后面

注意这个约定的别扭之处："相等"的结果是 0，而 0 在 if 里是"假"！ 所以 if (strcmp(a, b)) 和 if (strcmp(a, b) == 0) 意思正好相反， 写的时候一定要把 == 0 写上。

6.2 std::string 把三个问题全解决了

#include <string>               // 必须包含这个头文件

std::string s1 = "Hello";
s1 = s1 + ", world!";           // ① 自动伸缩，不用管大小
std::string s2;
s2 = s1;                        // ② 可以直接赋值
if (a == b) { /* ... */ }       // ③ == 比较的是内容

std::string 是什么？ 它是一个"自带管理功能"的字符串类型： 你只管往里放字，它自己负责向系统申请内存、自己记着有多长、自己保证结尾有 '\0'。 所以上面三个痛点它都能解决：

痛点 std::string 怎么解决
1. 手动管大小 它自己管：不够了会自动去申请更大的空间再搬过去
2. 不能整体赋值 它重载了 =：s2 = s1; 就是"把内容复制过去"
3. == 比的是地址 它重载了 ==：a == b 比的是内容

📌 "重载"是什么意思？ 同一个符号（=、==、+），对不同类型做不同的事，这叫重载。 对 int 来说 + 是加法，对 std::string 来说 + 是"把两段文字接起来"。 现在不用深究，知道"std::string 上的 =、==、+ 都是被专门定义过的"就够了。

6.3 常用操作速查

std::string s = "Hello";

s.size()          // 长度（也可以用 s.length()，一样）
s.empty()         // 是否为空
s[i]              // 像数组一样用下标取字符
s1 + s2           // 拼接（生成新字符串）
s1 += s2          // 追加（修改 s1）
s.substr(0, 5)    // 取子串：从第 0 个开始取 5 个
s.find("llo")     // 查找，返回位置；找不到返回 std::string::npos
s.c_str()         // 转成 C 风格字符串（要和 C 函数交互时用）← 第 4 章 D 会用到

几个要注意的点：

  • s[i] 的下标也是从 0 开始的，和数组一样（s[1] 是第 2 个字符）。
  • s.find() 找不到时返回 std::string::npos—— npos 是一个特殊的大数字（"不存在的位置"）。 ⚠️ 判断"找到没找到"不能写 if (s.find(...) == -1)， 正确写法是 if (s.find(...) == std::string::npos)。
  • s.size() 返回的类型不是 int，是这个类专门定义的无符号类型。 和 int 混着用偶尔会出警告，遇到就知道是这里。

实测输出：

s.size()          = 5      (长度)
s[1]              = e      (像数组一样用下标取字符)
s.empty()         = 0      (是否为空)
s += " there"     -> Hello there
s.substr(0, 5)    = Hello  (取子串)
s.find("there")   = 6     (找位置，找不到返回 npos)

6.4 ⭐ string 的输入：getline(cin, s)

std::string line;
getline(cin, line);             // 注意：写法是 getline(cin, 变量)，【不用】写大小！

和 cin.getline(char数组, n) 的区别：

cin.getline(s, n) getline(cin, s)
参数 (char数组, 最大长度) (cin, string对象)
要写大小吗 要 不用（string 自己管）
属于 istream 类的成员函数 <string> 里的普通函数
安全吗 长度受保护 完全安全

📌 这是 C++ 里最容易混的一对写法，务必分清： cin.getline(...) 有那个点 .；getline(cin, ...) 没有点。

  • 看到 . → 是 cin 自己的功能 → 参数写 (数组, 大小)
  • 没有 . → 是一个独立函数 → 参数写 (cin, 变量)

一个更简单的记法：cin.getline 管的是 C 风格数组（所以要手动告诉它大小）， getline(cin, ...) 管的是 std::string（不用告诉大小）。

⚠️ 好消息是：getline(cin, s) 同样会自动丢掉那一行的换行符， 所以第 5 节那个陷阱在 string 版本里是一样的—— cin >> year; 之后接 getline(cin, line); 同样会读到空串，同样要 cin.get();。

6.5 C++11 其他形式的字符串字面值（教材 4.3.5，p104）

前缀 类型 例子 干什么用的
u8"..." UTF-8 u8"你好" 明确用 UTF-8 编码存文字
u"..." char16_t u"hello" 16 位宽的字符（UTF-16）
U"..." char32_t U"hello" 32 位宽的字符（UTF-32）
L"..." wchar_t L"hello" "宽字符"，Windows API 常用
R"(...)" 原始字符串 R"(C:\path\file)" 里面的 \ 不再是转义符

先说这些前缀是干什么的： 普通的 "..." 每个字符占 1 字节，只能装下很小一部分字符（英文够用，中文勉强）。 要想稳当地处理中文、日文这些字符，就得用"每个字符多占几字节"的类型—— 上面这几个前缀就是用来明确指定这件事的。

R"(...)" 最实用：普通字符串里写 Windows 路径要写成 "C:\\path\\file"（\\ 是转义）， 用原始字符串就可以直接写 R"(C:\path\file)"，所见即所得。

📌 本课只需要认识这几行字面值的写法，不用掌握它们的用法。 char16_t / char32_t / wchar_t 的大小和用法在第 4 章后面的课程里才会碰到。

7. 本课常见坑汇总（每条都有实测证据）

# 坑 后果
1 int a[5]; 然后访问 a[5] 越界！拿到垃圾值或破坏别的变量（不报错）
2 循环写 i <= 5（数组 5 个元素） 越界一整个元素，最常见的低级错误
3 char s[5] = "hello"; 装不下 '\0'，编译报错
4 以为 int a[5] = {1,2}; 剩下的也是垃圾值 其实自动补 0
5 b = a; 想复制数组 编译错误（数组不能整体赋值）
6 cin >> name 想读带空格的名字 只读到第一个空格
7 cin >> year; 之后立刻 cin.getline(...) 读到空行（换行符残留）
8 if (ca == cb) 比较 C 字符串内容 比的是地址，永远错。要用 strcmp(...) == 0
9 sizeof(s) 和 strlen(s) 搞混 差 1，考试必错
10 getline(cin, s) 写成 cin.getline(s, n) 或反过来 编译错误
11 cin.getline(name, 80) 而 name 只有 20 格 缓冲区溢出：可能不崩溃、看起来还正常（最危险）
12 用逐个字符 {...} 初始化字符串，忘了 '\0' 打印时越读越远，输出垃圾（也可能碰巧看起来正常）
13 letters + 1 想"把内容加一" 实际是"挪地址"，cout 打出空字符串（见 3.6 节）
