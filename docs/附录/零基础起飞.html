零基础起飞 · 学 C++ 之前先把这些搞明白

这篇是给谁看的：会开机、会上网、会用微信，但没打开过命令行、没听过「编译」「进程」这些词的读者。 这篇要解决什么：让你翻开第 1 章讲义时，不再被「文件」「程序」「编译」这些词卡住。 怎么读：不用背，不用记。每一节都让你自己动手点一下，点完你就懂了。 要多久：认真读完 + 跟着做，大约 60–90 分钟。可以在电脑前坐好再开始。

先给你吃一颗定心丸：下面所有东西都不是"高深知识"，只是没人跟你好好说过而已。 你现在觉得陌生的词，一小时以后会觉得"就这？"。

1. 电脑到底在干什么

1.1 先用一个比方：电脑是一间厨房

你在厨房里做菜，需要三样东西：

厨房里的东西 电脑里对应的东西 它是干什么的
灶台和炒锅 CPU（中央处理器） 真正干活、真正"算"的地方。所有计算都在这里发生
料理台面 内存（memory，也叫 RAM） 临时摊开正在处理的东西。切到一半的菜、正在炒的锅，都放这儿
冰箱和储物柜 硬盘（硬盘 / 磁盘 / 存储） 长期存放东西的地方。关火下班了，东西还在这儿

关键的一句话：

CPU 只会"算"，但它自己不记得任何东西；它要算的东西必须先从柜子（硬盘）搬到台面（内存）上，算完再考虑要不要放回柜子。

这就是为什么电脑开机要等一会儿——它正把一堆东西从"柜子"搬出来。

1.2 台面和柜子最大的区别是什么

这两个东西经常被搞混，但它们的脾气完全不一样：

内存（台面） 硬盘（柜子）
断电后会怎样 东西全没了 东西还在
容量 小（通常 8G / 16G / 32G） 大（通常 256G / 512G / 1T）
速度 快 慢很多（但比人快无数倍）
用来干什么 正在处理的东西 长期保存的东西

所以：

  • 为什么写文档要经常按 Ctrl+S 保存？因为保存 = 从台面挪进柜子。不保存，一断电就没了。
  • 为什么电脑卡的时候，往往是内存（台面）不够用了？台面堆满了，东西只能挤来挤去。
  • 为什么你说"我的照片存哪了"？在硬盘（柜子）里。关机能丢的那个，是内存。

📌 后面讲"程序"和"进程"的时候，会再回到"台面 / 柜子"这个比方。这两个词你现在只要记住结论：内存断电就没，硬盘断电还在。

1.3 名词对照，先混个眼熟

你以后会听到的说法 其实指的是
CPU、处理器、核心 灶台（算东西的）
内存、RAM、8G 内存 台面（临时的）
硬盘、C 盘、D 盘、磁盘、存储空间 柜子（长期的）
显卡、GPU 专门算画面（图形）的一整套家伙
主板 把上面这些连起来的地基和线路

现在不用记，眼熟就行。 后面每出现一次，我都会再说一次它是厨房里的谁。

2. 什么是「文件」

2.1 先说为什么会有"文件"这个东西

回到柜子的比方：东西要长期放在柜子里，不能是一堆散沙。

假设你写了一篇作文，关掉电脑，明天想接着写。那么：

  • 这篇作文必须被放到硬盘上（不然关机就没了）；
  • 它必须有个名字，不然几万个东西你认不出哪个是它；
  • 它必须是完整的一整块，不能撒得满硬盘都是碎片。

于是有了文件。

一句话定义：文件 = 硬盘上一整块有名字的数据。

拆开看这三个词：

词 什么意思
硬盘上 它在柜子里，断电能活下来
一整块 它是一个完整的整体，要么整份在，要么整份不在
有名字 你能靠名字找到它、区分它

2.2 文件里装的到底是什么

表面上你看到的是字、是图、是歌、是视频。但硬盘本身不理解"字"和"图"——它只会存 0 和 1。

所以，一个文件本质上就是一大串 0 和 1 排成的队。至于这串 0 和 1 到底该被理解成文字、图片还是声音，取决于你用哪个程序去打开它：

这串 0 和 1 交给谁 你看到什么
记事本 一堆文字（可能还是乱码）
看图软件 一张图片
音乐播放器 一段声音
视频播放器 一段画面

这解释了一件让新手很困惑的事：为什么同一个文件用不同软件打开，看到的东西完全不一样？ 因为文件本身只是数据，是打开它的程序在"解释"它。

2.3 一个你天天在用但没意识到的例子

你微信里发的照片、收到的 Word 文档、存在桌面上的作业——它们全都是文件。没有例外。

你现在就可以验证一下：

动手 ①：在桌面上随便找一张图片，右键 → 属性。看两个东西：一个是"类型"，一个是"位置"。 你会发现它有个类型（比如 JPEG 图像），也有个位置（一个以盘符开头的一长串东西）。

记住了"类型"和"位置"这两个词，下面两节就是专门讲它们的。

3. 文件的名字和扩展名

3.1 一个文件有两个身份

身份 长什么样 作用
主名（文件名） 我的作业 给你自己看的，让你知道这是啥
扩展名（后缀） .txt 给电脑看的，告诉系统"该用什么软件打开它"

合起来就是 我的作业.txt，中间那个点（.）是分隔符。

记法：点后面那截，是给电脑的暗号；点前面那截，是给人看的标签。

3.2 常见的扩展名都是什么

扩展名 叫什么 谁来打开 白话解释
.txt 纯文本文件 记事本 只有文字，没有任何格式（没有加粗、颜色、图片）
.jpg .png 图片文件 看图软件 一张图
.mp4 视频文件 播放器 一段视频
.docx Word 文档 Word 带格式的文字
.zip .rar 压缩包 解压软件 把很多文件打包成一个，方便传输
.exe 可执行文件 双击就运行 能"跑起来"的东西，后面第 5 节专门讲
.cpp C++ 源代码文件 记事本 / 代码编辑器 你以后天天写的东西：用 C++ 语言写的指令
.h .hpp 头文件 编辑器 也是源代码的一部分，第 2 章以后会用到

📌 .cpp 和 .exe 的关系，是整篇材料里最重要的一对关系。先记住一句话：.cpp 是"菜谱"，.exe 是"按菜谱做好的一盘菜"。

3.3 ⚠️ 重点：Windows 默认藏着扩展名，你必须把它打开

这是本节最需要你动手的一步，对学编程来说它是刚需，不是可选项。

问题是这样：Windows 出厂设置默认不显示扩展名。也就是说，一个真名叫 作业.txt 的文件，在资源管理器里只显示成 作业。

这在平时没太大关系，但学编程会出大问题：

你会遇到的坑 不显示扩展名的后果
编译器要求文件必须叫 demo.cpp 你看到的是 demo，以为自己起对了名字，其实可能叫 demo.cpp.txt
文件双击没反应 你不知道它是 .txt 还是 .exe，无法判断该不该双击
老师让你改文件类型 你连"类型"藏在哪都看不见

"文件资源管理器"是什么：就是你平时点开"此电脑"、"我的文档"、"D 盘"时弹出来的那个窗口。任务栏上那个黄色文件夹图标就是它。按 Win + E 也能直接打开（Win 键就是键盘左下角那个有窗户图标的键）。

动手 ②：把扩展名显示出来（Windows 10 / 11）

  1. 按 Win + E 打开文件资源管理器（或者双击任务栏上的黄色文件夹图标）。
  2. 看窗口最上面那一排按钮，找到 「查看」（View），点它。
  3. 在展开的菜单里找到 「显示」（Show），鼠标移上去。
  4. 在子菜单里找到 「文件扩展名」（File name extensions），点一下，让它前面出现勾 ✔。
  5. 关掉窗口再打开，随便看几个文件，名字后面是不是多出了 .txt、.jpg、.exe？

做完立刻验证效果：

  • 去桌面看看，有没有叫 xxx.exe 的图标（快捷方式不算）；
  • 去"下载"文件夹看看，是不是有 .zip、.pdf。

别慌，这一步不会弄坏任何东西。就算点错了，再点一下把勾取消就还原了。

📌 如果找不到「查看」按钮：在资源管理器窗口里按 Alt 键，会冒出一条老式菜单栏，里面有「查看」；或者右键窗口空白处，也能找到「查看」选项。不同 Windows 版本位置略有差别，但关键词永远是查看 → 显示 → 文件扩展名。

3.4 显示扩展名之后，你要小心一件事

一旦扩展名显示出来了，你会发现可以重命名它（右键 → 重命名，或者按 F2）。

这说明扩展名是可以随便改的，但随便改会出乱子。 比如：

  • 把 照片.jpg 改成 照片.txt：文件内容一点没变，还是那张图，但你双击它会用记事本打开，看到一屏乱码。改扩展名不会转换文件内容，只是换了"用谁来打开"的约定。
  • 把 程序.exe 改成 程序.txt：程序本身没坏，但你双击它不会运行了。

新手守则：除非你明确知道自己在干什么，不要手动改扩展名。写 C++ 时，扩展名要老实写成 .cpp。

4. 什么是「文件夹」和「路径」

4.1 为什么需要文件夹

假设硬盘是个大柜子，你往里扔了 5 万个文件，全平铺在一起。然后你要找一张上周拍的猫照片——你打算怎么找？

所以需要"分类的抽屉"。文件夹（也叫"目录"）就是硬盘上的抽屉。

一句话：文件夹本身也是一个"东西"，只不过它里面装的不是数据，而是"一堆文件和其他文件夹的清单"。

对比 文件 文件夹
里面装什么 数据（字、图、声音） 其他文件和文件夹
能不能双击打开 能（用某个程序打开内容） 能（进入它，看里面有什么）
断电会丢吗 不会 不会
举例 作业.txt 我的文档、下载

文件夹可以一层套一层（抽屉里还有小抽屉），这就叫目录树——因为它长得像一棵倒过来的树：根在最上面，往下不断分叉。

4.2 什么是「路径」

问题来了：你有一层套一层的抽屉，你怎么精确地告诉别人"那个文件在哪"？

答案就是路径。它就是文件的快递地址。

一句话：路径 = 从某个起点开始，一层一层走到这个文件，中间要用什么名字，全写下来。

看一个真实的例子：

C:\Users\小明\Desktop\test.cpp

从左往右，一段一段拆开看：

这一段 叫什么 什么意思
C: 盘符 哪一个大柜子。电脑可以把硬盘分成几个"盘"：C 盘、D 盘、E 盘。C 盘通常是系统盘
\ 反斜杠 分隔符，相当于地址里的"→"，表示"进到下一层去"
Users 文件夹名 C 盘里的 Users 文件夹（中文系统里可能显示为"用户"）
\ 分隔符 继续往下
小明 文件夹名 Users 里面的 小明 文件夹。这就是你的用户名文件夹，你的桌面、下载、文档其实都住在它下面
\ 分隔符 继续往下
Desktop 文件夹名 桌面。中文系统里显示为"桌面"，但实际文件夹名就是 Desktop
\ 分隔符 继续往下
test.cpp 文件名 最后一段是文件本身，它前面所有内容就是它的"地址"

所以完整读法是：C 盘 → 用户 → 小明 → 桌面 → 名字叫 test.cpp 的那个文件。

就像一个地址：中国 → 江苏省 → 南京市 → 某小区 → 3 栋 502。每一段都不能少，少一段就找不到。

4.3 两个必须知道的细节

细节一：Windows 用反斜杠 \，网上常见正斜杠 /

写法 出现在哪
C:\Users\小明\Desktop\test.cpp Windows（你现在的系统）
/home/xiaoming/test.cpp Linux、macOS

学 C++ 的时候你还会遇到第三种写法：C:\\Users\\...（两个反斜杠）。那是因为在 C++ 代码里，单个反斜杠有特殊含义，所以要写两个来表示"我就是要一个反斜杠"。这个第 2 章会讲，现在别纠结。

细节二：文件夹名带空格是个坑

如果路径里有空格，比如 C:\我的 文档\test.cpp，在命令行里会被理解成"两段"。所以新手建议：以后建文件夹、起文件名，一律不要用空格和中文。

推荐 不推荐 为什么
cpp_learn 我的 C++ 学习 空格让命令行误解，中文可能遇到编码问题
test.cpp 测试 1.cpp 同上
chapter01 第 1 章 同上

用下划线 _ 代替空格，是最省事的做法。

4.4 绝对路径 vs 相对路径

这是新手最容易懵的一对词，但其实用一个"问路"的比方就懂了。

场景：有人问你"邮局怎么走？"

回答 A："中国 → 江苏省 → 南京市 → 中山路 → 88 号。" 回答 B："从这儿往前走，第二个路口左转。"

  • 回答 A 是绝对路径：从最顶上的起点（盘符）开始，一路写到底。不管你在哪问，答案都一样。
  • 回答 B 是相对路径：从你当前站的位置开始算。换个地方问，同样的回答就指到别处去了。
绝对路径 相对路径
从哪儿算起 盘符（C:\） 你"现在所在的位置"
长什么样 C:\Users\小明\Desktop\test.cpp test.cpp（就在当前位置）
Desktop\test.cpp（当前位置下的 Desktop 里）
换个目录还有效吗 有效，永远指向同一个文件 可能失效，因为"当前所在位置"变了
什么时候好用 要精确说明"就是这个文件" 在当前目录里干活，懒得写一长串

相对路径里还有两个符号，提前认识一下：

符号 读作 意思
. 一个点 当前位置（我自己这儿）
.. 两个点 上一层（回到父文件夹，"退一步"）

举个例子，假设你现在"站"在 C:\Users\小明\Desktop 里：

你写的 实际指的是
test.cpp C:\Users\小明\Desktop\test.cpp
..\test.cpp C:\Users\小明\test.cpp（退到上一层再找）
..\Documents\a.txt C:\Users\小明\Documents\a.txt

📌 怎么知道"我现在站在哪"？在文件资源管理器里，就是地址栏显示的那一串。在命令行里，就是提示符前面那一串（第 8 节会看到）。写相对路径前，先确认自己站在哪。

4.5 马上验证一下

动手 ③：打开文件资源管理器，在地址栏里点一下（整个路径会变成可复制的文字），看一眼完整路径长什么样。然后按 Win + E 新开一个窗口，进到"下载"文件夹，再看一次地址栏。

观察一下：这两次的路径，前面几段是不是一样的？（提示：都是 C:\Users\你的用户名\...）

5. 什么是「程序」

5.1 程序就是"硬盘上的一个文件"

你现在已经知道：文件是硬盘上一整块有名字的数据。

那么程序呢？答案是——程序也是文件，没有什么神秘的。

一句话：程序 = 一个存在硬盘上的文件，里面装的是一串"给 CPU 的指令"。

第 1 节说过，CPU 只干"算"这一件事。但 CPU 不会自己想"我该算什么"，它得有人告诉它一步步做什么。这一串"一步步做什么"的说明，就是指令。

程序文件，就是这些指令被打包存起来的结果。

比方 对应
一份菜谱（写在纸上，放在柜子里） 程序文件（.exe，躺在硬盘上）
你照着菜谱开始炒菜 运行程序（CPU 开始一条条执行指令）

关键区别：菜谱放在抽屉里的时候，菜不会自己出来。程序躺在硬盘上的时候，它什么也没干。

5.2 ⚠️ 重点区分：文本文件 vs 可执行文件

这是新手最容易踩的坑，一定要看清楚。

文本文件（.txt .cpp .md） 可执行文件（.exe）
里面装的是什么 给人看的文字 给 CPU 执行的机器指令
谁看得懂 人（你、我） 电脑
双击会怎样 用记事本打开，你能读到内容 运行！真的干活！
谁生成它 你用键盘敲出来的 编译器生成的（第 7 节讲）
能不能直接改 能，随便改 一般不能（打开就是乱码）

所以，最重要的一句话：

双击 .cpp 文件，什么都不会发生（最多打开记事本让你编辑），因为它只是给人看的文字。 双击 .exe 文件，程序才会跑起来，因为它里面是 CPU 能执行的指令。

"双击没反应"是新手最常见的第一号困惑。 记住这个区别，你就不会困惑了：你写的是"菜谱"，还没有人把它做成"菜"。

5.3 一个细节：.exe 文件看起来像乱码，这是正常的

你以后可能会好奇，用一个叫"记事本"的程序去打开一个 .exe（右键 → 打开方式 → 记事本）。你会看到一屏谁也看不懂的方块和怪符号。

这是正常的，不是文件坏了。 因为 .exe 里的内容是给 CPU 看的数字，而记事本只会把数字当文字解释——"解释错了"，所以看到乱码（这个现象第 9 节还会再讲一次）。

所以，.exe 的用法是：双击运行，不要打开看。

6. 什么是「进程」和任务管理器

6.1 从"死文件"到"活东西"

上一节说：程序躺在硬盘上的时候，什么也没干。

那么你双击它之后，发生了什么？

步骤 发生了什么 用厨房比方
1 系统把 .exe 里的指令从硬盘搬进内存 把菜谱从柜子里拿出来，摊在台面上
2 CPU 开始一条条执行这些指令 厨师照着菜谱开始炒
3 程序需要的数据也放在内存里 切好的菜、调料都摊在台面上
4 你关掉窗口，系统把内存里的东西清掉 收拾台面，菜谱放回柜子

第 1–3 步的状态，就叫"进程"。

一句话：进程 = 一个正在运行的程序的实例，它活在内存里，正在占用 CPU。

程序是"死"的（硬盘上的文件），进程是"活"的（内存里正在干活的东西）。 同一个程序可以同时开好几个进程——比如你开三个记事本窗口，就是三个进程。

程序（program） 进程（process）
在哪 硬盘（柜子） 内存（台面）
状态 死的，安静的 活的，正在吃 CPU 和内存
关机后 还在 没了
能有几个 一个 .exe 就是一个 可以同时有好几个
怎么产生 编译器生成 双击运行它

📌 为什么学编程必须懂这个：你写的程序会变成进程。程序写得不对，进程就可能失控——把内存吃光、把 CPU 占满到 100%、窗口点不动。这时候你必须知道怎么找到它、怎么弄死它。这就是下面要讲的。

6.2 任务管理器是什么

任务管理器是 Windows 自带的一个"监控台"，它让你看到：

  • 现在有哪些进程在跑；
  • 每个进程吃了多少 CPU、占了多少内存；
  • 谁在偷偷用网络；
  • 不想要谁，可以强制把它结束掉。

为什么一般人也要会这个：电脑卡的时候，你能看出是哪个程序在捣乱；软件假死（窗口变灰、点不动）的时候，你能把它关掉，不用重启电脑。

6.3 手把手：怎么打开任务管理器

最简单的方法（推荐记住这个）：

同时按 Ctrl + Shift + Esc 三个键。

对，就这么简单。三个键一起按下去，任务管理器窗口就出来了。

其他方法（万一忘了上面那个）：

方法 操作
右键任务栏 在屏幕最下面那条横条（任务栏）的空白处，右键 → 任务管理器
万能安全键 按 Ctrl + Alt + Delete，在出现的蓝屏菜单里点「任务管理器」
开始菜单搜索 按 Win 键 → 直接打字 任务管理器 → 回车
老手方式 按 Win + R → 输入 taskmgr → 回车

"任务栏"是什么：屏幕最下面那一条，左边有开始按钮，右边有时钟，中间是你打开的程序图标。找不到就看看最底下。

6.4 任务管理器能看什么、能干什么

打开后，如果是精简界面（只有几个正在运行的程序），点左下角 「详细信息」 展开完整列表。

你会看到一张表，每一行是一个进程，几列关键信息：

列名 什么意思 怎么用
名称 这个进程是谁 找出捣乱的是哪个程序
CPU 它现在占多少 CPU（越大越忙） 长期接近 100% 说明有程序在疯狂算
内存 它现在占了多少内存（台面） 某程序占了几 G，说明它是"大块头"
磁盘 它现在读写硬盘有多频繁 卡硬盘的时候看这列
网络 它在不在传数据 看谁在偷跑流量

两个最实用的操作：

操作一：找出占资源最多的

在「CPU」或「内存」这一列的标题上点一下，列表就会按这一列排序。再点一下反向排。这样谁最贪心，一眼就看到。

操作二：结束任务（俗称"杀掉进程"）

选中那一行 → 点右下角 「结束任务」（或者右键 → 结束任务）。

什么时候该用它：

情况 该怎么办
某个软件窗口变灰、点不动、转圈不停 结束它的任务。多数情况下不用重启电脑
你的程序写错了，界面卡死 结束它。这是学编程时最常用的一招
你写的程序在死循环，风扇狂转、电脑发烫 赶紧结束它。它在占满 CPU

📌 "死循环"是什么：你本来想让程序做 10 次，结果不小心写成了"永远做下去，没有停止条件"。它就真的永远做下去了。CPU 被它占满，风扇开始狂转——别慌，这非常正常，所有写程序的人都干过。 结束任务就行，代码改一改再来。

注意：结束任务 = 强制关掉，程序来不及保存就没了。所以别拿它去关正在写文档的 Word，会丢东西。它是"紧急刹车"，不是"正常停车"。

6.5 动手验证

动手 ④：按 Ctrl + Shift + Esc 打开任务管理器。 1. 点「详细信息」。 2. 在「内存」那一列标题上点一下，看哪个进程排第一。 3. 找到你现在正在用的浏览器，看它占了多少内存。 4. 随便开一个记事本，再回来看，是不是多了一个进程？关掉记事本，它是不是消失了？

做完这一步，你就已经比很多同班同学多会一件事了。

7. 什么是「代码」「编程语言」「编译器」

7.1 从"指令"到"代码"

第 5 节说：程序里装的是"给 CPU 的指令"。

但 CPU 能懂的指令长这样（一串数字）：

48 8B 05 B1 1A 00 00

这是机器码——CPU 唯一懂的语言。问题是：人没法用这个写东西。 写十行就晕了，而且没人看得懂自己在写什么。

那怎么办？让人写人能看懂的东西，再让工具翻译成机器码。

  • 人能看懂的东西 = 用某种编程语言写出来的代码；
  • 负责翻译的工具 = 编译器。

7.2 代码是什么

一句话：代码 = 用某种编程语言写的、给电脑的指令单。

"指令单"这个词是故意的。它不是散文，不是作文，它是一张一步接一步的清单，必须精确到电脑能一条条执行。

以后你会写的代码大概长这样（先看一眼，不用懂）：

#include <iostream>
int main()
{
    std::cout << "你好，世界！" << std::endl;
    return 0;
}

这 7 行就是你亲手写的"指令单"。它的意思是：准备一下打印功能 → 开始 → 打印"你好，世界！" → 换行 → 结束 → 报告一切正常。

现在的你看它像天书，这完全正常。第 2 章会一行一行拆开讲。现在你只要知道：这东西叫"代码"，它是给人看的，电脑还看不懂。

7.3 编程语言是什么，为什么需要它

一句话：编程语言 = 一套人和电脑之间的"中间语言"，人写起来还算顺手，同时有现成工具能把它翻译成机器码。

为什么要有这么一层？因为两边直接对话不可能：

谁 只能懂
CPU 机器码（一串数字）
人 自然语言（中文、英文）

编程语言就是架在中间的桥。 它比自然语言严格得多（因为电脑不能猜），比机器码好读得多（因为人得看懂）。

C++ 就是众多编程语言里的一个。别急着问"C++ 和别的语言哪个好"，现在的答案是：它们都是桥，只是造法不同。

7.4 编译器是什么：一个"翻译官"

一句话：编译器 = 一个程序，它的工作是把你写的 C++ 代码翻译成 CPU 能懂的机器码。

注意这句话里有个有意思的地方：编译器自己也是个程序。（就像那个帮你把中文菜谱翻成英文的人，他自己也是个人。）

完整的链路是这样：

角色 比方里是谁 在 C++ 里是什么
你写的字 中文菜谱 源代码（test.cpp）
翻译官 把中文翻成英文的人 编译器（g++）
翻译结果 英文菜谱 机器码 → 最终变成 .exe
执行的人 只会英文的厨师 CPU

三个关键点：

  1. 厨师（CPU）只看得懂英文（机器码）。 你的中文（C++ 代码）写得再漂亮，不翻译，电脑一个字都执行不了。这就是为什么双击 .cpp 什么都不会发生——菜谱还没翻译，厨师看不懂。
  2. 翻译是一整本一起翻的，不是做一步翻一句。这就是 C++ 这类"编译型语言"的特点。
  3. 翻译官会发现菜谱里的错。 比如你少买了一样东西（少写了一个分号），翻译官当场就说"这不行"，根本轮不到厨师下厨。这就是"编译错误"——你在第 1 章讲义里会看到这个词，它其实是个好消息：它在程序运行之前就帮你拦住了错误。

7.5 一个重要的心理准备

你的直觉 实际情况
我写完代码就能用了 不，还得编译一次，生成 .exe
改了代码文件就变了 不，改的是菜谱，exe（做好的菜）还是老的
程序能跑就说明写对了 不一定，能跑只代表"翻译官没意见"

最后一条是第 1 章的隐藏重点："能编译通过"和"程序是对的"是两件完全不同的事。 编译器的职责是检查"你写的语法对不对"，不是"你的想法对不对"。

📌 关于"编译四步"：编译器干活其实分四步（预处理、编译、汇编、链接），每一步产出什么文件，第 1 章讲义会详细讲。你现在完全不用管这四步，只要脑子里有一个画面就够了：一个翻译官，把中文菜谱翻成英文菜谱，翻之前还会检查有没有漏掉的材料。

8. 什么是「命令行 / 终端」

8.1 为什么还要学打字下命令

你可能会想：我都用鼠标点这么多年了，为什么学编程还要打字？

三个很实在的理由：

理由 说明
有些工具根本没有"窗口" 编译器 g++ 就是这样一个程序——它没有按钮、没有界面，你只能通过打字来用它
打字更快、更精确 一次编译、一次运行，两行字搞定，不用点鼠标找半天
报错信息都出现在那里 你写错代码时，编译器告诉你的错误信息，就是一行行文字打在这个黑窗口里的

一句话：命令行 = 一个"用打字代替点鼠标"的窗口。

它不是"高级模式"，也不是"黑客专用"。它只是另一种操作方式：鼠标是"指哪儿点哪儿"，命令行是"说清楚要它干什么"。

8.2 名词先对齐一下

你可能听过好几个称呼，其实基本是一回事：

叫法 说明
命令行（command line） 强调"打字输入命令"这种方式
终端（terminal） 强调"这是一个让你打字的窗口"
控制台（console） 老叫法，基本同义
cmd Windows 上最经典的那个命令行程序的名字
PowerShell Windows 上更新更强的命令行程序，用法类似

先别管哪个更好，用哪个都行，学 C++ 都够用。

8.3 手把手：怎么打开它

方法一（最简单，推荐）： 1. 按一下键盘左下角的 Win 键（有窗户图标那个）； 2. 直接打字：cmd； 3. 看到"命令提示符"出现，按 回车。

方法二：同样的步骤，打字 powershell，按回车。

打开之后你会看到一个黑底（或者蓝底）的窗口，里面有一行字，末尾在闪一个光标，大概长这样：

Microsoft Windows [版本 10.0.19045.3803]
(c) Microsoft Corporation。保留所有权利。

C:\Users\小明>

别慌，这是正常的。 它没有坏，也没有被黑。最后那一行 C:\Users\小明> 就是它在问你："你现在站在哪，要我干什么？"

📌 那个 C:\Users\小明> 叫什么：叫提示符（prompt）。它告诉你两件事： 1. 你现在站在哪个目录（C:\Users\小明，这就是你的"当前位置"）； 2. 它在等你打字（打完按回车才会执行）。

这正好接上第 4 节讲的相对路径——提示符里的路径，就是"相对路径从哪儿算起"的那个起点。

关掉它：直接打 exit 按回车，或者点右上角的 ×。放心，关掉命令行不会关机，也不会弄坏东西。

8.4 四个最基础的命令

在命令行里，打完命令必须按回车才会执行。这是新手最常忘的一步。

（1）dir —— 看这个目录里有什么

dir = directory（目录）的缩写。

C:\Users\小明> dir

输出大概长这样：

 驱动器 C 中的卷没有标签。
 卷的序列号是 1234-ABCD

 C:\Users\小明 的目录

2024/03/15  09:12    <DIR>          Desktop
2024/03/15  09:12    <DIR>          Documents
2024/03/15  09:12    <DIR>          Downloads
2024/03/20  21:05             1,024 备注.txt
2024/03/21  14:30             2,560 test.cpp
               2 个文件          3,584 字节
               3 个目录  98,765,432,100 可用字节

怎么读这张表：

你看到 意思
<DIR> 这一行是文件夹，不是文件
备注.txt test.cpp 这些是文件
中间那串数字 文件大小（字节）
最后两行 统计：几个文件、几个目录、硬盘还剩多少空间

📌 类比一下：dir 就等于你用鼠标打开一个文件夹、用眼睛看里面有什么。只不过这里是"用打字问它，它用文字回答你"。

（2）cd —— 换目录（"走到别的地方去"）

cd = change directory（改变目录）。这是四个命令里最重要的一个。

用法一：往下走

C:\Users\小明> cd Desktop

执行后，提示符变成：

C:\Users\小明\Desktop>

刚才你站在"小明"文件夹里，现在站到它下面的"桌面"里了。

用法二：往上退一步

C:\Users\小明\Desktop> cd ..

提示符变回 C:\Users\小明>。还记得第 4 节的 .. 吗？就是"上一层"。

用法三：一步跳到任意位置（绝对路径）

C:\Users\小明> cd C:\Users\小明\Documents

不管你原来站在哪，这一下就跳过去了。这就是绝对路径的好处。

📌 为什么编程时天天用 cd：因为编译器 g++ 干活的地方就是"你当前站着的目录"。你得先 cd 到你的代码所在的文件夹，才能编译它。"先 cd 到代码所在的文件夹"是学 C++ 的第一个日常动作。

（3）cls —— 清屏

cls = clear screen（清屏幕）。

C:\Users\小明> cls

执行后，满屏的字全都没了，只剩最上面一行干净的提示符。

别慌：它只是"擦干净白板"，没有删掉任何文件，也没有结束任何程序。只是让屏幕好看一点。

（4）exit —— 关掉命令行窗口

C:\Users\小明> exit

窗口关闭。跟点 × 一样。

8.5 四个命令小结表

命令 全称 干什么 提示符会变吗
dir directory 列出当前目录里的文件和文件夹 不变
cd 目标 change directory 换到另一个目录 会变（这是判断自己站对没有的方法）
cls clear screen 清空屏幕 不变
exit —— 关闭窗口 窗口没了

通用小技巧：

想干的事 怎么做
重看刚才打过的命令 按 ↑ 上箭头（能翻历史记录，非常好用）
命令打到一半想重来 按 Esc 清空这一行
补全文件/文件夹名字 打前几个字母，按 Tab 键，它会自动补全
复制粘贴 老的 cmd 里要用右键粘贴；PowerShell 里可以 Ctrl+V

8.6 现在动手试一遍

动手 ⑤：打开 cmd，按顺序打下面这几条，每条打完按回车，注意提示符的变化：

dir cd Desktop dir cd .. cls exit

重点观察：每次 cd 之后，提示符最前面那一串有没有变？这就是"你现在站在哪"。

⚠️ 如果提示 系统找不到指定的路径：说明你打的目录名不存在（可能你电脑上的桌面文件夹不叫 Desktop，或者名字大小写有差）。没关系，打 dir 看看实际有哪些文件夹，照着抄一个名字进去。打错命令完全不会弄坏电脑，最坏的结果就是它说"找不到"，你再打一次。

9. 字符编码和乱码是怎么回事

9.1 先看一个你一定遇到过的现象

打开一个从网上下载的文本文件，里面是这样的：

ÎÒ°®±à³Ì

或者这样的：

æˆ‘çˆ±ç¼–ç¨‹

又或者是这样的：

����

这不是电脑坏了，也不是文件中毒了。 这是"编码不匹配"。

9.2 用"密码本"来理解

第 2 节说过：硬盘上存的其实全是数字（0 和 1），不存在"字"。

那"字"是怎么变出来的？靠一本对照表：

一个数字 ↔ 一个字符 的对照关系，就叫字符编码（character encoding）。

比方：电脑里存了一个数字 65。

你用的对照表 65 被读成什么
表 A 字母 A
表 B 某个汉字
表 C 某个符号

同一堆数字，用不同的"密码本"去读，得到完全不同的字。 这就是编码。

一句话：字符编码 = 电脑"数字 ↔ 文字"的翻译对照表。

9.3 为什么会有好几本"密码本"

因为历史原因，不同地方各搞各的：

编码名 谁在用 特点
ASCII 最早的，只管英文 只够表示英文字母、数字、标点，装不下汉字
GBK 中文 Windows 的默认 能装汉字，是中国早年自己定的标准
UTF-8 现在国际上通用 全世界的字都能装，是现在的推荐做法

ASCII 装不下汉字，所以中国必须自己再定一套（GBK）。后来大家都想统一，就有了 UTF-8。结果就是：老系统习惯用 GBK，新软件喜欢用 UTF-8，两边一见面就可能打架。

9.4 于是就有了乱码

回到中文 Windows 的场景：

环节 用的密码本
中文版 Windows 的命令行（cmd），默认 GBK
很多现代编辑器、编译器的输出，默认 UTF-8

一方用 GBK 写，另一方用 UTF-8 读 → 读出来的东西全是错的 → 乱码。

就像一个中国人用中文写了封信，收信人拿英文字典去查——每个符号都能查到一个"对应物"，但整句话毫无意义。

记住这个结论就够了：

乱码不是电脑坏了，是"读的时候用错了密码本"。

9.5 顺手看一眼你电脑用的是哪本

动手 ⑥：打开 cmd，输入这条命令：

chcp

你会看到类似这样的输出：

活动代码页: 936

936 就是 GBK 的编号（中文 Windows 的默认）。如果是 65001，那就是 UTF-8。

想临时换成 UTF-8，可以输入 chcp 65001（临时生效，关掉窗口就恢复）。

现在不用去折腾这个。 你只需要建立一个认知：以后看到乱码，第一反应应该是"编码不匹配"，而不是"电脑坏了"。 具体怎么解决，等你真的遇到时再查也来得及。

📌 提前打个预防针：学 C++ 的过程中你一定会遇到乱码，特别是程序输出中文的时候。到那时你至少知道该往哪个方向想。这是所有人都会经过的一关，不是你特别笨。

10. 我改了代码，为什么运行结果没变？

这是新手问得最多的一个问题。答案已经在第 7 节埋好了：

你改的是"菜谱"（.cpp），但你运行的是上次做好的"菜"（.exe）。菜不会因为你改了菜谱就自己变。

10.1 完整的正确流程

每次改完代码，正确的顺序是：

步骤 做什么 用鼠标的说法 用命令行的说法
1 改代码 在编辑器里改，然后保存（Ctrl+S） 保存
2 重新编译 点"编译"按钮 g++ test.cpp -o test.exe
3 运行新的 exe 双击新生成的 .exe test.exe

第 2 步是新手最常漏掉的一步。

10.2 为什么必须重新编译

因为 .cpp 和 .exe 是两个独立的文件：

test.cpp test.exe
里面是什么 你写的 C++ 文字 翻译好的机器码
谁生成 你的键盘 编译器
改了代码后 变了（新菜谱） 没变（还是上次那盘菜）

编译器不会"盯着"你的文件自动重做。 除非你让它再翻一遍，否则 .exe 永远是你上次编译时的那个老版本。

10.3 一个很坑的细节：双击了"旧的 exe"

新手还常犯另一个错：

情况 发生了什么
你有两个 exe：test.exe（旧的）和 test_new.exe（新的） 你双击的是旧的那个
你在别的文件夹里还留着一份老 exe 你双击的是别的文件夹里那份

建议：编译前先看清楚输出文件的路径，运行前看清楚自己双击的是哪个文件。这条以后能帮你省下好几个小时的抓瞎。

10.4 症状对照表

你看到的现象 大概率原因 怎么办
改完代码，结果一模一样 没重新编译 再编译一次
编译了，还是老的 编译器报错了，旧的 exe 还在，你又双击了它 看编译输出，有没有 error
双击 exe 一闪而过 程序跑完就自动关了（正常行为） 在命令行里运行它，就能看到输出
双击 exe 没反应 你双击的可能是 .cpp 检查扩展名（第 3 节）
提示"拒绝访问" 程序可能还在运行 去任务管理器结束它（第 6 节）

第 2 行特别重要：编译失败了，上次那个旧的 .exe 还留在硬盘上。你双击它，当然还是老结果——于是你以为"改了没用"，其实是新的根本没生成出来。

📌 养成一个习惯：编译之后，看一眼有没有报错。没有报错，才去运行。这个习惯会让你少走无数弯路。

12. 动手清单：读完请做完这 10 件事

光读不做，等于没读。 下面这 10 件事，每件都不超过 5 分钟，请全部做一遍：

# 做什么 对应小节
1 打开文件资源管理器，把文件扩展名显示出来，然后随便看 5 个文件的后缀 第 3 节
2 在地址栏点一下，看一个完整路径长什么样，认出哪几段是文件夹、哪段是文件名 第 4 节
3 按 Ctrl + Shift + Esc 打开任务管理器，按内存排序，找出最占内存的进程 第 6 节

7 随便找一个 .txt 文件，右键 → 属性，看"类型"和"位置"两项 第 2 节
8 在桌面上新建一个文件夹，名字用纯英文 + 下划线（比如 cpp_learn），不要有空格 第 4 节
9 在命令行里 cd 到你刚才建的那个文件夹，用 dir 确认自己站对了地方 第 4、8 节
